## ② 运行时分型：真实时序下 a 类不可达（阻塞项）

探针：`node tests\probe-1.1.0\verify-021-runtime.mjs`（自带 harness，仅借 dev 的 `compress-helpers` 造事件）

```
FAIL RT-A-real-order-repost-is-accepted :: skipped=b-class-loss accepted=0 loss=1
PASS RT-B-bclass-is-unacceptable        :: skipped=["b-class-loss"] loss=["unacceptable"]
PASS RT-C-skip-audit-fields-complete    :: sessionId/cycle/compactionId/ruleSeq/kind/lossClass 齐全
```

**根因**：`runtime.js` 的 `hostReposted()` 用**重建那一刻**的 `postSurfaceNodes` 判 a 类（`runtime.js:2338-2347`）。真实时序是 `compaction/end` 之后**下一轮**宿主才写 `system/message`（`53ece2c2`：01:12:15 压缩 → 01:27:48 才写 74584），所以重建时永远看不到重发副本 → 每条 skip 都判 `b-class-loss` → `compaction-loss(unacceptable)`。

**为什么 564/564 没抓到**：`test/dsh-021-rebuild-a.test.mjs:84-96` 把重发副本插在 `compaction/end` **之前**（生产不可能出现的顺序），才让 `postSurface` 里出现重发节点。这是用造不出的时序验证了 a 类路径。

## ③ a/b 判别式（定稿，给开发照抄）

对每条被 shadow 的 `system/message` 规则 `r`，按顺序：

1. **`kind` 缺失/空 → `b`**（一律从严，**禁止**把两条 `kind=null` 互相配对当 a）；
2. **snapshot 里已过期**：压缩起点 surface 上存在**同 kind 且 `seq > r.seq`** 的 `system/message` → `a`（该副本是过期修订版，模型当前看到的是更晚那条；不要求逐字节）；
3. **延后比对**（必须在**下一次 `system/message` 落盘后**判，不能在重建时判）：取压缩后该会话第一条 `system/message`；
   - `sha256(其文本) == sha256(r.text)` 或 `其文本.includes(r.text)` → `a`；
   - kind 不同 / 文本不同 / 根本没有下一条 → `b`；
4. 第 3 步未落定前，状态记 **`unclassified`**，不计入 a；判据按 `unacceptable=0 && unclassified=0`。

补充（数据面）：本机 6 种 system-prompt 文本两两**互不包含**（4066/5775/7095/7501/7510/7847/8040 各是完整快照），所以第 2 步的"过期修订"只能靠**位置**（seq 更晚、同 kind）判定，不能靠包含关系。

## ⑤ 结论

- **不可提装机**（阻塞：`RT-A`）。
- 修法（二选一，必须配套）：
  1. **改变判定时机**：skip 先记 `unclassified`，在**下一次 `system/message` 写入**时补判 a/b 并补发 `compaction-loss-accepted`；判不出保持 `unacceptable`。
  2. 同时补第 2 条"过期修订"的同步判定（否则已过期副本仍会被判 b）。
- 修完我复跑：`verify-021-payload.mjs`（11/11）+ `verify-021-runtime.mjs`（RT-A/B/C 全 PASS）+ 真实会话样本回放（71577/1502/4463/62011/67152 应为 a）。
