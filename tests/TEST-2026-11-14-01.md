## 6. 观察与风险（不构成条款判定、未开 BUG 单）

1. **`writer=user` 也被准入拦截**：`OBS c1-user-writer-empty-detail :: writer=user 空正文 → message code=ENTRY_UNREADABLE`。`src/memory/contract.js:189` 注释称"用户直写不在此列"，实际 `src/tools/mem-tools.js:329` 对所有 `create` 生效——注释与行为不一致。是否影响"用户先存标题、后补正文"的既有用法，请开发确认（非本单条款）。
2. **拒绝码优先级变化**：准入检查位于根解析之前（`mem-tools.js:329` 早于 `:345`），空正文 + 无根/只读场景现在先报 `ENTRY_UNREADABLE`，不再先报 `ROOT_UNMANAGED`/`READ_ONLY`。开发已用夹具（补 `detail`）适配 5 个既有用例（`p2-negative-state`、`p2-multiprocess-lock`、`mem-routing-interface`、`roots-store-pool-edge`、`tools`），目标断言未削弱——本报告已逐条看 diff，仅新增夹具字段。
3. **旧数据残留**：去重返回既有条目时，若命中 1.0.2 时期"空正文"旧条目，仍可能读出空正文。本次 12 条旧账已由 00 全部 `expire`（`REQUIREMENTS.md:869`），故不影响本单；后续清库/迁移时注意。
4. **`MemoryStore.create()` 直调无准入**：准入只在 `mem_write` 工具与保护项生成侧（`protection-memory.js`）落实；直接调 store API 的内部代码可绕过。当前用户可见入口不经过该路径，记录备查。
