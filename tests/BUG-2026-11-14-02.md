## ② 期望 vs 实际

**C8 期望**（`REQUIREMENTS.md:1141`）：界面同时给出当前生效值 + 来源层，**并标「本会话有效」或「重启后失效」**。

**实际**（`node tests\probe-1.1.0\verify-d2.mjs` 输出原文）：

```
FACT C8-bubble-text :: "当前生效: 55%\n来源层: plugin\n生效时点: 立即生效（保存后重新加载配置）"
FAIL C8-session-durability-marker :: 是否含「本会话有效/重启后失效」=false
FACT C8-session-source-text :: "当前生效: 50%\n来源层: session\n生效时点: 立即生效（保存后重新加载配置）"
```

- 文案只有「当前生效 / 来源层 / 生效时点」，**没有**「本会话有效」或「重启后失效」；
- 更关键：`生效时点` 是**常量** `EFFECTIVE_AT_TEXT`（`src/settings-policy.js:10`），**不随来源层变化**——当 `source=session`（`/cg set` 写的进程内覆盖，重启即失效）时仍显示「立即生效（保存后重新加载配置）」，属**误导**（C8 缺句 + R-4 第③类"生效时点误导"风险）。

**C11 期望**（`REQUIREMENTS.md:1144`）：界面写明「**改的是哪一层**」与「立即生效/需重启」；**缺任一句判不过**。

**实际**：

```
FAIL C11-write-layer-wording :: 气泡文本里"改的是哪一层"=false
PASS C11-effective-timing-wording :: 生效时点=true
```

- 界面只有「来源层」（=当前**生效**层，`client.js:68`），**没有**"本次保存写入的是 plugin 配置层（profile patch）"这类**写入层**说明。用户看到 `来源层: builtin` 时无从知道输入框保存会写到 plugin 层。
