# BUG-2026-11-15-06 · 气泡 B2：恢复全局后「本次修改写入」与输入框不刷新

| 字段 | 值 |
|---|---|

| 日期 | 2026-11-15 |
| 严重度 | 低（状态刷新缺陷；功能成功：A1+A2 已清、大字回落 58%、来源层已变 `plugin`） |
| 证据 | `G:\DS-HARNESS\.dsh-file-attachment\image-25.png` |
| 关联 | C27/C29 清除会话自定义；`packages/dsh-context-governance/lib/client.js` |

## 现象（用户说法）

点「恢复全局设置」成功：大字回落 **58%**、来源层变 `全局（影响所有会话）(source=plugin)`；
但底部「本次修改写入」**仍显示** `本会话（session:A2，重启保留）`，输入框**仍保留原值 45**。

## 根因（代码定位）

`lib/client.js:521-527` `resetToGlobal()` 成功后只做了两件事：清 `error`、重取快照 `store.set({snapshot:next})`。

- 底部第 4 行来自 `renderBubbleText` 的 `writeLayerTextFor('session')`——**静态文案**，不随快照变化（同 B1，`:311`）；
- 输入框是组件本地 state `draft`（`:541 value: draft`），`resetToGlobal` **没有 setDraft**，
  所以快照已变 58%，输入框仍停在用户上次输入的 45；
- 无任何"已恢复全局"的可见状态，用户无法确认这一行描述的是"上一次动作"还是"当前状态"。

## 修法（rc.11 不动；建议进 1.1.1，与 B1 同批）

1. `resetToGlobal()` 成功后：
   - `setDraft(toPercentText(next.at))`——输入框跟随生效值（58），不再留 45 这个"看似未生效"的残值；
   - 置一次动作态 `lastAction='reset'`，写入层显示
     `本次修改写入：已清除本会话覆盖（A1+A2），当前生效来自 <layerLabel(next.source)>`；
     下次保存成功后该行回到 `session:A2` 口径（与 B1 的分档共用同一函数）。
2. 兜底：把"写入层"文案统一由 `writeLayerTextFor(entry, { source, lastAction })` 生成，
   **不允许任何一处直接引 `LABELS.zh.writeLayerSession` 常量**（B1/B2 同源，一次改干净）。
3. 可选（不阻断）：reset 成功短暂显示 `已恢复全局设置` 1.5s，与保存的 `已保存` 对称。

## 用例（1.1.1 验收）

- 假 fetch 序列：reset → 快照 `{at:0.58, source:'plugin'}`；断言
  ① 写入层含 `已清除本会话覆盖`、**不含** `session:A2`；
  ② 输入框 value == `58`（DOM 断言 `input[value]`，或抽 `stateAfterReset(next)` 纯函数单测）；
  ③ 大字 == `58%`、来源层 == `全局（影响所有会话）(source=plugin)`。
- 连续保存：save → 快照 `{at:0.45, source:'session:A1'}`；写入层按 B1 口径（`已落 A2`），
  不出现 `已清除` 残留。
- 回归：`/cg set reset` 命令面文案与 `verify-c27-c29-reset` 12/12 不受影响（只改 UI 视图模型）。

## 结论

状态刷新 + 文案缺陷，**不阻断 rc.11 装机验收**；修复排 **1.1.1**（与 B1 同批，同一函数改完）。
