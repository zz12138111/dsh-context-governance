## ⑥ 统计口径（可复跑）

- 容器：`session.v4.jsonl.zstd` 是**多 zstd frame 顺序追加**，不是裸 zstd 单流；`zstdDecompressSync(whole)` 只出第一帧（会让人误判"文件坏/事件少"）。
- 正确解：逐帧解析 frame header（magic `28 B5 2F FD` + FHD/窗口/dict/FCS + block 头）定位每帧边界 → 逐帧 `zstdDecompressSync` → 拼接 JSONL。本报告的 `58a2e845`：42,648 frame、0 解压失败、0 JSON 坏行、seq 连续（0…684x）。

## ⑨ a/b 类可执行判别式（C34③ 落点）

**前提**：`snapshotProtection` 已保留被 shadow 规则的 `text`（`protection.js:285`）；审计只落 **sha256**，不落正文（符合 C30）。

**事件层判别（两段）**

1. **同步段（重建那一刻，只能做这个）**：`rule.type==='system/message'` → 不 append，记 `surface-rebuild-skipped`，字段 `{reason:'no-open-step', sessionId, cycle, compactionId, ruleSeq, kind, textSha256}`。此时**无法**判 a/b（下一轮还没发生）——不要在重建里假装能分类。
2. **事后段（该会话下一次 `system/message` 落盘后判定）**，记 `recoverability`：
   - **a（可再生成，允许丢）** 满足任一：
     - **被覆盖**：压缩前 surface 上存在更晚的同 kind `system/message`（`seq > ruleSeq`），即该条是过期修订版；
     - **重注入同文**：下一次 `system/message` 的 `sha256(text)` == `rule.textSha256`；
     - **重注入超集**：下一次 `system/message` 的文本 `includes(rule.text)`（宿主用更大/更新的 prompt 覆盖）。
   - **b（不可再生成，不允许丢）**：以上都不满足，或压缩后**该会话没有新的 `system/message`**（无后续轮/无重写）→ **默认从严按 b**。
   - 判定时机可放在下一次 `system/message` 写入时的 hook，或测试侧对日志的事后断言。

**实测样本（两个会话 3/3 落在 a）**

### 10.1 对 §10.3 分型 loss 的意见（数据面站得住，但有三处必须收紧）

- **站得住**：loss 的最小单位是"被 shadow 的保护项"，**不是 shadowed seq**。`53ece2c2` comp@74576 的 1291 个 seq 里 system 规则只有 **1 条**（71577）→ 一次压缩只多 1 条 loss，不会"把真丢失淹掉"。
- **accepted 仍应进 `compaction-loss` 数组**，带 `disposition`；不进就等于静默丢弃，违反"不静默"原则，也无法事后对账。
- **判据不能只看 `unacceptable=0`**：`unclassified` 必须单列且**不得默认 accepted**（需求口径"判不出按 b 从严"），否则"没证据就放行"会重演 D-MGMT-021 同型问题。建议：`unacceptable=0 && unclassified=0` 才算过；`unclassified>0` 时给宽限期（下一次 `system/message` 落盘后补判），仍无法判定即记 `unacceptable`。

### 10.2 对 §10.4 v3a/v3b 的意见

- 判别式**可执行**，但 **`kind` 只能做路由、不能做主判据**：`system-prompt` 同样可能装一次性内容（例如任务专属提示）。主判据只能是内容证据：`sha256` 相同 / 原文被包含 / 同次压缩存在更晚副本（过期修订）。
- **71577 确属宿主可重生成**：压缩后第一轮 74584 与它**逐字节相同**（7501 字，sha `1a880bbab4de…`），同一 sha 在 `8b7b552a` 的 1502 也出现——不是偶发。
- **反对"缺失按可重生成兜底"**：`kind` 缺失、或压缩后拿不到新的 `system/message` 时，必须按 `unacceptable` 从严，不能默认 a。兜底方向要与"判不出按 b"一致，否则等于无证据放行。
- v3a（降级 user 回注）若落地则回到 0 丢失，判别式只留作对账；v3b 走分型 loss 时必须带上 10.1 的三条收紧。
