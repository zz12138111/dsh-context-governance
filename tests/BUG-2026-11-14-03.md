## ③ 根因（需求 2026-11-14 定稿；测试侧复核证据）

### 真因 ①：客户端注册未走官方 `ctx.slots.inject(...)` 约定，且吞错

- 现状（第 1 次预验装 `18013d9`）：`lib/client.js` 的 `apply` 直调 `ctx.slots.register`，外层 `try/catch` 静默吞错；`slots` 不可用时三处入口零注册。
- 官方约定：`ctx.slots.inject(slotName, () => ctx.slots.register({...}, Comp))`（证据：`dsh-client-ui-settings-shell/lib/client.js:182-189`；`dsh-cost-meter`/`dsh-context`/`skills-manager` 同写法）。
- **已否决**"缺 `dsh.client.inject`"假设：宿主 `parseDshClient()` 只强制 `platform`，`inject` 只是 row 排序依赖；`dsh-cost-meter` 无 `inject` 也能挂载。**`dsh.client` 不改**。
- 后果链：直调 register + 吞错 → 注册失败无痕 → chip/section 都不出现。

### 真因 ②：`webServer` 后挂，注册在服务就绪前整块跳过 → 快照路由 404

- 现状（`18013d9`）：`src/index.js:927` `if (typeof ctx.webServer?.register === 'function')` 直接摸服务；未就绪即跳过、无重试。
- 修法口径：`ctx.inject(['webServer'], (scoped) => scoped.effect(() => scoped.webServer.register({...})))`（同 `@local/dsh-computer-use`）。
- 后果链：路由未注册 → `GET /context-governance/policy-snapshot` 404 → 即使 chip 出现也只能显示 `压 —`。
