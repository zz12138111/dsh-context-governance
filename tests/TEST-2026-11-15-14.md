## ② 对照组（治理下线后 `/compact` 会不会崩）——**被挡，未执行**

想做的：临时会话里 `/compact`，压缩后续轮正常 → 证明"压缩本身好、只有治理重建崩"。
做不了的三条硬原因：

1. **本机 desktop GUI 需带 token 的 URL**：`http://127.0.0.1:7348/` 直连返回 `401 Unauthorized`，运行环境只给了 base URL，没有 token；`dsh_browser_open` 拒裸根地址。
2. **临时 profile 无 LLM 凭据**：`dsh headless --session-id ...` 起轮即 `MISSING_CREDENTIAL`（`no API key for provider route "deepseek-official"`），压缩要模型，跑不动。
3. **治理已下线** → `early-auto` 不可能再触发；只剩手动 `/compact`，仍受 (1)(2) 限制。

**替代证据（代码级，不是真机替代品）**：宿主编码器对 `compaction/start|end`（`turn:null`）与 `user/message` 裸载荷都放行，只拒绝 `{message}` 形态的 `system/message`；插件内唯一该形态写入点就是 `protection.js:423`。这与"压缩事务本身没坏"一致，但**不能替代真机两段验证**。

- **A（推荐）**：00/用户给我**带 token 的 GUI URL**，我在 GUI 里建临时会话 → `/compact` → 再发一条，全程不动 `profiles\desktop` 配置。

- **C**：用户本人在真机上跑一次 `/compact` + 后续一条消息，我只记录结果。
