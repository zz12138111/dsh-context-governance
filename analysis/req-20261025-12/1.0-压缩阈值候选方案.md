# `compact.at` 候选方案（只出方案，未改任何配置）

- 出单：2026-10-26 03:25（UTC+8），现状 1.0.0（pid 21372）
- 口径：`compact.at` = 占**观测窗口**比例；触发条件 `effective ∈ [at, native−0.02)`（`early-gate.js:76-79`）

## 1. 两个数不是换算关系，是两套阈值

| 量 | 来源 | 当前值 | 含义 |
|---|---|---|---|
| `effective` | `policy.js:396` `max(measured, estimated×1.35)` | 随会话变 | **测得**的压力（占窗口比例） |
| `native` | `policy.js:80` `floor(min(W×0.8, W−O−65536))/W` | 0.6934 | 治理侧算出的**宿主原生上限**（W=1,048,576、O=256,000） |
| `at` | 配置/策略层 | 0.60 | 用户设的触发点 |

- 二者同单位（0..1 比例），直接比较，**不存在换算**。
- 触发窗口 = `[at, native−0.02)` = 当前 `[0.600, 0.6734)`；`effective ≥ 0.6734` 时让给宿主原生。
- 1 个百分点 ≈ 10,486 tokens（1,048,576 窗口）。
- 注：宿主侧 `compaction-basic.thresholdRatio=0.65` 是宿主自己的开关，**不参与**上面 native 公式；native 一直是按公式算的，写进 README 的口径。

## 3. 候选（1M 窗口，native=0.6934）

| 方案 | at | 触发窗口 | 带宽 | 影响 |
|---|---|---|---|---|
| A 早压 | 0.55 | 55.0%–67.34% | 12.34pp（≈129k） | 更早省 token、每轮 prompt 更小；压缩次数更多，每次压缩≈一次全文摘要调用（实测 19:18 那轮 input=438,530 / output=3,575 tokens） |
| **B 现状（建议先保持）** | **0.60** | 60.0%–67.34% | 7.34pp（≈77k） | 默认值；已有 2 次真实触发样本，行为已知 |
| C 折中偏晚 | 0.62 | 62.0%–67.34% | 5.34pp（≈56k） | 多留约 2pp 上下文；仍留 5pp+ 余量，不易越界 |
| D 晚压 | 0.65 | 65.0%–67.34% | 2.34pp（≈24.5k） | 最接近硬上限；一次大 turn 就可能越过 67.34% → 让给宿主原生（≈69.34%），提前压形同虚设，**不推荐** |

现网样本（03:22 现采）：本项目会话 `5d1121ed` `effective=0.591` → `skip below-threshold`。若 at=0.55 它会在下一次 turn/end 就压；若 at=0.65 则不会。
→ 阈值一动，活跃会话的行为立刻变化（这个会话离 0.60 只差 0.9pp）。

## 4. 改法与回滚（都未执行）

| 路径 | 生效 | 回滚 | 备注 |
|---|---|---|---|
| `/cg set compact.at=0.55`（会话层，进程内） | 立即，全进程 | `/cg set compact.at=0.60` 或 `/cg set reset` | 最高优先级；重启失效；<0.30 需配置文件 ack |
| 插件配置（`cordis.patch.yml` 加 `dsh-context-governance` → `policy.values`） | 需重启 DSH | 删键/改回 0.60 再重启 | 配置文件层**不热重载**；改本机已装插件配置需先批 |
| 项目层 `.cg-policy.json`（仓库文件） | 需重启 DSH | 改回/删文件再重启 | 只允许 ≥0.45 的 at；不能设 armed/estimateSafety/ack |

- 不改代码、无数据迁移；审计字段与格式不变。
- 风险边界：`at` 超过 `native−0.02` 后永远走 `near-native` 分支（等于不提前压）；`at` 超过 `native` 会被政策层拒绝。
- 建议：先保持 0.60 不动；若用户要“更省”，先试 A=0.55 并观察 `early-forced` 频率与 `compaction-cost`；若要“更少压”，用 C=0.62 而不是 D。
