## 1. 什么算“等到了报告”

必须同时满足，缺一不算：

1. **本会话**：`report.sessionId === session.id`（`#record` 需补 `sessionId`）。
2. **新报告**：`report.compactionId !== prevReport?.compactionId`（B-2：不抄旧报告）。
3. **已收尾**：报告进入 ready 必须发生在**回注写回之后**（`#scheduleReinjection` 中 `state.report.reinjection` / `reinjected` 落定之后），不能是 `#record` 刚 push 的半成品。
4. **宿主 id**：`compactionId` 非空 UUID，**禁止** `early-*` cycle key；`compaction === 'committed'`。
5. **不跨会话**：同一根内另一会话的报告不得命中；测试必须覆盖。

> 中间态观察：当前工作树 `runtime.js` 已加 `waitForReport` / `#readyReports` / `sessionId`，但全文件没有 `#readyReports.add(...)` 与 `#notifyReportWaiters(...)` 调用。落地前必须接在回注写回之后（含 failure 路径）；否则每次 early 都会等满上限再写 `unknown`。

## 2. 等待上限：60000ms

- **硬上限 60000ms**（S1.2；唯一数字定义点 `runtime.js` 的 `EARLY_REPORT_WAIT_MS`，`early-wiring.js` 引用，不得两处各写字面量）。
- 依据：延迟不是固定值，随会话体量/落盘走——小会话 20ms（16:05）、14ms（16:35）；25MB 会话 ~513ms（16:44，500ms 只差 16ms）；同体量含大落盘 ~3013ms（17:00，3000ms 只差 3ms，且 `occurredAt` 比插件收到早约 3s）。任何固定短上限都是赌博，故取 60000ms 作安全网（§10）。
- 先查一次（可能已 ready），命中即 0ms；未命中事件驱动（`#notifyReportWaiters`），不轮询。
- 超时写 `unknown` + `compactionId=null`，不重试、不回溯改写；同时留 `early-report-wait` 诊断行。
- `timeoutMs` 可注入（测试 0/10/600）；生产上限 `Math.min(EARLY_REPORT_WAIT_MS, …)`。
- 等待发生在 `turn/end` 之后的异步 check 内，不阻塞 turn。

## 3. `compactionId` 与 cost 同 id

- **必须**：`early-forced.compactionId` == `compaction-cost.compactionId` == `/cg status last-compaction id` 前 8 位。
- 来源是 `summaryEvent.data.compactionId`，不是 cycle key。
- 没有 cost 行 = 证据不完整，不能判通过。

## 4. “turn 不被阻塞”的判据

- `session/event` handler 保持同步、不 `await`；`check()` 仍是 timer 内 `void` 调用。
- 等待只在 `check()` 内部，`await` timer/promise；禁止 `while` / 同步 sleep / `Atomics.wait`。
- 测试：报告延迟 600ms 时 `turn/end` handler 先返回；10ms 后到的 `turn/start` 仍被路由；不出现第二次 `compactNow`。
- `stop()`/dispose 清等待 timer，不留等待尾巴。

## 5. 语义不许动（diff 红线）

- `decideEarly` 输入/顺序、阈值/近 native/冷却/增量不动。
- `preProtect` 必须在 `compactNow` 之前，失败不调用；`markEarlyAccepted` / `discardEarlyProtection` 顺序与条件不动。
- `accepted=false`（busy/failed）**不等待**，直接 `early-aborted` / `early-failed`。
- 不新增/不改审计事件名与字段（`compaction` / `compactionId` 取值是本次唯一变化）。
- 不重复调 `compactNow`、不重新取引擎、不改 `getEngine`。
- B-2 保留：超时/无报告仍 `unknown`，不允许 fallback `committed`。

## 9. S1.1：500ms → 3000ms 的依据（2026-10-27 真机）

桌面真机（重启后新进程 pid 34728，仓库代码经 profile junction 加载，`resolved=D:\DS-PROJECT\DSH插件开发\packages\dsh-context-governance`），同一次真实触发：

| 时间（Z） | 事件 |
|---|---|
| 16:43:41.024 | `early-decision` force（effective=0.314，threshold=0.30） |
| 16:44:06.533 | `early-forced` accepted=true，但 `compaction=unknown`、无 compactionId（500ms 超时） |
| 16:44:06.546 | `compaction-loss`（id=b9c51708） |
| 16:44:06.549 | `reinjection`（id=b9c51708）→ 报告 ready |
| 16:44:06.550 | `compaction-cost`（id=b9c51708） |

- 报告 ready 比 500ms 上限晚约 **16ms**（`.533` 超时 → `.549` ready），不是过滤不匹配。
- 以 `.024` 起算整条链约 520ms：500ms 只差一点，且真机抖动会放大。
- 结论：S1.1 当时取 **3000ms**（约 6 倍余量）；**已被 §10 的 60000ms 取代**（第三轮真机又出现 ~3013ms）。等待在 `turn/end` 之后，不阻塞对话。

### 9.1 返回形状与诊断（不改语义）

- `waitForReport()` 返回 `{ ok, reason, report, waitedMs }`，`reason ∈ 'timeout' | 'mismatch' | 'none'`：
  - `none`：拿到本 cycle 新报告（`ok=true`）；
  - `timeout`：窗口内没有出现任何新候选报告；
  - `mismatch`：**等待期间**收到过新候选报告，但不满足会话/cycle/ready 过滤（别的会话抢先）；进入等待前已存在的旧报告不算候选，否则纯 timeout 会被误报（审核 S1.1-①）。
- 未命中时 `early-wiring` 追加 `early-report-wait`：`sessionId` / `cycle` / `reason` / `waitedMs`（毫秒整数），不记正文、不记 token；**命中不写**该行。
- `ok=false` 时以 `ok` 为准：即使返回对象里带 `report` 也不采用（审核 S1.1-⑥）。
- `accepted=false` 仍不等待；`ok=false` 不抛错、不改 `accepted`、不增加 `compactNow` 调用次数；仍写 `unknown`（B-2 保留）。
- 异常兜底（`await` 抛错）写 `reason='error'`，只作诊断，不属于 `waitForReport` 的枚举；`waitedMs` 记真实 elapsed（未进入等待时为 0＝未计时）。
