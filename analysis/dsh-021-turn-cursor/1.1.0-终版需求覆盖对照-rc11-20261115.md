## 结论

**rc.11 是否满足 1.1.0 终版功能需求：不满足（条件式）。当前 `2bea17d` = 实现缺口 3 类（P3/P5/P6，共 4 组待补）+ 真机未跑；补丁齐（同一笔 commit）并复跑全绿后 → 实现缺口 0，差距只剩"真机未跑"。**

**A. 实现缺口（3 类 / 4 组，均待同笔补丁）**
1. **P6 `roots/registry.js:439-440` 空 id 崩溃**：`pinned = sid===null ? null : …` 后仍用 `pinned !== undefined` 判空 → 取 `pinned.entry` 抛 `Cannot read properties of null ('entry')`（rc.10 `04:09:07.263 root-guard-error{phase:resolve}`）。违反 `:454①`（无 session id 应显式审计 `no-session-id`，不得崩）。
2. **P5 `via` 字段未达**：三证守卫主体已绿（门 11/11），但 29b 硬条件②要求放行时审计 `via: origin|sec-fetch|token`；`via` 尚未落地 → P5 未修完（真机也无法回溯证明来源）。
3. **P3-a `pointers` 被审计白名单丢弃**：`headerInjectedFields` 返回 `pointers`，但 `audit.js` 的 `AUDIT_FIELD_WHITELIST` 无该字段 → 行里丢失（实测 `header-injected` 只有 `count/lines`）。
4. **P3-b header 两行无 `sessionId`**：`header-injected`/`header-truncated` 的 details 均不带 `sessionId` → 行本身无法按会话归因（routing 已对：`memory-pointer-miss` 12 行全落会话根、主根 0）。
> 注：4 组建议**一笔补丁**（白名单同时覆盖 `pointers` 与 `via`；header 两行补 `sessionId`；registry 判空改 `pinned !== null`）。补丁 hash 到位后本表 A 段改"0 项"，并附复跑读数。

**B. 真机未跑（本表差距主体，rc.11 未装机）**：C11①②③（三类 UI 写 + `via`）、C24–C26（A2 读回/隔离/持久化，绑定新包重读）、C27/C29（`reset` 回落 + UI 入口）、C28（文案）、C32（四层标签）、C36 的 CP6/CP8、C37 显示级（`layers:`）、C38（P2/P3/P4 真机复验 + miss 去重复核）、C39 第二 DSH_HOME、C5 #4 三项；CP1–CP9 中除 CP2/CP4/CP7 外均待真机。

**C. 已知边界（均非缺口，Release notes 必写）**：`/cg policy show` 的 `layers:` 不含 A2 / A1 标签 `session`（显示级，`policy:` 行来源正确）；`user-store:` 分隔符混用（cosmetic）；`compaction-loss{rollback-point,b-class}` 假告警（需求裁 B，`8097e0a`/`d868e3a` 起改判 pass + `protection-covered`，旧事件不删）；CP5 不可造（宿主 cwd 校验，离线覆盖）；CP6 的 `observe-only` 无入口（审核裁定记未覆盖）；C39 第二 DSH_HOME 未覆盖（非 PASS）；token 由快照下发、本机进程可读（真边界是 loopback，Release notes 须写"不要把监听暴露到非 loopback"）；历史提交 `da29d52` 标"勿出包"（已被 `b059266` 收口）；`compliance-scan` 对解包目录假绿（出包=仓库级+包内双跑）。
