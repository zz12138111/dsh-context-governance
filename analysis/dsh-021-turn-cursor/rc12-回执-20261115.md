## 9. 作废原因与门整改（真机窗口首小时）

### 9.1 B5（BLOCKER）：hook 顺序违规，首次点 chip 即崩

- **现象**：rc.12 重启后 chip 点不动、气泡点不开（两个 UI 入口整体无响应）；rc.11 同操作正常。
- **根因（已定位到行）**：`87794f2` 的 `packages/dsh-context-governance/lib/client.js`
  - `:662` `if (!open) return null;`（早退）
  - `:669` `const [layout, setLayout] = react.useState(null);`
  - `:670` `react.useEffect(...)`（定位计算）
  → 关闭态渲染只跑到 14 个 hook；打开态跑到 16 个 hook。React 抛 `Rendered more hooks than during the previous render`，气泡子树崩，`EntryBoundary` 兜底后 chip 一起哑。
- **谁引入**：C40 实现（`87794f2`）新增 layout state/effect 时放错位置。rc.11（`222a718`）无此段，故正常。
- **修复**：把 `if (!open) return null` 移到 hook 之后（开发工作树已有该改动，方向正确，待提交）。
- **教训（写进常驻清单）**：**单帧渲染门永远抓不到 hook 数量不一致**——必须"关闭态渲染 → 触发打开 → 再渲染"的**状态切换门**。

### 9.2 门漏网清单（重建包前必须补）

1. **点击/切换门**：`createChip` 的 `onClick` / `onKeyDown` → `store.set({open})` → 气泡从 closed 渲染到 open 渲染**不抛错**；再点一次回到 closed 也不抛。
2. **C40 门现状为何绿**：它只渲染"打开态单帧"并断言几何/文案，从未做 closed→open 转换，因此 hook 数量差异永远不出现。**C40 9/9 是真的，但与 B5 无关**。
3. **P4 dispose 门**：删掉根目录 → 触发 guard dispose → 断言目录**仍不存在**、且不得以"写审计"为由 `mkdir` 复活。
