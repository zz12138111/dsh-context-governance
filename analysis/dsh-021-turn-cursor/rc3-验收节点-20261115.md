## 1. 范围（收口）

**纳入（问题实证，第 2 轮 cycle `f298a3fd` L1656–L1666）**
- ① `protection-write` 记 `ids=[1005,1006,1007]` + `protection-materialized moved=3`，但 `MEM-20261115-1006` 在 `memory/` 全目录 0 命中 → **审计指针不可解析**，调用方按 ids 找不到条目。
- ② 第 1 轮 ids `1003–1005`、第 2 轮又从 `1005` 起编 → `MEM-1005` 被覆盖成本轮 latest-user，原 rollback 条目消失 → **同日 id 复用**。

**必要配套（只这三条）**
- ③ `moved=N` 必须能逐条对账：落盘条数 ≠ N 时写审计（如 `protection-materialize-mismatch`），不得只报 moved 不报差。
- ④ id 分配跨重启单调：重启后从磁盘现有最大 id 续号，不回退、不复用。
- ⑤ 回归覆盖：同日多次压缩、重启续号、落盘缺条三态。

**不纳入 rc.3（避免范围膨胀）**
- 第 2 轮 `rollback-point` 词面损失（`summaryText.includes(keyword)` 与中文摘要「回滚」不匹配）——属判据优化，单列，C36 批次之后。
- `stale-lock-reclaimed` 未真机触发、`context-zip` notes 未落新 seg——观察项，不修。

## 2. 预计提交顺序（以开发实际拆分为准，每个提交须可独立 review）

1. `fix(protect): 指针 id 按当日落盘条目单调分配，重启从磁盘续号（禁止复用）`
2. `fix(protect): protection-write/protection-materialized 与落盘条目对账，缺条留审计`
3. `test(protect): 同日多压缩 / 重启续号 / 落盘缺条 三态回归`
4. （审核出）`review: rc.3 复核记录 + 出包核对`
