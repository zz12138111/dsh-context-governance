## 9. B8：按钮行不可见（真机 2026-11-15 13:4x）

**现象**：气泡这次**贴住 chip 上方、在窗内、不越界**（B6 修复成立），但面板只显示到「标题 / 45% / 45% / 本会话·已保存（重启保留）/ 重启后仍生效 / 输入 45」，**按钮行整行不见**，面板底部被窗口下沿裁掉。

**机制（代码确证，不是"滚动没生效"）**：
1. `wrapper` 只有 `maxHeight`（`:808`）**没有 `height`** → 子面板的 `maxHeight:'100%'`（`:823`）对**不确定高度**的包含块**解析为 none** → 面板按自然高度增长（约 290px）；
2. 而 `layout.height` 是**猜的**：`desired = min(260, 96 + 3*22 + 64) = 226`（`:697` 附近）→ `layout.top` 按 226 算；
3. 实际内容 ~290 > 226，`wrapper` 没有 `overflow` 裁剪 → 面板**溢出并穿过窗口下沿** → 按钮行被窗口边界裁掉，且面板内**没有滚动条**（因为 `overflowY:auto` 挂在面板上，但面板高度没被限住，没有溢出可滚）。

**判级：BLOCKER**——用户无法保存/恢复，C40 的核心功能不可用。

**修法（最小、可离线断言）**：
1. wrapper 给**确定高度**：`height: ${layout.height}px`（保留 `maxHeight` 亦可）+ `overflow: 'hidden'`；
2. 面板保留 `maxHeight:'100%'` + `overflowY:'auto'` + `minHeight:0`，各子行（标题/大值/三行/输入行/**按钮行**）加 `flexShrink:0`，防 flex 压缩；
3. **高度不猜**：面板首次渲染后读 `dialogRef.current.scrollHeight`，用 `min(260, scrollHeight)` 重跑 `computePopoverRect` 修正一次（差值 ≤1px 即停，避免与 `correctPopoverRect` 形成校正环）；
4. 门加：静态——wrapper 必须有 px `height` + `overflow`，面板必须有 `maxHeight:'100%'`+`overflowY:'auto'`，且**按钮行存在**；vm——内容高度 > 预估时，`layout.height ≤ 260` 且 `top + height ≤ vh − 8`；真机——**按钮行 rect 在视口内或经面板滚动可达**。

### 9.1 三条症状的归属（审核判定）

| 编号 | 症状 | 归属 |
|---|---|---|
| **B8a** | 按钮行（恢复默认 / 恢复全局 / 保存 / 打开设置）整行不可见 | 根因（高度估算 + 无确定高度 + 无裁剪） |
| **B8b** | 点「详情」后多两行，按钮更往下、彻底看不到 | **同根因**（内容变高 → 出界更多） |
| **B8c** | "面板里点不动" | **同根因的下游**（唯一可交互的按钮在视口外）。**不判为 pointer-events 缺陷**：`wrapper:none → panel:auto` 是合法命中链，且用户确实点开了「详情」；门里另加命中链断言防回归 |

### 9.2 修法取舍：按钮**常驻**（不要求用户滚动去找保存）

面板改 flex 列：内容区 `flex:1 1 auto; minHeight:0; overflowY:auto`，**按钮行单独成 footer `flex:0 0 auto`（不在滚动区内）**；wrapper 给确定 `height` + `overflow:hidden`；子行 `flexShrink:0`；高度用 `scrollHeight` 实测修正一次（详情展开时重算），差值 ≤1px 即停，避免与 `correctPopoverRect` 打环。

### 9.3 门（rc.15 必过）

- 静态：footer 在滚动区外且含保存按钮；body 有 `overflowY:auto`；wrapper 有 px `height`；面板 `maxHeight:100%`；
- vm：详情展开后 footer 仍在；`layout.height ≤ 260`；`top + height ≤ vh − 8`；内容超长时 body 可滚而 footer 不动；
- 真机：**按钮 rect 在视口内、无需滚动**；点保存能发出 `policy-set`；点详情后按钮仍在。
