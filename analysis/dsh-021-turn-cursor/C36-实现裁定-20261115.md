# C36 实现影响评估 — 审核裁定

日期：2026-11-15｜对象：开发 C36 实现影响评估（**未动代码**，符合要求）｜裁定人：审核打包
配套：放行判据见 `C36-放行检查点-20261115.md`。本裁定只定**验收口径**，不写实现方案；需求侧意见未代裁，以下为最终口径。

## 裁定 1：无 root 会话的 `mem_*`

**结论：接受（`ROOT_UNRESOLVED` + 不落项目记忆 + 只写根审计），附三个必须。**

- **M1 码可诊断**：`ROOT_UNRESOLVED` 必须随结果带 `sessionId / cwd / reason`，使调用方能区分「无根」与「磁盘/权限错」——不得回一个裸码让人查不出原因。
- **M2 范围**：**不得在项目根下创建或修改任何记忆文件**（索引、topic、`.bak` 都算）；判定在写之前，不做「先写后清」。
- **M3 仍受治**：该会话的压缩、审计、保护/回注照常（`root-unresolved` 审计按裁定 3 的触发规则），`/cg status` 显示 `project-root: unresolved`。
- **补充（澄清范围）**：若实现存在 **session 级记忆容器**，允许写 session 级（对应 R-SCOPE `:453`「记忆/分组标 root-unresolved」与多根 #2/#9 的「session 级归属」）；若不存在，一律不写，并留一条审计（去重）。**「不落项目记忆」≠「静默失败」**，这两点同时成立才算 PASS。

## 裁定 2：A2 写入时机

**结论：接受「只由显式 `/cg set`/UI 保存写 A2，自动学习值不回写」。A2 是用户承诺（C24–C30 / R11），自学习回写会把临时值变成持久承诺。**

附三个必须：

- **M4 标注不得冒充**：自动学习值必须标 `ephemeral`（或 `source=A1`），`/cg status` 与 `policy-resolved` 里**不得**出现 `A2`/`persisted`；重启后不得「复活」成 A2 记录。
- **M5 可撤销**：`/cg set reset` 要能清掉该会话 A2，否则「持久承诺」撤不掉。
- **判据**：显式设 0.55 → 重启后 A2 有键且保留；只靠自动学习未显式设 → 重启后 A2 **无**该 session 键（这一条进 C36 CP2/CP4 证据）。

## 裁定 3：`policy-resolved` 粒度与 A2 清理

**结论：接受「每 cycle 1 条」与「500 条 / 90 天 LRU」，但必须先定 `cycle`，并补 `root-unresolved` 的触发兜底。**

- **cycle 定义（定读）**：`cycle` = **压缩 cycle**，与 `self-heal-pending` / `compaction-loss` 用同一个 id。每 cycle 只写 1 条 `policy-resolved`（同 cycle 去重）。
- **`root-unresolved` 触发（补 C36 ⑤ 歧义，最终口径）**：**每会话首见 1 条 + 每压缩 cycle ≥1 条**，同 cycle 去重。
  理由：若只按「每压缩 cycle」，**无压缩的会话一条都不会有**，直接违背「不静默」；若按 turn，则刷屏。首见那条兜住无压缩会话，cycle 那条兜住长期无根会话。**开发按此实现，我按此验**——C36 检查点 §5 第 1 条据此关闭。
- **活跃保护**：清 A2 前两项都满足才可清 —— ① `updatedAt` 超 90 天；② 该 session 在宿主侧不再活跃（实现须写明判定来源：session 存储 mtime / 最近出现记录，二选一并写进审计）。显式 pin 的**永不清**。**正在用于 C36 的两会话 A2 重启前后必须存活**。
- **清理必须审计**：写 `a2-evicted{sessionId,key,at,reason,lastSeenAt}`；`/cg status` 可见最近清理条数 / keep 数。
- **判据**：人为超 500 条时，被清的一定是**非活跃**且每条都有 `a2-evicted`；两会话 A2 未被误清。
