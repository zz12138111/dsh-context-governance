# 口径对比：官方自愈 vs 插件重建（2026-11-15，需求侧；未改判据、未 commit 需求变更）

> 背景：用户已批方案 A——**删掉 rules 重建（含 skill-catalog），只留 `latestUser` 重建**；指令与目录交宿主下个 pre-step 自愈。
> 本文只做口径对比、需求条目清单与验收统一；技术细节（字段/行号/用例）由开发/测试/审核内部闭环，不上达 00。
> 范围：1.1.0 剩余。不改代码、不装、不重启；结论不以"已重启验证"为前提。

## 1. 官方逻辑（宿主）怎么保证压缩后指令/目录不丢

1. **每轮 pre-step 重读盘并重发 baseline**：`dsh-agent-instructions/src/index.ts:330-356`——按盘上 AGENTS.md 的 digest 变化重发当前 baseline；历史修订版不重放。
2. **目录按 digest 重发**：`dsh-tool-skill/src/index.ts:217-246`——skill 目录按 digest 重新生成并注入当前版本。
3. **system prompt 每轮重建**：`dsh-agent-loop/src/runtime-context.ts:78-113` 的 `SystemPromptProjection.project()`——每轮把非 head 的 system 节点 replace 成空，再由 loop 本体重建；中段 system 是宿主临时节点。
4. **压缩只动表面、不动盘**：AGENTS.md / skill 目录仍在磁盘，下一轮 pre-step 重新读取即可恢复"当前版本"。
5. **官方不恢复 `latestUser`**：被压缩替代的用户消息不会由宿主重新追加——这是插件必须自己管的。

## 2. 插件原本的逻辑（P3 `rebuildProtectionSurface`）

- 按 `kind` 收集**会话里所有历史修订版**（含 10 个旧 AGENTS.md、旧 baseline、旧 skill 目录）进 `rules`，逐条 `append` `user/message`，`source={plugin:'context-governance', form:'surface-rebuild'}`。
- 副本复制旧 `baseline:true/baselineIdentity`，让宿主误以为 baseline 已在、跳过重读盘。
- 1.1.0 每次压缩后 1–2 ms 追加一批：最后一次 **13 条 / 26,065 字符**；历史修订版被当"现行指令"送进模型，且伪造 baseline 身份。
- 用户批 A 的定性：这些 rules 副本**不是保护，是污染**；宿主下一轮会自愈当前版本，插件重建的只是历史垃圾。

## 3. 逐条对比

| 保护对象 | 官方是否保证 | 插件原兜底 | 判定 |
|---|---|---|---|
| 当前 AGENTS.md baseline | **是**：每 pre-step 按 digest 重读盘重发（`:330-356`） | 重建全部历史修订版 + 复制旧 baseline 标记 | **多余且有害**：删；历史修订版不得重放，baseline 身份不得复制 |
| skill 目录 | **是**：按 digest 重发（`:217-246`） | 重建旧目录副本 | **多余**：删 |
| system prompt（head/中段） | **是**：每轮 projection 重建（`:78-113`） | P3 system 分支（v3b 跳过/留痕） | **多余**：删；C34 的 pending 机制随之失效 |
| 最新用户消息 `latestUser` | **否**：宿主不恢复 | `append user/message` 重建 | **必须保留**（唯一真正的插件兜底） |
| 工具配对 / 批次 STATE / 回滚点映射 | 宿主规则 + 摘要；插件 M1 走记忆指针 | P3 不负责 | 不在本次改动面；M1 口径不变 |
| 丢失可观测（loss/审计） | 否 | `compaction-loss` + 审计 | **必须保留**，但 `rule-injection` 判定改为宿主自愈口径（见 §5） |
| baseline 身份/标记 | 由宿主写 | 插件副本复制旧标记 | **禁止**：插件不得写 `baseline:true` / `baselineIdentity`，不得冒充现行 baseline |

**结论**：插件原本"规则注入重建"整体是**多余兜底**（官方每轮自愈当前版本）；`latestUser` 重建是**官方不管、必须我们管**的唯一内容兜底；`loss/审计` 是**必须我们管**的可观测面。

## 5. 口径统一：`rule-injection` 验收 = 宿主自愈即恢复

**压缩时刻（插件可判）**：
- 不再 append 任何 rules 副本（无 `source.form='surface-rebuild'` 的 `user/message`，除 `latestUser` 一条）；
- `verifyProtection` 的 `rule-injection` 输出 `skip(reason='host-self-heal')` 并带被委托的 `seqs`（对账用），**不得计 fail、不得写 `compaction-loss(rule-injection)`**；
- `latestUser` 仍走重建 + pass；
- 不得写 `baseline:true`/`baselineIdentity`。

**C35③ 终稿（2026-11-15 真机后回归，三处同字）**：窗口（`compaction/end` → 首个 `turn/start` → 该 `turn/end`）内出现该 kind 的**非治理新节点**（`type∈{user/message,system/message}`、`seq>compaction`、`plugin!=='context-governance'`、`form!=='surface-rebuild'`）⇒ **pass**；窗口结束仍无 ⇒ **fail + `compaction-loss(rule-injection, unacceptable)`**；**digest 仅观察**：baseline `source.changes[]` 有 `path`+`digest` 时按 `sha1(trim(content))` 复算记录，不一致记 `self-heal-suspect` warn、读盘失败/字段缺失记 `self-heal-unverified` warn，**均不判 fail**（真机 cycle `76f00aed`：节点 digest `d2789382…`/`18354bec…` 与重算 `298adbeb…` 不一致，每轮假 15 条 `baseline-stale`）；skill-catalog 事件级即 pass；旧修订版由 `seq>`+非治理+窗口三重排除；digest 观察字段照记（`hashMatch`）。

**下个 pre-step（宿主自愈的验收证据）**：
- 出现新的 `user/message` 或 `system/message` 节点，`source.kind='agent-instructions'`（`form='instructions'`、`baseline:true`）或 `source.kind='skill-catalog'`；baseline 的 `changes[].digest` 逐 path 比对盘上 `sha1(trim(content))`（必过），skill-catalog 事件级即 pass；
- 该节点不是插件写的（`source.plugin !== 'context-governance'` / `form !== 'surface-rebuild'`）；
- 历史修订版**未被重放**（无旧 digest 的 baseline 节点、无旧 skill 目录副本）。

**判定**：
- 上述三条同时成立 ⇒ `rule-injection` 记为**恢复（pass，来源=host-self-heal）**；
- 窗口结束后仍无该 kind 的非治理新节点，或 baseline digest 任一不一致（`baseline-stale`）⇒ 记 `rule-injection` fail 并 `compaction-loss(rule-injection, unacceptable)`，不得静默；
- 证据字段：`seq`、`kind`、`digest`（盘上/节点）、`form`、`plugin`；审计来源标注 `self-heal`。
