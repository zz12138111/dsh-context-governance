## 2. 真需求还是假需求（用"不做会怎样"判）

**但"system/message 形态的规则重建分支"要单独看**：

## 3. A 形态是否满足原判据

**结论：满足当前判据，但不是"零降级"，是有界的能力收缩，必须带条件放行。**

- 原判据「5 类保护项 0 丢失」的落点是**规则注入**；当前规则注入以 `user/message` 出现 → user 分支重建仍覆盖 → **判据不破**。
- **事实修正（2026-11-15，测试时序推翻开发 v1；详见 §7）**：A 停掉的**不是**"head 副本的多余重建"（`replace(8,8)` 晚于重建 21 秒，重建时 seq 8 仍在 surface）；真实命中对象是**被 shadow 的中段 `system/message`**（首崩 `53ece2c2` 的 `71577`：append、`system-prompt`）。跳过 = 压缩后不回注该内容，**损失面真实**。规则类确实零命中（现存 system/message 无规则内容），但"零损失"不成立；损失按可再生成（a）/不可再生成（b）分类验收，见 §8③。

**放行条件（缺一不可）**：
1. **命中即审计、零命中不刷**：`surface-rebuild-skipped`（reason=`no-open-step`）**仅在确有 system 形态规则命中 shadow 时记**（零命中不产生审计噪音），字段必须带 `sessionId/cycle/compactionId/ruleSeq/kind`（与既有 rule-injection fail 同 cycle 成对，否则"可发现"退化成各说各话）；`compaction-loss` **不单独造**，由既有 `rule-injection fail` 自然触发（`protection.js:544-555` → `runtime.js:2322-2339`）——skip 审计是"命中痕迹"，loss 是"后果告警"，两者不重复造；
2. **user 分支重建保持**（规则注入主路径），C33 四态回归必须绿；
3. 新增用例：**模拟 system 规则被 shadow → 跳过不崩 + audit 出现 + user 规则仍重建**；
4. 文档（发布说明/README）写明「system 形态规则在压缩事务内不做兜底重建（无 open turn/step），跳过并审计」；
5. 若未来出现 `surface-rebuild-skipped` 且伴随 `compaction-loss` 的 `rule-injection` → **升级处理**（C 形态延后重建或要求宿主提供合法写入窗），单独立项，**不得默默吞掉**。

**对 C33 的答复**：**C33 不加"system 兜底除外"**。C33 是"任何插件补写的 `system/message` 必须合法；推不出就跳过+审计"——A 不再写 system/message，自然满足。另加 **C34** 覆盖"规则注入重建覆盖"（见 §4）。

## 7. 事实修正：时序与首崩机制（2026-11-15，测试独立核数；以本节为准）

**两处旧表述作废**：
1. ~~"旧 head 副本命中重建"~~：**时序不成立**。`8b7b552a` 中 `compaction/end` = 01:46:13，`replace(8,8)` = 01:46:34，晚 21 秒；重建在 `compaction/end` 的 microtask 内同步执行，当时 seq 8 仍在 surface，head 替换不可能成为命中源。
2. ~~"A 停的是宿主已维护 head 的多余重建"~~：真实对象是**被 shadow 的中段 `system/message`**，跳过 = 压缩后不回注该内容，**真实内容损失**。

**真实首崩机制**（`53ece2c2`，即 00 会话）：
- `comp@74576` = `early-auto`，01:12:15；
- `shadowedSeqs` 含**中段** `71577`（append、`source.kind=system-prompt`）→ 收进 rules → 触发重建 → 补写 `system/message` 只带 `{message}`、缺 `turn/step` → 编码器拒 → **921 秒空窗 + 用户 4 次失败**；
- 旁证：10-21、10-24 两次中段 shadow 均早于 P3（10-26），当时无重建分支，故未崩——同条件、有分支即崩，因果闭环。

**对 A 的含义**：崩溃会修好（不再写非法 payload）；但被 shadow 的中段 system 消息**压缩后不会回注**——损失面真实，不再是"零命中/零损失"。C34 按"以放弃回注换不崩"重写，损失面必须分类可验收。

**R6（v2，替代原 head 用例）**：构造中段 `system/message` 被 shadow（如 `71577`：append、`system-prompt`）→ 断言：①无 `system/message` append（`form==='surface-rebuild'` 计数 0）；②`surface-rebuild-skipped{reason:no-open-step}` 出现，字段齐且含丢弃内容分类；③loss 可观测、能判 a/b 类（见 §8）；④不抛异常、不重试；⑤时序反例：`replace` 晚于重建时不因 head 触发重建。

## 8. C34 判据文本 v3b r2（**pending 五条已入；已入 `REQUIREMENTS.md` C34**）

> 依据：用户批 A；**审核撤回装机口径，给出 pending 五条**；测试复跑 **RT-A 红**——宿主在 `compaction/end` 的**下一轮**才重发 `system/message`，而实现 `runtime.js:2379` 在**重建那一刻**用当时 postSurface 判"是否重发" → 恒 false → 每条中段 shadow 都记 `b-class-loss`、`unacceptable` 永远 >0、a 类不可达。故 a/b 判定必须延后（第三态 pending）。

**C34（A 档）：`system-prompt` 不重建——pending 延迟判定 + 分型 loss**

- ① **user 形态规则**（AGENTS.md / skill-catalog）压缩后被 shadow 时，重建必须发生；终态 `unacceptable` 丢失 = 0。
- ② **`system-prompt` 被 shadow** 允许跳过重建（不写 `system/message`），跳过时写 `surface-rebuild-skipped`：`sessionId/cycle/compactionId/ruleSeq/kind/contentSha256(=sha256(text))/windowTurnId/status:"pending"`，**不得伪造 turn**。
- ③ **第三态 pending**：待判期间**既不记 accepted 也不记 unacceptable，且不计入"保护通过"**。
- ④ **TTL = 1 轮（采用开发设计 v2 的选择，不设墙钟）**：起点 = 压缩后第一个 `turn/start`（绑定 `windowTurnId`），终点 = 该轮 `turn/end`；该轮结束仍未命中 → `unacceptable(reason:"ttl-expired")`；无后续 turn 时在 guard dispose / 会话结束 → `unacceptable(reason:"session-ended")`。**理由**：用户可能很久才发下一条，30s 墙钟会把空闲误判为 b。
- ⑤ **匹配（审核 v3 修正）**：**`kind` 非空时**，窗口内出现更新的同 kind 原生 `system/message`（`seq > ruleSeq`、`form ≠ surface-rebuild`、`plugin ≠ context-governance`）即 `accepted(match:"kind")`；`contentSha256`/`hashMatch` 仅作观察字段（真机重发内容会变：`8b7b552a` 前两条长度/哈希不同，`hashMatch` 只记录、不作判定）；**`kind` 为空时**按 `sha256(text)` 从严匹配 → `accepted(match:"sha256")`；窗口内无匹配 → `unacceptable`。
- ⑥ **不跨重启**：重启后所有 pending 一律转 `unacceptable(reason:"restart")`，不猜；终态 `reason` 集合固定为 `ttl-expired` / `session-ended` / `restart`。
- ⑦ **终态必落审计**：每个 `pending→accepted/unacceptable` 写一条 `surface-rebuild-resolved`，对账键 `compactionId+ruleSeq`；**重启扫描遇到 audit 轮转/窗口未覆盖**时必须写 `surface-rebuild-recovery-incomplete` 披露，不得静默。
- ⑧ **分型 loss**：`lossClass`（`system-prompt-skip`/`user-rule-loss`/`b-class-loss`）+ 派生 `disposition`（`accepted`/`unacceptable`）+ `dispositionRule=v1`；`compaction-loss` **只含终态 unacceptable**（判据只读它），`compaction-loss-accepted` 汇总 count/seqs、不逐条报警、可按 `compactionId` 回查；阈值可调（>10% 当日压缩仅提示）；**`accepted` 不得计入"已保护/已保留"**、不参与 `verifyProtection` 覆盖计数。
- ⑨ **判据只认终态**：`pending` 期间 `unacceptable` 既不成立也不算通过，终态结算后计 `unacceptable=0`。
- ⑩ **证据范围**：b=0 仅测试 25 条样本（a=21 / b=0 / 判不出=0 / 空正文 4 不计）成立，**不构成永久保证**；**新形态按 b 从严**（判定按"下一轮观测不到同 kind + sha256 一致"即 b）。
- ⑪ **升级条件**：`unacceptable` 命中、pending 超 TTL 未结算、accepted 与 skip 不成对、accepted 突增超阈值 → 升级（C 形态或宿主写入窗），不得常态。

**回归矩阵（含 RT-A/B/C/D）**：C33 四态 + R6 v2（中段 system shadow → 零 append + pending 字段齐 + 不崩）+ **RT-A1**（逐字节重发 → accepted(match:"kind")）+ **RT-A2**（非逐字节、真实形态 → accepted(match:"kind")，hashMatch=false）+ 两条 `kind=null` 负例+ **RT-B**（TTL 到点无重发 → unacceptable(ttl-expired) + resolved）+ **RT-C**（重启 → unacceptable(restart)）+ **RT-D**（dispose/会话结束且无下一轮 → unacceptable(session-ended)）+ **RT-E**（`kind` 空 + sha256 不匹配 → unacceptable）+ **RT-F**（重启扫描遇轮转 → `surface-rebuild-recovery-incomplete`）+ pending 期间零 `compaction-loss` + user 规则重建 + 时序边界（`replace` 早于重建才触发，晚于不触发）。

**被否方案（2026-11-15 终判）：`system` 内容降级为 `user` 形态回注**
- 编码层**能过**：`user/message` 不在 `STEP_EVENT_TYPES`（`relationships.ts:8`），`message-sources.ts:9` 允许 kind 非空且非 `plugin`，`assertMessageEventShape` 只查 role='user'；但**不可作为修复**：
  1. `hasNewer`（`protection.js:545-551`）只看"同 kind + 更大 seq + 在 post surface"、**不看 form** → user 副本必被判 `rule-injection: pass`，自证闭环；幂等查重/`form` 标记/kind 保留三条都改不动这条判据；

### 10.3 对 00 第 2 问的回答（需求侧建议；多家意见已并入）
**会变噪声。** 若每次中段 shadow 都按 `rule-injection` fail 报警：`53ece2c2` 一次就有 1291 个 shadowed seq，压缩频繁的会话一天可积累几十上百条"fail"，真丢失（user 规则被 shadow）会被淹没，告警失去筛选力。故 C34 必须写 **分型 loss**。

**字段写法（审核 05:0x 修订，需求侧采纳）**——不要只写一个 `disposition`（"代码自己宣布可接受"=被告兼法官，且日后宿主不再回写 head 时历史行会撒谎）：
- `lossClass`：原始分型，`system-prompt-skip` ｜ `user-rule-loss` ｜ `b-class-loss`；
- `disposition`：**派生自 `lossClass`**（不由 skip 处直接写）；
- `dispositionRule=v1`：策略版本号，便于日后重算；
- `compaction-loss`：**只含** `unacceptable`（判据只读它，老读方按 `failures` 报警不受影响）；`compaction-loss-accepted`：汇总 count/seqs，**不逐条报警**（开发实现建议，与审核三字段兼容）；
