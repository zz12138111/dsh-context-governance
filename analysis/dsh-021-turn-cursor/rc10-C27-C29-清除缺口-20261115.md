# rc.10 终版差距：C27/C29 清除会话自定义无效（实现缺口）

日期：2026-11-15｜对象：`7d72ad8`（rc.10）｜签发：审核打包
性质：**实现缺失/偏差**（非"验收证据未齐"），阻塞 1.1.0 终版；rc.10 技术面「可装=是」不变。

## 1. 现象（实测）

在「重启后」状态（该会话只有 A2、无 A1）：

```
BEFORE: policy: compact.at=0.50 (source=session:A2) … 层=本会话·已保存（重启保留）
SET reset → {"kind":"success","text":"… cleared: 0 session override(s)"}
AFTER : policy: compact.at=0.50 (source=session:A2) … 层=本会话·已保存（重启保留）
A2 磁盘仍有该 sid: true
```

同一进程内先 `/cg set`（A1 存在）再 reset 时才正常：`cleared: 1`，会话回落 builtin，A2 磁盘清除。

## 2. 根因（代码锚点）

- `src/commands/cg-status.js:663`：`sessionValues = policy.sessionValues(sessionId, { create: false })` —— 重启后 A1 桶不存在，返回空的 `EMPTY_SESSION_VALUES`。
- reset 分支（`:675-682`）`for (const key of Object.keys(sessionValues)) delete sessionValues[key]` —— 空桶 → 0 次 delete。
- A2 实际清除只挂在会话层 Proxy 的 `deleteProperty`（`src/index.js:426-433`：`if (key === 'compact.at') a2Store.clear(sessionId)`）。桶不存在 → Proxy 不触发 → A2 残留。

## 3. 需求缺口

- **C27**（`REQUIREMENTS.md:1189`）：「`/cg set reset` 回落到下一层（项目模板若有，否则 plugin）」——A2-only 状态回落不到下一层。
- **C29**（`:1191`）：「UI 提供『恢复全局设置』（清 A2 与 A1 该会话记录）→ 回落到项目模板或 plugin；不得残留孤儿记录」——①UI **无清除入口**（`lib/client.js` 仅有 `restore:'恢复默认'`，`restoreDefault` 只 `setDraft`，不写层）；②提示里给的替代 `/cg set reset`（`client.js:41` overrideNote）在 A2-only 状态无效；③A2 记录残留即"孤儿记录"。

## 4. 修复要求（给开发，最小面）

1. reset 时**直接**对 `compact.at` 清 A2（不依赖 A1 桶是否存在）：在 reset 分支显式调用 A2 清除入口（`a2Store.clear(sessionId)` 或等价封装），并审计 `policy-set{key:'*',value:'reset'}` 保持现状。
2. UI 增加「恢复全局设置」入口（C29 明文要求），文案与 C32 标签一致；点击后走同一 reset 链路（A1+A2 同清），成功后 chip/气泡回落到项目模板/plugin。
3. 单测：①A2-only → reset 后 A2 落盘无该 sid、status 回落 plugin；②A1+A2 → reset 后两层都清；③UI 入口存在（静态断言，与 UI 12/12 探针同批）。
4. 改完只要一个包（rc.10 重出或按用户口径递增，由 00 定），不动已验的面。

## 5. 对结论的影响

- 1.1.0 终版功能需求：**不满足**（本条为唯一实现缺口；其余差距均为真机门未跑）。
- rc.10 包技术面：仍「可装=是」；**建议修完再装机**，避免装一个必然被替换的包（多一次重启）。
- CP 清单新增一项离线门：**C29 reset/clear 覆盖 A2-only 与 A1+A2 两态**，并入常驻套件。
