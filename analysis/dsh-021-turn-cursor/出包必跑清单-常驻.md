# 出包必跑清单（常驻；每次出包/放行逐条执行）

用途：这是审核打包**每次出包都要跑**的标准动作表，不随版本变化。用户提过的门一旦进表即常驻，**不再依赖用户提醒**。
版本相关的临时项写在当版《放行清单》里；本表只放"永远要跑"的。

## 0. 前置
- `git fetch` → 锁定对象 commit；**干净 worktree 检出该 commit**（不从工作树打包）；已 push 的 commit 只追加、不 amend。
- 包只出一个：一个版本一个包，差一条必闭就退回、不出包。

## 4. CP9 外发可移植性（常驻门；C39）
1. **发布物零机器绑定**：对 `package.json` `files` 列出的全部文件 + 最终 zip 内文件，grep `DS-HARNESS|DS-PROJECT|19091|[A-Za-z]:\\` → **0 命中**。例外只有 Windows 长路径语法示例（`\\?\C:\x`）与通用盘符占位，登记进例外清单才可放行。
2. **基座唯一**：A2 `session-policy.json`、`plugin-policy.json`、`root-state-*`、`root-audit-*`、`pending-reconcile-*`、`sessions/`、`shared/`、`logs/` 必须全部由**同一个 `profileContext`（home 优先、dir 兜底）**推导；`USERPROFILE/HOME` 只能当 fallback，不得再拼 `.dsh`。
3. **后缀推导**：`-desktop` 一类后缀必须是 `profileContext.name` 推导，不得出现字面量。
4. **空基座 fail-closed**：env 皆空 / identity 不可得 → 不得生成相对路径、不得在 cwd（项目根）落任何文件；`/cg status` 显式 `user-store: unavailable (profileContext)`；`user-store-unavailable` 审计行落**根审计**（`<root>/memory/governance/audit.jsonl`，用户级不可用时唯一可落点，进程内恰 1 行；审计 sink 全不可用时退化为 warn 日志，二者择一必须在报告里写明）。
5. **命令面同源**：`/cg memory` 等命令面的 home 必须由 index 注入，与事件面同基座；`os.homedir()` 仅测试兜底。
6. **假 home 离线用例**（进常规套件）：假 `profileContext{name:'ext', home:<temp>/ext-home, dir:<temp>/ext-dir}` → 七类落盘全在 temp 下；`%USERPROFILE%\.dsh`、`%USERPROFILE%\context-governance`、进程 cwd 下**零新文件**；仅 env 时 fallback 一致；两者皆缺 → 不写盘；旧位置 store 可读且新写落新基座、只提示一次。
7. **真机边界**：「假 DSH_HOME 冷启动」在离线用假 profileContext 覆盖；真机第二个 home 需另起 DSH 实例，未开窗口则记「未覆盖」，不得默认 PASS。

## 5. 合规扫描（两跑，口径 2026-11-15 修正）
- **工具跑仓库级**：`node scripts/compliance-scan.mjs --strict --root <release-commit 的干净 worktree>` → **blocker=0**，explicit 看文件数（不得出现 "0 text files"——该工具按 git 跟踪文件扫，对解包目录跑会假绿）。
- **包内单独跑**：对 zip 解包目录逐文件 grep：凭据 9 类 + `DS-HARNESS|DS-PROJECT|<username>|[A-Za-z]:\\Users` + `session-<uuid>` → **0 命中**。
- 两跑不可互替；review/info 级逐条解释（如旧 review 文档的 `pass***` 掩码样例、仅在仓库不在包内）。

## 6. 逐文件对树
- zip 解包 → **CRLF→LF 归一** → 与 `git ls-tree -r <commit>` 的路径集合、`git show <commit>:<path>` 的内容逐文件比对：**文件数一致、内容哈希一致**；不得用工作树内容顶 commit 内容。

## 7. 包元数据
- 包名/版本（`1.1.0-rc.N`）、字节数、SHA256、文件数、LF 对树结果（N-N）、合规结果（blocker/warn/info）。

## 8. 结论页
- 「可装 = 是/否」+ 剩余真机门（CP1–CP9 状态）+ 需要用户动手的动作（重启窗口 / 真实压缩 / 临时 cwd 会话等）+ 已知边界（写进 Release notes 的条目）。

## 9. 常驻原则
- 用户提过一次的门（如 C39）进表即常驻；后续版本回归，不看是否被再次提醒。
- 发现表外缺口 → 当场补进本表并说明，不靠"这次记得"。
