## 3. 缺陷（必须并入 rc.10）

| ID | 缺陷 | 后果 | 修法要点 |
|---|---|---|---|
| P1 | A2/plugin-policy 用 `USERPROFILE/HOME + '.dsh'`，与 root-state 的 profileContext 基座不同源 | 外部 DSH home 非 `~/.dsh`（自定义 DSH_HOME、多 home、macOS/Linux）→ 策略写错位置；多 home 互相串；审计与策略分家 | 统一 `resolveUserHome(identity, env)`：`profileContext.home` → 优先；env 仅 fallback；**文件名不变** |
| P2 | 会话记忆 store 落在 `$HOME/context-governance/sessions`（本机已是 `~\context-governance`，非 `.dsh` 下） | 用户主目录留下游离目录；与审计/策略不同基座；外部机器同样错 | 迁到同一基座 `<home>/context-governance/{sessions,shared}`；**兼容读旧位置**（旧目录存在则继续用/一次提示，不丢已有记忆） |
| P3 | env 两者皆空时 `path.join('', '.dsh', …)` 退化成**相对路径**，A2 store 仍会 mkdir+write | 可能写进进程 cwd=项目根，违反「A2 不写项目根」红线；静默 | 空基座 → **fail-closed**：不建不写，`/cg status` 显式 `user-store: unavailable (profileContext)` + 审计一行 |
| P4 | 命令面没有注入 home，`/cg memory ...` 用 `os.homedir()` 兜底 | 修完 P1/P2 后命令面与事件面读写不同基座 → show/register 读不到、或又写到旧位置 | `commandOptions` 显式传 `home`（与 A2/会话记忆同源）；兜底仅测试用 |

## 4. 修复后必须成立的回归（我出包前逐条核）

1. **本机零漂移**：pc.home=`C:\Users\19091\.dsh` → A2/plugin-policy 路径不变；会话记忆从 `~\context-governance\sessions` 迁到 `~\.dsh\context-governance\sessions`，旧 store 仍可读（现存量仅 `session-f72e86a8` 测试库）。
2. **离线可移植用例**（测试自跑，我复核）：假 `profileContext{name:'ext', home:<temp>/ext-home, dir:<temp>/ext-dir}` → 断言六类落盘（A2、plugin-policy、root-state、root-audit、sessions、shared、logs）全在 temp 下；断言 `%USERPROFILE%\.dsh`、`%USERPROFILE%\context-governance`、进程 cwd 下**无新文件**。
3. 仅 env（无 identity）→ 走 fallback 且行为一致；两者都缺 → 显式不可用、不写盘。
4. 旧位置兼容：预先放一个旧 `sessions/<id>` → 能读回；新写入落新基座；只提示一次。
5. 常规门不退化：646 + 新增；layering（含我恢复的 4 门级）/chip/pset/memtools/UI/C11②/C38 全绿；CP0 缺失 0；`compliance-scan --strict` 0 blocker。
6. C39⑤「假 DSH_HOME 冷启动」：离线以假 profileContext 覆盖；**真机第二个 home 冷启动**需另起 DSH 实例，标「未覆盖」除非 00 另开窗口。
