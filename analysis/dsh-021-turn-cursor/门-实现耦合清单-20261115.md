## 4. 数量/上限断言集中点（最容易漏改的地方）

| 断言 | 出现处 | 变更时要同步 |
|---|---|---|
| footer 按钮 **= 2**（reset + save） | `ops-footer-pinned`（精确）、`b8-footer-visible`（>=2）、`b8-footer` | 增删任何 footer 按钮 |
| `恢复默认` / `打开设置页` 入口**不存在** | `ops-footer-pinned`（树+源码双查）、`b8-footer`（偏移 = -1）、`c27-c29`（文案） | 若要恢复这两个入口，必须先改门 |
| 输入框 **56px**（≤72） | `ops-footer-pinned`、`b8-footer` | 改宽度/字号 |
| 内容高度 **≤260** | `ops-footer-pinned`（wrapper px）、`b8-footer`、`c40-popover` | 改高度计算 |
| **bodyFloor 动态**（`computeBodyFloor`，随 footer 让位；极端档 96/70/32 视 footer 而定） | `ops-footer-pinned`（行为断言） | 改保底/让位算法 |
| footer **不得 `maxHeight`+`overflow:hidden`** | `ops-footer-pinned` | 改裁剪策略 |
| 弹层主视图 **≤3 行**、行宽 ≤18 汉字 | `c40-popover` | 改文案/字段 |
| 四层固定标签 | `ui-labels`(C32) | 改层级命名 |

> 修正记录：旧表把「下限 `96+88+44`」写成固定口径——那是 rc.16 时期 `b8-footer` 的静态算法；B11 后实现已改为 `computeBodyFloor` 动态让位，`ops-footer-pinned` 按公式断言，**不要再照着 96+88+44 改门**。

## 5. 使用与维护

1. **改实现前**：按"实现触点"查表 → 圈出会受影响的门 → 一起改、一起跑。
2. **加新门后**：在本表加一行（门文件 / 覆盖 / cases / 断言什么），并跑一次已知坏版验红（门牙）。
3. **删控件后**：先扫本表出现该控件的行，全改完再交付——B12/B14 就是漏了这一步。
4. **门红了先怀疑自己**：先看"是不是实现改了而门没改"，再怀疑实现；再查「缺失值 fallback 成历史常量」「样式常量当判据」两类假红。
5. **cases 数以实跑为准**：`node tests\probe-c36-38\run-at-commit.mjs <sha> <门>` 的 `TOTAL x/y` 即当前值。
