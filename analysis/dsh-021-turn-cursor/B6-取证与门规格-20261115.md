## 0. 定因（静态取证，已定 A 支，不需要用户 DOM）

用户环境 DevTools 禁粘贴、区域截图工具被遮罩搞坏 → 改从**宿主源码**取证（Electron asar 读 `app.asar`），两段硬证据：

1. **槽位挂载点**（`dsh-client-ui-conversation/lib/client.js`，offset ≈655461）：
   ```jsx
   <div className={InputBar.card} data-composer-card …>
     <div className={InputBar.overlayAnchor} data-composer-overlay>
       {renderSlot('conversation.input.overlay', {})}
   ```
2. **CSS**（同文件）：`GRgSLq_overlayAnchor{height:0;position:absolute;inset:0 0 auto}`（容器零高、透明）、`GRgSLq_card{position:relative}`、以及
   ```css
   .an3WzG_root[data-phase=active] .an3WzG_composerSeat{
     z-index:9; will-change:transform; position:sticky; bottom:0;
     overflow-anchor:none; background:linear-gradient(180deg, … var(--dsw-alias-bg-base) …)
   }
   ```

**`will-change: transform` 使该元素成为 `position:fixed` 后代的 containing block**（与真 transform 等效）。插件用视口坐标算 `left/top`，却被当成"相对 composer 座位"的偏移 → 面板落到 composer 下方/右侧 → **贴右下角 + 越出视口被裁**。

| 支 | 判定 | 理由 |
|---|---|---|
| **A** fixed 被劫持 | **成立** | `.composerSeat{will-change:transform}` 成为 containing block |
| B 面板巨大 | 排除 | 尺寸被 `≤min(360,vw−16)×260` 约束，截图可见内容量正常 |
| C slot 层自身盖住 | 排除 | `overlayAnchor` 是 `height:0`、透明、无背景 |
| D slot 有内容才挂载 | 排除 | 容器随卡片常驻（`sessionId!==undefined` 即渲染） |
| E 真空白 | 排除 | 关闭气泡立即恢复，与插件打开动作强相关 |

**关于当时并报的"对话区消失"（2026-11-15 13:3x 更正）**：该现象**归因存疑**——用户澄清"窗口透出桌面/底层画面"是第三方截图插件 `dsh-plugin-screenshot` 选区覆盖层的正常表现；因此"打开气泡时对话区消失"极可能来自该覆盖层，而非气泡。**它不并入 B6 结论**。B6 成立的只有「气泡脱锚、贴窗口右下、右/下被裁」，由宿主 `.composerSeat{will-change:transform}` 成为 `fixed` 的 containing block 实证。

C40 的"不遮对话区"仍保留为**回归项**（低成本、防未来），但不再作为 B6 的已证症状；窗口复测若仍出现"对话区消失"，再单独归因。

**取证方法教训**：当用户环境无法执行 probe 时，**改读宿主实现**比"猜修"更可靠，且可复跑、可引用行号——这条应写进常驻清单。


## 1. 四支判定表（拿到 `B6PROBE` 一行即可定性）

| 支 | 判据（数据） | 机制 | 修法 | 改动面 |
|---|---|---|---|---|
| **A** fixed 被劫持 | `panelChain` 任一层 `transform/filter/contain ≠ none` | `position:fixed` 相对该祖先而非视口 → 坐标被平移 + 被祖先 `overflow` 裁 | 面板节点 portal 到 `document.body`（**单节点**，wrapper `pointer-events:none`、面板 `auto`），或改用相对正确容器的 `absolute` | 中 |
| **B** 面板巨大 | `panel.w ≈ vw` 或 `panel.h ≈ vh` | 面板本身铺满，只露出右下内容 | 收紧尺寸：`width ≤ min(360, vw−16)`、`maxHeight ≤ 260`、`overflow:auto` | 小 |
| **C** slot 层自身盖住对话区 | `stackAtChatCenter[0]` 为宿主全屏层（非我方元素），且我方面板在其内 | `conversation.input.overlay` 这一层铺满且不透明 | **换 slot**（气泡与 chip 同挂 `conversation.composer.dock`，或宿主 overlay 专用槽），单开 commit | 结构性 |
| **D** slot 有内容才挂载 | `stackAtChatCenter[0]` 是我方**祖先容器**（非 `role=dialog`）、rect≈全屏、`background` 不透明 | 槽位一有子元素即挂载整层不透明容器 | 同 C：换 slot 或 portal 出该容器 | 结构性 |
| **E** 真空白 | 栈里无遮挡元素、对话区本身为空（无消息 DOM） | 非本插件引起 | 另行归因（可能空会话/滚动位置） | — |

**禁止的"修法"**：把面板继续留在 overlay slot 里靠 `z-index` 硬压宿主管线；给 wrapper 加不透明背景；用 `position:fixed` 而不 portal（A 支前提下）。

## 3. 门规格（rc.14 必须同时满足）

### 3.1 静态门（离线可跑，`verify-b6-popover-anchor.mjs`）

1. `B6-fixed-requires-portal`：若 `client.js` 使用 `position: 'fixed'` 渲染面板，则必须有 portal 到 `document.body` 的路径；否则红。
2. `B6-no-corner-fallback`：不得存在"取不到 chip 就用 `innerWidth−120 / innerHeight−120`"一类假坐标兜底（当前已删，防回归）。
3. `B6-no-anchor-means-no-render`：取不到锚点时必须 `layout=null` 不渲染（不得画在默认位置）。
4. `B6-slot-choice`：气泡若挂在 `conversation.input.overlay`，必须同时满足"portal 出该层"或其容器 `pointer-events:none` + 背景透明（D/C 支下则要求换 slot）。

### 3.2 真机 DOM 门（窗口内必跑，`b6-window-probe`）

几何（开气泡态）：
1. `|panel.centerX − chip.centerX| ≤ 8`；
2. 上弹时 `panel.bottom ≤ chip.top − 4`；下弹时 `panel.top ≥ chip.bottom + 4`；
3. `panel.left ≥ 8`、`panel.right ≤ vw − 8`、`panel.top ≥ 8`、`panel.bottom ≤ vh − 8`；
4. `panel.w ≤ min(360, vw − 16)`、`panel.h ≤ 260`；
5. 面板与输入框交集为 0。

可用性（本轮 B6 的核心，"对话区仍可见/可滚"）：
6. 开气泡前后，对话区容器 `getBoundingClientRect()` 的 `height/width` 偏差 ≤ 2px；
7. `document.elementsFromPoint(对话区中心)` 的栈里**不得出现**我方容器或任何不透明全屏层（只允许 dialogue 自身在其几何范围内出现）；
8. 对话区 `scrollHeight > clientHeight` 时仍可滚（滚动 `scrollTop` 能变）。

关闭态：
9. Esc / 外点 / 再点 chip 四种关闭后，`panel` 从 DOM 移除、焦点回 chip（`document.activeElement` 命中 `[data-cg-chip]`）。

## 5. 教训（写进常驻清单）

**纯函数几何门 + 单帧渲染门 = 掩盖两类真机缺陷**：
- B5：hook 数量随状态变化（单帧看不出）；
- B6：面板在真实 DOM 的落点与"非目标区域是否被遮挡"（纯函数看不出，必须有真实布局与层叠）。
→ 凡"浮层/弹层"组件，门必须包含 **真实 DOM rect 断言 + 非目标区域可见性断言**；无法离线布局时，以**真机 probe** 作为常驻门，截图只作体验证据、不作判据。
