# D-MGMT-023：保护指针 id 不可解析 / 同日复用（rc.3）

真机病例（rc.2，`session-5d1121ed`）：`protection-write` 记了 `MEM-20261115-1006`，memory 层索引/topics/`.bak` 全 0 命中；第 1 轮产生 `1003–1005`，第 2 轮又从 `1005` 起编，`MEM-1005` 被覆盖成本轮 latest-user。

## 1. 根因（两条，都是老代码）

1. **id 复用**：`protectSync` 的 id 只从 `PROTECTION_ID_FLOOR=1000` 起、在“当前已加载键（`#entries ∪ #protectionEntries`）”上找空位。被同标题去重丢弃、或被 discard/归档的条目**从不进入这两个 map**，其 id 下一轮就被重新分配。
2. **审计与落盘不同源**：同标题去重在 **materialize** 时才做（`#findRecentByTitle`），而 `protection-write` 在 protectSync 时就记了 journal 全部 id → 被去重丢掉的条目（1006）只在审计里有、落盘没有。

## 2. 修法

| commit | 内容 |
|---|---|
| `47f1c82` | ① id 持久高水位 `protection/.id-watermark`（`date→最大序号`），分配 = `max(floor, 高水位+1)` 递增，分配后立即落盘；启动时与已加载条目/journal 取并集续号。② 同标题去重前移到 `protectSync`：重复条仍进 journal（本周期回注不丢）但打 `deduped` 标记，只计入 `dedupedIds`。③ materialize 跳过 `deduped`，`moved/ids` 只数真正落盘的条；兜底去重只对**已落盘条目**比对（修掉“别的周期 pending 同标题把本轮真条目误判成重复”的隐患）。 |
| `4a2cfee` | `protection-write` 的 `ids` 只记会落盘的条，重复条单列 `dedupedIds`；`protection-materialized{moved,requested,dedupedIds}`；`requested > moved` 时写 `protection-entry-missing{requested,moved,missing,missingIds}` + warn。 |

## 3. 判据与测试

- 新增 `test/d-mgmt-023-id.test.mjs`（4 例）：同日两轮 id 单调递增、跨重启续号（读 `.id-watermark`）、discard 不回收号段、去重前移后 journal 留 2 条而物化只落 1 条且 `ids` 全可解析。
- 新增 `test/d-mgmt-023-audit.test.mjs`（3 例）：`protection-write.ids` 逐条 `store.get` 可解析且 `moved=requested`、无 `protection-entry-missing`；白名单反证保留 `dedupedIds/missingIds/requested/missing`；旧 journal 兜底去重只落 1 条。
- 全量：`node --test "test/*.test.mjs"` = **592 / 592 pass**（基线 585 不降，净增 7）。

## 4. 复验项（N3/真机）

1. **指针可解析率 100%**：`protection-write.ids` 每个 id 在 memory 层（索引或 topics）可解析；`dedupedIds` 属“只回注不落盘”，不计入分母（审计已单列）。
2. **同日不复用**：同一天连续两轮压缩，第二轮 id 严格大于第一轮最大值；重启后继续递增（`.id-watermark` 生效）。
3. **moved 与落盘一致**：`protection-materialized.moved` = 实际落盘条数 = `ids.length`；差 ≥1 必有 `protection-entry-missing`。
