判定分档（同一 kind 只命中一次）：

- 主判事件级：窗口内出现该 kind 的非治理新节点 ⇒ `self-heal-verified`（`mode='event-level'`，`reason='baseline-event-level'`）
- `mismatch` → 另发 `self-heal-suspect`（warn），仍 pass；`unreadable` → 另发 `self-heal-unverified`（warn），仍 pass；**均不产 loss**（v4 起；v3 的 `baseline-stale` fail 已作废）
- `unverified` → `self-heal-unverified`（`mode='event-level'`、`disposition='warn'`）+ 仍写 `self-heal-verified`（事件级通过）
- `skill-catalog` → 只走事件级（宿主目录无 per-entry digest），不引 `ctx.get('skills')`

未自愈（窗口到期/中止/会话结束/重启）→ `self-heal-missing` + `compaction-loss`，不静默。

## 6. kill switch 语义（审核复核 b 的答复：写进文档，不把登记移出开关）

`protection.rebuild.enabled=false` 时的实际行为，按代码事实写死：

| 项 | 开关关闭时 |
|---|---|
| latestUser 副本重建 | 跳过（`surface-rebuild-disabled` 留审计） |
| `rebuilt.delegated` | 恒为空（`rebuildProtectionSurface` 未被调用） |
| `#pendingHeals` 登记 | **不发生** |
| `self-heal-pending/verified/unverified/missing` | **一条都不写** |
| `compaction-loss(rule-injection)` | **不写** → 规则丢失不观测、不报警 |

也就是说：**kill switch 关闭的是整段分型审计，不只是重建**。这是有意的取舍——回滚开关的语义是「治理整段不介入」，若要「只关重建、仍观测自愈」得把登记移到开关外，那会让回滚态仍产出 `self-heal-*` 与假 `compaction-loss`（重建没做、窗口内也没人重放，loss 无从判定），反而制造噪声。因此：

- 回滚时不要指望 `self-heal-*` 事件；对账口径退回 1.0.3 行为（只看 `protection` 报告与 `surface-rebuild-disabled`）。
- 装机走查若要看 C35 判定，必须保持 `protection.rebuild.enabled=true`（默认值）。

代码注释同口径：`src/compress/runtime.js` 登记点上方。
