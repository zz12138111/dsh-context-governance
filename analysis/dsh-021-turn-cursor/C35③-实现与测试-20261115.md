## 1. 实现落点

| 位置 | 内容 |
|---|---|
| `src/compress/runtime.js` `#pendingHeals` / `#registerPendingHeal` | `compaction/end` 后把被 shadow 的 `rule-injection` 类别（`agent-instructions` / `skill-catalog`）登记为「待宿主自愈」，窗口从 `turn/start` 绑定 `windowTurnId` |
| `src/compress/runtime.js` `#matchPendingHeal` | 窗口内出现该 kind 的非治理新节点即命中：`type∈{user/message,system/message}`、`seq>seqAtEnd`、`source.plugin!=='context-governance'`、`source.form!=='surface-rebuild'` |
| `src/compress/runtime.js` `#verifyBaselineDigests` | `agent-instructions` 的 `source.changes[]` 逐 path 读盘算 `sha1(trim(content))`：全一致 `match`；任一不一致 `stale`；读盘失败/字段缺失/路径不可解析 `unverified` |
| `src/compress/runtime.js` `#settlePendingHeals` / `#settleAllPendingHeals` | `turn/end`（仅已绑定窗口）→ `host-self-heal-missing`；`turn/abort` → `turn-aborted`；`stop()` → `session-ended`；启动扫描 → `restart`；每类各写一条 `compaction-loss(rule-injection, b-class-loss, unacceptable)` |
| `src/audit.js` | 新增事件 `self-heal-pending|verified|unverified|missing`；白名单字段 `form/plugin/digest/mode/path` |

判定分档（同一 kind 只命中一次）：

- `match` → `self-heal-verified`（`mode='baseline-digest'`，带 `digest`）
- `stale` → `self-heal-missing`（`reason='baseline-stale'`）+ `compaction-loss`，不再写 verified
- `unverified` → `self-heal-unverified`（`mode='event-level'`、`disposition='warn'`）+ 仍写 `self-heal-verified`（事件级通过）
- `skill-catalog` → 只走事件级（宿主目录无 per-entry digest），不引 `ctx.get('skills')`

未自愈（窗口到期/中止/会话结束/重启）→ `self-heal-missing` + `compaction-loss`，不静默。

## 3. 本轮修掉的一个真 bug

初版在 `switch` 里新增了重复的 `case 'user/message'`，把后面的 `compact-checkpoint` 记账分支遮住 → `checkpointSeq` 恒为 null，`artifact` 校验 fail（11 个旧用例红）。已改为在同一分支内先 `#matchPendingHeal` 再走 checkpoint 记账。教训：事件分支按「事件类型」唯一，新增逻辑必须并入既有 case。
