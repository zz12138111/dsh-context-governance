# C31 loopback 口径裁定：算缺口（A）

日期：2026-11-15｜对象：`7d72ad8` 的两条写路由｜裁定：审核打包（技术/安全口径，不上达用户）

## 事实

- 插件注册两条 POST 写路由：`/context-governance/session-policy`（写 A2）、`/context-governance/plugin-policy`（写 plugin 全局），见 `src/session-policy-route.js:17/139`。
- 现有防护：仅 POST、body ≤4 KiB、`sessionId` 白名单、`at∈[0,1]`、`Origin != Host → 403`、`no-store`。
- **无 remote-address 校验**；且 `crossOrigin()`（`:46-56`）在 **Origin 或 Host 任一缺失时返回 false**（按放行处理，注释写"交给宿主同源策略"）。
- 监听绑定不归插件：`webServer.register` 只挂路由，宿主怎么绑端口/是否反代由用户环境决定。

## 后果（外部用户场景）

1. 非浏览器客户端可**不带 Origin** 直接 POST → 同源校验根本不触发；也可随意伪造 Origin → 同源校验对 curl 无效。
2. 若宿主 Web 服务被用户绑到 `0.0.0.0`/被反代/被局域网可达，任何人都能改写**全局阈值**或任意会话阈值（只能影响压缩频率，不泄数据）；属于"策略被外部篡改"，非"只影响本机"。
3. C31 明文要求「仅 loopback」「Origin 缺失 → 403，不得当可选」，当前实现两条都不满足。

## 裁定：A 算缺口（并入 rc.10 与 C27/C29 同批）

修复要求（两条都做，缺一不可）：
1. **强制 loopback**：校验 `req.socket.remoteAddress` ∈ {`127.0.0.1`,`::1`,`::ffff:127.0.0.1`}（含 IPv4-mapped 写法），否则 **403 `not-loopback`**；两条写路由共用同一守卫（抽公共函数，别复制）。
2. **同源必做**：`Origin` 与 `Host` 同源 **或** `Sec-Fetch-Site: same-origin|none`，二者皆无/非法 → **403 `missing-origin`**（不再"缺就当可选"）。浏览器 POST fetch 会自动带 Origin/Sec-Fetch-Site，正常 UI 不受影响。
3. 测试：假 req 覆盖 ①loopback+同源→200；②`::ffff:127.0.0.1`→200；③远地址→403；④无 Origin 且无 Sec-Fetch-Site→403；⑤跨源→403；⑥超长 body/坏 sessionId 仍按原码；⑦UI 探针的假 req 补 headers/remoteAddress（否则会假红）。
4. 行为变更写 Release notes：写路由现在拒绝非 loopback 与非同源（含无 Origin 的脚本调用）。

## 影响

- 1.1.0 终版差距：从 1 项（C27/C29）变 **2 项**（+C31）；同批修完再装机，仍只出一个 rc.10。
- 不改需求文字（按 C31 原文实现），无需用户改口径。
