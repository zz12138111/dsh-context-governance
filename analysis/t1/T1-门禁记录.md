## F1：模型下一次请求消费前替换生效

### 路径 A：`tools/post-execute`（比 `tool/result` 更早）

宿主流水线（`@deepseek-ai/dsh-tools/README.zh.md:109`）：

```
tools/pre-execute → guard → tools/execute → tools/post-execute（检查/替换）
→ finalizeContent → tools/result（仅观测）
```

时序证据：
- `post-execute` 的 accept decision 替换 `content`：`dsh-tools/lib/types/index.js:1152-1188`；
- `finalizeScheduledExecution` 先跑 `postExecute`：`:1018-1029`；
- Agent loop `commitReady` 先 `finalize`（`:570`），**下一行**才 `appendToolResult`（`:571`）；
- `appendToolResult` 用 `result.content` 构造 message 并 `session.append("tool/result")`：`dsh-agent-loop/lib/index.js:691-706`。

实测（只读会话 + 1 次 subagent）：
- 需求会话 `f72e86a8`：7 条 `web_fetch` 的 `tool/result` 已是 host spill-policy 折叠版（49,929–49,933 字符），spill 原文 55,400–104,606 字节，omitted 5,700–52,880；head/tail 均能在原文找到。
- subagent `ff71b121`：`grep` 一次，原文 74,075 字节；`tool/result` 49,932 字符（`Found 250 matches` + 头/尾 + notice `Omitted 24371 bytes`），spill 文件 74,075 字节；call seq 20 → result seq 21。
- `pwsh`（硬排除）由 tokenGuard 折：2 例，摘要 1,573/2,196 字符，spill 8,137/9,370 字节。

### 路径 B：宿主 `tool-result-pruner`（压缩触发，新口径允许）

`@deepseek-ai/dsh-compaction-tool-result-pruner`：
- 默认 `thresholdChars=8192`、`headChars=4096`、`tailChars=1024`，中间插 `[... tool result middle pruned ...]`（`lib/index.js:8-14`）。
- 压缩压力/溢出确认后，`compaction-basic` 调 `pruneSession`（`:926-944`）。
- `pruneSession` 对每个超预算 `tool/result`：
  1. 先 `session.append("compaction/prune", { shadowedRange, shadowedSeqs:[seq], shadowedTokenCount: tokenMeter.estimateMessage(original) })`（`:159-166`）；
  2. 再 `session.append("tool/result", {...event.data, message: pruned}, { surfaceOp:{op:'replace',startSeq,endSeq}, sourceEventSeqs:[seq] })`（`:167-177`）。
- README 明确：“后续请求看到的将是保留的头 + middle pruned + 尾，模型不会看到原文第二份副本”（`README.zh.md:116`）。

真机会话 `58a2e845`（开发）实例：
- 8 条 `compaction/prune`（seq 4177–4191），全部为 `read`；原结果 8,392–19,153 字符 → 替换版 5,159 字符；`shadowedTokenCount` 2,106–4,797；替换版全部带 `sourceEventSeqs:[原seq]`。
- 紧接着 `compaction/start(seq 4193) → summary → end`；下一次请求的 `assistant/message`（seq 4201）prompt 水位 24,006（input 4,038 + cacheRead 19,968），而压缩前最后一条（seq 4171）为 791,339（input 811 + cacheRead 790,528）。这不是“只写审计”：替换版是 surface 节点，下一次请求消费它。
- 证据：`analysis/t1/data/f1-evidence.txt`、`analysis/t1/data/b1-baseline.json`。

## F2：不叠加（含宿主 pruner）

### 默认不重叠

- 本机 profile：`~/.dsh/profiles/desktop/cordis.patch.yml:87-92`：`tokenGuard.enabled=true`，`tools:[pwsh]`；本插件名单不含 `pwsh`/`read`。
- tokenGuard 源码：`internal/token-guard.mjs:28`（默认 `pwsh`）、`:260-319`（post-execute）、摘要以 `[token-guard]` 开头。
- 宿主 pruner 在压缩点先于任何 `compaction/start` 监听器运行；M1.1 若也在压缩点扫描，看到的是已折结果，必须跳过。

### 跳过规则（`analysis/t1/fold-probe.mjs`，21/21）

1. `decision.kind !== 'accept'` → 原样返回。
2. `decision.value` 存在 → 原样返回（避免 content/value 冲突）。
3. 工具不在名单 / `pwsh`/`read` → 原样返回。
4. 文本含 `[token-guard]` → 跳过。
5. 文本含 `[cg-fold]` → 跳过（幂等）。
6. 文本含宿主 spill notice `(Omitted N bytes. Full formatted result stored at: …)` → 跳过。
7. 文本含宿主 pruner 标记 `[... tool result middle pruned ...]` → 跳过。
8. 事件带 `sourceEventSeqs` 指向 `compaction/prune.shadowedSeqs`（或 `surfaceOp.replace`）→ 跳过（`alreadyPruned` 分支）。
9. 多块/带 image → 跳过；< `minChars` → 跳过。

### 瀑布顺序

- 宿主 spill-policy `prepend:true`（最外层）：先 `next()` → 本插件（内层）折叠 → 宿主看到折叠后内容且低于 `maxInlineTokens`（默认 12500）→ 不再处理。
- tokenGuard 与本报插件都是普通监听器；本机 bundle 顺序 computer-use 在 context-governance 之前，tokenGuard 外层先折 `pwsh`，本插件看到标记跳过。
- **边缘**：若用户把 tokenGuard 名单加到本插件工具且预算低于折叠后长度（<约 800 token），反向顺序可能二次压缩；默认名单/预算不触发。F2 要求（本插件跳过已标记结果）已满足；文档需写明保持 tokenGuard 仅 `pwsh` 或让折叠结果低于其预算。

## B2：宿主 pruner vs M1.1 T2（按模板 8 维）

| 维度 | 宿主 `tool-result-pruner` | M1.1 目标 | 处置 / 要回答的问题 |
|---|---|---|---|
| 触发时机 | 压缩压力/溢出确认后，`compaction-basic` 调 `pruneSession`，先于 `compaction/start` | 结果入史即折（持续） | **自研触发（需需求批准）**。B1 证不出早折收益（开发/审核 0 命中）；若复用宿主时机，宿主已先折完 >8192，T2 增量≈0。T2 要有增量必须**早于**宿主 pruner。 |
| 阈值/保留 | 8192 码点；头 4096 + 尾 1024 | 8000 字符；头尾各 1500 | **对齐宿主**（复用 8192/4096/1024）可避免两套阈值打架；若需求坚持 8000/1500/1500，必须作为显式差异并只保留一套生效。 |
| 工具范围 | 全部文本结果（含 `pwsh`/`read`） | 白名单；绝不折 `pwsh`/`read` | **自研（硬约束）**。但宿主仍会折 `pwsh`/`read`；M1.1 只决定自己折什么，不阻止宿主。 |
| 替换协议 | `session.append` + `compaction/prune` 影子定价 + `sourceEventSeqs` + `surfaceOp.replace` | 同协议 | **必复用，不自研**。T2 若要早折，也必须用这套 append 替换 + 影子定价；不得自定义事件/仅审计。 |
| 原文留存/回读 | 原文留会话日志，靠回放取；模型无直接指针 | spill 文件 + 原生 `read` 指针 | **自研增量（spill 指针）**。复用协议时原文仍在日志，spill 是可 `read` 的增量；若不用 spill，就只剩日志回放，不满足“原生 read 回读”。 |
| 配置项 | `thresholdChars/headChars/tailChars` | `fold.*` 一组 | **命名/语义对齐**（如 `fold.minChars` 对应 `thresholdChars`，头尾同名），避免两套阈值同时生效；具体键名在 T2 定。 |
| 审计/成本 | 只有 `compaction/prune` 影子价 | `cg-fold` 审记 + 成本归属 | **自研增量**：折叠次数/原始/保留/省略/spill/回读；成本仍按 M1.2 `cost-v1.1` 口径，不混估算。 |
| 与 tokenGuard | 无感知 | 跳过已折结果 | **自研增量**：`[token-guard]`/`[cg-fold]`/spill/prune 标记跳过；默认名单不重叠，扩展名单时按 F2 规则。 |

**结论（一句）**：**T2 走「复用宿主协议 + 只做增量」——替换/影子定价/原文留日志全部复用 `session.append` + `compaction/prune`，不独立实现协议；增量只有触发、名单、spill 指针、审计、tokenGuard/pruner 跳过。**

**工作量/风险差**：
- 复用：协议/事件/影子价/回放兼容代码为 0；T2 只需折叠决策 + spill + 审计 + 测试，风险集中在“早于宿主 pruner”的时序与 `session.append` 重入。
- 独立实现：需自建替换+影子价+回放兼容，风险高且违反“不得自研替换协议”，不选。
- **但**：若触发对齐宿主（压缩点），宿主 pruner 已覆盖全部 >8192 结果，T2 增量≈0；若保留“早折”，B1 又证不出净收益。**因此 T2 范围需需求先拍板**：停项（宿主已覆盖）或批准早折（复用协议 + spill/audit 增量）。

## 风险与 T2 前置

- `job_output` 的 `finalizeContent` 在 policy 后截断，可能裁掉指针；T2 必须按 job 的 `outputLimitBytes` 跳过或保证指针在截断点前。
- 宿主 pruner 已折 `read`/`pwsh`；M1.1 名单排除它们，但宿主行为仍在；B1 显示这是开发会话的主要节省来源，不能算 M1.1 的收益。
- 早折若用 `session.append` 替换协议，需要验证在 `session/event` 回调内同步 append 是否允许、是否会被 publish 锁拒绝；T2 先做最小实验，不得直接生产实现。
- 宿主 spill-policy 与 pruner 都在压缩点工作；M1.1 早折后宿主 pruner 看到的是折叠后结果（<8192），不会再折；若 M1.1 spill 写失败，必须保留原文让宿主兜底。
- PTC 嵌套调用的 dispatch log 走宿主 `tools/ptc-dispatch-log`，本单不覆盖；T7 需明确。
