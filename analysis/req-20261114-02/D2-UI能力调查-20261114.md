# D2「设置里加一个压缩百分比输入框」——宿主 UI 能力调查（2026-11-14）

> 目的：回答用户质问「别人的插件都能有 UI，我们就加个简单的小百分比设置框这么复杂吗？」。
> 方法：只读核对宿主 `app.asar` 内官方包 README/源码 + 本机 `~/.dsh/profiles/desktop/node_modules` 已装插件的实证，**未改任何代码、未装任何东西**。
> 证据副本：`analysis/req-20261114-02/d2-evidence/`（从 asar 解出的官方 README 与关键 client 源）。
> 提取方式：只读 Node 脚本按 asar 头解析（`jsonLen` 在偏移 12，JSON 起于 16，数据区 4 字节对齐）。

## 0. 结论（一行）

**可行。** 第三方插件给设置页加一个数字框是**官方支持的公开机制**（不是我们自造），最短路径 = **自建 client 半侧（手写 `lib/client.js`，不需要打包器）+ `settings.section` 卡片 + Schemastery `Config` 的 `.volatile()` 字段**；要让界面显示"当前生效值/来源层"，再加一条**宿主 `ctx.webServer` GET 路由**（loopback、与 `cost-meter`/`computer-use` 同样的官方用法）。
**唯一"不复杂"的幻觉要打破**：宿主确实有 schema 自动表单（`autoGenerate`），但**没有任何已发布的客户端去渲染它**（官方 README 原话），所以"只声明配置就自动出框"这条路**不存在**；必须有 client 半侧。

**结论**：所谓"别人的插件都有 UI"，走的就是 **`dsh.client` + 自带 client bundle + slots 注册**；我们此前没有 client 半侧，所以"加个框"看起来复杂——**复杂在 client 半侧，不在宿主能力**。

## 3. 给治理插件的最短可行路径

| 步 | 内容 | 文件 |
|---|---|---|
| ① 包声明 | `exports += {"./client": "./lib/client.js"}`；`dsh.client = { platform: "web" }`（inject 按需，见 §5-1）；`files` 加 `lib/client.js`（+`locale/*.json` 如需） | `packages/dsh-context-governance/package.json` |
| ② 宿主半侧：可编辑配置 | 新增 Schemastery `Config`，把 `compact.at` 声明为 `.volatile()`；`ctx.inject(['settings'], …)` 内 `configure({auto:false}, ctx.fiber)`；写入落**当前 profile 的 Cordis patch = plugin 层** | `src/index.js`、`src/policy.js`（读取复用） |
| ③ 宿主半侧：立即生效（可选但推荐） | 监听配置 reload / volatile 引用变化，重算 policy（现状只在 `apply` 读一次，所以要重启才生效） | `src/index.js` |
| ④ 客户端半侧：设置页卡片 | 手写 `lib/client.js`：`window.__ModuleLoader__.load({id, factory})`；`ctx.slots.inject('settings.section', () => ctx.slots.register({name:'settings.section', id:'context-governance', order:…, label, inject}))`；卡片内一个百分比输入框；读写走 `configForms.get(entryId).set('compact.at', pct/100)` | `lib/client.js`（新，估算 250–400 行） |
| ⑤ "生效值/来源层/会话语义"取数 | `ctx.webServer.register({ method:'GET', path:'/context-governance/policy-snapshot', handler })` 返回 `{ at, source, sessionOverride, effectiveAt }`；client 同源 `fetch` | `src/index.js`（或新 `src/settings/policy-snapshot.js`） |

- **不需要**：打包器/构建链（bundle 可手写）、独立端口（复用宿主 webserver）、WebView/独立页面。
- **新增面**：一条 **loopback GET 路由**（无鉴权，与 `cost-meter`/`computer-use`/`notify-me` 同模式）；只读、只暴露阈值与来源层，不含记忆内容。
- **若不加路由**（更小改动）：C8 降级为"卡片显示 **plugin 层值** + 生效时点 +'全链来源见 `/cg status`'"，但**不满足**"显示当前生效值+来源层"原判据（需我书面收窄）。

## 4. 不可行 / 受限（说清卡在哪）

1. **"只声明配置、设置页自动出表单"不可行**：宿主有 `autoGenerate`，但官方 README 明说没有已发布客户端渲染它（§1.8）。卡在**客户端侧没这个渲染器**，不是我们没找到。
2. **本机 0.2.1-rc.3 未随包发布 `dsh-client-ui-slots` / `dsh-client-ui-primitives`**（asar 内无此包；三个第三方插件虽然 `inject` 了它们）。说明 `dsh.client.inject` 不是"必须存在的包"；`ctx.slots`/`ctx.configForms` 是宿主服务。**开发须按实测可用的服务写，不要照抄 inject 名单。**
3. **手写 bundle 离线无法验证真实渲染**：只能验语法/纯函数/渲染函数输出；浏览器挂载要真机。→ 建议在窗口 R7 验；若想在出包前验，需**用户批准一次"装 dev 包"**（红线 1，不能自行装）。
4. **`package-manifest:93` 说"安装器/加载器不强制 engines"**，但开发在 app-boot 找到 `evaluatePluginCompatibility` → `skippedBundles` 的跳过路径（见 REQ-02 探针 #6）。两说并存，**只能窗口实证**——本轮升级已喊停，不影响 D2。

## 5. 交开发前需回的三个点（不阻塞"可行"结论）

1. **`dsh.client.inject` 写不写、写哪些**：`cost-meter` 一个都没写也能挂 `settings.section`；`dsh-context` 写了 6 个。以"能跑"为准，给出实测依据。
2. **立即生效能否做到**：`volatile` 字段 + `config-reload` 监听后能否拿到新值并重算 policy；做不到就界面写"重启后生效"（C11）。
3. **路由要不要来源检查**：`dsh-client-connection` 等 route owner 自己实现请求策略（`host-webserver:130`）；我们这条只读 GET 是否沿用同源/回环校验，给方案。
