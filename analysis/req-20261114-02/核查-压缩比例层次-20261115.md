> 触发：用户原话「让需求看之前那个全局设置，**我要的是一个会话一个上下文压缩比例设置，不是全局**，这个有问题，看下是不是他需求口径写错了。」
> 结论先行：**是需求口径写漏了，不是用户记错。** D2 原文允许"按实现取其一"，实现取了全局；而更早的 D-设置页 原始规格明确要求"改动落在哪一层（会话/项目/配置）要**可选且可见**"。

## 2. 建议的 1.1.0 范围变更（用户要"一个会话一个比例"）

**主路径（本轮必做）：UI 默认写"本会话"（session 层），语义 = 本会话有效、重启后失效。**

| 项 | 建议 |
|---|---|
| 写入层 | chip/气泡的「保存」= **session 层**（等价 `/cg set compact.at=`），立即生效、只影响当前会话、重启失效 |
| 全局默认 | 设置页 `settings.section` 保留"保存为全局默认（plugin 层，影响所有会话）"，**文案必须写明"全局"**；两入口都显示当前层与生命周期 |
| `/cg set` | 与 UI **写同一层、等价**；`/cg set reset` 可清掉 UI 设置；后写覆盖前写 |
| 层可见/可选 | UI 必须显示「本会话」与「全局」的区别；不再出现"只写全局且不说明" |
| **不做** | **不引入"每会话持久各自值"的新存储**（那是另一套数据设计，需用户另批，建议 1.2.0 候选） |

**为什么不建议做持久会话级**：会话级持久要求按 sessionId 落盘并做迁移/TTL/清理，且会话数量无上限；1.1.0 已在返修中，加新存储会把"范围变更"升级为"新功能 + 数据设计"。**先满足用户"不是全局"的诉求，重启失效由 UI 文案讲清楚。**

## 4. 现实约束（写判据时要算进去）

- 治理插件**现已从本机下线**（bundles 16、`/context-governance/policy-snapshot` 404、日志未再增长）→ **下一步先由 00 重装再验**；
- 当前真正生效的压缩阈值只剩 `compaction-basic` 行上的**全局 `thresholdRatio: 0.65`**，且该行已被 `dsh-context-zip` 接管 → **会话级设置要在插件重新上线后才可验**；预验窗口必须先确认"插件在场 + 快照 200 + defaultAt"。
- 由此，**会话级写入需要宿主侧写入口**（客户端不能直接调 `/cg set` 命令）。方向可选手：本地 loopback POST（同源校验）或宿主 remote；**具体技术路线交开发/审核，需求只约束"不得绕过 C8/C11/安全边界、不得引入公网面"**。
