## 2. 配置条目与命名空间

- 表单/命名空间主键 = `entry.options.id`（`dsh-settings/lib/index.js:432`），我们的条目 id = **`dsh-context-governance`**（`packages/dsh-context-governance/cordis.patch.yml:12`）。
- 只有 schema 里声明的 **`.volatile()`** 字段进入表单（`dsh-settings:418`）；Schemastery `.volatile()` 只允许**固定路径**、不能落在 dict/动态键下（`schemastery/lib/index.mjs:235-246` 校验）。
  → 所以不能直接 volatile 化 `policy.values['compact.at']`（dict 动态键），须新增固定字段 **`policy.at`**（number 0–1），由我们合入 plugin 层。

## 3. 生效路径（决定"C9 文案"）

- `Config = Schema.object({policy: Schema.object({ at: Schema.number().min(0).max(1).step(0.01).volatile() })})`：Schemastery object 非严格模式会保留未知键（`lib/index.mjs:518` `merge(result, data)`），不丢现有配置字段。
- plugin 读 `config.policy.at` 的 **volatile 引用 `.get()`** 得实时值；`app-boot/config-reload` 后重算 `buildPolicyState`，经新增 `root-guards.updatePolicy(rootId, policy)` 下发到**每个已建 root**（多根逐个更新）。
- 若 R7 真机发现 reload 后引用未变：只改一处文案常量（C11 钉死）为「重启后生效」，逻辑不动。

## 4. 安全边界

- 快照路由 **只读 GET**、路径固定 `/context-governance/policy-snapshot`、只出 `{at, source, sessionOverride, effectiveAt, native}`，不含记忆内容与本机绝对路径；非 GET → 405；无写入口。
- 设置卡片只放 `compact.at`（百分比 0–100，内部 /100）；`estimateSafety` / `lowThresholdAck` / `armed` 无 UI 入口。
- 校验复用 `validateLayer`（`AT_MIN=0.20`、`<0.30` 需 ack、项目层 `0.45`、动态上限 `native−0.02`），拒绝文案与 `/cg set` 同源。
- `dsh.client` 只写 `{platform:'web'}`（不抄第三方 inject 名单）；卡片 `inject` 只列自用服务。

## 5. 不采用

- 不引打包器/构建链（手写 `lib/client.js`，加顶部格式/依赖注释块供审核核）。
- 不自造配置通道（不用自定义 POST 写文件；写一律走 `configForms`→profile patch）。
- 不扩设置面到其它键（只 `compact.at`）。
