# E2 · 回注形态实验记录与默认形态建议（REQ-20261025-01 M1 门禁）

> 结论先行：**默认回注形态 = ID + 状态 + 指针**；仅当“摘要可读且该 ID 未被摘要覆盖”时，允许补一行标题；**详情永不回注**；摘要不可读时只放 ID+状态。
> 证据级别：6 组真实压缩区间结构分析 + 真实 context-zip 引擎的 prompt 级隔离实验 + 16 篇真实摘要的结构化保留统计；**不含真实模型接续评分**（留给 T7 场景 S1–S6）。
> 红线遵守：只读；未启动第二个 DSH、未改已装插件/配置。

---

## 1. 三种形态的定义

| 形态 | 一条回注长这样 | 字符数（本实验样本） |
|---|---|---|
| 详情 | `MEM-… 待确认（见记忆）` + 一段 100–300 字理由/背景 | 177 |
| 标题+指针 | `MEM-… 待确认：默认回注形态选 ID+状态+指针（见记忆）` | 43 |
| ID+状态 | `MEM-… 待确认（见记忆）` | 26 |
| （对照）context-zip 工作笔记 | 只进摘要指令，不进会话历史 | 243 |

## 2. 结构实验：会不会被“吞”

**方法**：读取本机 16 次真实压缩的 `compaction/summary.shadowedRange` 与 checkpoint 的 seq；假设治理层在 checkpoint 之后**立刻**注入一条短消息（`seq = checkpoint + 1`），判断它是否落在下一次压缩的 shadow 区间内。

**结果（6 对“本次压缩 → 下次压缩”，全部来自 00 会话 7 次压缩）：**

| 本次 checkpoint | 下一次压缩 shadow | 注入 seq | 被吞 | 下次起点 == 本次 checkpoint |
|---|---|---|---|---|
| 3527 | 3527–5986 | 3528 | 是 | 是 |
| 7662 | 7662–9804 | 7663 | 是 | 是 |
| 11479 | 11479–14338 | 11480 | 是 | 是 |
| 16094 | 16094–20929 | 16095 | 是 | 是 |
| 20940 | 20940–25508 | 20941 | 是 | 是 |
| 25537 | 25537–28856 | 25538 | 是 | 是 |

- **6/6 被吞**：下次压缩的 span 从上次 checkpoint 起算，checkpoint 之后的一切（含回注）都会进入下一次摘要输入、被 checkpoint 替换。
- **6/6 下次起点 == 上次 checkpoint**：这是宿主 `selectCompactableRange()` 的行为（表面首个非 system 节点就是 checkpoint，`dsh-compaction-basic/lib/index.js:410-433`）。
- 推论：**只要“每次压缩后注入一次”，回注不会跨压缩在表面堆积 → 不会结构性重复**。
- 反向风险：在同一压缩周期内反复注入（每步/每轮）会让同一指针在保留尾部重复；prompt 实验证实引擎**不做去重**（见 §3 的 duplicate 行）。

数据：`analysis/e1e2/data/e2-structural.json`；脚本：`lab/e2-structural.mjs`。

## 3. Prompt 实验：三种形态进入摘要输入的样子

**方法**：只读复制已装 context-zip 0.1.10 的 `engine/lib/engine.js` 到临时目录，配 `@deepseek-ai/dsh-llm` 桩；把三种形态各作为一条 `user/message` 放进被压缩区间，截获 `summarize()` 实际收到的完整 `messages`（含五段式指令）。

| 用例 | prompt 字符 | 相对基线 Δ | 标记命中次数 | 五段指令 |
|---|---:|---:|---:|---:|
| 无回注（基线） | 4,722 | 0 | 0 | 5/5 |
| 详情回注 | 4,899 | **+177** | 1 | 5/5 |
| 标题+指针 | 4,765 | **+43** | 1 | 5/5 |
| ID+状态 | 4,748 | **+26** | 1 | 5/5 |
| ID+状态（连续注入两次） | 4,778 | +56 | **2** | 5/5 |
| 工作笔记（对照） | 4,965 | +243 | 0 | 5/5 |

- 三种形态**都原样进入摘要输入**，引擎不过滤、不改写指针行。
- 详情回注的 177 字符会被摘要模型再处理一次；这正是“第二段摘要/改写漂移”的来源，违反架构不变量 5。
- 连续注入两次 → prompt 里出现两份；**去重必须由治理层自己做**（注入前查当前表面是否已有该 ID 行，或用“每压缩周期一次”的时机约束）。
- 工作笔记只进指令、不进会话历史（`notesInInstruction=true, notesInMessages=false`）——这证明 context-zip 的 notes 是另一条通道；M1 不依赖它，但可作为 T3 的对照。

数据：`analysis/e1e2/data/e2-prompt.json`；脚本：`lab/e2-prompt-harness.mjs`。

## 4. 真实摘要的结构化保留（辅助）

16 篇真实摘要（6 篇宿主自由摘要 + 10 篇 context-zip 五段式）：

| 指标 | 全部 16 篇 | 五段式 10 篇 | 自由摘要 6 篇 |
|---|---:|---:|---:|
| 平均字符 | 5,459 | 3,816 | 8,197 |
| 含 `DEC-*` 决策编号 | 7 篇 / 26 个 | 6 篇 / 19 个 | 1 篇 / 7 个 |
| 含批次号（如 511/958） | 7 篇 / 17 个 | 3 篇 / 10 个 | 4 篇 / 7 个 |
| 含 Windows 路径 | 16 篇 / 224 个 | 10 篇 / 120 个 | 6 篇 / 104 个 |
| 含 `MEM-*` 记忆 ID | 0（尚未投产，无样本） | 0 | 0 |

- 摘要**确实会保留**结构化 ID/路径/批次号（尤其五段式），所以“摘要可读 → 按覆盖判断是否补标题”在数据上成立。
- 但保留率不是 100%；不能假设“摘要里一定有某条记忆”，所以默认形态必须**自带 ID+状态**，不能只依赖摘要。
- `MEM-*` 无样本：其被摘要保留的概率未知，这是 E2 的已知缺口，靠 T4 的覆盖判断与 T7 场景验证。

数据：`analysis/e1e2/data/e2-summary-analysis.json`。

## 5. 结论与建议（供 T4 实现与需求回写）

### 5.1 默认形态

**ID + 状态 + 指针**：

```
MEM-20261025-017 待确认（见记忆）
MEM-20261025-003 仍生效（见记忆）
```

### 5.2 条件增强（唯一允许的“加字”）

仅当 **摘要可读** 且 **覆盖判断未命中**（摘要里找不到该 ID/标题关键词）时，补一行标题：

```
MEM-20261025-017 待确认：默认回注形态选 ID+状态+指针（见记忆）
```

理由：43 字符的边际成本可控；覆盖未命中时纯 ID 对模型几乎没有信息量；覆盖命中时再加标题会直接推高“回注重复率”。

### 5.3 其他分支

| 情况 | 形态 |
|---|---|
| 摘要不可读 / 覆盖判断不可用 | 只放 `ID + 状态 +（详情查记忆）`，不猜内容 |
| 新会话 / 唤醒 | 与回注同形态：只放活动与待确认条目的指针；详情由模型 `mem_query` 拉取 |
| 详情 | **永不回注**（违反则视为缺陷；T7 需有检查项） |

### 5.4 时机与去重（E2 的结构结论直接约束 T4）

1. 只在 `compaction/end` 之后注入一次；会话开始/唤醒时再注入一次。
2. **不要每步注入**：同一压缩周期内会重复（prompt 实验 duplicate 行）。
3. 注入前做一次“当前表面是否已有同一 ID 行”的去重；能命中就不重复写。
4. “被吞”审计口径：记录注入 `seq` 与当时 `compactionId`；下一次 `compaction/summary` 到达时，检查 `injectionSeq ∈ shadowedRange` → 标记“被吞”，不要靠“模型说没看到”来判断。

### 5.5 为什么不选“标题+指针”做默认

- 43 vs 26 字符的差距小，但每轮回注 N 条时会被放大；M1 的 header 预算应优先给“覆盖面”，不是给重复标题。
- 已覆盖条目补标题直接制造重复；未覆盖才需要。
- 详情回注 177 字符 + 二次摘要风险，明确排除。

## 6. 未验证项与对门禁的影响

- **没有真实模型的接续评分**：本实验证明“形态会进入摘要输入、不会被引擎过滤、跨压缩不会结构性重复”，但不能证明“模型看到 ID+状态就能接上”。这属于 T7 的 S1–S6 验收，不是 E2 前置门禁的定义（E2 只要求选出默认形态）。
- **MEM-* 在摘要中的保留率未知**：T4 的覆盖判断必须把“未命中”当默认（宁可多补一行标题），不能反过来假设“没写就是没覆盖”。
- **长会话尾部**：结构结论基于本机 6 对压缩；更长的会话仍应保持“每次压缩后一次”的注入策略。

**E2 门禁判定：通过。** 默认形态已选定（ID+状态+指针；未覆盖时补标题；详情永不回注），并给出可执行的时机/去重/审计约束。
