## 2. G2-B turn 中失败形态（pre-step）

两次取样，形态不同、结论一致（turn 中不可压）：

1. 预置已 abort 的 signal（第一次实例）：
   ```
   G2B rejected name=AbortError msg=This operation was aborted elapsed=0ms
   ```
   → abort 优先，未进入压缩（安全）。
2. live signal，3s 后 abort 兜底（第二次实例，`G2_PROBE_MODE=b2`）：
   ```
   G2B2 rejected name=ManualCompactionError msg=manual compaction requires an idle agent with no waking queued work elapsed=0ms
   ```
   → **宿主明确要求 idle**，turn 中必被拒。

**P3-1 真机复现**：当前 `isBusyCompactionError()`（`src/compress/early.js:22-30`）匹配
`name==='ManualCompactionError' && /busy/i`、`code==='BUSY'`、`/not idle|busy/i && /compaction/i`；
真实文案 `manual compaction requires an idle agent with no waking queued work` **三项都不命中** → 会被映射为 `failed` 而非 `busy`。
建议（0.2.2 接线时）：增加 `/requires an idle agent|no waking queued work/`，或对 `name==='ManualCompactionError'` 且含 `/\bidle\b/` 统一判 busy，并补单测用该真实文案。

## 4. G3-1 `measure()` 即时性

探针在 4 类时机记录 `tokenMeter.measure(session)` 的 `Σtokens` 与 `contextPressure.surfaceTokens`：

| 时机 | Σmeasure | surfaceTokens | 说明 |
|---|---|---|---|
| 首回合 pre-step(step=1) | 0 | 0 | 新会话 surface 尚未建立（预期） |
| assistant/message（回合 1） | 3216 | 3216 | **逐点相等** |
| turn/end（回合 1） | 3216 | 3216 | 相等 |
| compaction/end 后 microtask | 2173 | 2173 | 压后立即下降且相等 |
| 回合 2 pre-step | 2252 | 2252 | 已含回注后的 surface |
| assistant/message（回合 2） | 3781 | 3781 | 相等 |

**判定**：`measure()` 在 turn 边界与压缩后即时反映当前 surface；**唯一例外**是新会话首回合 pre-step（surface=0），与 0.2.1 的“measured 取 usage、estimated 取 meter”口径不冲突。

## 5. G3-2 `effective` 口径

- `/cg status` 实测（上）：`estimated < measured`，`adjusted = estimated × 1.35`，`effective = max(measured, adjusted) = measured`；`ratio = measured/estimated = 3.00`；`window=1M (session cb5d7522)`（projection，1,048,576），与 0.2.1 的 `native=0.6934` 同源。
- 压后 `last-cost before=3216 after=2252`（tokenMeter），`tokensAfterSource=tokenMeter`：压后即时可取，不需要等下一轮。
- **未触发**：`effective ≥ native−0.02`（0.6734）——本会话规模远低于 native，该分支仍是纸面口径；留作发布说明的已知限制。
