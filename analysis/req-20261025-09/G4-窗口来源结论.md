# G4 · 窗口 / `native` 来源结论（REQ-20261025-09，0.2.1 前置）

> 状态：**结论已定**，落 `DECISIONS.md` `DEC-PLUGIN-20261025-40`。审核可引用本文。
> 日期：2026-10-26。范围：只回答“窗口/native 的数值从哪来”，不改 0.2.0 行为（0.2.0 仍用配置窗口）。

## 0. 问题

0.2.0 的 `native` 与压力四段分母都取自**配置** `policy.windowTokens/reservedTokens`（默认 1,000,000 / 256,000 → `native=0.6785`）。这是假设值：真实路由窗口不同（或换模型）时，`native` 与四段读数会整体偏移，且目前无法从 `/cg status` 判断分母来源。G4 = 找宿主是否有权威窗口值，定 0.2.1 的来源优先级。

## 1. 候选路径：`sessionProjections.contextPressure`

源码事实（`app.asar` 内 `@deepseek-ai/dsh-token-meter`）：

- 注册：`ctx.sessionProjections.register(contextPressureProjectionDefinition)`，key = `"contextPressure"`，`stateVersion: 5`。
- 状态 schema（节选）：
  - `pressureTokens?` — provider 报告的上一次请求 prompt 大小（uncached input + cacheRead + cacheWrite；不含输出）。
  - `projectedTokens?` — “下一次请求”的 prompt 估算（`pressureTokens` + 采样后 surface 增量）。
  - `contextWindow?` — **“Newest recorded route capacity; absent when no adapter advertised one.”**
  - `surfaceTokens` / `sampledSurfaceTokens` — fold surface 总量与采样锚点。
- `contextWindow` 由 `request/context` 事件的 `data.contextWindow` 写入（每个会话至少 1 条 `request/context`；本机真实会话日志已解出）。
- `sessionProjections` 是**根作用域服务**（`AgentLoop.inject` 含它）。**可见性受加载顺序影响，不是固定晚挂载**：0.2.0 真机 `capability@apply`（`16:11:21.204Z`）里已是 `get.sessionProjections=obj`；本探针实例在 apply 时为 `absent`、约 2s 后才 `object`——两者都出现过。实现按需 `ctx.get('sessionProjections')`、**每次判断**，读不到就回退，不写“固定 2s 后可用”。
- `stateOf(session,'contextPressure')` 返回的是**状态**（含 `pressureTokens` / `contextWindow` / `surfaceTokens` / `sampledSurfaceTokens`），**不含 `projectedTokens`**——后者是 wire view 字段。需要 `projectedTokens` 时：用 `sessionProjections.snapshot(session,['contextPressure'])` 取 view，或按定义自算 `pressureTokens + surfaceTokens − sampledSurfaceTokens`。

## 3. 结论（0.2.1 按此实现）

| 项 | 结论 |
|---|---|
| 窗口 `W` 来源 | **优先 `contextPressure.contextWindow`**（provider 广告的 route capacity）；缺省/为 0/投影不可用时回退 `policy.windowTokens`（配置） |
| 输出预留 `O` | 宿主无对应字段 → 保持配置 `policy.reservedTokens`（默认 256000） |
| `native` | `floor(min(W×0.8, W−O−65536))/W`，`W` 用上述来源；**必须标注来源** `window=1048576 (projection)` / `(config fallback)` |
| 取数时机 | 按需 `ctx.get('sessionProjections')` + **每次判断**（可见性取决于加载顺序，实测 apply 时 absent 与 obj 都出现过）；不硬 inject；读不到/取不到就回退配置。**性能**：`stateOf` 会 `materializeCells(session)`，*每次 status/判定只取一次并缓存*，不要每事件都调；返回的是 **live 引用，只读不改**。 |
| `W` 防御 | 取用前校验 `Number.isInteger(W) && W > 0`（host state 是 apply 直接写的原始值，schema 只约束 wire view/初始化）；不满足即回退配置。 |
| 同源要求 | **`native` 与压力分母必须同源、同时改**（审核 Q2）：不能出现 `native=0.6934`（投影 W）而 `ratio` 仍按 1e6 算的混搭；0.2.1 里两处都从同一个 W 解析函数取，`/cg status` 显示同一来源标注。 |
| 数值影响 | `W=1,048,576` 时 `native=727040/1048576≈0.6934`；配置默认 `1,000,000` 会低估约 1.5pt → 0.2.1 起 `native` 必须优先用投影窗口 |
| 压力四段（后续） | `measured` 可改用 `pressureTokens/W`（provider 实测，替代我们自算的 usage 和）；`projectedTokens` 不在 `stateOf` 里，需 `snapshot(session,['contextPressure'])` 或自算 `pressureTokens + surfaceTokens − sampledSurfaceTokens`；两处都必须标源，不能悄悄换 |

## 4. 明确不做的

- 0.2.0 不改代码（仍配置窗口）；本结论只约束 0.2.1。
- 不把 `contextWindow` 当“压缩触发阈值”——它只是分母；阈值仍是 `compact.at × W`。
- 不在 provider 不广告窗口时猜值：回退配置并在 `/cg status` 标 `(config fallback)`。
