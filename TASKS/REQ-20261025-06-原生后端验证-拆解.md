> 红线：不改用户 desktop profile、不卸载 context-zip、不动安装态；**只允许新建隔离 profile 实例**（用户 2026-10-25 决策）；不 push。
> 版本：验证不强制升版；发现缺陷才出 **0.1.15**。

## T1 离线回放（先做，零风险）

- 从 `~/.dsh/sessions` 中定位 6 次**自由摘要**（非五段式）的 `compaction/summary` 事件；
- 用现有适配器逻辑回放：`applySummaryObservation` / `selectMode` / 覆盖判断；
- 输出：后端识别结论（`adapter` 应是什么）、摘要 readable 判定、回注应走哪条分支；
- 预期：若识别为 `none/unknown` → 即为缺陷候选（交给 T5）。

## T2 隔离 profile 实例（用户已批准）

- **不碰 desktop**：新建独立 profile（名如 `native-test`），不装 context-zip、不加 redirect；
- **端口/目录隔离**：独立端口、独立工作目录、独立测试工作区；与桌面实例错开；
- 插件用 **junction/软链**指向源码（与桌面一致的方式），不改用户安装；
- 证据：profile 路径、端口、启动命令、桌面实例未受影响的截图/日志；
- 用后：可保留但需停实例；不得长期占用资源。

## T3 自动压缩验证

- 触发方式（择一）：构造长上下文触发 pressure；或用小窗口模型；或先手动压一轮再构造；
- 检查链路：`compaction/start` → `summary`（自由文本）→ checkpoint → `end`；我们的 `protection-write` → `reinjection` → `compaction-cost`；
- 重点：5 类保护项是否 0 丢失；回注形态是否为“标题 + 指针”；成本字段来源是否正确（`usage` measured / `tokenMeter` estimate）。

## T4 手动压缩验证

- `/compact` 一轮，验 S4=B：记忆指针、`manual-compaction-loss` 告警、回注能看出最后一句；
- 记录与 context-zip 下的差异（如果有）。

## T5 结论与可选修复

- 逐项给 D1-1～D1-5 的“通过 / 不通过 + 证据路径”；
- 若不通过：判定是**识别缺陷**、**分支缺陷**还是**宿主行为**，给修复建议；
- 需改代码 → 出 0.1.15，范围最小化，并先报需求确认；
- 报告写清“原生后端可用性”结论，供 M2 与发布说明引用。

## 明确不做

- 不改 desktop profile、不卸载/禁用 context-zip、不改 `isolate`；
- 不接 ACP、不推远端、不做折叠。
