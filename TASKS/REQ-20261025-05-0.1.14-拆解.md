## T1 同源约束（主）

- **现状**：0.1.13 从消息正文取 `x/y`，但 `2/6`（收口计数）、`183/183`（测试数）会命中 → 判 `fail` → 写 `manual-compaction-loss` 假阳性（真机 `seq=11453 ratios=["2/6"] → fail`）。
- **改法（依 `DEC-20261025-46`）**：
  1. 候选来源 = `user/message` 与 `assistant/message` 的**正文**；
  2. **无论 user 还是 assistant，都必须同一条消息内出现批次语义关键字**（`批次` / `进度` / `progress` / `batch`）才成为候选；
  3. 批次语义与比例**必须在同一条消息内**，跨消息拼凑不算；
  4. 无关键字 → `skip(reason=no-batch-semantics)`，**不判 pass/fail**。
- **验收**：`2/6`、`183/183` 在 0.1.12/0.1.13 的快照里都不得判 `fail`；用户消息仅 `8000/1500` 无关键字 → `skip`。

## T2 日期排除

- `YYYY/MM` 形式：**首段为 19xx / 20xx、次段为 1–12**（如 `2026/10`、`2026/12`）时，不算比例；
- 判定在候选阶段直接排除，不进入 `ratios`；
- 验收：`2026/10` 样本不得进 `ratios`。

## T3 正文保留

- `stripStructuredPayload` 现在会把 `{511/958}` 这类正文比例吞掉；
- 改法：**只剥“像 JSON 的 `{…}`/`[…]`”（含引号或冒号）**，其余内容原样保留；`{511/958}` 不含引号/冒号 → 保留；
- 验收：`{511/958}` 能作为候选被识别（在满足 T1 关键字前提时）。
