## T1 batch 识别收窄（只此一处改判据）

- **现状**：`protection.js` 用宽正则 `/批次|batch/i` + 日期比例；命中审计 JSON dump 里的 `"batch"` 字段 → 取不到 `x/y` → `ratios=[]` → `ratiosCovered([])` 恒 true（`protection.js:396`）→ **空泛 pass**。
- **改法**：
  1. 取数范围收敛到 **`user/message` 与助手消息正文**（assistant 文本），**排除** `tool/call`、`tool/result` 与任何 JSON 载荷；
  2. 只认 **“数字/数字”明确比例**（如 `8000/1500`、`511/958`）；百分比等其它形态不猜；
  3. `ratios=[]` → 判定 **`skip`**（不是 `pass`）；
  4. `skip` 时审计写原因（如 `no-ratio-in-user-messages`），可回溯。
- **验收**：见 T2/T7。

## T2 假阳性回归样本（必须有）

- **反例**：一条 tool 结果里含 `{"batch": ...}` JSON（或审计 dump）→ 必须 `skip`，不得 `pass`。
- **正例**：用户消息里带 `8000/1500` → 必须识别并正确比对（当前值/总量），结果可判 `pass` 或 `fail`。
- 样本落 `analysis/` 或测试夹具；报告写清“改判前后差异”。
