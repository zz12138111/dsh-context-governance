## T1 能力探测双行（先做，15 分钟级）

- **现状**：`capabilities.js` 只在 apply 探测一次；apply 时 `compaction-basic`/`token-meter` 可能尚未注册 → 记成 `absent`，被误读为“宿主不支持”。
- **做法**：
  - apply 时照旧记 `capability@apply`（保留历史对照）；
  - 首个会话事件（`turn/start` 或 `session` 之后首个事件）再探测一次，记 `capability@ready`；
  - 两行都只记类型（`fn`/`obj`/`absent`/`throws`），不记值。
- **探测名单**：现有 `SELF_PROBES` / `SERVICE_PROBES` 基础上补 `tokenMeter`（`ctx.tokenMeter`、`ctx.get('tokenMeter')`）。
- **验收**：真机或隔离 profile 上出现两行；`compaction`/`tokenMeter` 在 `@ready` 行给出真实结论。

## T2 tokenMeter 延迟获取

- **现状**：`runtime.js:189-195` 在构造时读一次并缓存 `null`，之后永不重试。
- **做法**（按可行性从高到低，任选其一落地，首选 1）：
  1. `ctx.inject(['tokenMeter'], (c) => { meter = c.tokenMeter })` —— 与本插件已有的 `ctx.inject(['commands'], …)` 同机制；服务就绪时回调；
  2. `#measureTokens` 内按需读取（`ctx.tokenMeter ?? ctx.get('tokenMeter')`），成功即缓存，失败下次再试；
  3. 两者并存：注入为主，按需为兜底。
- **禁止**：`inject` 只做可选注入，**不得**把 `tokenMeter` 加进硬 `inject` 数组（硬依赖会让插件 inactive）。
- **验收**：模拟“服务晚注册”的单测通过；真机上 `tokensBefore` 非 null（若 meter 确实可用）。

## T3 usage 兜底 + 来源字段

- **做法**：
  - 订阅 `assistant/message`，缓存每个会话**最后一条** `usage`；
  - `compaction/start`（或 `compaction/summary`）时冻结 `tokensBefore` = 最后一条 `inputTokens + cacheReadTokens + cacheWriteTokens`；
  - `compaction/end` 后**第一条** `assistant/message` 到达时补 `tokensAfter`（同口径）；
  - 来源标记：`tokensBeforeSource` / `tokensAfterSource` ∈ `tokenMeter` | `usage` | `none`；
  - 可选 `tokensBeforeParts` / `tokensAfterParts`（input/cacheRead/cacheWrite）。
- **审计**：`auditVersion: 'cost-v1.1'`；**只增字段，不删不改**已有字段语义。
- **顺序**：`tokenMeter` 优先，取不到才用 `usage`；两者都没有 → `null` + `none`，不估算、不伪造。
- **验收**：三条路径各有单测；审计无正文、无路径。

## T4 文档与状态命令

- `docs/T8-回注自愈与成本归属.md` 补「v1.1 来源字段 + 三路口径」；
- `/cg status` 的 cost 行显示 `tokensBefore/After` 及来源（例如 `before=141232(usage) after=38011(usage)`）；
- 明确写：usage 是“每次调用用量”，不是“省下的 token”。

## T5 测试

覆盖 5 类：① 服务晚注册后能拿到 meter；② meter 缺失走 usage；③ 两者全缺 → null + none；④ 来源字段正确；⑤ 审计/状态命令无正文、无路径、无凭据。

## T6 验证与 provider 结论

- 隔离 profile 或真机（用户重启后）跑一次压缩，取 `audit.jsonl` 里 `compaction-cost`；
- 给出 `ctx.compaction` 可用性结论：可获取/不可获取 + 证据（`capability@apply`/`@ready` 的 `get.compaction` 列；裸属性 `X=throws` 不是可用性信号）。
  - **已结案（2026-10-25）**：`get.compaction(strict=false)` 在 `@apply` 13:18:10Z / `@ready` 13:18:23Z **均为 `undefined`** → 本部署插件 scope **未提供** `compaction` 服务（“有 impl 未 active”会返回 `obj`）。因此「回注时点修正」在该部署下**不可行**，只能走事件时序推断（现方案），不再作为待查项；`get.tokenMeter=obj` 稳定，延迟获取路径无问题。
- 结论只用于 P1 决策，**本单不改压缩后端、不替换 provider**；「回注时点修正」不再是待查前提，除非宿主/部署方式变化再重新探测。
