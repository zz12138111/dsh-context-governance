# 上下文治理插件 · 新用户说明（草案）

> 状态：**草案**，随 1.0 发布更新；面向第一次接触本插件的人。
> 原则：只写**已具备**的能力；不写未验证的收益数字；不承诺未做的功能。

## 一句话

**给长任务加一层"不断线 + 会提前压"的治理**：压缩前先记住，压缩后接得上；不用你设策略，装好默认就工作。

## 你可能遇到过

1. **长任务到一半，上下文满了被压缩**，模型问"我们做到哪了"——你重说一遍。
2. **换个会话继续**，模型不知道项目规则、上次的决定、还差哪几步。
3. **明明还有空间，宿主压得很晚**，一压丢很多，接不上。
4. **手头几个工作区**，插件只管一个，别的项目等于没装。
5. **压了好几次**，花了多少、省了多少，心里没数。

## 它做什么（默认开，装了就生效）

- **压缩前先固化**：把任务目标、待办、最近决定、批次进度、关键约束写进**项目记忆**；压缩后只回注「ID + 状态 + 指针」，不产生第二段摘要。
- **新会话带状态**：header 默认开，只带**动态状态**（实测注入量是**几十 tokens 级**，不是整段摘要）。
- **提前压**：上下文到窗口的 **60%**（真实占窗口比例）就找安全时机压，早于宿主原生的 **~67.85%–69.34%**；**不抢宿主**——到原生点就让路。
- **每个工作区都管**：按会话 cwd 自动认定项目根，多个工作区**各自记忆、各自压缩**，不用每个工作区装一次。
- **每次压缩留成本记录**：压前/压后 token、后端类型、数据来源，都能查（**汇总账本在 1.1**）。

## 怎么用

- 装完**默认就是开的**；`/cg status` 看当前状态与根。
- 想关**本会话**：`/cg compact disarm`（立即生效，重启回默认）。
- 想关**全局**：配置 `compact.early.armed=false`。
- 想**更晚压**：`/cg set compact.at 0.65`（须小于 `native−0.02`），或选 `research` 档（不提前压）。

## 它不做什么（先讲清，避免误解）

- **不提供"危险动作拦截"**：宿主暂不支持可靠拦截前钩子，等支持后再立项；文档与状态栏都不会谎称有这个保护。
- **不做** UI 图表、货币成本、跨机器同步。
- **不做**成本汇总账本（1.1）。
- **压缩不可逆**：会话原文会丢，只留记忆指针——**重要内容请主动记进记忆**。

## 谁适合

- 长任务（**20 轮以上**）、工具输出大、需要跨会话继续的人；
- 多个工作区、希望**一次安装管全部**的人；
- **不适合**：只跑短问答、或要求"压缩后原文必须完整保留"的人。

## 已知限制（发布时一并披露）

- 重建副本约 **3.4KB/周期**，未单列进成本字段；
- 自动压缩自然触发场景（D1-3）**未真机验证**；
- **「提前压比宿主原生更省」目前没有 A/B 数据**——机制上更早释放上下文，但收益未量化。
