## 0. 一句话结论

**M1 工程验收闭环**：S4=B、回注、审计、成本字段、失败降级都有真机/回放证据；但有三类边界——provider 路线不可用（只能事件级）、前后水位读不到（`tokensBefore/After=null`）、S3 默认关。M2 建议先做“**成本聚合与预算可见**”和“**S3 开关策略**”；provider 路线**已定案不做**（`DEC-20261025-48`：preset 隔离不改、收益≈0，M2 不依赖）。

## 2. M2 候选

| ID | 候选 | 解决什么 | 价值 | 成本 | 建议 |
|---|---|---|---|---|---|
| A | 成本聚合与预算可见 | 现在只有单次 `compaction-cost`，看不到按会话/项目/天的总量，也没有预算告警 | 高 | 低–中 | **优先** |
| B | S3 开关策略 | header 代码已存在但默认关；没有按项目开关、预览、预算、审计 | 高 | 低 | **优先** |
| C | 前后水位读数 | `tokensBefore/After` 恒 null，净节省无法算 | 中 | 高/未知 | 并入 A，先标未知/代理 |
| D | provider 路线探索 | `ctx.compaction` 本 scope 不可得（preset 作用域隔离，设计行为） | — | — | **已定案不做**（`DEC-20261025-48`；M2 不依赖 provider） |

### A. 成本聚合与预算可见

- **问题**：cost-v1 是单周期记录；用户要回答“这周/这个项目花了多少、哪类压缩最贵”，现在要手工翻 audit。
- **最小实现**：
  - 读 `compaction-cost` 事件，按 `sessionId / project / model / backend / day` 聚合；
  - `/cg cost`（或扩展 `/cg status`）输出：周期数、shadowed、summary、injected、dropped、backendUsage、实测/估算分列；
  - 预算阈值只做“提示”，不做阻断；金额可选（有价格源才换算）。
- **验收**：聚合值 = 事件逐条求和；不重复计 `tokensDropped`；实测/估算不混算；`tokensBefore/After` 保持 `null` 或标“代理/未知”，不伪造。
- **与 M1 边界**：不改 cost-v1 字段；不补 tokenMeter；不做账单级金额。

### B. S3 开关策略

- **问题**：新会话 header 能带偏好，但默认关；没有“按项目开、先预览、限预算、可审计”的开关策略。
- **最小实现**：
  - 按项目/会话配置 `memoryHeader.enabled`；
  - 开启前可预览将注入的 header 文本与 token 估算；
  - 注入一次、有预算、有 audit；
  - 关闭立即生效，不注册 handler。
- **验收**：开启后 header 含偏好 ID/标题；关闭后零注入；重复启动不重复注入；预览与实注一致；audit 可查。
- **与 M1 边界**：默认仍关；只放偏好/任务态，不放开全量记忆；不自动开启。

### C. 前后水位读数

- **问题**：`tokensBefore/After` 恒 null，导致“净节省”只能看 shadowed/summary/usage，不能看压缩前后压力。
- **最小实现**：
  - 先探测能否公开拿到 tokenMeter；
  - 拿不到时，用 `backendUsage.total` 或 `shadowed` 做“代理水位”，字段明确标 `proxy`；
  - `tokensAfter` 暂不猜，标 `unknown`。
- **验收**：有源时填实测；无源时填 `null/unknown/proxy` 并给原因；不把代理值混进实测。
- **与 M1 边界**：不改宿主、不造第二套 meter；如果宿主不开放，接受长期 `unknown`。

### D. provider 路线探索（已定案不做，`DEC-20261025-48`）

- **结论**：该部署下 `ctx.compaction` 在插件 scope 不可得，根因是 **preset 作用域隔离（`isolate.compaction: true`，设计行为）**；`get.compaction(strict=false)` 实测 `undefined`。
- **定案**：**不改隔离**。理由：宿主压缩行为/压力阈值/审计时序均不变；`cordis provide` 同 scope key 重复注册会抛错（`@local/dsh-computer-use/presets/cordis.patch.yml` 有两处 compaction 组）；插件侧 mode 会由 `event-level` 变 `full`（保护失败进 `degraded-protection`）；收益≈0（插件不需要 provider）。
- **口径**：「回注时点修正」不可行，**不再作为 M2 前置期待**；M2 不依赖 provider。如需验证，只允许在**隔离 profile 实验**中进行，标注为实验、不在主线。

## 3. 不建议做

| 不做 | 理由 |
|---|---|
| 补 tokenMeter / 改宿主 | 越过插件边界；M1 已接受“前后水位未知”的降级 |
| 修复“手动压缩必吞最新用户消息” | 宿主行为；S4=B 已用“预写 + 告警 + 回注”接住，不改宿主 |
| 硬接管 `ctx.compaction` | 无公开路线时属于补丁/hack；风险高于收益 |
| 默认开启 S3 header | 用户已定默认关；先做开关与预览 |
| 账单级货币成本 | 没有稳定价格源；先做 token 聚合 |
| 把 M1.1 折叠/ACP/工具隐藏塞进 M2 | M1.1 已单独立项；ACP 等 E3/E4；工具隐藏需能力边界决策 |
| 重开 M1 范围 | M1 已闭环；遗留项按 M2/验证缺口处理 |

## 4. 建议优先定的两条

1. **A 成本聚合与预算可见**：直接回答“token 花在哪、花了多少”，复用 cost-v1，低风险、可快速验收；C 的前后水位作为 A 的“未知/代理”子项，不单独立项。
2. **B S3 开关策略**：代码已存在，成本低；解决“新会话带偏好”的连续性问题；但必须默认关、可预览、有预算。

**并行建议**：D 已定案不做（`DEC-20261025-48`）；M1.1 折叠按已定 `REQ-20261025-02` 排期（已收口），不混入 M2。
