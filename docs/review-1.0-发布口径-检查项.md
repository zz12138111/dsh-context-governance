## 1. 发布说明禁用句（硬闸）

- **禁用**：「1.0 = …危险动作有检查…」（`#5098` 原句）。该能力 G-M3-1 证据不足，`DEC-20261025-76` 已定**不做**，且不做事后告警式伪保护。
- **允许的唯一写法**：「1.0 不提供动作校验，等宿主支持 `pre-execute` 后再立项。」
- 检查方式：发布材料全文检索 `危险动作`、`动作校验`、`确认式`、`拦截`；正文只允许出现否定式表述。

## 3. 需要校正的发布材料表述（我发现的）

- 定义 §2.1 R-3 写「**扫描 0 命中**」——与现采不符：`compliance-scan` 当前为 **`blocker=0 / review=2 / info=86`**（227 个文本文件）。两条 `review` 是**文档在描述凭据形态**的示意串误报（`docs/review-context-governance-0.3.2.md:166`、`analysis/…/G2-G3-真机验证报告.md:117`），已记在 `docs/review-context-governance-0.3.2.md` §9.4。
- 建议发布口径改为：「敏感扫描 **0 blocker**；2 条 review 为文档示意串（非真实凭据），人工确认；另有 info 级本机路径/会话 id，发布物需脱敏或排除 `analysis/`。」
- 检查方式：发布材料不得出现「扫描 0 命中 / 无任何发现」的绝对表述。

## 4. 启用方案到位后我复核什么（不预设默认值，仅列约束）

需求侧已锁死的边界（复核时逐条验，不自行补设计）：
- 默认值必须与用户拍板一致；默认关时须**完全静默**（不取服务、不审计、不触发，已有 §11 行为证据）；
- 开启通道：插件配置层 + 会话命令；**项目层 `.cg-policy.json` 禁止设置 `armed`**（恶意仓库不能打开真实压缩）；**不得有环境变量开关**；
- 命令与状态：`/cg status` 显示 `early=on (session)` / `off (default)` / `off (policy:…)`；会话级开启须二次确认，文案写明“真实压缩、原文丢失、只有记忆指针”；
- 审计：`early-armed` / `early-disarmed` 带来源层与会话短 id，与 `early-*` 同族；
- 真实触发证据：R-2 若列入门禁，需一次可复核的 `early-forced` + `compaction-cost`（隔离 profile 或用户会话均可），并附 `/cg status` 原文落盘；
- 打开 `armed` 前，用户须再批一次（本轮不含）。
