## 4. 启用方案复核口径（用户已拍 **默认开**，2026-10-26）

> 默认开把风险面从“用户主动打开”变成“所有会话首次越过阈值就可能真实压缩”，且**不可逆**。以下逐条验，不自行补设计。

### 4.1 「首次真实触发时的用户可感知性」（00 要求必验，默认开下的唯一控制面）

| # | 判据 | 证据要求 |
|---|---|---|
| P-1 | `/cg status` **一眼可见**当前状态：`early=on (default)` / `off (session)` / `off (policy:…)` / `off (config)` | 状态行原文 + 三种状态各一条 |
| P-2 | 会话内可**立即 `disarm`**，且**下一次 `turn/end` 不再触发**（同会话生效，不需重启） | 真机/隔离：disarm → 触发点不出现 `early-forced`；状态变 `off (session)` |
| P-3 | `early-armed` / `early-disarmed` **审计留痕**：带来源层（default/config/session/policy）与会话短 id，不记正文 | audit.jsonl 原文 |
| P-4 | 首次触发**可感知**：`early-forced` 审计 + `/cg status` 的 `last-compaction` / `early` 段能看出“刚才真的压过” | 一次真实触发的 status 原文 + audit 行 |
| P-5 | 关闭路径明确：`/cg compact disarm`、配置 `compact.early.armed=false`、以及 `compact.early=false`（策略总闸）三者都能停用；research profile 仍默认 false | 三条各验一次（可单测 + 隔离真机） |

### 4.2 通道与安全边界（需求锁死）

- **默认值 = 开**：配置解析默认 `true`；`/cg status` 显示 `on (default)`（不得显示成“会话开启”）。
- **项目层禁止**：`.cg-policy.json` 里出现 `compact.early.armed`（无论 true/false）→ **忽略并写 `policy-invalid`**（含 key 与原因），不得因恶意仓库打开或关闭真实压缩；需单测。
- **不做环境变量**：全仓 grep `process.env` 无 armed 相关键；需断言。
- **命令**：`/cg compact arm` / `/cg compact disarm`（会话级）；`arm` 因默认已是开，若保留则用于“会话内重新开启”，必须与 status/audit 一致。
- **审计族**：`early-armed` / `early-disarmed` 与 `early-decision/skipped/forced/aborted/failed` 同族，白名单字段受控、无正文。
- **不可逆提示**：默认开之下不会每次弹确认，故 release notes 必须写明“超过阈值会真实压缩、原文只留记忆指针；可用 `/cg compact disarm` 关闭；项目配置不能打开、只能关闭”。

### 4.3 R-2 门禁（隔离 profile，≥1 次真实提前压）

一次可复核证据，缺一不可：
1. 隔离 profile 中会话越过 `at` 且低于 `native−0.02` → 真实触发；
2. `early-forced` 审计（`compaction=committed`、`protection=ok|failed|null`、`reinjected`、`delayMs`）；
3. 对应 `compaction-cost`（`tokensBefore/After` + 来源）；
4. `/cg status` **原文落盘**（`analysis/…/status-<时间>.txt`），不得只贴摘录；
5. 触发前后 `header-injected`/记忆未被破坏（保护 + 回注的证据）。

### 4.4 我在发布材料里会挡的写法

- 不得写“默认关 / 需要手动开启”（与用户决定相反）；
- 不得写“提前压安全 / 无风险 / 可回滚原文”（实际不可逆）；
- 不得写“项目配置可开启”（必须写“项目层不生效”）；
- 不得写“扫描 0 命中 / 无任何发现”（见 §3）。

### 4.5 发布物**必需段落**（默认开；不是可选提示）

00 要求：默认开之下，用户第一次遇到压缩若不知道发生了什么，会当故障报上来。以下段落必须出现在 Release notes / README 的「提前压」小节，缺一不可：

> **提前压（默认开启，不可回滚）**
> 当会话上下文压力超过 `compact.at`（默认 0.60，真实占窗口比例）且低于宿主 native 阈值时，插件会在 `turn/end` 后自动触发一次**真实压缩**。
> **压缩会丢弃会话原文，只保留记忆指针与最后一条用户消息**；请确保重要内容已记入记忆。
> 可随时用 `<命令名以实现为准>` 在当前会话关闭（会话级、立即生效）；也可用配置 `compact.early.armed=false` 永久关闭。
> **项目层 `.cg-policy.json` 对该开关不生效**（既不能开启也不能关闭）；不存在环境变量开关。

发布前检查：
1. `<命令名以实现为准>` 必须替换成开发实现、且经我复核的命令（`/cg compact disarm` 或最终命名），**不得写错命令**；
2. 三句话（真实压缩/不可逆 + 如何关闭 + 项目层不生效）逐句必须在，不能合并成一句模糊表述；
3. 项目层语义已定（§4.6）：项目层一律不生效；若未来有新的需求/用户决定改变它，本段与 §4.2 需同步改并重新复核。

### 4.6 项目层对 `armed` 的语义（已定，按需求版）

- **定论**（依据：需求原文 + 用户拍板「三通道照需求建议」）：**项目层 `.cg-policy.json` 对该开关一律不生效**——出现 `compact.early.armed`（无论 `true`/`false`）→ 忽略 + 记 `policy-invalid`（含 key 与原因）；既不能开启、也不能关闭真实压缩。
- 实现与复核口径按此；发布文案写「**项目层 `.cg-policy.json` 对该开关不生效**」，**不得写“只能关不能开”**。
- 历史更正（防复发）：00 2026-10-26 曾转述为“项目配置只能关不能开”，该转述**已作废**——需求从未如此规定，用户也未如此拍板；错因是转述时带入了“允许关闭更安全”的技术推断。依据始终是需求原文与用户决定。
- 若未来有人想改成“可关不可开”，需要新的需求/用户决定，不能从实现侧或转述侧引入。

### 4.7 两条必须写准的口径（00 要求固化）

1. **`/cg status` 的 `adapter=` 不是“后端已识别”**：它是插件侧推断结果；隔离实测 context-zip 下仍显示 `host-basic (inferred)`。发布物/README 说明后端能力时，**只能引用 profile 的 redirect + bundle**（如 `0.1.0-context-zip` + `dsh-context-zip`），不得写“status 显示 context-zip 即已识别”。
2. **`trigger=manual` ≠ 用户手动压缩**：插件提前压走宿主 `compactNow(agent, signal, 'early-auto')`，宿主按 `sourceCommandId != null` 记为 manual。发布物描述自动提前压时，**不得写成“用户手动压过”**；需要区分时写“宿主 manual API 路径（含插件自动触发）”。
