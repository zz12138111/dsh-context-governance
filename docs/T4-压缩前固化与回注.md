## 2. 写什么（5 类保护项）

| 顺序 | 类别 | type / 默认状态 | 标题 | 指针 |
|---|---|---|---|---|
| ① | 最新用户消息 | `fact` / active | `最后用户消息：<首行 ≤200>` | `session:<id>#<seq>` |
| ② | 规则注入 | `criterion` / proposed | `规则在场：<path1>、<path2>…`（取每种注入最新一条） | 最新规则消息 seq |
| ③ | 未完成批次 | `progress` / active | `批次 STATE：TASKS\…-STATE.md`；无 STATE 文件时 `批次进度：511/958` | 批次消息 seq |
| ④ | 回滚点 | `anchor` / proposed | `回滚点：<路径>` 或 `回滚点：<关键词>` | 回滚消息 seq |
| ⑤ | 未闭合工具调用 | `fact` / active | `未闭合工具调用：call_1, call_2` | 首个未闭合 call 的 seq |

- **不写正文**：只写首行/路径/ID；`detail` 恒为空。
- **ID 预留区间**：`MEM-YYYYMMDD-1000+`（避开普通条目，`ID_PATTERN` 接受 3+ 位）。
- **journal 结构**：`memory/protection/<cycle>-<hash>.json`；`protectSync` 同步写，`materializeProtection` 异步并入 `topics/*.md` 与 `MEMORY.md`。
- **崩溃恢复**：下次 `MemoryStore.open` 发现残留 journal 会自动物化；物化前 `mem_query({ids})` 仍可从 journal 读到。
- **敏感信息**：标题命中凭据形态时替换为“（敏感内容已省略）”；仍不写正文。

## 3. 回注

- 触发：`compaction/end` 处理器内 `queueMicrotask`；只对本次 cycle 一次。
- 形式：一条 `user/message`，`source.kind='plugin:context-governance'`，`source.cycle=<compactionId>`；内容：

```
[context-governance] 压缩后受保护指针（cycle 5a1f0b0e，manual=false）：
MEM-20261025-1000 仍生效：最后用户消息：继续 T4（见记忆）
MEM-20261025-1001 待确认：规则在场：~/.dsh/AGENTS.md（见记忆）
...
```

- 覆盖判断：按类别用摘要文本匹配标题/批次数字/回滚路径/callId；未覆盖才带标题。
  - **手动压缩**：最新用户消息**强制带标题**（S4 要求“调用方能看到最后一句”）。
  - 摘要不可读：只放 ID+状态（手动最新用户仍保留标题）。
- 预算：≤8 行 / ≤800 字符；超预算记录 `reinjection-budget`。
- 回注内容永不包含 `detail`；详情由模型 `mem_query({ids})` 取。
- 注入被下一次压缩吞掉是预期（E2），不重复尝试。

## 4. 失败与降级

| 失败 | 行为 | audit |
|---|---|---|
| journal 同步写失败 | 不阻断压缩；mode→`degraded-protection`；本 cycle 不回注 | `protection-write-failed` |
| journal 物化失败 | 条目仍从 journal 可查；mode→`degraded-protection` | `protection-materialize-failed` |
| 回注 append 失败 | mode→`observe-only`；后续 cycle 不再写/注 | `reinjection-failed` |
| 重复 cycle | 忽略重复 start；不重复注入 | `duplicate-cycle-start` / `reinjection-skipped` |
| 插件在 summary 才挂上 | 无法在摘要前固化；audit 留痕；不注入 | `protection-write-skipped` |
| 保护项为空 | 无 journal；不注入 | — |

“写不进”不阻断压缩 = 保护是尽力而为，压缩事务继续；“注不进”转 observe-only = 不再对上下文做任何写入，只审计。

## 5. 与需求口径的差异

- **原因一句话**：`checkpoint` 的 append 处于发布期，`session.append` 重入会被宿主拒绝，且宿主在同一同步栈里立刻 append `end`，两者之间没有可插入窗口。
- **影响范围一句话**：仅回注时点从“checkpoint→end 之间”后移到 `end` 发布后的首个 microtask；仍在同一 tick、下一次模型调用之前，回注内容/去重/S4 验收口径均不变。

**要求 3“checkpoint 之后、end 之前注一次”在当前公开接口下不可实现**：

1. checkpoint `user/message` 的 append 回调里，`session.append` 会因“append 发布期间禁止重入”抛错；
2. 宿主在 `commitCompactionBody()` 返回后同一同步栈里立刻 `session.append('compaction/end')`，两者之间没有 JS 可插入窗口；
3. 因此实现为 **`compaction/end` 发布后的首个 microtask**——仍在同一 tick、下一轮模型调用之前；对“不被本次压缩吞掉”没有影响（E2 已证注入会在下一次压缩被吞，时机在 end 前后不改变这一点）。

已记 `DEC-PLUGIN-20261025-09`（待 00 转用户知悉）。若要求字面“end 之前”，唯一路径是替换压缩 provider（M1 明确不做）。

## 6. 关键路径判断（压缩前落盘会不会拖慢压缩）

- 实际开销：5 个小对象（标题 ≤200 字符 + 指针）序列化后约 **2–4 KB**；同步 `writeFileSync + fsyncSync + renameSync`，不重写主题文件、不跑哈希、不调 LLM。
- 位置：仅发生在 `compaction/start`（低频；本机实测 47 会话 / 16 次压缩），一次压缩的摘要 LLM 调用通常是**秒级**；同步写典型 <5 ms，最坏受磁盘/杀软影响可达数十 ms。
- 结论：**不构成关键路径瓶颈**，但它是 host 主线程上的同步 IO；M1 可接受。T7 建议在真实安装后用 audit 的 `durationMs`（已写入 `protection-write`）统计 p95，若 >50 ms 再考虑把 journal 改为 append-only 小文件/减少 fsync（不能改异步，否则违反“摘要前落盘”）。
- 失败安全：同步写失败 → 降级 + audit，不阻塞压缩；不会因为记忆层异常导致压缩挂起。
