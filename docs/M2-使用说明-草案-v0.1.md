# 上下文治理插件 · 使用说明（M2 预览版）

> 面向使用者。演示参数以 1M 上下文窗口为例；实际数值随模型自动变化。
> 状态：草案，随 M2 一起评审。

---

## 1. 一句话

**它帮你在长会话里提前压缩上下文：不用等到系统自己压，把过时信息先清掉，顺手记录省了多少。**

系统自己有一个压缩点：上下文用到窗口约 **67.85%** 时会自动压。本插件让你把这件事**提前**，比如 60% 就压，代价是每压一次花一次摘要调用的钱。

---

## 2. 它帮你做什么 / 不做什么

| 做 | 不做 |
|---|---|
| 在你要的比例提前压缩 | 不会让压缩**更晚**发生 |
| 每个会话单独设定比例 | 不替换系统的压缩实现 |
| 用 profile 给不同类型会话不同默认 | 不做图表仪表盘 |
| 记录每次压缩省了多少、花了多少 | 不换算成钱（只记 token） |
| 管理记忆（决定、偏好、待办、进度） | 不删除原始对话（原文仍在会话日志里） |

---

## 3. 安装与开启

1. 在插件页搜索安装本插件，**装完即生效**，默认已开启提前压（`compact.at=0.60`）。
2. 想全局改默认：在 profile 的 `cordis.patch.yml` 里加一行配置。
3. 想单会话改：用 `/cg set`（见下）。
4. 不想用了：插件页停用即可，系统回到原生行为（67.85% 自动压）。

---

## 4. 三个最常用的命令

| 命令 | 作用 |
|---|---|
| `/cg status` | 看当前用了什么策略、压力到哪、上次压缩省了多少 |
| `/cg set compact.at=0.5` | 本会话改成 50% 就压 |
| `/cg cost` | 看这段时间压缩花了多少、省了多少 |

另外两个偶尔用：

| 命令 | 作用 |
|---|---|
| `/cg compact now` | 立即压一次（冷却期内需要 `--force`） |
| `/cg policy show` | 解释当前设置是从哪一层来的 |

---

## 5. 一个场景走一遍

假设你有一个长会话，1M 窗口：

1. 你没改任何设置。默认 `compact.at=0.60`。
2. 聊到大约 60 万 token 时，插件主动压一次：把前面旧内容收成摘要，后面的继续。
3. 你在 `/cg status` 里会看到：

```
policy: compact.at=0.60 (source=builtin)
pressure: measured=0.583  estimated=0.412  adjusted=0.556  effective=0.583
last-early: forced
last-cost: 省 12k/请求，摘要花 3.1k
```

4. 想更早压（更省上下文、但摘要更频繁）：`/cg set compact.at=0.45`。
5. 想更晚：见第 8 节 FAQ。

## 6. 参数说明（什么时候调）

| 参数 | 通俗解释 | 默认 | 什么时候调 |
|---|---|---|---|
| `compact.at` | 用到窗口多少比例就压 | `0.60` | 想更省就调低；想少花摘要钱就调高（最高到系统原生点以下） |
| `compact.early` | 是否允许提前压 | 开 | 想完全交给系统时关掉 |
| `compact.cooldownMin` | 两次压缩至少隔多久 | 10 分钟 | 会话很激烈时调大 |
| `compact.minDeltaTokens` | 压完后至少再涨多少 token 才允许再压 | 2 万 | 防止反复压 |
| `compact.estimateSafety` | 估算校正系数（专家项，只能改配置） | 1.35 | 见第 7 节的 ratio 再决定 |

**上限**：`compact.at` 不能超过系统的原生触发点（约 0.6785），超了会被拒绝——本插件不做“推迟”。

---

## 7. 怎么确认它真的生效了

看 `/cg status` 的 `pressure` 行，四个数分别是：

| 字段 | 含义 |
|---|---|
| `measured` | 上一次模型调用实测的用量（准，但滞后一步） |
| `estimated` | 插件按字符估算的用量（即时，一般偏低） |
| `adjusted` | 估算 × 安全系数（用来逼近真实） |
| `effective` | 实际用来判断的值 = 上面两者取大 |
| `ratio` | 实测 ÷ 估算；大于 1 表示估算偏低 |

- `ratio` 长期明显大于 1（比如 1.4）：说明这个模型的估算偏低，当前系数合理；
- `ratio` 接近 1：说明估算准，可以把系数往 1.0 调（省点摘要钱）；
- 调系数只改配置文件，`/cg set` 不提供，避免误操作。

## 8. 常见问题

**Q：我想让压缩更晚发生，可以吗？**
不行，本插件只做“提前”。想晚压就别设（或设为上限），系统会在 67.85% 自己压——这就是最好的“晚压策略”。

**Q：为什么我没看到它提前压？**
按顺序检查：
1. `/cg status` 里 `early=on` 吗？`off` 时只提示不压（`compact.early` 是纯配置开关；引擎通道状态是 0.2.1 的 `early-channel`，0.2.0 还没有）；
2. `effective` 有没有到 `compact.at`；
3. 会话是不是一直在跑长任务、没有 `turn/end` 时机（长 turn 里不压）；
4. 冷却/增量门槛是不是没满足。

**Q：`/cg compact now` 为什么提示我加 `--force`？**
因为在冷却期内。加 `--force` 会真的压一次并留审计。

**Q：压完会不会丢东西？**
压缩是系统原本的行为，本插件只是换了时机；受保护内容（最新用户消息、规则、批次进度等）会先写进记忆再回注。原始对话仍在会话日志里。

**Q：会不会因为插件出错导致会话崩？**
不会。插件只在旁边触发，不在系统的压缩决策链里。它失败最多是“没提前压”，系统仍会在原生点压。

**Q：`estimateSafety=1.0` 能用吗？**
能，但只建议懂的人用：估算偏低的模型上它会**几乎不触发**（看起来像没生效），估算偏高的模型上会**过早压**。

---

## 9. 风险与边界

- **有成本**：每次压缩都是一次摘要调用；调低 `compact.at` 会更频繁，钱也更多。
- **不推迟**：只提前，不支持延后。
- **估算有误差**：插件用系数校正，不是会计级精确。
- **长 turn 限制**：只在回合交界处生效，长任务中途不打断。
- **失败不影响系统**：插件异常只是不提前压，系统兜底。

---

## 10. 隐私

- 审计只记**数字与工具名**，不记会话正文、不记文件路径；
- 记忆文件在项目目录内，可 git、可人工编辑；
- 卸载插件不会删除已有记忆文件。
