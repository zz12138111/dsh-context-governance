## 0. 通用准备（每次演练都做）

```powershell
$profId = 'native-test'                                # 或 desktop-test-contextzip
$prof   = Join-Path $env:USERPROFILE ".dsh\profiles\$profId"
$stamp  = Get-Date -Format 'yyyyMMdd-HHmmss'
$out    = "D:\DS-PROJECT\DSH插件开发\analysis\req-20261025-12\drills\$stamp-$profId"
New-Item -ItemType Directory -Force $out | Out-Null

# 备份 profile 关键文件（与 Runbook §3 同口径）
Copy-Item (Join-Path $prof 'package.json') (Join-Path $out 'package.before.json')
Copy-Item (Join-Path $prof 'cordis.patch.yml') (Join-Path $out 'cordis.before.yml') -ErrorAction SilentlyContinue

# 记录基线
function Get-CgProfileState { param($p)
  $m = Get-Content (Join-Path $p 'package.json') -Raw -Encoding UTF8 | ConvertFrom-Json
  $r = try { (Get-Content (Join-Path $p 'node_modules\@deepseek-ai\dsh-compaction-basic\package.json') -Raw -Encoding UTF8 | ConvertFrom-Json).version } catch { 'absent' }
  [pscustomobject]@{ dependencies=@($m.dependencies.PSObject.Properties).Count; bundles=@($m.dsh.profile.bundles).Count; redirect=$r;
    pluginDep=(@($m.dependencies.PSObject.Properties.Name) -contains 'dsh-context-governance');
    pluginBundle=(@($m.dsh.profile.bundles) -contains 'dsh-context-governance') } }
$before = Get-CgProfileState $prof
$before | ConvertTo-Json | Set-Content (Join-Path $out 'state.before.json') -Encoding utf8
$before | Format-List
```

**判定要留证**：每个演练结束把 `state.before/after`、命令输出、`/cg status` 原文一并写进 `$out`。

## 1. 安装演练（Install）

- 前置：隔离 profile 无该插件（`pluginDep=False`、`pluginBundle=False`）；包来源 = 当前候选包目录（或 zip 解压目录）。
- 步骤：
  1. 建 junction：`New-Item -ItemType Junction -Path "$prof\node_modules\dsh-context-governance" -Target <插件包目录>`；
  2. 按 Runbook §4 的 Node 脚本写 `dependencies`（`file:<绝对路径>`）与 `dsh.profile.bundles` 追加；
  3. 校验：JSON 无 BOM、`Test-Path` 解析 `cordis.patch.yml`/`src/index.js`、`createRequire` 能 resolve `dsh-context-governance/package.json`；
  4. 启动隔离实例 → 跑 `/cg status` → 保存原文。
- 通过判据：`dependencies` +1、`bundles` +1、junction 解析正常、`/cg status` 出现 `version=1.0.0`（或候选版本）且无 `registration failed`/`perception=none` 告警。

## 2. 卸载演练（Uninstall）

- 前置：完成安装演练、隔离实例已停。
- 步骤：
  1. 删除 junction（只删链接，**不动插件源码目录**）；
  2. 从 `dependencies` 与 `dsh.profile.bundles` 移除该插件条目（Node 写回、无 BOM）；
  3. 校验 `pluginDep=False/pluginBundle=False`、JSON 可解析；
  4. 重启隔离实例 → 确认 `/cg` 命令不存在（或返回 usage）、宿主压缩行为恢复。
- 通过判据：profile 回到 `state.before`；宿主能按其默认阈值触发压缩（对照 `native=0.6934`/`0.6785` 口径），无残留报错；插件源码目录完整。

## 3. 回滚演练（Rollback）

- 前置：`D:\DS-PROJECT\_backup\dsh-plugins-v0.2.1\` 中的 v0.2.1 插件包（zip 解压到临时目录）；隔离 profile 当前为干净或 1.0 候选。
- 步骤：
  1. 若已装候选版：按卸载演练移除；
  2. 解压 v0.2.1 包 → 按安装演练装回；
  3. 启动隔离实例 → `/cg status` 确认 `version=0.2.1`、记忆/header 正常；保存原文；
  4. 演练后恢复到演练前状态（移除或装回候选版），并把 profile 恢复证据落盘。
- 通过判据：`/cg status` 版本 = 0.2.1；`header-injected`/`mem_query` 正常；profile 无 BOM、无残留依赖；全程未触碰 `desktop`。
