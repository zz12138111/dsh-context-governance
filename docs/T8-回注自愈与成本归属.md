## 1. T8-1 回注失败可自愈（ROB-01/06）

**旧行为**：一次 `session.append` 失败 → `#disableReinjection()` → `observe-only`，此后每个周期 `protection-write-skipped`；**S4=B 的预写被永久关掉**，只能重启恢复（STATUS 曾列为已知风险/T8 首项）。

**新行为**（`src/compress/runtime.js`）：

1. **每次失败都留审计**：`reinjection-failed`（带 `count`=连续失败次数）；不再一次性永久关闭。
2. **连续失败 N 次才降级**：默认 `N=3`（`reinjection.maxFailures` 可配 1–20）。达到阈值时：
   - 写 `reinjection-degraded`（`count`/`reason=max-consecutive-failures`）；
   - 模式变 `degraded-protection`，reason `reinjection-suspended`；
   - **只暂停一个周期**的保护写（`protection-write-skipped`，reason=`reinjection-suspended`），不是永久。
3. **降级期间仍能读、能回注**：本周期用既有记忆里的 `session:<id>#…` 指针回注（与 T6 只读降级同一套 fallback），不新增写入。
4. **自愈**：下一次 `compaction/start` 自动重试（清除“暂停一个周期”标志）；回注成功即写 `reinjection-recovered`、清连续失败计数、恢复到**选择器给出的正常模式**与后续预写（本机 `adapter=none` 时是 `event-level`，只有 provider 可见时才是 `full`）。
5. `/cg status` 的 `protection:` 行显示 `reinjection=enabled(streak=N)` 或 `suspended(N/max)`。

**测试**：
- `T8-1 自愈`：模拟一次 append 失败（默认 N=3，不降级）→ 下一周期保护写恢复、回注成功、`reinjection-recovered`、streak=0、恢复选择器正常 mode（测试里 provider 可见故为 full）。
- `T4-5`（阈值=1）：失败 → `reinjection-degraded`；下一周期暂停写但用既有指针回注成功 → 自愈。
- `S4-F`（场景层）：同上断言（降级可见、仍尝试回注、自愈）。

## 2. T8-2 成本归属审计（REQUIREMENTS ⑦ A）

一个压缩周期一条 `compaction-cost`，在 `compaction/end` 后的回注 microtask 之后写入（能带上注入估算与吞掉计数）。**只记 token，不记金额**。

| 字段 | 来源 | 口径 |
|---|---|---|
| `compactionId` | start 事件 | 主键 |
| `sessionId` / `project` | 会话与配置 | 维度 |
| `trigger` | `compaction/start.sourceCommandId` | `auto` / `manual` |
| `backend` | 适配器 kind | 维度（`none`/`host-basic`/`context-zip`） |
| `model` | `summary.data.provider`/`model` | `provider/model` |
| `occurredAt` | `compaction/end.time` | ISO 时间 |
| `tokensBefore` / `tokensAfter` | 宿主 `tokenMeter.measure(session)` 求和 | **measured**；无 meter → `null` |
| `tokensShadowed` | `summary.data.shadowedTokenCount` | **measured** |
| `tokensSummary` | `summary.data.usage.outputTokens` | **measured**；无 usage → `null` |
| `backendUsage` | `summary.data.usage`（仅 input/output/cacheRead/cacheWrite/total 五个数值字段） | **measured**；无则字段省略 |
| `tokensInjected` | 回注文本长度 `ceil(chars/4)` | **estimated**（`estimateMethod=chars/4`） |
| `injectedEntries` | 回注指针条数 | 计数 |
| `tokensDropped` | 上一次回注 token 被本次 `shadowedSeqs` 吞掉时累加 | **estimated**（来自 `reinjection-shadowed`） |
| `backendCostSource` | `measured`（有 usage）/ `unknown` | 口径 |
| `governanceCostSource` | `estimated`（有注入估算）/ `unknown` | 口径 |
| `estimateMethod` | `chars/4` / `none` | 口径 |
| `auditVersion` | `cost-v1.2`（0.1.12 起；读方按 `cost-v1` 前缀匹配，勿精确匹配） | 版本 |

- 审计白名单同步新增上述字段：数值字段限制为非负有限数；`backendUsage` 只保留五个已知 token 计数；字符串字段仍走 8 类凭据脱敏。
- **不含正文/标题/路径**：`t8-cost` 用例对 `audit.jsonl` 原始文本断言无消息正文、批次号、回滚路径、摘要标题。
- 实测/估算分列：`backendCostSource` 与 `governanceCostSource` 独立，`null` 表示取不到，绝不把估算混进实测字段。

## 6. M1.2 探测修正与成本实测（v0.1.11）

> 依据：`REQUIREMENTS.md` REQ-20261025-03；`docs/M1-可行性复查-20261025.md`。
> 边界：只修探测时机 + 成本实测；不改回注逻辑、不改记忆、不改折叠。

### 6.1 能力探测双行

- apply 时写 `capability@apply`；首个 `session/event` 后写 `capability@ready`。
- 两行都只记服务名/类型（`fn`/`obj`/`absent`/`throws`），不记值。
- 写入两处：`logs/governance.log`（诊断行）与 `audit.jsonl`（`capability@apply`/`capability@ready`，`probe` 为 `text-array`）。
- 探测名单新增 `tokenMeter`：`ctx.tokenMeter` 与 `ctx.get('tokenMeter')`。
- 目的：apply 时 `compaction`/`tokenMeter` 可能尚未注册；@ready 用真实结果修正“服务存在却被记 absent”。

### 6.2 tokenMeter 延迟获取

- 不在硬 `inject` 数组里加 `tokenMeter`（缺服务会让插件 inactive）。
- 两条路并存：
  1. `ctx.inject(['tokenMeter'], cb)` 可选注入；服务就绪时缓存 meter；
   - **P3-1 修正**：`ctx.inject` 返回 cordis **Fiber**（不是 dispose 函数）；`stop()` 只调用 `fiber.dispose()`，不再把返回值当函数调用。父 fiber 仍兜底；这里选择“修实现”，因为原写法会抛 `TypeError` 被 catch 吞掉，虽然无害但语义错误。
  2. `#measureTokens` 内按需 `ctx.tokenMeter ?? ctx.get('tokenMeter')`，成功才缓存，失败不缓存 `null`，下次再试。
- 取不到 meter → 走 usage；两者都取不到 → `null` + `none`，不估算。

### 6.3 usage 兜底与口径

- 订阅 `assistant/message`，按会话缓存最后一条 usage。
- `tokensBefore`（checkpoint 前最后一次模型调用）：
  - 优先 tokenMeter（`tokenMeter.measure(session)` 求和）；
  - 否则用最后一条 `assistant/message.usage` 的 `inputTokens + cacheReadTokens + cacheWriteTokens`；
  - 否则 `null` + `none`。
- `tokensAfter`（`compaction/end` 后第一条 `assistant/message`）：
  - tokenMeter 可用时，在 end 后回注 microtask 之后测量；
  - 否则等第一条 `assistant/message`，用同一 usage 口径补齐；等不到（插件卸载/下一周期开始）→ `null` + `none`。
- 原始分量可选记录：`tokensBeforeParts` / `tokensAfterParts`（仅 `inputTokens`/`cacheReadTokens`/`cacheWriteTokens` 三个数字）。
- `tokensBeforeSource` / `tokensAfterSource` ∈ `tokenMeter` | `usage` | `none`。
- `auditVersion` 升为 `cost-v1.2`（M1.2 为 `cost-v1.1`；0.1.12 的 T2′ 增 prune 字段，仍只增不改）；**读方按 `cost-v1` 前缀匹配**，不要按 `cost-v1` 精确匹配，否则会漏掉 `cost-v1.1`/`cost-v1.2` 行。**只增字段，不改已有字段语义**，旧解析器仍可用。
- 注意：usage 是“每次调用用量”，不是“省下的 token”；只做水位，不冒充节省量。
- **P3-4/5 延迟写（已知且接受）**：meter 不可用时，`compaction-cost` 要等 `compaction/end` 后第一条 `assistant/message`（或 stop/下一周期开始冲刷）才落盘。期间：
  - `/cg status` 的 `last-cost` 可能短暂显示**上一周期**的值；
  - audit 里该 `compaction-cost` 行可能晚于后续事件、**不紧挨** `reinjection`/`compaction/end`。
  读取时以字段 `occurredAt`/`ts` 判断，不要按 JSONL 行序推断“同一周期”。

### 6.4 `/cg status`

`/cg status` 与 `/cg status last-cost` 都显示 `last-cost:` 行：

```text
last-cost: before=141232(tokenMeter) after=38011(usage) trigger=auto pruned=4797 tools=read:8
```

取不到/尚未写入时 `before`/`after` 显示 `-(none)`；无 prune 显示 `pruned=0 tools=-`；没有成本记录时显示 `last-cost: none`。

### 6.5 provider 结论（ctx.compaction）

- 只读证据：宿主 `@deepseek-ai/dsh-compaction` 定义 `ctx.compaction` 服务；`dsh-base` 默认挂 `compaction-basic`；本机 profile 有 `thresholdRatio: 0.65`；真机会话有真实压缩事件（`compaction/start → summary → end`）。
- 结论：**可获取**（ready 时 `ctx.compaction`/`ctx.get('compaction')` 应为 `obj`）；apply 时的 `absent` 是探测时机，不是宿主不支持。
- 证据路径：`dsh-base/cordis.patch.yml` 的 `compaction-basic` 行；`dsh-compaction/lib` 服务定义；`~/.dsh/sessions/...` 的 `compaction/start` 事件。
- 本单不替换 provider、不改压缩后端；真机 `capability@ready` 行由用户重启后确认。

### 6.6 测试

- `test/m1.2-cost.test.mjs`：晚注册 meter（inject + 按需）、usage 兜底与 parts、两路全缺、`/cg status` last-cost、能力双行。
- 既有 `t8-cost` 更新为 `cost-v1.2` 并断言来源；全量通过。

## 7. T2′ 宿主 prune 观测（v0.1.12）

> 依据：REQ-20261025-02 收口版；T2=A（只观测宿主 pruner，不早折、不写 spill）。
> 生产代码边界：只读 `compaction/prune` + 替换事件元数据；**不改写任何 `tool/result` 内容、不 append 替换事件、不写 spill**。

### 7.1 观测事件

每条宿主 `compaction/prune` 写一行 `prune-observed`：

| 字段 | 来源 | 说明 |
|---|---|---|
| `sessionId` | 当前会话 | 维度 |
| `seq` | prune 事件 seq | |
| `shadowedStart` / `shadowedEnd` | `shadowedRange`（缺失时用 `shadowedSeqs` 首尾） | 缺失为 `null`，不猜 |
| `shadowedTokenCount` | `shadowedTokenCount` | 缺失为 `null` |
| `tool` | 替换事件 `message.source.callId` → 本会话 `tool/call.name` | 反查不到 `unknown`，**不读正文** |
| `replacementSeq` | 紧随的替换 `tool/result` seq | 未等到为 `null` |
| `cycle` | `current` / `outside` | 见 7.2 |

- **去重**：同一 `sessionId + shadowedStart + shadowedEnd` 只记一次。
- **归属**：`compaction/end` 之后、`compaction/summary` 之前的 prune 记 `current`；`summary` 之后或没有后续 compaction 的记 `outside`（只进会话累计，不进单周期成本）。
- 宿主顺序是 `compaction/prune` → 替换 `tool/result` →（多条）→ `compaction/start`；插件先挂起 observation，`start`/`summary` 时归 `current` 并落审计。
- 失败/形状变化：仍记 `shadowedTokenCount`，`tool=unknown`、`replacementSeq=null`；异常只 log/audit，不抛宿主。

### 7.2 成本接入

`compaction-cost` 新增（只增字段，`auditVersion=cost-v1.2`）：

| 字段 | 口径 |
|---|---|
| `tokensPruned` | 本周期 `cycle=current` 的 `shadowedTokenCount` 之和；**measured**；无 prune → `null`（unknown），不写 0 冒充 |
| `pruneCount` | 本周期 `prune` 条数（去重后） |
| `pruneTools` | 最多 5 项 `name:count`（按 count 降序，同 count 按 name） |

- 无 pruner 环境：`pruneCount=0`、`tokensPruned=null`、`pruneTools=[]`；`/cg status` 显示 `pruned=0 tools=-`。
- 读方兼容：`auditVersion` 按 `cost-v1` **前缀匹配**（`cost-v1.1`/`cost-v1.2` 都命中），不要精确匹配 `cost-v1`。
