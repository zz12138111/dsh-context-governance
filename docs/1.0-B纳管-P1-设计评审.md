### 1.3 P1 过渡态（必须写进评审结论）

P1 完成时，**只有主根被完整治理**（与今天等价），其他根：

- 会被 registry **发现并登记**（state v2 + root audit 可见），但 `governed=false`；
- runtime **不观测、不保护、不回注、不写记忆、不写审计**（按 `unmanaged-root` 跳过，只留一次 logger warn）；
- 不再有“外部会话只记 cost 行”。

因此 **P1 单独不可上机/不可发布**：若此时替换桌面插件，`G:\DS-HARNESS` 等其他工作区会从今天的“只记成本”退化为“完全不碰”。**P1 代码验收用临时目录测试；桌面安装/重启等 P2 完成、00 批准后再做。** 这与“P1 期提前压仍只主根”一致，也避免 B-1（提前压跑在没有保护/回注的会话上）。

> 若 00/审核要求“P1 期间仍保留其他工作区的成本账”，替代方案是：其他根只写 `compaction-cost` 到 **root audit**（用户级，带 `root` 字段），P2 再改为每根 audit + 完整治理。代价是 P1 的 root audit 混入成本行、P2 还要删。**默认不选**，仅列备选。

## 2. 根 registry

### 2.1 数据模型

**根键（rootKey）**：`normalizeRootPath()`（已存在则 realpath + Windows 盘符大写）+ Windows 下小写折叠。目的：同一根的不同大小写/短名/8.3 写法只产生一个条目。键在 state 里是对象键，**展示用 `root` 字段**。

**条目（entry）**：

| 字段 | 类型 | 含义 |
|---|---|---|
| `root` | string（绝对路径） | 展示/落盘用的规范路径（原始大小写） |
| `origin` | `'inferred' \| 'config'` | 第一次进入 registry 的来源（config=命中显式配置根） |
| `inferredAt` | string \| null | 首次推断时间；config 来源为 null |
| `inferredFromCwd` | string \| null | 首次推断时的会话 cwd |
| `firstSeenAt` | string | 第一次登记时间 |
| `lastSeenAt` | string | 最近一次有会话命中（写盘节流，见 §2.4） |
| `state` | `'active' \| 'fail-closed'` | fail-closed = containment 拒绝，该根不纳入（P1 不建 store） |
| `failClosedReason` | string \| null | `memory-root-absolute` / `memory-root-escape` / `memory-root-symlink-escape` / `memory-root-unwritable`（仅 containment 类，最后一项 P2 才可能出现） |

> 不持久化会话列表（隐私 + churn）；会话→根映射只活在进程内。

**样例（v2，由本机 v1 迁移 + 再发现一个根）**：

### 2.2 生命周期

```
apply()
  ├─ identity = resolvePersistenceIdentity(ctx)          // 不变
  ├─ rootAudit = createRootAudit(identity)              // 用户级，apply 即建文件
  ├─ state = loadStateV2(stateFile)                     // 读 v2 / 迁移 v1 / 损坏处理
  ├─ registry = new RootRegistry({state, rootAudit, configRoot, home})
  ├─ attachRoot = configRoot ?? state.primaryRoot
  ├─ attachRoot != null → startRuntime(attachRoot)      // 与今天同路径
  └─ attachRoot == null → 等首个会话事件推断 → 登记 + primary → startRuntime
session/event(session)
  ├─ registry.resolveSessionRoot(session)
  │    ├─ cwd 空/无 .git 祖先 → { status:'no-root' }    // 完全不碰
  │    ├─ 命中 config 根 → { source:'config' }
  │    ├─ 已在 state → { source:'persisted' }
  │    └─ 新根 → 登记 + 写 state + root audit('root-registered')
  └─ status:
       'managed'     → 今天的行为（P1 只有 primaryRoot）
       'unmanaged'   → 跳过（P1；P2 起改为 managed）
       'no-root'     → 跳过（3A）
```

### 2.3 会话→根算法（伪代码）

```
resolveSessionRoot(session):
  sid = session.header.id ?? session.id ?? null
  cwd = sessionCwd(session)                      // header.cwd 优先，退回 session.cwd
  if sid != null and pin.has(sid):
     pinned = pin.get(sid)
     if cwd != '' and !cwdWithinRoot(cwd, pinned.root):
        drift(sid, pinned.root, cwd)             // 只诊断，不换根
     return pinned
  if cwd == '': return { status:'no-root', reason:'cwd-missing' }
  root = inferRootFromCwd(cwd, {exclude: identity.home ?? identity.dir})
  if root == null: return { status:'no-root', reason:'no-git-ancestor' }
  entry = ensureRoot(root, {cwd})                // 已存在→lastSeenAt；新的→登记+写 state
  if sid != null: pin.set(sid, entry)            // 首个可判定事件定根
  return { status: entry.root === primary ? 'managed' : 'unmanaged', entry, source }
```

- `pin` 上限 1000 条 LRU；无 `sid` 的会话不 pin（每事件现算，cwd 稳定时结果一致）。
- **cwd 为空 → `no-root`（fail-closed）**。今天 `unattributed` 是“放行给主根”（`scope.js:64-65`），B 下这会变成“未知会话写进主根记忆”的风险，故改判。**这是相对 1.0 #1 的行为变化，请审核确认**（见 §8 待确认 3）。
- `root-drift` 写**pinned 根**的 per-root audit（managed 时）；unmanaged 只 logger。

### 2.4 持久化、并发、节流

- **读**：`loadStateV2(stateFile)`；v1 文件 → 先迁移（§3.3）；损坏 → 见 §3.2。
- **首次推断（无 state 文件）**：沿用 v1 的 `tmp + link` **独占发布**（`root-state.js:178-210`）：两进程同时首推，只有一方建文件，另一方读回既有 `primaryRoot`。v2 下同样是“先建文件者定主根”。
- **后续写入（文件已存在）**：`read-merge-write` —— 读当前 v2 → 按 key 合并（新条目 union；`lastSeenAt` 取 max；`state` 一旦 fail-closed 不被普通登记覆盖）→ 原子 `tmp+rename`。两进程同时加不同根 = 两个条目都留下；同时加同根 = key 相同、内容等价。
- **写盘节流**：`lastSeenAt` 内存里实时更新，落盘条件 = ①新根 ②fail-closed ③迁移 ④距上次落盘 >1h。避免每个会话都重写状态。
- **失败**：state 写失败 → 内存继续（状态只在本次进程有效）、`rootAudit('root-state-write-failed')`、`/cg status` 显式 `state-write-failed`；**不抛错**。
- **根上限**：64 个；超出 → 不登记（该根会话按 `unmanaged`/`no-root` 跳过）+ root audit `root-limit` + warn。P2 再谈淘汰。

### 2.5 API 形状（`src/roots/registry.js`）

| 成员 | 返回 | 说明 |
|---|---|---|
| `static load({stateFile, rootAudit, configRoot, home, now, logger})` | `RootRegistry` | 读/迁移/损坏处理 + 建对象 |
| `resolveSessionRoot(session)` | `{status, entry, source, reason?, drift?}` | 唯一会话判定入口；`status ∈ managed\|unmanaged\|no-root` |
| `ensureRoot(root, {cwd, origin})` | `entry` | 登记/刷新；内部写 state + audit |
| `failClosed(rootKey, reason)` | `boolean` | 标记 + 落盘 + audit |
| `list()` | `entry[]` | 只读快照（status 用） |
| `counts()` | `{roots, active, failClosed, managed}` | status 行 |
| `primary` | `entry \| null` | P1 挂载根 |
| `stateFile` / `rootAuditFile` | `string` | status/诊断 |

## 3. 状态文件 v2 + v1 迁移

### 3.1 schema

```jsonc
{
  "version": 2,                 // 必填，严格 === 2
  "profile": "desktop",         // 可空；身份名（诊断）
  "roots": { "<rootKey>": { ...entry... } },  // 必填，对象
  "primaryRoot": "D:\\...",     // 可空；P1 过渡字段
  "configRoot": "D:\\...",      // 可空；v1 镜像语义保留（只审计，不参与选择）
  "migratedFrom": 1,            // 可选；仅迁移时写
  "migratedAt": "ISO"           // 可选；仅迁移时写
}
```

**读取校验**（不抛错，坏 → `null` 或逐项拒绝）：

- 顶层必须是对象、`version===2`、`roots` 是对象；未知字段**容忍**（向前兼容）。
- 条目坏值（`root` 非绝对/空、`origin` 非法、`state` 非枚举、时间非字符串）→ **该条目丢弃**（其余保留），并 `rootAudit('root-entry-invalid', {reason})`；不因一条坏数据让整文件失效。
- `primaryRoot` 不在 `roots` 里 → 视为 `null` + audit（P1 回落到等待推断）。
- 字段值一律重新走 `normalizeRootPath`；`rootKey` 由 `root` 重算，**不信任文件里的键**（防手工改键指向别处）。

### 3.2 损坏 / 版本不符

| 读到 | 动作 |
|---|---|
| 文件不存在 | 正常：等首推 |
| JSON 解析失败 / 顶层类型错 / `roots` 不是对象 | **不覆盖**：同目录 rename 为 `root-state-<p>.corrupt-<UTC>.json`，root audit `root-state-corrupt`，按“无 state”启动 |
| `version===1` | 迁移（§3.3） |
| `version===2` | 正常加载 |
| `version > 2`（未来格式） | **不改名、不覆盖、本次进程不写 state**（防降级写坏未来数据）；按“无 state”启动 + root audit `root-state-unsupported-version`；P1 只有 config 根能挂，否则等推断（仅内存） |

> 损坏文件**只 rename 不删除**（用户级目录，属允许写入位置；不碰任何项目文件）。

### 3.3 v1 → v2 迁移（一次性、幂等）

1. 读 v1，按现有 `readRootState()` 校验（`version:1` + `root` 绝对 + `inferredFromCwd/configRoot/instance` 可选）。
2. 备份：`copyFile(stateFile, root-state-<p>.v1.bak)`（已存在 `.v1.bak` 则加时间戳，不覆盖旧备份）。
3. 构造 v2：
   - `roots[fold(v1.root)] = {root, origin:'inferred', inferredAt, inferredFromCwd, firstSeenAt: inferredAt ?? now, lastSeenAt: now, state:'active', failClosedReason:null}`
   - `primaryRoot = v1.root`
   - `configRoot = v1.configRoot ?? null`
   - `migratedFrom:1, migratedAt:now`
4. 原子写（`tmp+rename`）+ root audit `root-migrated {fromVersion:1,toVersion:2,root,path,backupPath,rootCount:1}`。
5. **幂等**：已是 v2 → 直接返回，不备份、不重写；迁移中途崩溃 → 文件仍是 v1（rename 原子）→ 下次重迁。
6. 迁移**不改变**任何项目文件、不创建根内文件（只读 v1 的用户级文件）。

**v1 代码回滚警告**：v1 的 `readRootState()` 只认 `version===1`，会读不出 v2 → 首次推断时 `persistInferredRoot` 遇 EEXIST 读回 null → `writeRootState` **覆盖 v2**。所以：**回滚到 v1 代码前，先把 `.v1.bak` 恢复成 `root-state-<p>.json`**；否则根 registry 丢失。P1 期间桌面不装新代码，风险只在开发机测试目录。

### 3.4 与“根不得静默改变”的关系

- 重启后：`primaryRoot` 从 v2 读回，不再重新推断 → 不静默变根。
- 首推时两进程竞争：`link` 独占，输方读回赢方的主根。
- `configRoot` 增删仍按 v1 语义写 `project-root-changed`（移到 root audit，见 §4）。
- 记忆不迁移、不删除（R-MEMROOT 第 5 条）。

## 4. 审计双通道

### 4.1 两个 sink

| 通道 | 文件 | 归属 | 写什么 | 写失败降级 |
|---|---|---|---|---|
| **root audit**（profile 级） | `<home>/context-governance/root-audit-<profile>.jsonl` | 用户级；`apply` 即建（`AuditLog.#ensureFile` 现状） | 根生命周期、迁移、fail-closed、containment、根变化、身份 | in-memory 保留、logger warn、`/cg status` 的 `root-audit:` 行显 `failures=` |
| **per-root audit** | `<root>/memory/governance/audit.jsonl` | 每个纳管根；跟 store 同生命周期（P1 只有主根） | 会话级：压缩成本/loss、保护、回注、header、early、policy | 沿用 T6 只读降级（`auditWriteFailures`/`auditSkippedReadOnly`），不阻断压缩 |

两个 sink 都复用 `AuditLog`（同一白名单/脱敏/8 MiB 轮转），只是 `file` 不同。`audit.maxBytes` 同时作用于两者。

### 4.2 事件归属迁移

| 事件 | 今天写哪 | P1 起写哪 | 理由 |
|---|---|---|---|
| `persistence-identity` | per-root | **root audit** | 身份/状态文件路径是 profile 级事实 |
| `inferred-fresh` | per-root | **root audit** | 主根首次推断，P1 只有主根 |
| `project-root-changed` | per-root | **root audit** | 根变化是根级事件 |
| 其余（`apply`/`capability*`/`policy*`/`header*`/`protection*`/`reinjection*`/`compaction-*`/`prune-observed`/`early-*`/`cycle-*`） | per-root | **不变** | 都是某个根内会话的事实 |

新增事件（root audit）：`root-registered`、`root-migrated`、`root-state-corrupt`、`root-state-write-failed`、`root-state-unsupported-version`、`root-entry-invalid`、`root-fail-closed`、`root-limit`、`root-audit-unavailable`、`containment-violation`、`root-unmanaged`（P1 过渡；每个会话一条，含 `sessionId/root`）。
`root-drift` 写 **pinned 根的 per-root audit**（managed 时；unmanaged 只 logger，P2 再补）。
P2 预留：`memory-tool-rejected`（§5）。

新增白名单字段：`rootKey`、`rootCount`、`managed`、`fromVersion`、`toVersion`、`backupPath`、`violation`、`target`。不新增任何正文类字段。

### 4.3 隔离规则（硬约束）

1. root audit **不写**会话正文、摘要全文、条目 detail；只写路径/键/计数/枚举/原因（沿用白名单）。
2. per-root audit **不写**其他根的事件、不写 profile 级迁移/registry 事件。
3. **跨根不写**：A 根会话的任何事件（含 cost/loss）不得落进 B 根 audit。P1 的 `unmanaged-root` 因此**不写 per-root audit**（P2 起写它自己的根 audit）。
4. 两个 sink 都只追加、不阻塞主流程。
