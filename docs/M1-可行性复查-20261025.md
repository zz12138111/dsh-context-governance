## 二、证据

### 1. tokenMeter 存在但没接上

- `dsh-base/cordis.patch.yml` 默认挂载 `- id: token-meter, name: '@deepseek-ai/dsh-token-meter'`。
- `compaction-basic`、`compaction-tool-result-pruner` 源码均 `ctx.tokenMeter.measure()/estimateMessage()`。
- 插件侧：`src/compress/runtime.js:189-195` 构造时读一次，包在 try/catch 里，失败即永久 `null`；未使用本插件已有的 `ctx.inject([...], cb)` 机制（`src/index.js:341` 已用于 `commands`）。

### 2. 会话日志里 usage 齐全（兜底通道）

真机会话 `session-58a2e845-…`（9159 事件）只读统计：

- `assistant/message` 共 1199 条，**1199/1199 带 `usage`**；样本 `{inputTokens:20662, outputTokens:227, cacheReadTokens:2432, cacheWriteTokens:0, totalTokens:23321}`；
- `request/header` 只有 `header/reason`，**不带 usage**（不能用来算水位）；
- `compaction/summary` 带 `usage`（摘要调用用量，不是水位）。

口径：水位 = `inputTokens + cacheReadTokens + cacheWriteTokens`。

### 3. ctx.compaction 真实存在

- `@deepseek-ai/dsh-compaction` 定义服务 `ctx.compaction`（每个 context 一个实现）。
- 本机 profile `~/.dsh/profiles/desktop/cordis.patch.yml` 有 `- id: compaction-basic … thresholdRatio: 0.65`。
- 同会话存在真实压缩：`compaction/start(seq=4193) → summary(4195) → end(4197)`（自动）、`8535→8537→8539`（手动，`sourceCommandId`）。

### 4. 宿主已默认折叠工具结果

- `dsh-base/cordis.patch.yml` 有 `- id: tool-result-pruner, name: '@deepseek-ai/dsh-compaction-tool-result-pruner'`。
- 默认：`thresholdChars=8192`，`headChars=4096`，`tailChars=1024`，中间插 `middle pruned` 标记；**压缩触发时**执行；原文仍留会话日志；协议为 `session.append` 替换事件 + `compaction/prune` 影子定价。
- 真机会话里 `compaction/prune` 8 条（seq 4177–4191，紧接 `compaction/start`），`shadowedTokenCount` 4797/2315/2106/3928/2253/2163/3278/2805。
