## 2. 可逆性（事实判断）

GitHub 官方文档（[Setting repository visibility](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/managing-repository-settings/setting-repository-visibility)）明确：
- **转私有不会把公开 fork 转私有**：GitHub 会把公开 fork 分离到新 network，**public forks are not made private**。
- **转公开**：代码对所有人可见、**任何人都可以 fork**。
- 已克隆/已 fork/已下载的提交对象**无法撤回**；搜索引擎、第三方镜像、GHArchive 等不在 GitHub 控制内；Actions 已下载的 artifact 同理。
→ **不存在“先公开看看、不行再撤回”的选项；只能事前避免。**

### 8.1 顺序：**清史在前，修缺陷在后，公开在最后**

建议流水线（节点编号沿用 §7.7）：

```
0 已闭合（曾公开）
→ 1 备份
→ 3 树清洗 + 本地新根提交（不推）+ 全量测试 + compliance-scan --strict
→ 4 ★ force-push + 删旧 tag            ← 隐私面在此闭合
→ 修 B-1/B-2（若决定修）：新提交落在干净历史上 + 测试
→ 6 ★ v1.0.0 tag
→ 7 ★ public
→ 8 ★ Release
```

理由：
1. **A 方案会丢弃全部旧历史**，先修也没有可追溯的修复链；先在旧史上修等于白攒一层记录。清史后修，修复提交天然成为干净历史的一部分，且公开后「1.0.0 → 修复」的叙事清楚。
2. **清史不被缺陷决策阻塞**：private 仓 force-push 零外部影响，可以立刻做；缺陷是否修、怎么修，可并行等结论，不会造成返工。
3. **公开必须最后**：若先公开再修，带 B-1 的 1.0.0 会先上线并进入 Release/tag；之后修复还要动 tag/Release。
4. **B 方案（filter-repo）才需要预判白名单**：先修会让修复涉及的新文件也要进白名单，容易返工；A 方案无此问题（这也是 A 更适合本仓的原因之一）。

**唯一禁忌**：清史 force-push 之前，不要再往远端推任何新提交（当前本地 6 笔未推提交也算在内——它们的内容将进新根提交的树，历史被丢弃，属预期）。已推的 `origin/feat` = `7457880`，清史时一并重写。

### 8.4 Actions 日志：不逐字读也能闭合——**删 run 是确定性闭合**

背景：我此前未能完整加载 run 日志（页面虚拟化），所以**不能假设日志干净**。且已发现一个具体风险：`t7-replay.test.mjs` 的断言 needle 直接写着用户名——任何打印该源码片段、失败断言或 diff 的日志都会带出它；run #1 又确实失败过（ubuntu 路径测试）。

三层闭合，按确定性排序：

1. **主路径（确定性）：公开前删除全部 run（含 artifacts/caches）**。理由：公开面 = GitHub 上可访问的对象；run 删除后日志/artifact 不再可访问。这不依赖读日志，只依赖一个可验证结果——`GET /repos/{owner}/{repo}/actions/runs` 返回空列表（或页面 Actions 页为空）。**盲区从「日志内容是否干净」降为「日志曾经存在」，而后者已被删除动作覆盖**，与清史一起构成「新访问者看不到旧内容」。
2. **加强证据（机器过滤，不靠人眼）**：若用户要求保留日志或要证据，下载 run 日志到 `_backup/actions-logs/`，跑
   `grep -aiE 'C:\\Users\\|<用户名>|DS-PROJECT|MEM-2026|snapshot-11509'`，把输出存成 `grep-result.txt`；**零命中即证据文件**，不需要我逐字读。注意：本机未安装 `gh`，走 API 需 token/联网，属特权动作，须 00/用户执行。
3. **只作背景、不单独当证据**：6 个 run 均由本仓 workflow 触发，workflow 内容已逐行审过（checkout/setup-node/npm test/gitleaks，无 secrets 打印）；但这只能降低概率，不能排除测试失败输出，故不作为闭合依据。

结论：**以 1 为闭合条件，2 为可选加强；公开前必须完成 1。** 若用户不接受删 run，则必须先完成 2 且零命中，才可转 public。
