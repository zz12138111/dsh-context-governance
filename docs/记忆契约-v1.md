# 任务态记忆契约 v1

> 适用范围：`REQ-20261025-01` M1 的内置最小记忆（`packages/dsh-context-governance/`）。
> 对应架构：`docs/上下文治理插件-架构说明-v1.0.md` §5（记忆）、§6.5（回注）、§9.3（恢复路径）。
> 状态：T2 定稿；T3–T6 只增不改本契约的字段/状态语义。

## 1. 定位

- 只记**任务态**：决定、偏好、待办、进度、事实、判据、锚点。
- **不保存原始对话**；`source` / `evidence` 是**指针**（会话 ID + 消息位置、文件路径、哈希）。
- 详情留在记忆里，按需用 `mem_query` 读取；回注只放 ID/状态/指针。
- 不引入数据库/向量检索；文件人可读、可 git 管理、可人工编辑。
- 项目记忆是**唯一长期可写状态**；摘要与索引都是派生数据，不能反向覆盖记忆。

## 2. 目录与文件

默认根目录：`<projectRoot>/.dsh/memory/`（`memoryRoot` 可配置）。

```
.dsh/memory/
├─ MEMORY.md                 派生索引：一行一条；每次写后重建；不要手改
├─ .writer.json              进程间写者锁 {pid, startedAt, project, version}
├─ audit.jsonl               审计 JSONL（T4 起；只写元数据，不写正文）
├─ protection/               压缩前同步落盘的保护 journal（物化成功后删除）
└─ topics/
   ├─ decision.md            每种 type 一个主题文件
   ├─ preference.md
   ├─ todo.md
   ├─ progress.md
   ├─ fact.md
   ├─ criterion.md
   └─ anchor.md
```

主题文件格式：Markdown + 显式条目块；块外文字被忽略（允许人工备注）。

```markdown
<!-- entry:MEM-20261025-001 -->
### MEM-20261025-001
- title: 插件名定为 dsh-context-governance
- type: decision
- status: active
- project: DSH插件开发
- writer: user
- confidence: 1
- risk: low
- createdAt: 2026-10-25T08:00:00.000Z
- updatedAt: 2026-10-25T08:00:00.000Z
- supersedes:
- supersededBy:
- source: session:<id>#<seq>
- evidence: docs/DECISIONS.md

<detail 正文，可多段>
<!-- /entry -->
```

硬性格式规则：

- 每个块必须闭合；`<!-- entry:` 数量必须与块数一致；重复 ID、未知字段、缺字段、类型与文件名不符都视为**文件损坏**。
- 文件非空时，要么以 `# topics/<type>.md` 开头，要么至少含一个合法条目块；否则视为损坏。
- `detail` 内不得出现 `<!--`（防止块标记注入）。
- 除 `detail` 外所有字段都是单行值；`confidence` 解析为 0–1 数字。

### 2.1 保护 journal（T4）

- `compaction/start` 必须在摘要生成前同步落盘，因此 T4 先写 `protection/<cycle>.json`（临时文件 + fsync + rename），**不直接改写主题文件**；
- 保护条目 ID 预留 `MEM-YYYYMMDD-1000+`，避免与普通条目抢号；`detail` 恒为空，只放首行/路径/callId 与 `source` 指针；
- 随后异步 `materializeProtection` 把 journal 条目并入 `topics/*.md` 与 `MEMORY.md`，成功后删除 journal；物化完成前 `query/get` 仍能读到 journal 条目；
- 进程在物化前崩溃：下次 `open` 自动物化；
- `audit.jsonl` 同步追加，只写事件/ID/计数/原因，不写消息正文、摘要正文或路径内容；
- 保护条目同样受 §6 敏感信息规则约束（标题命中凭据形态时只写“敏感内容已省略”）。
- 细则与验收用例：`docs/T4-压缩前固化与回注.md`。

## 3. 字段

| 字段 | 必填 | 说明与约束 |
|---|---|---|
| `id` | 是（存储分配） | `MEM-YYYYMMDD-NNN`，本地自然日 + 项目内递增；创建后不可改 |
| `type` | 是 | `decision` / `preference` / `todo` / `progress` / `fact` / `criterion` / `anchor` |
| `status` | 是 | `proposed` / `active` / `superseded` / `expired`（见 §4） |
| `project` | 是 | 项目命名空间；与存储的 project 一致；≤120 字符 |
| `title` | 是 | 一行摘要；≤200 字符；不得含换行 |
| `detail` | 否 | ≤8,000 字符；不抄整段对话；不得含凭据 |
| `source` | 否 | 来源指针（会话/消息位置），≤500 字符；不是原文 |
| `evidence` | 否 | 证据指针（文件、哈希、日志位置），≤500 字符 |
| `writer` | 是 | `user`（用户确认）/ `rule`（规则提取）/ `model`（模型提取） |
| `confidence` | 视情况 | 0–1；`writer=model` 必须显式给；`user` 默认 1，`rule` 默认 0.9 |
| `risk` | 否 | `low`（默认）/ `high`；高风险=不可逆删除、预算、权限、技术路线变更 |
| `createdAt` / `updatedAt` | 是（存储写入） | UTC ISO-8601 |
| `supersedes` | 否 | 取代的旧 ID（只能由 supersede 操作产生） |
| `supersededBy` | 否 | 被哪条新记录取代（由 supersede 操作回填） |

## 4. 状态、写入者与风险

| writer | 默认 status | 说明 |
|---|---|---|
| `user` + `risk=low` | `active` | 用户直写可直接生效 |
| `rule` + `risk=low` + `type∈{progress,fact}` | `active` | 低风险进度/事实可直接生效（如批次计数） |
| 其他（模型写入、高风险、其余规则提取） | `proposed` | 执行动作前必须确认 |

硬规则：

1. `writer=model` 必须带 `confidence`；默认 `proposed`。
2. `risk=high` 一律先 `proposed`；即使 `writer=user` 也不能直接创建为 `active`，须显式确认。
3. 创建时显式传 `status:"active"` 只在上述两条允许的场景成立；否则报 `CONFIRMATION_REQUIRED`。
4. 状态迁移：`proposed → active`（confirm）、`proposed/active → expired`（expire）；`superseded` 只能由 supersede 产生；不允许反向迁移。
5. 不原地覆盖：新记录用 `supersedes` 指向旧记录，旧记录转 `superseded` + `supersededBy`；旧记录不删除。
6. 删除：M1 不提供物理删除；过期用 `expired` 标记，保留追溯。

## 5. 并发与持久化（M1 硬语义）

| 语义 | 实现 |
|---|---|
| 进程内单写者 | 所有写操作进一条 promise 队列（`#queue`），串行化；失败不阻塞后续 |
| 原子写 | 同目录临时文件 → 写入 + fsync → rename 覆盖；读侧看不到半个文件；残留只在 `.tmp-*` |
| 备份 | 覆盖前留一代 `*.md.bak`；用于损坏恢复 |
| 进程间 | `.writer.json` 锁（pid + startedAt）；**活跃持有者 → 本次只读**；死进程/损坏锁 → 覆盖 |
| 外部修改检测 | 写前对比已加载文件的 size/mtime/hash，并扫描 `topics/` 是否有未知新文件；命中 → 只读 + `EXTERNAL_MODIFICATION` |
| 损坏 | 解析失败 → 尝试 `.bak`；成功则用备份内容只读；失败则只读+告警；**不覆盖损坏文件** |
| 恢复 | 人工处理外部修改后 `reload()` 可重新取得写权；不自动合并 |
| 跨进程合并 | M1 **不承诺**；多会话同项目由锁显式提示，不假装“加锁就安全” |

写入失败（磁盘/权限）向上抛错；T6 的“压缩前写失败 → 重试一次 → 仍失败跳过本次压缩并告警”由压缩路径实现，不在存储层静默吞错。

## 6. 敏感信息

- 记忆**永不保存**凭据、密钥、账号密码；只保存“在哪里找”的指针。
- 写入前扫描（命中即拒绝 `SENSITIVE_CONTENT`）：私钥头、GitHub token、OpenAI key、Slack token、AWS key、`password/secret/api_key/token = …` 赋值形态。
- 审计日志同样按此口径脱敏（T5 落实）。
- 人工编辑文件绕过扫描：损坏/敏感由审核与人工负责；插件加载时不做内容扫描（M1 不做 guardrail）。

## 7. 工具契约

### `mem_write`

| 参数 | 说明 |
|---|---|
| `op` | `create` / `update` / `confirm` / `supersede` / `expire` |
| `id` | 既有 ID（update/confirm/supersede/expire 必填） |
| `type` / `title` / `detail` / `writer` / `confidence` / `risk` / `source` / `evidence` / `project` | 条目字段（create/supersede；update 只允许可编辑字段） |
| `status` | 创建时可选；非法直提 `active` 会被拒 |
| `supersedes` | 兼容入口；正常应使用 `op=supersede` |

返回：`{id, status, type, title}`（supersede 另带 `superseded`）。`source` 缺省时自动写 `session:<当前会话 id>`。

### `mem_query`

| 参数 | 说明 |
|---|---|
| `ids` | 指定 ID 时**返回详情**（每次 ≤20 个） |
| `type` / `status` | 过滤 |
| `text` | 标题+正文关键词（大小写不敏感） |
| `limit` | 默认 20，上限 100 |

返回：`{count, entries}`。**无 `ids` 时不返回 `detail`**——这是“详情留记忆”的强制点。

## 8. 回注指针格式（E2 结论）

| 情况 | 形态 |
|---|---|
| 摘要可读，条目已覆盖 | `MEM-20261025-017 仍生效（见记忆）` |
| 摘要可读，条目未覆盖 | `MEM-20261025-017 待确认：<一行标题>（见记忆）` |
| 摘要不可读 | `MEM-20261025-017 待确认（详情查记忆）` |
| 详情 | **永不回注** |

- 状态标签：`proposed→待确认`、`active→仍生效`、`superseded→已被取代`、`expired→已过期`。
- 注入时机：`compaction/end` 之后一次；会话开始/唤醒一次；不每步注入。
- 去重：注入前查当前表面是否已有同一 ID 行；有则不重复。
- 被吞审计：记录注入 seq；下一次 `compaction/summary` 时检查 `seq ∈ shadowedRange`。

## 9. 失败语义（本层）

| 情况 | 行为 |
|---|---|
| 配置非法 | `resolveConfig` 抛错 → 插件不加载，DSH 正常（由入口保证） |
| 锁被活跃写者持有 | 只读；`status.readOnlyReason = writer-lock:<pid>`；告警 |
| 外部修改 | 首次写被拒 + 转只读；人工处理后 `reload()` |
| 主题文件损坏 | 用 `.bak` 只读 + 告警；无备份则只读 + 空内容；不覆盖损坏文件 |
| 工具注册失败 | 记录在 `failures`，其他工具继续注册；入口写 warn |
| 写入后索引失败 | 条目已落盘，索引告警；下次写重建 |
