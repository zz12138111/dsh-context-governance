# 上下文治理插件 · 架构说明

> 版本：v0.3（复用修订稿）
> 日期：2026-10-25
> 状态：草案，供外部评审；未定稿、未落需求、未开始实现。
> 变更：按“薄治理层 + 现成能力适配”修订；记忆改为内置最小文件存储；压缩后端可插拔（宿主 / context-zip / billion-context），零硬依赖；补充复用边界与 MVP。

---

## 0. 一页摘要

**问题**：长会话的上下文越来越贵；压缩之后容易接不上；已经定下的事、批次进度、判据没有稳定的落点，导致重复决策和返工。

**方案**：不做第二个压缩引擎、记忆数据库或配置框架；只做一层薄治理——

1. **任务态契约**：决定、偏好、待办、进度、判据、锚点；
2. **压缩保护与回注**：保护清单、压缩前固化、压缩后回注；
3. **策略**：什么时候、对什么、做到什么程度；
4. **审计**：动作与结果可核对。

**复用**：压缩沿用现成后端（默认跟随已装后端，没有就用宿主默认；可选 context-zip、billion-context）；配置用宿主设置与 Schemastery；观测用宿主 token 计量与 context 面板。

**记忆**：内置最小文件存储；调用少、要求低；不引入数据库，不依赖第三方记忆插件。

**边界**：不改 DSH、不接管会话、不保存原始对话、不做领域专用功能。

**形态**：单插件、零硬依赖、标准安装；本机自用 + 通用发布。

## 1. 背景与问题

### 1.1 三个反复出现的问题

| 问题 | 表现 | 后果 |
|---|---|---|
| 上下文膨胀 | 对话越长，每次模型调用都要重读全部历史；工具输出、工具定义占很大比例 | 成本随轮次上升；接近上限时被迫压缩 |
| 压缩后断线 | 摘要把任务状态、决策、批次进度丢掉；压缩后要重新问、重新找 | 长任务接不上；严重时返工 |
| 重复与无痕 | 已拍板的事被重问；批次中断只能翻对话猜进度；判据只存在于对话里 | 返工成本高于“写下来”的成本 |

### 1.2 一个基本判断

**会话是易失的，项目是长期的。** 要点应该跟项目走，而不是跟某一次会话走。压缩、换会话、定时唤醒，本质是同一件事：当前上下文不要了，但任务还要继续。

### 1.3 两种“真相”

- **原始对话**：证据真相。由 DSH 保存，只读，插件不删不改。
- **项目记忆**：操作真相。唯一长期可写的状态，决定“接下来做什么”。
- **摘要、索引、每轮视图**：派生数据。由对话和记忆生成，不能反过来覆盖记忆。

## 2. 目标与非目标

### 2.1 目标

1. **长会话可续**：压缩、换会话、定时唤醒后能接上，不用重新问。
2. **花费可控**：能看见上下文构成，能按策略减少进入量。
3. **用户可定义策略**：用配置文件表达“什么时候、对什么、做到什么程度”，不写代码。
4. **通用**：标准 DSH 插件，桌面/Web 可用；不绑定业务领域。
5. **稳定**：失败显式、原文可回读、可整体禁用或摘除。

### 2.2 非目标

- 不写压缩引擎；
- 不写通用记忆数据库、向量库、embedding 服务；
- 不写配置框架或新的设置 UI 框架；
- 不写内容安全 guardrail；
- 不做调度器；
- 不修改 DSH 本体、不接管会话循环；
- 不做某个领域（影音、游戏、开发等）的专用功能。

**关于“全局偏好”**：可以有一个很小的全局偏好文件，但默认关闭、只放偏好与教训、不放任务状态；它不是“全局记忆库”，也不跨机器同步。

## 3. 总体结构与定位

```
DSH 与现成插件
  ├─ 压缩后端：宿主默认 / context-zip / billion-context（可选）
  ├─ 设置与配置：cordis.patch + 设置页 + Schemastery
  ├─ 计量：token meter / context 面板
  └─ 文件策略与审批
            │ 适配（薄）
┌───────────┴──────────────────────────────┐
│ 治理层（自研薄层）                         │
│  任务态契约 · 策略与保护 · 压缩前后 · 审计  │
│  内置最小记忆（项目文件夹）                 │
└───────────────────────────────────────────┘
```

### 3.1 一句定位

**现成的轮子继续用；我们只做把轮子接起来的治理层。**

### 3.2 复用与自研边界

| 能力 | 直接复用 | 我们只做薄层 |
|---|---|---|
| 压缩 | 宿主 `compaction-basic`、context-zip、billion-context（ACP）、确定性剪枝 | 保护清单、压缩前固化、压缩后回注、后端选择、审计 |
| 记忆 | 不引入外部存储 | 最小文件存储、任务态契约、索引、原子写、确认/冲突/过期 |
| 校验 | Schemastery/JSON Schema；宿主文件策略与审批 | 固定检查库、受保护内容检查 |
| 配置 | `cordis.patch` + 设置页 + Schemastery | 策略 schema、解释生效来源、干跑 |
| 观测 | token meter、context 面板、cost meter | 动作审计、压缩前后归因、失败率 |

**不写**：压缩引擎、通用记忆数据库、配置框架、内容安全 guardrail、调度器、向量库。

### 3.3 为什么这样分

- 压缩、记忆、配置都是成熟领域，重复实现只会带来维护负担和冲突；
- 但“任务态契约、压缩保护/回注、策略解释、审计”是现有插件普遍不做的，正好是缺口；
- 用“治理层”把它们串起来，单插件、零硬依赖，也方便以后替换任一后端。

## 4. 核心不变量

以下不交给用户配置：

1. **原始对话只读、可回读**：插件不删、不改、不搬原始记录。
2. **项目记忆是唯一长期可写状态**：摘要、索引、每轮视图都是派生，不得反向覆盖记忆。
3. **摘要引用记忆条目**：压缩前发现的新要点，先写记忆（带来源），再进摘要。
4. **折叠可回读**：任何被折叠的内容，保留原文或可定位的指针。
5. **失败显式、回退默认**：插件失败不影响 DSH；配置非法时插件不加载，DSH 继续用默认行为。
6. **受保护内容不可压缩**：最新用户消息、规则注入、工具调用与结果配对、批次清单与回滚点。
7. **定时唤醒只读记忆**：只注入摘要与未完成批次，不拉整段历史。
8. **不自建第二存储、不抢第二压缩后端**：记忆只有一份；压缩同一时间只用一个后端，冲突显式提示。
9. **记账用宿主口径**：上下文用量以 DSH 自己计量为准，不另造“省钱数字”。

## 5. 记忆：内置最小文件存储

### 5.1 定位

- 只记**任务态**：决定、偏好、待办、进度、判据、锚点。
- **调用少、要求低**：不做向量检索、不做 embedding、不做复杂查询；关键词、文件路径、按需读取足够。
- 不替代原始对话；不追求“记住一切”。

### 5.2 存储约定

- 放在**项目文件夹**里，跟项目走；新会话、压缩后、定时唤醒都读它。
- 结构参考成熟做法：一份索引（`MEMORY.md`，一行一条）+ 主题文件；索引只注入摘要或按需读取。
- 项目/领域一个命名空间；同一项目多会话时按写者分目录，避免互相覆盖。
- 原子写（临时文件 + 重命名）；需要时加锁；文件可 git 管理、可人工编辑。
- 敏感信息不进记忆；支持本地专用文件与忽略规则。

### 5.3 最小结构

| 字段 | 含义 |
|---|---|
| `id` | 稳定编号，便于摘要引用与去重 |
| `type` | 决定 / 偏好 / 待办 / 进度 / 事实 / 判据 |
| `status` | 待确认 / 生效 / 已被取代 / 过期 |
| `project` | 归属项目或领域 |
| `title` | 一行摘要 |
| `detail` | 必要细节，不抄整段对话 |
| `source` | 来源会话与消息位置（指针，不是原文） |
| `writer` | 用户确认 / 规则提取 / 模型提取 |
| `confidence` | 可信度；模型提取必须标 |
| `时间` | 创建、更新、过期 |
| `supersedes` | 取代了哪条旧记录 |
| `evidence` | 证据指针：文件、哈希、日志位置 |

### 5.4 写入来源与确认

- **用户确认**：可以直接生效。
- **规则提取**：低风险进度、批次计数可直接生效；高风险动作必须待确认。
- **模型提取**：默认“待确认”，不直接生效。
- **高风险**（不可逆删除、预算、权限、技术路线变更）：先入“待确认”，压缩可以继续，但**执行动作**必须等确认。

### 5.5 冲突与过期

- 不原地覆盖；新记录用 `supersedes` 指向旧记录。
- 两条记录矛盾时标记冲突，等确认；不自动合并成“折中说法”。
- 过期用状态标记，不静默删除；删除留一行“谁删、删什么、为什么、何时重议”。

### 5.6 并发、敏感信息、项目识别

- **并发**：同一项目默认单写者；多会话写时用原子写与锁；合并靠 `supersedes` 与状态，不做“最后写入者赢”。
- **敏感**：不存凭据、密钥、账号密码；必要时只存引用位置；审计日志同样脱敏。
- **项目识别**：优先显式配置；没有配置时退到 git 根目录；再没有则用路径规则；跨项目不自动继承。

### 5.7 不做什么

- 不做数据库、向量检索、embedding 服务；
- 不做全局记忆库；
- 不自动把所有对话都“记下来”；
- 不依赖第三方记忆插件（未来可作为可选适配，但不是默认）。

## 6. 压缩：后端可插拔

### 6.1 原则

- **不写引擎**。
- 默认**不强制替换**：当前 profile 已装什么后端就用什么；没有就用宿主默认。
- 用户可显式指定后端；切换失败时回退默认，并明确提示。

### 6.2 可选后端

| 后端 | 状态 | 特点 | 依赖 |
|---|---|---|---|
| 宿主 `compaction-basic` | 默认兜底 | 零依赖、最稳 | 无 |
| `context-zip` | 可选 | 五段式交接 + 分段回读 + 工作笔记 | 已装则用 |
| `billion-context`（ACP） | 可选 | 模型自写检查点、可逆、分层蒸馏 | 已装则用 |
| 确定性剪枝 | 可选（后续） | 零 LLM、可精确计量 | 可选 |

### 6.3 治理层负责什么

- **触发**：比例、绝对量、回合数、手动、安全点（任务边界、批次完成、测试通过）；
- **保护**：最新用户消息、规则注入、工具配对、批次清单、回滚点；
- **压缩前固化**：把关键状态写入项目记忆；
- **压缩后回注**：把摘要与未完成事项放回上下文；
- **审计**：记录用了哪个后端、压了什么、失败没有；
- **回退**：后端失败时回宿主默认；仍失败则保留原上下文并报错。

### 6.4 适配器契约（薄）

一个后端适配器只需提供：

- 能力声明（能否回读、能否分段、是否模型自写）；
- 执行压缩（输入范围与保护清单，输出摘要/分段与记账）；
- 回读（按段或按范围找回原文）；
- 失败语义（什么情况算失败、如何回退）。

不要求后端实现我们的策略或记忆逻辑。

## 7. 校验：配置 + 动作

### 7.1 配置校验

- 用 Schemastery / JSON Schema 校验字段类型、取值范围、互斥关系；
- 配置非法：**插件不加载**，在设置页/命令/日志显式报告；DSH 继续运行；
- 支持干跑：只校验、不执行。

### 7.2 动作校验

- **固定检查库**：一组命名检查项（如“删除前必须有回滚映射”“入库前确认上级目录不是剧集”），配置只引用检查项，不写任意脚本；
- **受保护内容检查**：压缩/折叠前确认保护清单未被覆盖；
- **高风险动作**：复用宿主权限与审批，不自己造审批系统；
- **内容安全**：不在本插件范围；交给现有 guardrail/审核工具。

### 7.3 不做什么

- 不写 guardrail 引擎；
- 不做内容审查；
- 不执行用户任意脚本（v1）。

## 8. 配置与策略

### 8.1 四层配置

从低到高：**内置默认 → 插件配置 → 项目配置 → 会话覆盖**。后者覆盖前者；任何一层都可只写差异。复用宿主 `cordis.patch` 与设置页，不新造配置系统。

### 8.2 规则四要素

- **条件**：任务类型、上下文压力、轮次、工具调用量、手动；
- **动作**：折叠、注入、压缩、限制工具、提醒；
- **保护**：哪些内容不能动；
- **预算**：注入多少、保留多少、压缩后剩多少。

规则是配置文件，不是代码；启动时校验，非法直接拒绝；支持解释“最终生效的是哪一层、哪条规则、为什么触发”。

### 8.3 不做什么

- 不写配置框架；
- 不新造设置 UI 框架；
- 不承诺任意脚本扩展（留接口，后议）。

## 9. 运行流程与生命周期

### 9.1 一次会话的流程

1. **开始 / 唤醒**：读项目记忆，注入一小段摘要（目标、待办、最近决定、关键约束）。
2. **每次模型调用前**：按策略决定是否补充提醒、是否限制工具、是否提示批量。
3. **工具返回后**：长输出折叠成“头尾 + 文件路径”，并记录用量。
4. **到压缩条件**：先把关键状态写进记忆 → 调用当前压缩后端 → 把摘要放回上下文 → 记录审计。
5. **结束**：更新记忆与审计；原始对话仍留在 DSH 日志里。

### 9.2 生命周期与失败语义

| 阶段 | 输入 | 输出 | 重复执行是否安全 | 失败时回退 | 告警 | 预算 |
|---|---|---|---|---|---|---|
| 开始 / 唤醒 | 项目标识、记忆文件 | 每轮视图的初始摘要 | 是 | 空摘要，继续会话 | 记忆不可读时告警 | 摘要 token 上限 |
| 模型调用前 | 视图、策略 | 注入内容、工具状态 | 是 | 跳过注入，用默认工具面 | 注入失败告警 | 注入 token 上限 |
| 工具返回后 | 工具结果 | 折叠结果 + 指针 | 是（同一结果） | 保留原文，不折叠 | 折叠失败记日志 | 字符/字节上限 |
| 压缩前 | 视图、记忆 | 固化条目、保护清单 | 是 | 放弃本次压缩，保留上下文 | 必须告警 | 时间/条目数 |
| 压缩 | 旧对话、保护清单 | 摘要、被收起范围 | 视后端而定 | 回退宿主默认压缩 | 必须告警 | 调用次数/时间 |
| 压缩后 | 摘要、记忆 | 回注后的视图 | 是 | 只注入最小摘要 | 回注失败告警 | 注入 token 上限 |
| 回合结束 | 事件、用量 | 指标、审计记录 | 是 | 先缓存，下次补写 | 写失败记日志 | 字节上限 |
| 会话结束 | 状态、未决项 | 记忆更新、收尾记录 | 是 | 下次开始时补写 | 写失败告警 | 时间/字节 |

### 9.3 恢复路径

- **记忆写入失败**：放弃本次压缩、保留上下文、显式告警；若已接近硬上限，回退宿主默认压缩并明确提示。
- **压缩失败**：回退宿主默认；默认也失败时，保留原上下文并报错，不丢原文。
- **记忆文件损坏**：进入只读，使用最近备份；不阻塞会话，但告警。
- **插件被禁用**：行为无残留；记忆文件仍在，可人工读取。

## 10. 与 DSH 的集成

- **只使用公开接口**：读取事件与用量、模型调用前补充内容、替换/适配压缩后端、注册工具/命令/设置页。
- **零硬依赖**：只装宿主也能用；context-zip、billion-context 等是可选适配。
- **标准安装/卸载**：普通 DSH 插件；可整体禁用；卸载后不留行为残留。
- **冲突检测**：同一时间只允许一个压缩后端；检测到冲突时显式提示，不静默。
- **版本检查**：发现接口不匹配时降级到宿主默认，并报告原因。

## 11. 关键设计决策

| 决策 | 选择 | 理由 | 替代方案 |
|---|---|---|---|
| 架构厚度 | 薄治理层 + 适配 | 不重复造轮子；维护面小 | 全栈自研 |
| 记忆存储 | 内置最小文件存储 | 调用少、要求低；零依赖、可读可 git | 数据库、第三方记忆插件 |
| 压缩 | 后端可插拔，默认跟随已装 | 社区百花齐放；不绑定 | 自研引擎、强制单后端 |
| 配置 | 宿主配置 + Schemastery | 复用成熟校验与设置页 | 自研配置框架 |
| 校验 | 固定检查库 + 宿主审批 | 安全、可解释、可控 | 通用 guardrail 引擎 |
| 观测 | 复用宿主计量 | 避免第二套数字 | 自建全量面板 |
| 默认状态 | 轻量、少打扰 | 简单任务不被拖累 | 默认全开 |

## 12. 可行性

## 13. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 适配多个压缩后端带来版本/行为差异 | 统一适配器契约；后端能力声明；默认回退宿主 |
| 与已装压缩插件冲突 | 同一时间只允许一个后端；检测冲突并提示 |
| 记忆文件损坏或并发写坏 | 原子写、锁、备份、只读降级 |
| 记忆与摘要出现两个说法 | 记忆唯一可写；摘要引用记忆 ID；派生不反向 |
| 规则太复杂，用户不会配 | 预设、示例、解释生效来源、干跑 |
| 折叠过度，信息丢失 | 保留原文与指针；受保护内容检查 |
| 依赖第三方插件失效 | 零硬依赖；适配器失败回退宿主；显式告警 |
| 版本升级导致接口失效 | 健康检查；限定已验证版本；显式降级 |

## 14. 验收指标

### 14.1 测量方法

- 同一组任务场景，分别在“关闭插件”和“开启插件”下跑，记录基线；
- 上下文构成按类目统计：规则、工具定义、用户、模型文本、工具参数、工具结果、注入记忆；
- 净节省 = 减少的输入 token −（压缩 + 回注 + 记忆读取带来的额外成本）；
- 先测量、后定目标；没有基线不承诺百分比。

### 14.2 指标

| 类别 | 指标 | 说明 |
|---|---|---|
| 续接 | 压缩后接续成功率 | 压缩/换会话后继续，无需重新问关键信息 |
| 续接 | 重复决策次数 | 已生效决定被再次询问或再次决策的次数 |
| 成本 | 上下文构成与每轮用量 | 按类目统计，能回答“为什么大” |
| 成本 | token 净节省 | 见 14.1 公式 |
| 折叠 | 回读成功率 | 被折叠内容的指针能找回原文的比例 |
| 折叠 | 信息丢失事件 | 折叠导致任务判断错误的次数，目标为 0 |
| 失败 | 失败显式率 | 失败被报告而不是静默的比例 |
| 失败 | 回退成功率 | 回退后会话仍可继续的比例 |
| 依赖 | 零硬依赖可用性 | 只装宿主时功能可用；适配器可选 |
| 依赖 | 冲突检测 | 多后端冲突能被发现并提示 |
| 开销 | 插件延迟、磁盘、审计日志量 | 每阶段耗时与占用 |
| 安全 | 未保护删除次数 | 受保护内容被误删/误压的次数，目标为 0 |

## 15. 建议的最小闭环（MVP，待定）

### 15.1 M0：观测基线（不改行为）

只接宿主原语，跑一周：记录上下文构成、压缩事件、动作与失败；不做自动压缩、不隐藏工具、不改行为。

### 15.2 M1：最小闭环

- **任务态契约**：内置最小文件存储，只记决定、待办、进度、判据的最小集；
- **压缩保护**：最新用户消息、规则注入、工具配对、批次清单、回滚点；
- **压缩前固化 + 压缩后回注**；
- **压缩后端**：默认跟随已装后端；没有就用宿主默认；context-zip / billion-context 作为可选适配；
- **审计**：上下文构成、压缩前后用量、动作记录；
- **可选**：保守阈值的工具输出折叠。

### 15.3 只做实验，不承诺收益

- 批量调用提示：先测量“是否减少调用次数、减少多少”。

### 15.4 延后

- 自研压缩引擎；
- 数据库/向量检索；
- 工具隐藏；
- 用户脚本扩展；
- 宽版本兼容；
- 领域包独立插件；
- 批量调用收益承诺。

## 17. 术语

- **上下文**：每次模型调用时实际发送的内容，包括历史消息、工具结果、系统提示等。
- **压缩**：把旧对话替换成摘要、删除可删段或只保留关键段，目的是减少上下文占用。
- **回注**：压缩后把摘要或要点重新放回上下文。
- **固化**：压缩前把关键状态写入项目记忆的动作。
- **折叠**：把长工具输出缩成头尾摘要 + 文件指针，原文仍可回读。
- **项目记忆**：放在项目文件夹里的要点记录，跨会话保留，是唯一长期可写状态。
- **每轮视图**：本轮真正注入上下文的那部分内容，由记忆和对话派生。
- **策略**：用户配置的规则，决定何时、对什么、做到什么程度。
- **判据**：判断对错的规则或依据；落成记忆条目后可被引用和检查。
- **回滚点**：能撤销一次变更的证据或映射，属于受保护内容。
- **定时唤醒**：由调度在约定时间触发的会话启动；插件只读记忆摘要，不自己建调度。
- **全局偏好**：可选的、很小的跨项目偏好文件；默认关闭，只放偏好与教训。
- **适配**：把现成后端（压缩/存储/校验）接进治理层的薄代码。
- **后端**：实际执行压缩或存储的现成实现。
