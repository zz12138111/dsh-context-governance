## 0. 一页摘要

M3 = **三块功能 + 一块发布就绪**，作为 1.0：

1. **动作校验最小集**（补架构 §7.2；**不能拦截就不做**）；

## 2. 目标（可验收）

1. **动作校验可用**：三条固定检查项，执行前拦截并要求确认；**若无法拦截，1.0 不提供该功能**（不做“事后告警”这种伪保护）。

## 4. 组成

### 4.1 动作校验最小集（§7.2）

**固定检查库（初版三条）**

| # | 检查项 | 触发条件 | 行为 |
|---|---|---|---|
| **C1** | 高危删除/移动前必须有回滚点 | **仅** `rm -rf` / 递归删除 / 带通配删除 / `git reset --hard`，**且目标不在白名单目录** | 拦截并要求给出备份路径或 commit |
| **C2** | 写操作不得越出工作区 | 写/改/删路径经 `realpath`（或等价物）解析后不在工作区根下 | 拒绝，提示真实解析路径 |
| **C3** | git 危险动作 | `push --force`、`filter-branch`、改 remote、tag 发布 | 直接拒绝（tag/发布归用户批准） |

**C1 白名单（默认约 15–20 项，可配置追加）**

```
构建产物：dist build out target .next .nuxt public/build bin obj
测试覆盖：.coverage coverage .nyc_output .pytest_cache __pycache__
缓存/虚拟环境：.venv venv cache tmp .cache node_modules
日志：logs *.log
```

- 命中白名单 → **只记审计，不拦截**；
- 项目可在 `<project>/.cg-policy.json` 追加 `checks.whitelist`（只增不减，不能用它把白名单目录移出保护范围之外做危险删除）；
- 单文件 `rm`、普通 `mv` → 只记录，不拦截。

**约束**
- 配置只引用检查项（`checks: [C1, C2]`），**不写脚本**；
- 不造审批系统，交互复用宿主权限/审批；
- **门禁 G-M3-1**：pre-execute 是否能拦截/否决。
  - 可拦截 → 按上表执行；
  - **不可拦截 → 1.0 不提供动作校验**（不降级为“检测+告警”），文档写明“等宿主支持后开放”。

**验收**
- C1：`rm -rf dist` 不拦、`rm -rf src` 拦；单文件 `rm` 不拦；
- C2：`cd ..` 式相对路径与绝对路径都要能识破（用真实路径解析）；
- C3：force push / 改 remote 被拒；
- **不可拦截时**：功能不存在，文档与 `/cg status` 不谎称有保护。

### 4.2 S3 header 默认开

**默认开（内置层）**，两形态：

| 形态 | 判定 | 注入内容 |
|---|---|---|
| **精简（有规则文件）** | 工作区根存在 `AGENTS.md` / `CLAUDE.md` 或同类 | 进度 / 待办 / 决定 / 锚点；**不含偏好与规范** |
| **完整（无规则文件）** | 上述文件不存在 | 上述四类 + **偏好 1 行**（标注“偏好（非硬规则）”） |

**配额（固定 8 行以内）**

```
待办 2 · 进度 2 · 决定 2 · 锚点 1 · 偏好 1（仅完整形态）
每类内按更新时间倒序；某类不足时空位让给 待办/决定
```

**固定包裹格式**

```
[CG-MEMORY · state-only · budget 8 lines]
- D1 决定：不做推迟压缩 (dec-012)
- P1 进度：0.2.1 窗口/校验层 (prog-031)
- T1 待办：G4 结论已落，等 0.2.2 开工 (todo-004)
[IF CONFLICT: AGENTS.md / system rules win]
```

**六条护栏**

1. **预算**：≤8 行 / ≤800 字符；只放 `ID + 一行标题`，详情不进 header；
2. **来源**：只取 `status=active`；超过 **14 天**未更新标 `[Old]`（上限 30 天可配），**仍注入**、排在同配额末尾；
3. **零注入**：无项目目录或记忆为空 → 完全不注入；
4. **冲突声明**：固定最后一行（见格式）；
5. **可关闭**：`/cg header off`（本会话）、项目配置、插件配置；
6. **审计**：每次注入记 `header-injected`（条数、token 估算、形态、来源层）。

**边界**
- **子会话默认不注入**（任务单一，注入会干扰专注、浪费 token）；
- 只读模式：只读记忆，不写；
- `[Old]` 条目不删除，靠预算被挤掉。

### 4.3 “不重问”评测（非功能）

- 场景：压缩后提问“只有记忆里才有”的问题，观察 `mem_query` vs 重问；
- ≥3 场景（决定 / 待办 / 进度各一）；
- 产出评测记录；不达标回查回注内容与 header 文案。

### 4.4 发布就绪（1.0 硬门禁）

1. **干净历史能力（技术准备）**：发布前确保当前树可独立导出、无未脱敏真实内容；**具体发布形态由用户决策点 D-R1 定**，本节不默认“换新仓库”。原因：真实快照已在历史中，`filter-branch` 被规则禁止，删文件不能清历史。
2. **增量防护**：`.gitignore` 加入 `analysis/**/snapshot-*`、`analysis/**/*-test-*.jsonl`、`analysis/**/*cost-sample*` 等模式，防止再误提交。
3. **敏感扫描**：CI 阶段跑 gitleaks 或 trufflehog（**安装/引入需用户批准**）；同时保留一条本地只读扫描（无外部依赖）覆盖：真实路径、内网 IP、`api_key`/token 形态、`snapshot-*` 文件名。
4. **文档定稿**：README、使用说明的命令与版本一致（0.2.x 实际可用 vs 计划）。
5. **兼容矩阵**：DSH 0.2.x、压缩后端（原生 / context-zip）、M1.1 取消项。
6. **安装/卸载/回滚**：卸载后行为恢复；记忆/审计文件处置说明。
7. 打包与 Release 由审核打包负责；tag/发布前用户批准。

## 5.5 用户决策点：D-R1 发布形态（不是技术项，需用户拍板）

**背景**：当前仓库历史里已有 6 个被跟踪的文件含真实内容（`analysis/req-20261025-05/real/snapshot-11509.json` 等）；规则禁止 `filter-branch`，删文件不能清历史。

| 选项 | 做法 | 代价 | 可逆性 | 适用 |
|---|---|---|---|---|
| **A. 新仓库、干净历史** | 从当前树做初始提交，新建远端仓库 | **现有 issue/PR/提交历史不继承**，未来追溯断档 | **不可逆**：历史回不来 | 要公开、且隐私优先 |
| **B. 现仓库保持私有，另行发布** | 历史留在私有仓库；对外只发 Release 包/只读镜像 | 公开可见的“源码史”缺失，但私有追溯保留 | **可逆**：私有仓库还在，可随时改为公开 | 要公开代码但不公开历史 |
| **C. 暂不公开** | 1.0 仅本机/私有可用 | 无外部用户 | **完全可逆**：随时可切 A 或 B | 先自用、后决定 |

**不提供**：直接在公开仓库沿用现有历史——真实内容不可撤回。

**决策人**：用户（不是需求/00 能定）；需求负责把选项与代价写清，00 负责转达。**未定之前，1.0 不执行任何公开推送。**
