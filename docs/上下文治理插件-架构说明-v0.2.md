# 上下文治理插件 · 架构说明

> 版本：v0.2（评审修订稿）
> 日期：2026-10-25
> 状态：草案，供外部评审；未定稿、未落需求、未开始实现。
> 变更：按外部评审补“定位与分层、核心不变量、生命周期与失败语义、验收指标、记忆结构与并发/敏感信息、MVP 闭环”，并修正“配置非法”的表述。

---

## 0. 一页摘要

**问题**：在 DSH 里，长会话的上下文越来越贵；压缩之后容易接不上；已经定下的事、批次进度、判据没有稳定的落点，导致重复决策和返工。

**方案**：做一个外挂插件，围绕四件事提供能力——**记什么、扔什么、什么时候做、有没有守住**。具体分为五块：记忆、压缩、观测、策略、减少输入。

**边界**：不改 DSH、不接管会话、不保存原始对话、不做某个领域专用功能。领域差异用配置表达。

**目标形态**：单插件、模块化、可配置；标准 DSH 安装方式；本机先自用，成熟后可作为通用插件发布。

---

## 1. 背景与问题

### 1.1 三个反复出现的问题

| 问题 | 表现 | 后果 |
|---|---|---|
| 上下文膨胀 | 对话越长，每次模型调用都要重读全部历史；工具输出、工具定义占很大比例 | 成本随轮次上升；接近上限时被迫压缩 |
| 压缩后断线 | 摘要把任务状态、决策、批次进度丢掉；压缩后要重新问、重新找 | 长任务接不上；严重时返工 |
| 重复与无痕 | 已拍板的事被重问；批次中断只能翻对话猜进度；判据只存在于对话里 | 返工成本高于“写下来”的成本 |

### 1.2 一个基本判断

**会话是易失的，项目是长期的。** 因此要点应该跟项目走，而不是跟某一次会话走。压缩、换会话、定时唤醒，本质是同一件事：当前上下文不要了，但任务还要继续。

### 1.3 两种“真相”

- **原始对话**：证据真相。由 DSH 保存，只读，插件不删不改。
- **项目记忆**：操作真相。唯一长期可写的状态，决定“接下来做什么”。
- **摘要、索引、每轮视图**：派生数据。由对话和记忆生成，不能反过来覆盖项目记忆。

## 2. 目标与非目标

### 2.1 目标

1. **长会话可续**：压缩、换会话、定时唤醒后能接上，不用重新问。
2. **花费可控**：能看见上下文由什么构成，能按策略减少进入上下文的总量。
3. **用户可定义策略**：用配置文件表达“什么时候、对什么、做到什么程度”，不写代码。
4. **通用**：标准 DSH 插件，桌面/Web 可用；不绑定某个业务领域。
5. **稳定**：失败显式、原文可回读、可整体禁用或摘除。

### 2.2 非目标

- 不做 agent 运行时，不接管会话循环；
- 不修改 DSH 本体；
- 不做全局记忆库，不做跨机器同步；
- 不做某个领域（影音、游戏、开发等）的专用功能；
- 不保存原始对话，原始记录仍由 DSH 管理。

**关于“全局偏好”**：可以有一个很小的全局偏好文件，但默认关闭、只放偏好与教训、不放任务状态；它不是“全局记忆库”，也不跨机器同步。

## 3. 总体结构与定位

```
DSH（会话、模型调用、工具、日志）
      │ 公开接口
┌─────┴──────────────────────────────┐
│ 插件                                │
│  策略配置 ──► 决策 ──► 动作          │
│                 │      ├─ 记忆读写     │
│                 │      ├─ 压缩         │
│                 │      └─ 减少输入     │
│  事件与用量 ──► 观测与审计            │
└────────────────────────────────────┘
      │
 项目文件夹（记忆文件）
```

### 3.1 一句定位

**记忆是唯一长期可写状态；压缩与折叠是派生视图的生成动作；策略决定动作何时发生；观测记录动作与结果。**

### 3.2 归属与可禁用性

| 能力 | 类别 | 可否单独禁用 | 依赖 |
|---|---|---|---|
| 记忆 | 核心状态 | 可关闭，但关闭后跨会话/压缩续接能力消失 | 无 |
| 压缩 | 派生动作 | 可禁用，回退 DSH 默认压缩 | 记忆、策略 |
| 减少输入 | 派生动作 | 可禁用 | 策略 |
| 策略 | 控制，横切 | 不可禁用，只保留最小默认 | 无 |
| 观测 | 审计，横切 | 可禁用，不影响行为 | 无 |

### 3.3 五块职责

| 块 | 职责 | 不做什么 | 主要产出 |
|---|---|---|---|
| **记忆** | 记录决定、偏好、待办、进度、关键文件、判据；跨会话、跨压缩保留 | 不抄整段对话，不替代原始日志 | 项目记忆文件、按需召回的接口 |
| **压缩** | 到条件时收敛旧对话；压缩前固化要点，压缩后回注 | 不删原始对话，不动受保护内容 | 摘要/分段记录、审计事件 |
| **观测** | 记录上下文用量、构成、压缩动作、失败与告警 | 不改行为，不替用户判断 | 用量与构成报告、审计记录 |
| **策略** | 决定什么时候、对什么、做到什么程度 | 不硬编码业务规则 | 生效的规则与来源说明 |
| **减少输入** | 折叠长工具输出、按需收起不用的工具、提示批量调用 | 不改变工具语义，不隐藏能力而不告知 | 更少的进入量、明示的工具状态 |

### 3.4 为什么这样分

- **记忆**回答“留什么”，**压缩**回答“扔什么”，**观测**回答“有没有守住”，**策略**回答“什么时候做”。
- 四件事分开，才能单独替换、单独验证：换压缩方式不影响记忆；改策略不影响观测口径。
- **策略与观测是横切能力**，不适合当成“可砍的业务模块”；但可以把高风险动作（工具隐藏、脚本扩展）单独关闭。

## 4. 核心不变量

以下不交给用户配置：

1. **原始对话只读、可回读**：插件不删、不改、不搬原始记录。
2. **项目记忆是唯一长期可写状态**：摘要、索引、每轮视图都是派生，不得反向覆盖记忆。
3. **摘要引用记忆条目**：压缩前发现的新要点，先写记忆（带来源），再进摘要；摘要不另造一套矛盾说法。
4. **折叠可回读**：任何被折叠的内容，保留原文或可定位的指针。
5. **失败显式、回退默认**：插件失败不影响 DSH；配置非法时插件不加载，DSH 继续用默认行为。
6. **受保护内容不可压缩**：最新用户消息、规则注入、工具调用与结果配对、批次清单与回滚点。
7. **定时唤醒只读记忆**：只注入摘要与未完成批次，不拉整段历史。
8. **记账用宿主口径**：上下文用量以 DSH 自己的计量为准，不另造一套“省钱数字”。

## 5. 数据分层与项目记忆

### 5.1 三层数据

| 层 | 归属 | 内容 | 生命周期 |
|---|---|---|---|
| **原始对话** | DSH | 用户消息、模型回复、工具调用与结果 | 由 DSH 保存；插件不删不改 |
| **项目记忆** | 插件 | 决定、偏好、待办、进度、关键文件、判据 | 长期；跟项目走；人可读、可校验 |
| **每轮视图** | 插件 | 本轮真正放进上下文的那一小部分 | 临时；每轮生成，有预算 |

项目记忆内部可以有一份索引（一行一条），但索引只是记忆的辅助，不单独算一层。

### 5.2 写入、读取与清理

- **写入**：用户确认、规则提取、模型提取；压缩前做一次固化；会话结束时补记。
- **读取**：新会话开始、压缩后、定时唤醒时，读取一小段摘要；需要细节时按需检索。
- **清理**：由策略决定保留期；过期项标记而不是静默删除；删除动作留痕。

### 5.3 项目记忆的最小结构

一条记忆至少包含：

| 字段 | 含义 |
|---|---|
| `id` | 稳定编号，便于摘要引用与去重 |
| `type` | 决定 / 偏好 / 待办 / 进度 / 事实 / 判据 |
| `status` | 待确认 / 生效 / 已被取代 / 过期 |
| `project` | 归属项目或领域 |
| `title` | 一行摘要 |
| `detail` | 必要细节，不抄整段对话 |
| `source` | 来源会话与消息位置（指针，不是原文） |
| `writer` | 用户确认 / 规则提取 / 模型提取 |
| `confidence` | 可信度；模型提取必须标 |
| `时间` | 创建、更新、过期 |
| `supersedes` | 取代了哪条旧记录 |
| `evidence` | 证据指针：文件、哈希、日志位置 |

### 5.4 写入来源与确认

- **用户确认**：可以直接生效。
- **规则提取**：低风险进度、批次计数可直接生效；高风险动作必须待确认。
- **模型提取**：默认“待确认”，不直接生效；高风险决定尤其如此。
- **高风险**（不可逆删除、预算、权限、技术路线变更）：先入“待确认”，压缩可以继续，但**执行动作**必须等确认。

### 5.5 冲突与过期

- 不原地覆盖；新记录用 `supersedes` 指向旧记录。
- 两条记录矛盾时标记冲突，等确认；不自动合并成“折中说法”。
- 过期用状态标记，不静默删除；删除留一行“谁删、删什么、为什么、何时重议”。

### 5.6 并发写

- 同一项目/领域默认**单写者**；多会话同时写时，用原子写（临时文件 + 重命名）和锁，避免半截文件。
- 合并靠 `supersedes` 与状态，不做“最后写入者赢”。
- 审计日志追加写，不覆盖；日志可轮转。

### 5.7 敏感信息

- 不存凭据、密钥、账号密码；确实需要时只存“引用位置”，不存值。
- 记忆文件可能被 git 提交：支持本地专用文件、忽略规则、导出前脱敏。
- 审计日志同样脱敏，不把敏感原文写进去。

### 5.8 项目识别

- 优先**显式配置**项目标识；没有配置时退到 git 根目录；再没有则用路径规则。
- 项目标识写进记忆头部；跨项目不自动继承，避免串味。
- 新会话只读当前项目的记忆；全局偏好默认不读。

## 6. 运行流程与失败语义

### 6.1 一次会话的流程

1. **开始 / 唤醒**：读项目记忆，注入一小段摘要（目标、待办、最近决定、关键约束）。
2. **每次模型调用前**：按策略决定是否补充提醒、是否限制工具、是否提示批量。
3. **工具返回后**：长输出折叠成“头尾 + 文件路径”，并记录用量。
4. **到压缩条件**：先把关键状态写进记忆 → 压缩 → 把摘要放回上下文 → 记录审计。
5. **结束**：更新记忆与审计；原始对话仍留在 DSH 日志里。

### 6.2 生命周期与失败语义

| 阶段 | 输入 | 输出 | 重复执行是否安全 | 失败时回退 | 告警 | 预算 |
|---|---|---|---|---|---|---|
| 开始 / 唤醒 | 项目标识、记忆文件 | 每轮视图的初始摘要 | 是 | 空摘要，继续会话 | 记忆不可读时告警 | 摘要 token 上限 |
| 模型调用前 | 视图、策略 | 注入内容、工具状态 | 是 | 跳过注入，用默认工具面 | 注入失败告警 | 注入 token 上限 |
| 工具返回后 | 工具结果 | 折叠结果 + 指针 | 是（同一结果） | 保留原文，不折叠 | 折叠失败记日志 | 字符/字节上限 |
| 压缩前 | 视图、记忆 | 固化条目、保护清单 | 是 | 放弃本次压缩，保留上下文 | 必须告警 | 时间/条目数 |
| 压缩 | 旧对话、保护清单 | 摘要、被收起范围 | 视实现而定 | 回退 DSH 默认压缩 | 必须告警 | 调用次数/时间 |
| 压缩后 | 摘要、记忆 | 回注后的视图 | 是 | 只注入最小摘要 | 回注失败告警 | 注入 token 上限 |
| 回合结束 | 事件、用量 | 指标、审计记录 | 是 | 先缓存，下次补写 | 写失败记日志 | 字节上限 |
| 会话结束 | 状态、未决项 | 记忆更新、收尾记录 | 是 | 下次开始时补写 | 写失败告警 | 时间/字节 |

### 6.3 恢复路径

- **记忆写入失败**：放弃本次压缩、保留上下文、显式告警；若已接近硬上限，回退 DSH 默认压缩并明确提示。
- **压缩失败**：回退 DSH 默认压缩；默认也失败时，保留原上下文并报错，不丢原文。
- **记忆文件损坏**：进入只读，使用最近备份；不阻塞会话，但告警。
- **插件被禁用**：行为无残留；记忆文件仍在，可人工读取；下次启用时校验。

## 7. 配置与策略

### 7.1 四层配置

从低到高：**内置默认 → 插件配置 → 项目配置 → 会话覆盖**。后者覆盖前者；任何一层都可只写差异。

### 7.2 用户定义的规则

一条规则由四部分组成：

- **条件**：什么情况下触发（任务类型、上下文压力、轮次、工具调用量、手动）；
- **动作**：做什么（折叠、注入、压缩、限制工具、提醒）；
- **保护**：哪些内容不能动（最新用户消息、规则注入、工具配对、批次清单、回滚点）；
- **预算**：最多花多少（注入多少、保留多少、压缩后剩多少）。

规则是配置文件，不是代码。启动时校验，非法配置直接拒绝并说明原因；提供“干跑”和“解释生效来源”的能力。

### 7.3 校验与解释

- 启动时校验字段类型、取值范围、互斥关系；
- 支持只校验不执行（干跑）；
- 能回答“最终生效的是哪一层、哪条规则、为什么触发”。

### 7.4 不可配置的安全项

见第 4 节“核心不变量”。

### 7.5 配置非法的语义

配置非法时，**插件拒绝加载**，并在设置页/命令/日志显式报告原因；**DSH 继续运行**，回退到无插件或默认行为。不是“DSH 起不来”。

## 8. 与 DSH 的集成

- **只使用公开接口**：读取事件与用量、模型调用前补充内容、替换压缩实现、注册工具/命令/设置页。
- **标准安装/卸载**：作为普通 DSH 插件安装；可整体禁用；卸载后不留行为残留。
- **失败隔离**：插件出错不影响 DSH 本身；错误必须可见，不静默吞掉。
- **兼容**：先保证当前使用的 DSH 版本；发布前再评估更宽的范围；提供健康检查，发现接口不匹配时显式降级。

## 9. 关键设计决策

| 决策 | 选择 | 理由 | 替代方案 |
|---|---|---|---|
| 插件数量 | 单插件、内部模块化 | 一次安装、统一配置；模块仍可独立禁用 | 多插件拼装 |
| 记忆位置 | 项目文件夹，文件优先 | 人可读、可 git、可移植；跨会话自然续上 | 全局数据库、会话内存 |
| 真相归属 | 原始对话只读；项目记忆唯一可写；摘要/视图派生 | 防止“记忆说 A、摘要说 B” | 摘要也可写回记忆 |
| 压缩方式 | 可替换 | 不同任务、不同引擎；失败可回退 | 绑定某一种压缩实现 |
| 策略形式 | 声明式配置 | 安全、可解释、可校验 | 允许用户写脚本 |
| 观测与行为 | 先观测，再改行为 | 避免拍脑袋调策略；可回滚 | 直接改行为 |
| 默认状态 | 轻量、少打扰 | 简单任务不被复杂系统拖累 | 默认全开 |
| 与生态 | 优先适配共存 | 不重复造轮子，冲突显式提示 | 硬替代 |

## 10. 可行性初步判断

| 能力 | 判断 | 说明 |
|---|---|---|
| 替换压缩实现 | 可行 | DSH 已有对应接口，生态里有先例 |
| 模型调用前注入内容 | 可行 | 生态里有先例 |
| 注册工具/命令/设置页 | 可行 | 标准插件能力 |
| 记忆存文件、跨会话读取 | 可行 | 普通文件读写 |
| 通用地折叠工具输出 | 待验证 | 目前有“只对某类工具生效”的先例，通用接口需确认 |
| 按会话隐藏工具 | 待验证 | 会改变模型可用能力，需要接口与提示配合 |
| 引导批量调用 | 只能引导，不能保证 | 取决于模型行为；收益需实测 |
| 压缩前后插入动作 | 待验证 | 需要确认压缩事件的可用时机 |
| 跨 DSH 版本兼容 | 待评估 | 接口可能随版本变化 |

这些“待验证”项应在正式开发前用小实验确认，不在需求阶段假设成立。

## 11. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 规则太复杂，用户不会配 | 提供预设与示例；默认值可用；解释生效来源 |
| 折叠过度，信息丢失 | 保留原文与指针；保护清单；可回读 |
| 与现有压缩/记忆插件冲突 | 明确互斥关系；优先做适配而不是硬替换 |
| 版本升级导致接口失效 | 健康检查；失败显式；限定已验证版本 |
| 记忆串味或污染 | 项目隔离；全局默认关；写入需归属；模型提取默认待确认 |
| 并发写坏文件 | 单写者、原子写、锁、备份、追加审计 |
| 敏感信息进仓库 | 不存凭据；脱敏；本地专用文件与忽略规则 |
| 插件自身开销 | 默认轻量；只在需要时动作；有预算 |

## 12. 验收指标

### 12.1 测量方法

- 同一组任务场景，分别在“关闭插件”和“开启插件”下跑，记录基线；
- 上下文构成按类目统计：规则、工具定义、用户、模型文本、工具参数、工具结果、注入记忆；
- 净节省 = 减少的输入 token −（压缩 + 回注 + 记忆读取带来的额外成本）；
- 先测量、后定目标；没有基线不承诺百分比。

### 12.2 指标

| 类别 | 指标 | 说明 |
|---|---|---|
| 续接 | 压缩后接续成功率 | 任务在压缩/换会话后继续，无需重新问关键信息 |
| 续接 | 重复决策次数 | 已生效的决定被再次询问或再次决策的次数 |
| 成本 | 上下文构成与每轮用量 | 按类目统计，能回答“为什么大” |
| 成本 | token 净节省 | 见 12.1 公式 |
| 折叠 | 回读成功率 | 被折叠内容的指针能找回原文的比例 |
| 折叠 | 信息丢失事件 | 折叠导致任务判断错误的次数，目标为 0 |
| 失败 | 失败显式率 | 失败被报告而不是静默的比例 |
| 失败 | 回退成功率 | 回退到默认行为后会话仍可继续的比例 |
| 开销 | 插件延迟、磁盘、审计日志量 | 每阶段耗时与占用 |
| 安全 | 未保护删除次数 | 受保护内容被误删/误压的次数，目标为 0 |
| 安全 | 配置校验通过率 | 非法配置被拒绝且不影响 DSH 的比例 |

## 13. 建议的最小闭环（MVP，待定）

### 13.1 M0：观测基线（不改行为）

先跑一周，记录上下文构成、压缩事件、动作与失败；不做自动压缩、不隐藏工具、不改行为。

### 13.2 M1：最小闭环

- **压缩保护**：最新用户消息、规则注入、工具配对、批次清单、回滚点；
- **压缩前固化 + 压缩后回注**：只固化决定、待办、进度、判据的最小集；
- **最小项目记忆**：文件存储、人可读、带来源指针、过期标记、待确认状态；
- **工具输出折叠**：头尾 + 文件路径 + 可回读，先做保守阈值；
- **观测**：上下文构成、压缩前后用量、动作审计。

### 13.3 只做实验，不承诺收益

- 批量调用提示：先测量“是否减少调用次数、减少多少”，不承诺百分比。

### 13.4 延后

- 按会话隐藏工具；
- 用户脚本策略；
- 数据库存储；
- 宽版本兼容承诺；
- 领域包独立插件；
- 批量调用的收益承诺。

## 15. 术语

- **上下文**：每次模型调用时实际发送的内容，包括历史消息、工具结果、系统提示等。
- **压缩**：把旧对话替换成摘要、删除可删段或只保留关键段，目的是减少上下文占用。
- **回注**：压缩后把摘要或要点重新放回上下文。
- **固化**：压缩前把关键状态写入项目记忆的动作。
- **折叠**：把长工具输出缩成头尾摘要 + 文件指针，原文仍可回读。
- **项目记忆**：放在项目文件夹里的要点记录，跨会话保留，是唯一长期可写状态。
- **每轮视图**：本轮真正注入上下文的那部分内容，由记忆和对话派生。
- **策略**：用户配置的规则，决定何时、对什么、做到什么程度。
- **判据**：判断对错的规则或依据，例如“入库前先确认上级目录不是剧集”；落成记忆条目后可被引用和检查。
- **回滚点**：能撤销一次变更的证据或映射，例如改名映射表、备份路径；属于受保护内容。
- **定时唤醒**：由调度在约定时间触发的会话启动；插件只读记忆摘要，不自己建调度。
- **全局偏好**：可选的、很小的跨项目偏好文件；默认关闭，只放偏好与教训，不是全局记忆库。
