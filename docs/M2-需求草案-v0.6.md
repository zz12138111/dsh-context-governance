> 状态：草案 v0.6，供评审复核；v0.5 → v0.6 变更见 §12。
> 日期：2026-10-25
> 依据：架构 v1.0 §6/§8/§14；DSH asar 只读调研；外部评审四轮意见。
> **范围**：**“推迟（抑制）”不纳入 M2**；仅保留说明与可行性记录（附录 A）。

---

## 0. 一页摘要

**M2 只做一条主线：提前压缩，省上下文、去掉过时信息，并把账算清楚。**

- `compact.at` 的语义是**真实占窗口比例**（用户视角），我们负责用安全系数把估算校正回来；
- **提前压**：到点后于安全时机主动调一次 `compactNow`；
- **不抢宿主**：宿主原生点（≈67.85%）之前动手，一到原生点立刻让路；
- **可关闭**：`compact.early=false` 的会话（如 `research`）完全交给宿主，仍保留记忆与回注；
- **账本**：每次压缩与决策留痕，收益估算必须带假设行。

**不做**：不造引擎、不换摘要后端、不接管 provider、**不包装宿主决策点**、不做 UI 仪表盘、不做货币成本。

---

## 1. 背景与关键事实

- 引擎在 agent preset 内：`thresholdRatio 0.8` + `headroomTokens 65536`；
  `native = floor(min(W×0.8, W−O−65536))`，1M 窗口/256k 预留下 ≈ **678k ≈ 67.85%**。
- preset 平面任何 patch 层都够不到。
- 取引擎唯一路径：`agentPresets.serviceFor(agent, 'compaction')`。
- 引擎契约：`compactIfNeeded` / `compactNow` / `compactRegion`。
- `tokenMeter` = chars/4 估算，本例低估约 28%；`usage` 是实测，滞后一步。

---

## 2. 目标（可验收）

1. **提前压可用且默认开**：真实压力到 `compact.at` 时安全时机压一次。
2. **不抢宿主**：`effective` 到达 native 时一律让路。
3. **可关闭**：`compact.early=false` 时不干预，交由宿主原生压缩。
4. **每层可配**：内置 / 插件配置 / 项目 `.cg-policy.json` / 会话覆盖。
5. **可解释**：`/cg status` 同时显示实测、估算、校正、生效四值压力与误差比值。
6. **可审计**：每次判断、压缩、跳过、放弃、失败都有记录。
7. **成本可见**：按会话/项目/天/模型聚合；收益估算必须显示假设行。
8. **与记忆协作**：显式 profile；偏好只作默认值（`active` 才生效）。

## 3. 非目标

- **不做推迟/抑制**（不包装 `compactIfNeeded`）；
- 不造引擎、不换摘要后端、不接管 provider、不改 preset 平面；
- 不做 UI 图表、不做货币成本、不做跨机同步；
- 不改 pruner / 折叠 / spill；不做行为推断自动打标。

## 4. 组成

### 4.1 策略层（0.2.0）

四层：内置 → 插件配置（`cordis.patch.yml`）→ 项目 `<project>/.cg-policy.json` → 会话 `/cg set`。

| 参数 | 含义 | 默认 | 范围 | 可 `/cg set` |
|---|---|---|---|---|
| `compact.at` | **真实**占窗口比例到多少就压 | `0.60` | `0.20` ~ dynamic native | 是 |
| `compact.early` | 是否提前压 | `true` | bool | 是 |
| `compact.cooldownMin` | 两次压缩最小间隔 | `10` 分钟 | ≥1 | 是 |
| `compact.minDeltaTokens` | 距上次压缩至少新增 token | `20000` | ≥0 | 是 |
| `compact.estimateSafety` | 估算放大系数 | `1.35` | `1.0–1.6` | **否**（仅配置文件） |
| `compact.lowThresholdAck` | 允许 `<0.30` | `false` | bool | 否 |
| `reinject.maxChars` / `maxLines` | 回注预算（既有） | 800 / 8 | 既有 | 是 |

- **语义**：`compact.at` 指**真实占用**，不是估算值；判定用 `effective`（见 4.2）。
- **动态上限**：`compact.at > native` 时拒绝，提示“超过宿主原生触发点，M2 不支持推迟”。
- **关闭方式**：`compact.early=false` —— 不参与提前压，宿主照常在 native 点压；记忆/保护/回注仍然工作。
- **专家项不拦截**：`estimateSafety` 只从配置文件读，用配置注释提示风险，不做逻辑拦截：

```yaml
# 专家选项：估算放大系数，默认 1.35。
# 若该模型 chars/token 估算精准，可下调至 1.0（会更晚触发）。
# 若模型估算偏低而调低系数，可能导致「永远不触发」，本插件不为此负责。
- id: dsh-context-governance
  config:
    compact.estimateSafety: 1.35
```

### 4.2 提前压（0.2.1，核心）

**取引擎**：`agentPresets.serviceFor(agent, 'compaction')`；拿不到 → `early=unavailable`，其余照常。

**压力口径**

```
measured  = 上一次 assistant/message 的 usage 比例（滞后，准）
estimated = tokenMeter.measure() 的估算比例（即时，偏低）
adjusted  = estimated × estimateSafety
effective = max(measured, adjusted)
```

**触发条件（全部满足才调 `compactNow`）**

1. `compact.early=true`；
2. `effective ≥ compact.at`；
3. `effective < native − 余量(0.02)`（**宿主优先**）；
4. 当前无进行中的压缩（`compaction/start` 未配 `end`）；
5. 距上次压缩结束 > `cooldownMin` 且新增 ≥ `minDeltaTokens`；
6. 处于安全时机（如 `turn/end`）。

**调用后复检**

- 返回“宿主已完成/已在进行”类失败 → 静默放弃，记 `early-aborted(host-compacted)`，不重试、不报错；
- 其他失败 → 指数退避最多 3 次，仍失败记 `early-failed`，不影响会话；
- 成功 → 更新“上次压缩时间”。

**审计**：`early-decision`、`early-forced`、`early-skipped(reason)`、`early-aborted(host-compacted)`、`early-failed`。

**硬约束**

1. 不在宿主调用链上：失败只是“没提前压”，宿主仍在 native 点压。
2. 绝不打断正在进行的工具调用或模型流。
3. 长 turn 内不检查；审计记 `early-skipped(turn-in-progress)`。

### 4.3 成本账本（0.2.2）

- 数据源：`compaction-cost`（`cost-v1.2`）+ `early-*` 审计。
- 聚合：`sessionId` / `project` / `day` / `model` / `backend`。
- 预算：只提示（`budget.warnAt`），不阻断。
- 口径：`usage` = measured；`tokenMeter×safety` = estimate；不混算；未知保持 unknown。

**`/cg cost` 收益输出格式（假设行必须在最上面）**

```
Estimated Benefit (Rough Assumption)
  Based on 12 remaining turns (session average).
  Tokens Saved: +14,500  |  Summary Cost: -3,100  |  Net: +11,400
```

- 始终先打印假设行，再给数字；数字全部标注 `estimated`；
- “预计剩余请求数”按本会话历史平均每轮请求数估，可配置覆盖；
- 不作计费依据。

### 4.4 表面与命令

```
/cg status
  policy: compact.at=0.60 (source=project)
    chain: builtin 0.60 → profile(coding) 0.60 → project 0.58 → session 0.60
    native=0.6785  early=ready
  pressure: measured=0.583  estimated=0.412  adjusted=0.556(×1.35)  effective=0.583
            ratio measured/estimated≈1.41 → 系数 1.35 合理
  last-early: decision=forced at 2026-10-25T… (省 12k/请求，摘要花 3.1k)
  last-cost: before=… after=… pruned=… tools=…

/cg policy show          # 解释合成过程与每层来源
/cg set compact.at=0.55  # 会话覆盖
/cg compact now [--force]# 手动立即压；冷却期内需 --force（两步确认）
/cg cost [--by …]        # 账本（含假设行）
```

## 5. 会话特点与偏好

- **profile 显式打标**：`batch` / `coding` / `research` / `review`；不自动推断。
- 默认参数表：

| profile | compact.at | compact.early | 回注预算 | 说明 |
|---|---|---|---|---|
| `batch` | 0.45 | on | 400 / 4 行 | 长跑、重复内容多 |
| `coding` | 0.60 | on | 800 / 8 行 | 保代码上下文 |
| `research` | — | **off** | 1600 / 16 行 | **默认不提前压**，保留最多细节，交给宿主 |
| `review` | 0.55 | on | 800 / 8 行 | 结论导向 |

- **为什么 research 用 `early=false` 而不是 `compact.at=native`**：`native` 随窗口/输出预留变化，写死会漂移；`early=false` 是语义，换模型也成立。
- **偏好**：`type=preference` 且 `status=active` 才影响默认值；`proposed` 不生效。
- **合成顺序**：显式层（会话 > 项目 > 插件）> 标签层（profile/偏好）> 内置默认。
- **晚压的用户话术**：设 `compact.early=false`（或选 `research` profile）就是最好的“晚压策略”——宿主在 67.85% 自己压。

## 6. 安全机制

### 6.1 估算误差与安全系数

- `adjusted = estimated × 1.35` 用于逼近真实；
- **方向**：估算偏低 → 校正后触发位置正确；估算偏高 → **过早压**（安全但更贵）；
- **裸估算模式**（`estimateSafety=1.0`，专家项）：
  - 模型估算偏低 → **几乎不触发**（宿主先压，表现为“没生效”）；
  - 模型估算偏高 → 过早压；
  - `/cg status` 打黄牌：`⚠️ 裸估算模式（无安全系数）`；
- M2.1 固定全局系数；**M2.2 用账本 ratio 做按模型校准**。

### 6.2 冷却与相对增量

时间冷却 + 增量冷却双条件，避免阈值边缘反复压。

### 6.3 失败不影响宿主

取不到引擎、调用失败、退避耗尽，最多是“没提前压”；宿主仍在 native 点压。失败一律留审计。

### 6.4 忙与长 turn

只在安全时机（`turn/end` 等）检查；长 turn 内不检查、不打断；压力冲过 native 由宿主处理，记 `early-skipped(turn-in-progress)`。

### 6.5 为什么不包装宿主引擎

包装能实现“推迟”，但风险高（进宿主决策链、双闸门冲突）。本期不做；未来单独立项。

## 8. 验收标准（草案）

1. **提前压生效**：`effective` 到 `compact.at` 时压一次；`early-forced` 审计；事件流完整。
2. **不抢宿主**：`effective ≥ native−余量` 时不主动压（`early-skipped(above-native)`）。
3. **可关闭**：`compact.early=false` 时完全不干预，`/cg status` 显示 `early=off(profile=research)`。
4. **失败不伤宿主**：模拟抛错 → 会话继续，宿主仍能压，`early-failed` 有记录。
5. **宿主已压**：模拟“调用后宿主已完成” → 静默 `early-aborted(host-compacted)`。
6. **防抖**：cooldown + minDelta 双条件生效。
7. **长 turn**：不检查、不打断。
8. **手动压两步**：冷却期内无 `--force` 返回提示；带 `--force` 执行并审计。
9. **参数约束**：`compact.at > native` 被拒绝并说明。
10. **可解释**：`/cg status` 打印四段压力 + ratio + 合成链 + native。
11. **账本**：假设行在最上面；两个实测数 + `estimated` 标注。
12. **记忆协作**：`proposed` 偏好不生效。
13. **不回归**：M1 的 S1–S6 通过；生产代码无折叠、无引擎包装。

## 附录 A：“推迟”的能力说明与代码可行性（不纳入 M2）

保留记录，**不实现、不测试、不验收**。

- **原理**：包装 preset 作用域引擎的 `compactIfNeeded`，压力低于策略点时返回 `null`，到点再调用原方法。
- **可行性**：方法可包装；第三方 dsh-compact 已验证该路径。
- **为什么不做**：
  1. 可用区间极窄（1M/256k 下 native 678k、硬上限 744k，仅约 6.6 个点）；
  2. 风险高（进宿主决策链、双闸门冲突、失败可能堵死压缩）；
  3. 与“省上下文”目标相反（推迟增加每请求成本）。
- **未来**：单独立项，三环境隔离实验后再谈。
