## 2. 架构：RootGuardPool（每根 guard）

### 2.1 现状与改造点

- P1/P2：`index.startRuntime` 建**一个** `CompressionGuard`（store/audit/projectRoot/scope 固定主根）+ 一个 `wireEarlyCompaction` + 一个 `registerMemoryHeader`。P2 的 `RootStorePool` 只服务 `mem_*`。
- P3：把 guard/header/early 的 store/audit/policy/window 全部按 `rootId` 路由；**每个可判定根一个 guard**，共享 P2 store pool（但 guard 持有 pin，TTL 不得关）。
- 会话根仍由 `RootRegistry.resolveSessionRoot` 唯一判定（configRoot 强制合并；pin 稳定）；P3 不写第二套根判定。

### 2.2 组件

```js
// src/compress/root-guards.js（新）
RootGuardPool {
  #guards = new Map();        // rootId -> { guard, entry, storeHandle, header, policy, lastUsed }
  #subscription = null;       // 单一 session/event 订阅（路由，不是每 guard 各订一份）
  start()                     // ctx.on('session/event', route)；全局仅一份
  route(session, event)       // try/catch 按根隔离：resolve -> entry -> guard -> guard.handleEvent
                              // 任一 guard 抛错只写 root audit root-guard-error，不阻断其他根
  getOrCreateGuard(entry)     // storePool.pin(entry) + new CompressionGuard({store, audit, projectRoot, policy...})
  guardForSession(session)    // 给 early/header/status 用
  closeAll()                  // 先停全局订阅；逐 guard dispose；unpin；错误按根隔离
}
```

- **路由隔离**：`route` 内每根 `try/catch`；某根 guard 构造/处理抛错只记 `root-guard-error`（root audit）+ logger，**继续处理/不影响其他根**；不得让单根异常冒泡到宿主订阅。
- **guard.dispose(reason)**：从路由移除该根 → 清该根 early 的 timer/cooldown/pending cycle → 对未完成 cycle 写 `cycle-abandoned`/`interrupted`（该根 audit；accepted 未确认的标 `unknown`）→ 按 §4.3 将未关联 journal 转 `orphaned/unknown`（**不 discard**）→ unpin store → 标记 closed；**只回收对象不算 dispose**。
- **全局订阅一份**：`RootGuardPool` 持有唯一 `session/event` 订阅；guard 自身**不再各自订阅**（P1 `guard.start()` 的订阅在 P3 改为由 pool 路由）。`closeAll` 先解除订阅，再逐根 dispose，避免关闭中仍收事件。
- **每根 guard**：`CompressionGuard` 增加 `handleEvent(session,event)`（公开现有 `#handle` 的路由入口）与 `setPolicyResolver`/`setWindow` 按根；guard 的 `projectRoot/project` 来自 entry，不读全局 config。
- **store pin**：`RootStorePool` 增加 `pin(entry)`/`unpin(entry)`：guard 生命周期内 `refs+1`，TTL 不关；guard idle 超时或 closeAll 时 unpin。P2 `mem_*` 的 per-call ref 不变。
- **guard 生命周期**：懒创建（首个该根会话事件）；idle 超时（默认 30min，无事件、无 pending cycle）close guard + unpin；closeAll 统一；根数超阈值只告警（与 P2 一致，不硬拒）。
- **无根/未知 cwd**：不建 guard、不观测、不审计（3A）；root watcher 保留。
- **fail-closed 根**：不建 guard；已有 guard 收到根状态 fail-closed → 关闭 guard、停止 early；`mem_*` 继续按 P2 拒绝。

### 2.3 每根 policy / window

- 每根独立 `buildPolicyState(configForRoot)`：`<root>/.cg-policy.json`、profile 标签、插件层、会话 `/cg set`（session 所属根）。`policyState` 按 `rootId` 存放；命令侧解析 `session → root → policy`。
- 每根 `#lastSession`/`request/context.contextWindow` 独立（需求 `:470`）：A 的窗口不喂 B 的 `native`。
- `/cg status` 显示本会话根 + 该根 policy/window/lastCost；`/cg roots` 仍列全部根（P1/P2 已有）。
- `compact.early.armed`/`compact.early` 按根/会话；A disarm 不影响 B。
- 项目层 `.cg-policy.json` 按根读取；不可读/非法 → 该根回退，审计 `policy-invalid`。

#### 2.3.1 项目层读取时机 / per-root invalid 归因（评审点 5）

- **读取时机**：懒——该根**首个可判定会话事件创建 guard 时**读一次 `<root>/.cg-policy.json`；不在 apply 扫描磁盘、不按会话反复读；运行中文件变更**不热加载**（与现有“策略链 attach 时算”一致；需重启/重建 guard 才生效）。
- **读取对象**：只读该根文件；A/B 各读各；文件缺失 = 项目层空（不审计 invalid）；读失败/>64KB/路径逃逸/整层被拒 = 该层整层拒绝、回退下一层，**归因该根**。
- **invalid 归因**：`policy-invalid` 写**该根 per-root audit**，字段 `root`/`rootId`/`source=project`/`key`/`reason`/`path`；**绝不写别根**；`/cg status` 的 `policy-invalid:` 行按本会话根显示；窗口/会话层 invalid 也带 `rootId`。
- **隔离**：每根 `policyState` 独立；A 的项目层/窗口/`/cg set` 不影响 B；`profile` 标签与 `/cg set` 仍按会话，生效值按会话所属根。
- **只读**：读项目层不改/不建/不删项目文件。

### 2.4 header

- 每个根一个 header 构建器（读该根 store）；`registerMemoryHeader` 或新 router 在**首个会话事件**按 `rootId` 注入该根记忆，并写该根 audit `header-injected`。
- 子会话：不注入（`isSubagent`），不写记忆；根继承父根。
- 同一会话只注入一次（现有 first-step 语义保持）。
- A 根 header 不得读 B store；header 文本不含跨根条目。

## 3. 四件套按根（write → materialized → reinjection → cost）

| 阶段 | 触发 | 写入/落点 | 审计 |
|---|---|---|---|
| **write** | **early**：`turn/end` 调 `compactNow` **之前**的 `preProtect` **预写**；**host-native**：`compaction/start` | 该根 `MemoryStore.protectSync` → `<root>/memory/governance/protection/<cycle>.json` | 该根 audit `protection-write`（`phase=early-prewrite`/`start`）/ failed |
| **materialized** | start 后 microtask（现有） | 该根 store `materializeProtection` → 该根 `topics/` + `MEMORY.md` | 该根 audit `protection-materialized` / failed |
| **reinjection** | `compaction/end` 后 microtask | 该根 guard 生成指针，`session.append` 回注到本会话；不跨根 | 该根 audit `reinjection` / `skipped` / `failed` |
| **cost** | 周期 end / start 补偿 | 该根 audit `compaction-cost`/`loss`；该根 guard `lastCost` | 同根审计；`rootId`/`project` 展示 |

**early 预写/复用**：`preProtect(session)` 在 `compactNow` 前生成 cycleKey、快照并写 journal；`compactNow` accepted 后 journal **保留**并标 `pending-unknown`；`compaction/start`（含超时迟到）到达才按会话/cycleKey 复用并关联 compactionId，**不重新快照**；预写失败 → 不 early；start 未到/超时只告警，**不 discard**；仅 `compactNow` 明确失败/拒绝或宿主明确证明未压缩才 discard，session 结束仍无 start 转 `orphaned/unknown` 归档（§4.3）。

**硬保证**：
- 四个阶段全部使用**同一个** `entry`/`rootId`/store/audit；不允许“start 在 A、end 在 B”这种中途换根（session pin 已保证）。
- 每条 cost 行带 `rootId`；`project` 只展示（P2/需求 `:472`）。
- 测试：A/B 各跑一次压缩，A 的 protection/topics/audit/cost 只在 A；B 同理；A 动作不改 B 文件 hash/mtime。

## 4. B-1 不复现（硬约束）

### 4.1 定义

**B-1 = 我们的提前压被触发，但该会话根没有保护/回注/成本落点。** 不允许出现。

### 4.2 early 前置门禁（**含预写，按顺序**）

1. `registry.resolveSessionRoot` 有 active entry（有根）；
2. `RootGuardPool.guardFor(entry)` 存在且 store `status.writable === true`；
3. 该根 audit 可写；
4. 该根 policy `compact.early === true`、`compact.early.armed === true`（或会话 disarm 覆盖）；
5. `memoryRoot` containment 通过；
6. 既有条件：cooldown/minDelta/`effective < native−0.02`/无进行中压缩；
7. **`preProtect(session)` 预写成功**：快照非空、`store.protectSync(preCycleKey)` 返回成功、journal 在**该根** `<root>/memory/governance/protection/` 落盘、该根 audit `protection-write(phase=early-prewrite)`。

任一不满足（含第 7 条预写失败）→ **不调用 `compactNow`（断言 `compactNow=0`）**，写该根 `early-skipped`（reason：`no-root`/`read-only`/`guard-unavailable`/`protection-prewrite-failed`/`out-of-scope`），不把“跳过”渲染成压缩。

### 4.3 触发后的状态机

```
turn/end
  → 门禁 1–7 → preProtect 成功（journal 已在该根，状态 pending）
  → compactNow
     ├─ 明确失败/拒绝（未接受）→ early-failed/aborted；discardProtection(preCycleKey)
     │  （触发阶段可立即确认未压缩）；不 materialize
     └─ accepted（含“不确定宿主是否压缩”）→ 状态 pending-unknown，journal 保留
          → 宿主 compaction/start 到达（含超时后迟到）
             → 复用该 journal（关联 compactionId，不重新快照）
             → materialize → end → reinjection → cost（全部该根）
          → start 未到/超时
             → 状态 unknown；只告警 + audit early-start-timeout
             → **不 discard、不 materialize、不回注、不声明 protected/成功**
             → 同一 session 的下一次 compaction/start 仍优先复用该 journal
          → 直到 start 到达完成，或宿主明确证明未压缩（明确 compaction=skipped
            或未压缩回执），才 discardProtection
          → session 结束/dispose 仍无 start：转 orphaned/unknown 归档，不 discard、
            不补写 protected（终态归档不是“未压缩”结论）
```

**时间窗规则（B-1 关键）**：
- start 等待阈值 `startWaitMs`（P3 新增，默认 120s，测试可注入；**只影响告警/状态从 `pending` 转 `unknown`，不影响 journal 保留**）。
- `accepted` 之后**不得**因 start 未到、超时或疑似 abort 而删 journal；超时只把状态从 `pending` 变为 `unknown`，journal 原位保留并标 `unknown`。这样“宿主已压缩但 start 迟到”仍能复用预写保护，不会因先删 journal 退化成无保护。
- `compactNow` 明确失败/拒绝（未接受）或宿主明确 `compaction=skipped` 是**唯一**可立即 `discardProtection` 的“确认宿主未压缩”证据；`accepted` 本身不等于已压缩，也不等于未压缩，只能保留。
- 一个 session 同时最多一个 pending journal，pending 期间门禁 6 的“无进行中压缩”视为占用，不发起新的 early；下一次 start 到达时复用该 journal（迟到 start 或下一轮压缩都先保护），完成后清 pending，再允许新 early。
- session 结束/dispose 仍无 start：写 `early-start-missing`（`protection=unknown`、`materialized=false`），journal 转 `<root>/memory/governance/protection/orphaned/` 并标 `unknown`，**不 materialize、不回注、不写 `protected`/`reinjected`/成功 cost**；归档是终态清理，**不是**“宿主未压缩”证据，不得调用 `discardProtection` 冒充确认。orphaned 的 TTL/GC 放 P4，删除时审计 `protection-orphan-gc(reason=ttl)`。
- 若宿主实际压缩而 start 从未出现，这是宿主事件缺口，需在 P4 文档/审计中如实披露为 `unconfirmed`，不冒充已回注。

- **保护先于压缩**：early 路径的 protection 在 `compactNow` 前已落盘；若宿主随后实际压缩，保护已存在，不出现“有压缩无保护”。
- 预写后 `compactNow` 失败但宿主仍自行压缩（竞态）：因失败路径可能已 discard，start 到达时按 host-native 路径重新 start-time protection，失败则**显式降级**（§4.4），不算我们 early 成功；若 journal 尚未 discard（accepted/unknown），优先复用。
- 预写失败 → **不 early**；若宿主原生压缩仍发生（非我们触发），按 §4.4 显式降级/披露，不冒充 P3 全覆盖。
- 本进程内 `earlyDisabled[rootId]` 熔断只在预写失败/保护失败后置位；恢复需下一次成功 protection/store 探测；熔断期间 `early-skipped(b1-fused)`。

### 4.4 宿主原生压缩在只读根（如实披露）

- 宿主原生压缩**不受我们控制**；根 store 只读/fail-closed 时无法写 protection journal，只能：
  - 该根 audit 记 `compaction-cost`/`loss`（能取到就记，取不到 null+unknown），带 `protection=unavailable`；
  - 写 `protection-skip(reason=read-only/guard-unavailable)` + `b1-host-native-unprotected` **诊断**；
  - `/cg status` 显示该根 `protection=unavailable`、`early=fused/off`。
- **不得写成“P3 已全覆盖/所有压缩都有保护”**；P3 只保证**我们触发的 early 不会在不可保护时发生**，宿主原生只读场景显式降级并披露（P4 Release/文档同步）。
- 测试负向：只读根上模拟 host-native 压缩 → cost/审计存在、`protection=unavailable`、**`compactNow=0`**；不得显示 protection=ok。

## 5. 子会话（P3 细则）

- 根：父根已知 → 继承（P1 已有）；父根未知 → 自身 cwd；否则 3A。
- 压缩/保护/回注/审计：按父根 guard **照常**；四件套落父根。
- **不写持久记忆**：`mem_write` 拒绝（P2）；header 不注入。
- **保护 journal 不 materialize 成持久记忆**：P3 给 `MemoryStore` 增加 `discardProtection(cycleKey)`（或 materialize 时按 `subagent` 跳过并删除 journal）；周期结束/回注后清理，避免 topics/MEMORY.md 出现子会话标题。
- 子会话 cost 行带 `subagent:true`，账本可分列；不冒充父会话条目。
- 测试：子会话压缩有 protection/reinjection/cost；父根 topics 不新增子会话标题；header 无。

## 6. 生命周期/并发（继承 P2 池）

- guard 每根懒创建；store pin 防 TTL；guard idle 30min 或 closeAll 关闭；**dispose 必须停掉该根 early timer/pending cycle 并解除路由**，不能只回收对象；每根 writer lock 不变；同根两进程仍只读/锁提示。
- 根状态 fail-closed/state 删除：关闭该 guard、unpin、停止 early；pending journal 按 §4.3 转 `orphaned/unknown` 归档，不冒充未压缩；旧记忆不迁移。
- `RootGuardPool.closeAll` 先清全局 subscription，再逐 guard dispose（清 timer/pending、未确认 journal 转 `orphaned/unknown` 不 discard、unpin）；timer `unref`；单根 dispose 失败只 logger/root audit，继续其他根。
- 只有**一份** `session/event` 订阅；`route` 按根 try/catch，**A 根 guard 抛错不得卡 B 根**。
- 不同根 guard 独立；A 的 pending cycle 不影响 B；共享 store pool 的打开上限只告警。
- `/cg status` 的 `stores:` 加 guard 数/early 熔断数（可选）。

## 10. 需要评审拍板/确认

1. **每根 guard 实例**（推荐）vs 单 guard 多根上下文——是否接受每根实例（状态简单、隔离强，内存/探测成本按根）。
2. **store pin/idle 关闭**：guard 生命周期内 pin；idle 30min/closeAll unpin——阈值是否接受。
3. **B-1 门禁**：early 前 `preProtect` **预写** journal（不是 start 才写），预写失败断言 `compactNow=0`；start 复用 journal；**`accepted` 后 journal 保留并标 `unknown`，超时只告警不删，仅 `compactNow` 明确失败/拒绝或宿主明确证明未压缩才 discard；start 永不出现则终态转 `orphaned/unknown` 归档、不得写 protected**；宿主原生只读显式 `protection=unavailable` 披露——确认。
4. **header 路由**：按根 store/首会话单次；子会话不注入——确认。
5. **子会话保护 journal 不 materialize**：`discardProtection` 位置/审计（P3 实现细节）。
6. **每根 policy/window**：每根 `buildPolicyState`、`#lastSession` 分桶；项目层按根——确认。
7. **P3 测试量**（~24，含 B2c/B2d 时间窗两条）与 pack 数字；P3 不安装/不发布/不宣称闭环——确认。
8. **旧数据**：P3 只读既有记忆/审计，不迁移；根变化旧数据留原路径——确认。
9. **项目层读取/归因**：guard 创建时读一次（不热加载）、`policy-invalid` 落该根 per-root audit 且带 `rootId/path`、A 不影响 B——确认。
10. **路由隔离**：全局单订阅 + 按根 try/catch（A 抛错不卡 B）——确认。
11. **dispose/closeAll**：停该根 early timer/pending cycle、abort 审计、解除路由、unpin；closeAll 先停订阅——确认。
