## 2. 三道实现门禁

1. **`startWaitMs` 定时器 `unref` + 清理**
   - `CompressionGuard.#schedule` 默认 `setTimeout`，`markEarlyAccepted` 后调用 `timer.unref()`；`dispose()` 清 timer 并归档 pending journal。
   - `RootGuardPool.closeAll` 先停根路由订阅，再逐根 `dispose`；`dispose` 调 early `stop` + guard `dispose`。
   - 测试：`test/p3-early-window.test.mjs` B2e（dispose 后 0 次超时触发）。
2. **B2c / B2d**
   - B2c：超时后 journal 仍 pending；迟到 start 复用，`compactNow` 仅 1 次；`protection-write` 仅 1 条（phase=early-prewrite）。
   - B2d：start 永不出现；终态归档 `protection/orphaned/`，`protection=unknown`，无 `protection=ok`/回注/成功 cost。
   - 另：B2f 预写失败断言 `compactNow=0`；B1 只读根 `early-skipped(read-only)`。
3. **orphan**
   - `MemoryStore.archiveProtection` 只移动到 `protection/orphaned/` 并标 `unknown`；P3 不做 TTL/GC（P4）。
   - 只有明确失败/拒绝或宿主明确未压缩才 `discardProtection`；`dispose`/`closeAll` 不 discard。

## 3. 生产接线

- `index.js`：`RootRegistry.load({ manageAllRoots: true })`；**根已知路径**由 `RootGuardPool` 持有唯一 `session/event` 订阅；主根 guard 先建，其他根首个会话事件懒建。
- **旧 `early-wiring.js` 独立订阅已移除**：index 传 `subscribe:false`，`turn/end` 由 pool 路由到该根 early；`compress-integration` 断言根已知路径只有 1 个 `session/event` 订阅。
- **无根启动例外（验收口径见 §3.1）**：apply 时根未知，pool 尚未建立；`firstInferenceRootWatcher` 另挂一份 `session/event`，只负责首个 cwd → 根推断。根确定后它立即退订并进入 `startRuntime` 的 `RootGuardPool`；因此订阅口径是：**guard 路由由 pool 承担；无根 bootstrap 期间另有 1 份职责不同的首推 watcher，根确定后消失**。
- 每根 `CompressionGuard`：该根 store/audit/projectRoot/policy/window；`preProtect` 在 `compactNow` 前写 journal。
- `header`：`registerMemoryHeader` 的 `resolveStore/getHasRuleFile/onInjected` 按会话根路由；子会话不注入、不写持久记忆。
- `/cg status`/`/cg set`/`/cg compact`：按会话根取 policy/store/guard/audit。
- 子会话（G8）：保护 journal 只供本周期回注；`#materializeProtection` 跳过并审计 `protection-materialize-skipped(subagent)`，end 后 discard，不写 topics/MEMORY.md。

### 3.1 订阅验收口径（B：两份、职责不同）

P3 生产存在**两份** `session/event` 订阅，边界如下，**不得再写成“生产只有 1 份”**：

| 订阅 | 位置 | 触发条件 | 职责 | 退订/生命周期 |
|---|---|---|---|---|
| `firstInferenceRootWatcher` | `src/index.js:1325` | 仅 apply 时 `rootInfo.root === null`（no-root bootstrap） | 读首个 cwd → `inferRootFromCwd`/`claimPrimary`；写 root-state 与 root audit；**不建 guard/store、不做 protection/回注/成本、不写 per-root 记忆** | 首次推断成功后、进入 `startRuntime` 前立即 `watcherDispose()`，之后不再存在 |
| `RootGuardPool` | `src/compress/root-guards.js` | 根已知的 `startRuntime` 路径 | 常规路由：每根 guard、四件套、header 由独立 `agent/pre-step` 负责；`early` 由 pool 的 `turn/end` 路由，**不另挂订阅** | `closeAll` 先停订阅再逐根 dispose；root 未知时不创建 |

**为何不冲突（验收断言）**：

1. **触发条件互斥**：`firstInferenceRootWatcher` 只在 `rootInfo.root === null` 时工作；root 一旦非空，`attachFirst` 直接 return，且订阅在进入 `startRuntime` 前已退订。
2. **职责不重叠**：首推 watcher 不调用 `CompressionGuard`、不写 protection journal、不写 per-root audit/记忆；pool 不参与首推 cwd 推断。
3. **旧 early 订阅为 0**：`wireEarlyCompaction` 在 index 全部传 `subscribe:false`，`turn/end` 仅走 pool；不得再出现第三份。
4. **计数口径**：
   - root 已知 apply → `session/event` 恰 **1**（pool）；
   - root 未知 apply → 恰 **1**（firstInference watcher），推断完成后变 **0**，`startRuntime` 建立 pool 后变 **1**（不是同时 2）；
   - 任意时刻 `firstInferenceRootWatcher` 与 `RootGuardPool` **不同时活跃**。
