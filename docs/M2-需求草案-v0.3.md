## 0. 一页摘要

**M2 的核心目的：让“什么时候压缩”可控，并且把压缩前后的账算清楚。**

用户原始诉求：**提前压缩，省上下文、去掉过时信息**。因此：

- **提前压是主路径，默认开启**（`compact.at=0.60`，比宿主原生 ≈0.6785 早约 8 个点）；
- **推迟**是配套能力；
- **成本账本**回答“提前压值不值”；
- 所有机制带兜底：估算放大、双冷却、异常透传、fail-open、忙时顺延。

**不做**：不造引擎、不换摘要后端、不接管 provider、不做 UI 仪表盘、不做货币成本。

---

## 1. 背景与关键事实

### 1.1 DSH 原生机制

- 引擎在 **agent preset** 内：`thresholdRatio: 0.8` + `headroomTokens: 65536`；
  有效触发点 = `floor(min(W×0.8, W−O−65536))`，1M 窗口 ≈ **67.85%**。
- **preset 平面任何 patch 层都够不到**。
- 取引擎唯一路径：`agentPresets.serviceFor(agent, 'compaction')`。
- 引擎契约：`compactIfNeeded` / `compactNow` / `compactRegion`；手动 `/compact` 即 `compactNow`。
- 宿主压力检查在 **`pre-step`**（两步之间）执行——这是“允许压缩”的时机。

### 1.2 生态

| 插件 | 角色 | 与 M2 关系 |
|---|---|---|
| `compaction-basic` | 原生引擎 | 包其决策点，不改引擎 |
| `context-zip` | 替换摘要 | 不动；闸门同样生效 |
| `tool-result-pruner` | 压缩点折叠大工具结果 | 不动 |
| `dsh-context` | 上下文/成本可视化 | 不重复做图表；我们做策略效果账本 |
| `dsh-compact` | 第三方闸门 | **本期不装、不验**；共存按保守策略处理 |

### 1.3 本机实测

- 本插件 scope 拿不到 `ctx.compaction`（`strict=false → undefined`）；
- `tokenMeter` = chars/4 估算，本例**低估约 28%**；
- `usage`（`assistant/message`）= 实测，滞后一步；
- 手动 `/zip-compact` 不触发 `pruneSession`。

## 2. 目标（可验收）

1. **提前压可用且默认开**：`compact.at` 低于宿主原生点时，按策略主动压一次。
2. **推迟可用**：`compact.at` 高于原生点时，抑制到策略点再放行。
3. **每层可配**：内置 / 插件配置 / 项目 `/project/.cg-policy.json` / 会话覆盖。
4. **可解释**：`/cg status` 打印合成链、宿主原生点、闸门状态、最近决策。
5. **可审计**：每次判断、主动压、跳过、失败都有记录。
6. **成本可见**：按会话/项目/天/模型聚合；实测与估算分列；能回答“提前压赚了多少”。
7. **与记忆协作**：显式 profile；偏好只作默认值（`active` 才生效）。

## 3. 非目标

- 不造引擎、不换摘要后端、不接管 provider、不改 preset 平面；
- 不做 UI 图表、不做货币成本、不做跨机同步；
- 不改 pruner / 折叠 / spill；
- 不做行为推断自动打标。

## 4. 组成

### 4.1 策略层（0.2.0）

四层：内置 → 插件配置（`cordis.patch.yml`）→ 项目 `<project>/.cg-policy.json` → 会话 `/cg set`。

| 参数 | 含义 | 默认 | 范围 |
|---|---|---|---|
| `compact.at` | 到多少压力就压 | `0.60` | `0.30–0.85`（`0.20–0.30` 需 `lowThresholdAck`） |
| `compact.early` | 允许主动提前压 | **`true`** | bool |
| `compact.cooldownMin` | 两次压缩最小间隔 | `10` | 分钟 |
| `compact.minDeltaTokens` | 距上次压缩至少新增 token | `20000` | token |
| `compact.estimateSafety` | 估算放大系数 | `1.35` | `1.0–1.6` |
| `compact.lowThresholdAck` | 允许 `compact.at < 0.30` | `false` | bool |
| `gate.force` | 检测到已包装时仍强开闸门 | `false` | **危险，见 §6.5** |
| `reinject.maxChars` / `maxLines` | 回注预算（既有） | 800 / 8 | 既有 |

- 校验：白名单键；未知键或越界 → 拒绝该层 + `policy-invalid` 审计，退回上一层。
- 解释：`/cg status` / `/cg policy show` 打印合成链。

### 4.2 闸门层（0.2.1）

**取引擎**：`agentPresets.serviceFor(agent, 'compaction')`；拿不到 → 降级“只提示不拦截”，`gate=unavailable`。

**两条路径**

| 方向 | 机制 | 条件 |
|---|---|---|
| 推迟 | 包装 `compactIfNeeded`：压力 < `compact.at` 返回 `null` | `compact.at` > 原生点 |
| 提前压 | 压力 ≥ `compact.at` 且 < 原生点时调 `compactNow(agent, signal)` | `compact.early=true`（默认） |

**硬约束**

1. **Fail-open**：闸门自身异常 → **放行** + `gate-error` 审计；绝不由治理层堵死宿主压缩。
2. **异常透传**：溢出/上游错误**原样透传**，不吞、不改造。
3. **溢出救援永不放拦**：`trigger == context-overflow` 直接透传。
4. **`compactNow` 安全调用**（见 §6.4）：
   - 只在允许压缩的时机调用（宿主 `pre-step` 同一时机优先）；
   - 每次尝试失败走指数退避，最多 3 次，严禁重试风暴；
   - 不可用时记 `forced-skipped(reason)` 并顺延给宿主。
5. **共存保守**：包装时打 Symbol 标记（防重复自包）；检测到来源无法确认 → **禁用自身 + 告警**；仅当 `gate.force=true` 才强开（风险见 §6.5）。
6. **防抖**：`cooldownMin` 与 `minDeltaTokens` **双条件**同时满足才允许再次自动触发。

**审计**：`gate-decision`、`gate-forced`、`gate-error`、`forced-skipped`、`gate-force-enabled`。

### 4.3 成本账本（0.2.2）

- 数据源：`compaction-cost`（`cost-v1.2`）+ `gate-decision` / `gate-forced`。
- 聚合：`sessionId` / `project` / `day` / `model` / `backend`。
- 命令：`/cg cost [--by day|project|model] [--since …]`。
- 预算：只提示（`budget.warnAt`），不阻断。
- 口径：`usage` = measured；`tokenMeter×safety` = estimate；不混算；未知保持 unknown。

**提前压收益口径（评审回写后定稿）**

```
tokensSavedPerRequest = 压缩后首条请求 usage − 压缩前最后一条 usage   (measured)
summaryCost           = 本次压缩调用的 usage                          (measured)
benefitEstimate       = tokensSavedPerRequest × 预计剩余请求数 − summaryCost   (estimated，须标假设)
```

- 只给两个**实测数** + 一个**显式标注假设的估算**；
- 不给单一“这次省了 N token”的确定数（那是伪造）；
- 预计剩余请求数默认按“本会话历史平均每轮请求数”估，允许配置覆盖。

### 4.4 表面与命令

```
/cg status               # 策略链 + 原生点 + 闸门状态 + 最近决策 + last-cost
/cg policy show          # 解释当前生效来源与合成过程
/cg set compact.at=0.5   # 会话覆盖
/cg compact now [--force]# 手动立即压；冷却期内需 --force（两步确认）
/cg cost [--by …]        # 账本
```

## 6. 安全机制

### 6.1 估算误差（M2.1 静态）

```
pressure = max(上一次 usage 实测比例, 估算比例 × 1.35)
```

- 1.35 为全局值（28% 低估换算 ≈1.39，留余量）；
- **M2.2 再做自校准**：账本记录每次“同一时刻 usage vs 估算”的成对样本，积累后按模型取 p90；M2.1 不实现动态系数。

### 6.2 冷却与相对增量

时间冷却 + 增量冷却双条件，避免阈值边缘反复压。

### 6.3 溢出双保险

- 溢出触发 → 透传；
- 任何异常 → 透传原异常 + 审计。

### 6.4 忙时顺延（评审新增风险）

- 若 `compact.at` 已到、但 `compactNow` 因时机不可用（agent 忙）无法执行：
  **放弃提前压，顺延给宿主原生 `compactIfNeeded`**；
- 审计 `forced-skipped(busy)`；**不打断、不重试**；
- 若连续多个周期都 `forced-skipped`，`/cg status` 提示“提前压在忙会话中不可用，建议调低或依赖宿主”。

### 6.5 `gate.force` 风险（评审新增风险，用户拍板保留）

- 默认 `false`；检测到引擎来源无法确认时**默认禁用自身并告警**；
- `gate.force=true` 时：启动日志 **ERROR 级警告**、`/cg status` 红色标记、审计 `gate-force-enabled`；
- **文档必须写明**：强开等于在未验证路径上包装宿主引擎，可能出现压缩循环报错、死锁或上下文溢出；出问题先设回 `false`；
- 用户已知情并接受（开源早期产品，明确告知即可）。

## 8. 验收标准（草案）

1. **提前压生效**：`compact.at` < 原生点时，会话在策略点被主动压缩；`gate-forced` 审计；事件流完整。
2. **推迟生效**：`compact.at` > 原生点时，闸门抑制到策略点。
3. **Fail-open**：注入闸门异常 → 宿主仍能压缩，`gate-error` 有记录。
4. **溢出不拦**：溢出路径全程透传（测试/回放证明）。
5. **忙时顺延**：模拟 agent 忙 → `forced-skipped(busy)`，不打断、不重试。
6. **防抖**：cooldown + minDelta 双条件生效。
7. **手动压两步**：冷却期内无 `--force` 返回提示；带 `--force` 执行并审计。
8. **可解释**：`/cg status` 打印合成链、原生点、闸门状态。
9. **成本账本**：两个实测数 + 标注假设的估算；聚合 = 逐条求和。
10. **记忆协作**：`proposed` 偏好不生效。
11. **不回归**：M1 的 S1–S6 通过；生产代码仍无折叠。
