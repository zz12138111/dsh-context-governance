# T7 · 只读降级人工验证脚本（0.1.5）

> 目的：在真机上制造“记忆根不可写”，验证插件进入 `read-only`、压缩不被阻断、恢复后写入回来。
> 影响面：**只 deny 一个目录** `memory\governance`，不碰 profile、不重启、不改插件配置；步骤末尾有还原与 ACL 备份。
> 预计耗时：3–5 分钟；需要一次手动 `/compact`（或一次自动压缩）。

## 0. 前置

```powershell
$root = 'D:\DS-PROJECT\DSH插件开发\memory\governance'
$log  = 'D:\DS-PROJECT\DSH插件开发\logs\governance.log'
$acl  = "$env:TEMP\cg-memory-acl-$(Get-Date -Format yyyyMMdd-HHmmss).txt"

Test-Path $root          # True
Get-Content $log -Tail 3 # 应能看到 version=0.1.5 … perception=event
```

`/cg status` 先记一份基线：`compression: … mode=event-level`、`protection: … read-only=`（应为空）。

## 1. 备份 ACL（可回滚）

```powershell
icacls $root /save $acl /t
$acl   # 记住这个路径
```

## 2. 制造不可写（只限制写，不限制读）

```powershell
icacls $root /deny "${env:USERNAME}:(W)"
```

验证真的不可写（**预期失败**，报 `Access is denied` / `拒绝访问`）：

```powershell
New-Item "$root\.t7-write-probe" -ItemType File -ErrorAction Stop
```

> 若这里居然成功：说明账号有其它放行来源，删掉 probe 并改用 `/deny "${env:USERNAME}:(W,AD,DC)"` 再试一次；仍不行就停手报 00，不要动系统权限。

## 3. 触发一次压缩

在任一工作区会话里执行 `/compact`（手动压缩入口；context-zip 下也可用 `/zip-compact`）。
没有手动入口就等一次自动压缩（长会话压力触发）。

预期（**压缩本身照常完成**，摘要正常产生；只是治理层写不进）：

```text
[context-governance] memory read-only (root-not-writable:EACCES); protection writes and audit appends are suspended, compaction continues
```

`/cg status` 预期出现：

```text
protection: writes=0 writeFailures=0 … pendingJournals=0 reinjection=enabled read-only=root-not-writable:EACCES
audit-health: writeFailures=… skippedReadOnly=…
```

若写失败发生在 `protectSync` 而不是启动探测，原因会是 `write-failed:EACCES`，同样算通过。

## 4. 恢复写入

```powershell
icacls $root /remove:d "${env:USERNAME}"
New-Item "$root\.t7-write-probe" -ItemType File -ErrorAction Stop   # 现在应成功
Remove-Item "$root\.t7-write-probe" -Force
```

再触发一次压缩（`/compact`）。预期：

```text
[context-governance] memory root is writable again; read-only cleared
```

`/cg status` 的 `read-only=` 消失，`protection: writes=` 增加，`audit.jsonl` 恢复追加。

## 5. 收尾与回滚

```powershell
# 若第 4 步 restore 不干净，用备份恢复：
icacls "$root" /restore $acl
Get-Content $log -Tail 10 | Select-String 'read-only|writable again|protection-write'
```

留证据：

- `logs\governance.log` 里 `memory read-only (...)` 与 `read-only cleared` 两行；
- `/cg status` 前后截图/文本；
- 一次压缩周期的 `audit.jsonl` 行（只读期间应没有新 audit；恢复后恢复）。

## 6. 判定

| 观察点 | 通过判据 |
|---|---|
| 只读触发 | 日志出现 `memory read-only`，原因含 `root-not-writable` 或 `write-failed` |
| 压缩不阻断 | 该次压缩仍产生 summary/checkpoint/end，宿主无报错 |
| 不写记忆/审计 | 只读期间无新 `protection-write`；`audit.jsonl` 不增长（或只有失败计数） |
| 恢复 | ACL 还原后下一次压缩日志出现 `read-only cleared`，`read-only=` 消失且写入计数增加 |
| 回滚安全 | 最终 ACL 与步骤 1 备份一致；`.t7-write-probe` 不存在 |

> 注意：只读期间**不要**删 `memory\governance` 下任何文件；不要改 `cordis.patch.yml`；不要重启 DSH（恢复靠下一次压缩的探测）。
