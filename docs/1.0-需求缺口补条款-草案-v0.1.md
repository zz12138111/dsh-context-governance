## 1. 条款清单（6 条）

### R-SCOPE（归属 `REQ-09`；对应第 1 条「跨项目无保护无账」）

**现状缺什么**：需求只写了观测侧「`#lastSession`（最近观察到的**本项目**会话）」（`REQUIREMENTS.md:467`）；**触发作用域与保护作用域是否必须一致，没有任何条款**；「非本项目会话被压缩时是否必须保护/记账」零条款（`onlyProject` 在需求文档零出现）。

**建议条款原文**
> **R-SCOPE-1**：提前压的**触发作用域必须与保护/观测作用域一致**。对任一会话，若保护/观测不生效（例如不在 `projectRoot` 之下），提前压**必须 skip**，审计 `early-skipped(reason=foreign-session)`（审核提议名；`out-of-scope` 亦可，**最终枚举归审核**）；**不得存在"被压缩但无保护、无回注、无成本"的会话**。
>
> **R-SCOPE-2**：凡观测到真实压缩（含宿主原生压缩），成本账本必须有对应记录；取不到数值写 `null` 并标 `unknown`，**不得整行缺失**。

**影响**：`early-wiring` 触发前判定、`runtime` 观测/保护过滤与触发共用同一判定、成本账本覆盖面；测试需覆盖「外部会话 → skip 且不出现 `early-forced`」「成本行不缺失」。

**是否改变已发布行为**：**是**——外部会话将不再被插件提前压（宿主原生压缩仍可能发生，不在插件控制范围）。

### R-AUDIT（归属 `REQ-09`；对应第 2 条「无结果仍写 `committed`」）

**现状缺什么**：0.2.2 验收只要求「`early-forced` 审计、事件流完整」（`REQUIREMENTS.md:499`），**未定义 `committed` 的判定依据**；实现无 fresh report 也写 `committed`。

**建议条款原文**
> **R-AUDIT-1**：`early-forced.compaction` 只能取**本次触发**的事实结果，枚举 `committed` / `skipped` / `failed` / `unknown`；**无 fresh report 时必须写 `unknown`**，不得沿用上一轮报告、不得用默认值补位；`unknown` 不得被 `/cg status` 或账本渲染为成功。
>
> **R-AUDIT-2**：`early-forced` 与 `compaction-cost` 必须成对出现在同一触发周期内；只有前者时账本须显式标 `cost=missing`，不得静默。

**影响**：审计白名单与枚举、`/cg status` 渲染、账本聚合；测试需覆盖「无 fresh report → `unknown`」「失败事件不写 `committed`」。

**是否改变已发布行为**：**是**——审计值变化，旧的无依据 `committed` 不再出现。

### R-AT（归属 `REQ-09`；对应第 4/5 条「窗上界 + 空窗」）

**现状缺什么**：写了「上限 dynamic native」（`REQUIREMENTS.md:413`）与「`effective ≥ native−0.02` 不压」（`:398`），但**没写"接近 native 是否允许"、没写跨机器口径、没定义 `(native−0.02, native]` 空窗语义**。

**建议条款原文**
> **R-AT-1**：`compact.at` 的**有效上限 = `native − 0.02`**（不抢宿主余量）；任何层设 `at ≥ native − 0.02` 一律拒绝（`policy-invalid(reason=above-effective-window)`）。
>
> **R-AT-2**：`native` 动态变化；运行时生效值落入 `[native − 0.02, native]` 时该层**自动失效**并审计 `policy-invalid(reason=window-shrunk)`，**不得继续显示 `early=on`**。
>
> **R-AT-3**：`at` 语义是**真实占窗口比例**，跨机器/跨模型语义一致；但「可用触发窗宽度 = `native − 0.02 − at`」随窗口大小变化，**插件不保证跨机器同一触发点**；文档必须写明，并在 `/cg status` 给出当前窗宽。
>
> **R-AT-5（跨机器示例，写进文档）**：配置窗口 `native=0.6785` 时，`at=0.60` → 窗宽 `0.6785−0.02−0.60 = 0.0585`（5.85pp）；`at=0.65` → 窗宽 `0.0085`（0.85pp）；`at=0.66` 起 `<0` → 按 R-AT-1 拒绝。文档须以此为例说明"调高 at 等于收窄可用窗"。
>
> **R-AT-4**：`(native − 0.02, native]` **不是合法配置区间**（与 R-AT-1 同口径）；因 `native` 变化落入该区间时按 R-AT-2 失效并提示。

**影响**：`policy.js` 校验与运行时失效判定、`early-gate` near-native 判定对齐、`cg-status` 显示；测试把 0.65/0.66/0.67 从「永不触发」改为「被拒」。

**是否改变已发布行为**：**是**——收紧。已有配置若落在该区间，升级后会被拒或失效，需用户调整。

### R-PROFILE（归属 `REQ-09`；对应第 7 条「profile 全局单值」的入口问题）

**现状缺什么**：需求只说「profile 按会话打标」（`docs/M2-需求草案-v0.6.md:164-165`），**没有规定入口形态**（命令？会话元数据？配置键？）——批次 4 因此无法动工。

**建议条款原文**
> **R-PROFILE-1**：profile 必须**按会话隔离**——同一进程内 A 会话为 `research` 时，B 会话的 `coding` 不受影响；`/cg status` 必须显示**本会话**的 profile 与来源。
>
> **R-PROFILE-2（入口）**：**入口形态由实现定**（命令 / 会话元数据 / 配置键均可），需求只约束效果与可观测：设置后本会话立即生效、会话间互不影响、重启后可重建（或明示不持久）。
>
> **R-PROFILE-3（fail-safe）**：若宿主无法提供会话级标识，**必须如实报告"不满足"**，不得用进程级单值冒充"按会话打标"。

**影响**：`index.js:71`（现全局单值）与 profile 读取路径；`/cg status` 需带会话维度；测试覆盖「A 会话 research、B 会话 coding 并存」。

**是否改变已发布行为**：**是**（profile 从全局单值变为按会话；与第 6 条同一改造面）。

### R-INSTALL（归属 `REQ-12` + `REQ-09`；对应第 8 条「发布包写死 projectRoot」）

**现状缺什么**：安装后 `projectRoot` 如何解析、发布包能否带本机绝对路径，**需求零条款**；发布包现写死 `D:/DS-PROJECT/DSH插件开发`（`packages/dsh-context-governance/cordis.patch.yml`），换机器/换项目后所有会话都成"外部会话"→ 只压不护。

**建议条款原文**
> **R-INSTALL-1**：发布物（包、配置、文档、示例）**不得包含本机绝对路径**；`projectRoot` / `memoryRoot` / `logFile` 等在发布包中必须为空或相对值。
>
> **R-INSTALL-2**：`projectRoot` 未配置时，默认取**当前会话 cwd 所属项目根**（与"本项目"判定同源），不得回退到某个固定路径；配置相对路径时相对 `projectRoot` 解析。
>
> **R-INSTALL-3**：`/cg status` 必须显示当前生效的 `projectRoot` 与其来源（`default` / `config`）；安装文档必须写明「换机器/换项目时如何确认 `projectRoot`」。
>
> **R-INSTALL-4**：`projectRoot` 与会话 cwd 不匹配时，启动日志与 `/cg status` 必须显式提示（`scope=outside`），不得静默"只压不护"。
>
> **R-INSTALL-5（安装步骤要求）**：安装文档必须写明 `projectRoot` 的解析规则与默认值；发布包默认 `projectRoot` **为空**（= 按会话 cwd 自动判定），不得预填任何绝对路径；「项目根」定义为**含 `.git` 的最近祖先目录**（无 `.git` 时取 cwd 本身），且 `/cg status` 显示解析结果与来源。

**影响**：`cordis.patch.yml` 默认值、`index.js` 解析、`cg-status` 显示；`REQ-12` 干净包扫描需新增「无本机绝对路径」检查项；测试覆盖默认解析与不匹配提示。

**是否改变已发布行为**：**是**——发布包默认值与解析行为变化，本机安装需改配置。

### R-SESSION（归属 `REQ-09`；对应第 6 条「会话层实为进程级」+ 止损通道）

**现状缺什么**：需求原文写「只影响当前会话」（`docs/1.0-状态定义-v1.md:66`、`docs/review-1.0-发布口径-检查项.md:43,82`），但**未规定"会话标识不可得"时该怎么办**；开发查实生产环境 `invocation.sessionId = null`，可退通道可能压根没通。

**建议条款原文**
> **R-SESSION-1**：`/cg compact disarm` / `/cg set` 的**会话级**语义必须按会话标识生效（同一进程内互不影响）；这是「默认开 + 可退通道」交换条件的兑现（`docs/1.0-状态定义-v1.md:58`）。
>
> **R-SESSION-2（fail-safe）**：若运行环境拿不到会话标识，**不得退化为进程级并仍声称"已关闭本会话"**；必须如实报告"会话级不可用"（`/cg status` 可见 + 审计一行），并允许用户改用配置级/策略级关闭。
>
> **R-SESSION-3（优先级不变）**：会话命令 > 配置 > 内置默认；`compact.early=false`（策略总闸）始终优先、命令不可绕过（`TASKS/REQ-20261025-09-提前压启用-拆解.md:43`）。

**影响**：`index.js:290`（apply 建一次的对象）、`cg-status.js:394`（写同一对象）、命令上下文取 sessionId 的路径；测试覆盖「两会话并存、A disarm 不影响 B」与「无 sessionId → 明示不可用」。

**是否改变已发布行为**：**是**（若当前实为进程级，改后语义收紧；用户会看到"会话级不可用"的如实提示）。

### R-LOSS（归属 `REQ-10`/M1 回归面；对应第 10 条「自动压缩保护失败不落审计」）

**现状缺什么**：S4=B 只定义了手动压缩的告警（`REQUIREMENTS.md:28`：「自动压缩下 5 类受保护内容 0 丢失；手动压缩允许原文丢失，但必须有记忆指针、audit 显式告警」）；**自动压缩一旦丢失，审计要求未定义**。

**建议条款原文**
> **R-LOSS-1**：保护丢失审计必须覆盖**所有压缩模式**——自动（`manual:false`）与手动（`manual:true`）都写 loss 行（`compaction-loss`，旧名 `manual-compaction-loss` 可保留并加 `manual` 字段区分）；**`manual` 只描述语义，不作为是否审计的条件**。
>
> **R-LOSS-2**：自动压缩下的保护丢失属**严重事件**（M1 承诺自动压缩 0 丢失），除 loss 行外必须同时写 `protection-failed` 并在 `/cg status` 显式标出，不得只写 audit。
>
> **R-LOSS-3**：历史自动压缩样本（如 `ca9c9bb8`）若确无 loss 行，复核报告必须注明「是未发生丢失，还是未落审计」，不得默认前者。

**事件名/枚举归属**：审计 schema（事件名、字段白名单、`auditVersion`）**归审核**（`docs/review-1.0-发布口径-检查项.md` §4.2 审计族由审核维护）；需求侧只约束**语义**——必须覆盖 `manual:false`、必须可区分 `manual`、必须进 `/cg status`。**需求侧建议**（供审核决，非硬性）：复用 `manual-compaction-loss` + `manual` 字段（最小改动、旧解析器兼容）；若审核选择新增 `compaction-loss`，需求接受，但须保证旧解析器不静默失明。

**影响**：`runtime.js` loss 写入条件、`/cg status`、历史样本回查；测试覆盖 `manual:false` 丢失 → loss + `protection-failed`。

**是否改变已发布行为**：**是**——新增审计行，自动压缩丢失将显性化。
