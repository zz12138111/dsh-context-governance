## 1. 验收 checklist（10 条 + 需求新增第 11 条，条件纳入）

### 1. B-1 跨项目：压缩动作跨出边界、保护/账本不跨

- **验什么（按模式）**：
  - **单项目模式**（显式绝对 `projectRoot`，本机现状）：外部会话（根 ≠ 配置根）不触发插件提前压；外部会话的宿主原生压缩只记事实与用量；本项目四件套齐；
  - **多项目模式**（`projectRoot` 为空，新装默认）：每会话按 cwd 上溯 `.git` 得自身根，**不存在「外部会话」**；有根会话四件套齐（记忆根隔离归第 11 条）；无 `.git` 会话 → skip。
- **怎么验**：单项目 → 双窗口（配置根会话 + 另一 git 仓会话）；多项目 → 两个 git 仓会话 + 一个无 git 目录会话；审计 `grep -n 'early-skipped\|early-forced'`；对 `compactNow` 下 spy 计数。
- **通过判据**：
  - 单项目：外部会话 `compactNow=0`、无 `early-forced`、`early-skipped(reason=foreign-session)`（枚举定稿）；外部原生压只写**事实与用量**（cost/usage，无 protection/reinjection、不读写外部记忆）；本项目四件套齐；
  - 多项目：**不出现 `foreign-session`**（语义上无 foreign）；每个 git 仓会话写自身记忆（交叉验第 11 条）；无 git 会话 `early-skipped(reason=no-project-root)`（新增枚举）、无 memory 写入；
  - 两模式共同：双会话不串写；`/cg status` 可见「模式 + 项目根来源 + skip 原因」。
- **证据**：`analysis/req-20261025-12/1.0-10条-复验/01-B1/`（audit 摘录、status 输出、测试名、双会话 id）。

### 2. B-2 `committed` fallback

- **验什么**：无 fresh report 时 `compaction` 不写 `committed`；有报告时才写；枚举有定义。
- **怎么验**：单测构造「accepted + report=null」；复跑一次 R-2 看审计；抽样审计核字段。
- **通过判据**：全仓无「无报告也写 committed」路径；无报告时写 `null`/`unknown`（按定稿语义）；有报告时 `committed` 可解释；`/cg status` 与 audit 对得上。
- **证据**：`.../02-B2/`（测试输出、audit 行、R-2 复跑记录）。

### 3. 两个死键 `compact.cooldownMin` / `compact.minDeltaTokens`

- **验什么**：两键真正生效（cooldown 内不重复触发、delta 不足不触发），不是只被解析。
- **怎么验**：单测两个方向（cooldown、minDelta 各一条负向）；真机把 cooldown 设大、把 minDelta 设大各观察一轮；`/cg status` 看两键显示。
- **通过判据**：改值带来可观测的行为差异；两键在解析→wiring→status 全链路可达；非法值被拒绝。
- **证据**：`.../03-keys/`（测试名、status、两次触发时间差）。

### 4. 触发窗上界随 native 变

- **验什么**：`compact.at` 允许上界与 native 的关系（`≥ native−0.02` 不主动压）、跨不同窗口（如 1M/200k）的换算与展示。
- **怎么验**：单测不同 `windowTokens`；真机 `/cg status` 看有效上界与来源；配超上界值看是否拒绝/提示。
- **通过判据**：上界动态计算且展示；**`at ≥ native−0.02` 一律拒绝**（`policy-invalid(reason=above-effective-window)`）；跨窗口口径一致。
- **证据**：`.../04-window/`（测试、status 输出、拒绝提示文本）。

### 5. 空窗 `(native−0.02, native]` 的合法性

- **验什么**：合法但永不触发的配置不再静默显示 `early=on`；给诊断（提示或拒绝）。
- **怎么验**：配置 at 落空窗 → 看 `/cg status` / `/cg set` 输出；单测覆盖该区间。
- **通过判据**：`(native−0.02, native]` **不是合法配置区间**（一律拒绝）；`native` 收缩使已生效值落入该区间时**自动失效** + 审计 `policy-invalid(reason=window-shrunk)`，且 **`/cg status` 不再显示 `early=on`**。
- **证据**：`.../05-gap/`（命令输出文本、测试名）。

### 6. 会话层实为进程级 → 按会话级实现（用户已拍路 B）

- **验什么**：`/cg set`、`/cg compact arm|disarm` 按 sessionId 分桶；A 会话关闭不影响 B；重启回默认。
- **怎么验**：单测双 session 分桶；真机同进程双会话（或双会话注入集成测试）A `disarm` 后 A 不触发、B 仍触发；`/cg status` 各会话独立显示来源。
- **通过判据**：分桶隔离成立；`source=session` 只对当前会话；重启清空；与 §4.5 文案（会话级、立即生效）一致。
- **证据**：`.../06-session/`（测试、双会话 status/audit 对照）。
- **P0 前置（2026-10-26 定）**：会话标识当前取自 `invocation.sessionId ?? invocation.session?.id`（`cg-status.js:404`），而宿主真实字段是 `invocation.agent.session.id`（开发查实）→ 生产为 `null`。**未解决前不得落 #6**；#6 落地时 `early-armed`/`early-disarmed` 审计的 `sessionId` 必须非空且为会话短 id；id 缺失要**拒绝并提示**，不得写空桶。证据：单测（id 缺失 → 拒绝）+ 真机一条 `early-disarmed` 含短 id。

### 7. profile 全局单值 → 按会话打标

- **验什么**：同一 profile 不同会话可用不同档位/preset（需求 `v0.6:164-165`）。
- **怎么验**：单测两会话不同 preset；真机两会话各自 `/cg status`。
- **通过判据**：按 sessionId 记忆、互不影响；持久化/结束后的语义明确。
- **证据**：`.../07-preset/`（测试、两会话 status 对照）。

### 8. 发布包写死 `projectRoot`

- **验什么**：发布包/示例不含本机绝对路径；`projectRoot` 安装时解析（默认或可配）；换机器可用。
- **怎么验**：在干净目录/隔离 profile 做一次安装演练；对发布包 `grep -R` 本机路径应为 0；README 示例全占位。
- **通过判据**：0 本机路径命中；安装后日志里 `projectRoot` 指向安装项目而非作者机器；换机器无报错。
- **证据**：`.../08-install/`（安装演练日志、包内文件清单、grep 结果）。

### 9. 判定压力取全局最近会话

- **验什么**：窗口/压力取当前会话（或本项目会话），不取全局最近会话；跨会话不串号。
- **怎么验**：双会话同时不同压力 → `/cg status` 与审计的 `current/native` 标注来源会话；单测注入两会话窗口。
- **通过判据**：来源会话正确、可复算；换会话不串号（此条正是此前 00 压力数字误读的根因）。
- **证据**：`.../09-window-source/`（双会话对照表、测试、audit 行）。

### 10. 自动压缩保护失败不落审计

- **验什么**：`manual:false`、`trigger:auto` 的保护失败也落 loss 事件。
- **事件名定稿（2026-10-26 夜 v2）**：统一为 **`compaction-loss`**（新写一律用它，带 `manual:boolean` + `trigger:'auto'|'manual'`）；`manual-compaction-loss` 仅保留为**历史读取别名**（不再新写，读取端两者都认）；`src/audit.js` 枚举新增该项；`/cg status` 显示最近一条 loss 的 manual/trigger；auditVersion 按现有规则 +1。
- **怎么验**：单测构造 auto + 保护失败；若真机可造 auto 失败则补一条现场证据。
- **通过判据**：auto/manual 都落；字段能区分 `manual`/`trigger`；不重复写。
- **证据**：`.../10-auto-loss/`（测试、audit 行；现场证据有则附、无则标「仅代码路径+单测」）。
- **历史回查（Q3 定）**：对 `ca9c9bb8` 等历史自动压缩样本**必须回查**，逐条结论三选一：**发生丢失 / 未发生 / 无法判定（写原因）**；**不得默认「未发生丢失」**。样本清单+结论落 `.../10-auto-loss/historical.md`（样本 id、触发类型、保护项命中、结论、依据行号）。

### 11. R-MEMROOT：记忆根按项目根隔离（需求侧新增，待用户白天确认后纳入）

- **验什么**：`memoryRoot` 相对 `projectRoot` 解析；不同项目根**不得跨项目读写记忆**；`projectRoot` 按会话判定且**同一会话内不因 cwd 变化漂移**；无 `.git` 祖先时明确 skip 且不产生记忆文件；显式绝对路径=单项目模式；发布包不预填绝对路径；`/cg status` 可见本会话项目根与记忆根。
- **怎么验**：两个临时 git 仓库 A/B 各开会话 → 各写一条记忆 → 断言 A 的 memory 目录不含 B 的 session 记录、B 读不到 A；同一会话内 `cd` 子目录后 status 项目根不变；无 `.git` 的临时目录开会话 → status 显示 skip 原因且不落 memory 文件；配置绝对路径 → 两会话按定稿共用或明确拒绝；隔离 profile 安装演练查包内无绝对路径。
- **通过判据**：上列逐项成立；审计/记忆文件路径不交叉；status 同时显示「本会话项目根 / 记忆根 / 来源（配置|会话判定）」。
- **证据**：`analysis/req-20261025-12/1.0-10条-复验/11-memroot/`（双仓 memory 树、status、测试名）。
- **⚠ 口径冲突（白天必须定）**：R-MEMROOT-2「projectRoot 按会话 cwd 上溯 `.git`」与 R-SCOPE-1/#1「不在 `projectRoot` 下即 skip」互斥——项目根若随会话派生，几乎不存在「外部会话」（除无 git 会话），B-1 的 skip 语义与 Q1「外部会话原生压缩记账」都要改。两种读法：**(a)** `projectRoot` 仍由配置固定，R-MEMROOT 只约束 `memoryRoot` 相对解析 + 跨项目隔离（与 #1/#8 兼容，本判据先按 (a) 写）；**(b)** 多项目自动纳管（每个 git 会话一个根），则 #1 要改「未登记/无 git → skip」，且默认往任意仓写 memory 属重大行为变化，需用户拍。**(b) 成立时第 1/11 条需重写。**

## 6. 口径决定与批次顺序（2026-10-26 夜，供开发直接用）

- **批次顺序（开发已重排，我认）**：1a(#6+#9+#3) → 1b(#7) → 2(#1+#2) → 3(#4+#5) → 4(#8) → 5(#10)；#6/#7 先行、#1 在后，符合 G-B；每批仍按 G-A/G-C/G-D 验收。
- **B-4（新增独立跟踪项）**：命令侧会话标识为 `null`（`cg-status.js:404` 取 `invocation.sessionId ?? invocation.session?.id`，宿主真实字段为 `invocation.agent.session.id`）。**单独立项：是；升级为阻塞：是（经 1a）**——#6 分桶后若仍取 null，`disarm` 写空桶/失效，等于可退通道塌掉；同时 `early-armed/disarmed` 审计 `sessionId` 为空违反 §1.1「审计带会话短 id」。注意：**#6 之前** `disarm` 写进程共享 map，仍能全局关闭，不得写成「现在完全没生效」；准确说法是「会话级语义不成立 + 审计 id 空；#6 后若仍 null 则失效」。
