# 1.0 修复验收 · 10 条清单 + 批间门禁（审核打包）

> 范围：用户 2026-10-26 拍板「10 条全修」。编号沿用需求侧归类：
> ①需求缺口 = 1、2、4、5、10；②实现偏离 = 3、6、7、9（8 以②为主）；其中 **1 = B-1**。
> 纪律：**复核一律按当时证据现采**，不以开发自测代替；每条证据落盘，缺证据即未过。
> 本清单只定义验收，不写实现方案；实现由开发排批。

## 1. 十条验收 checklist

### 1. B-1 跨项目：压缩动作跨出边界、保护/账本不跨

- **验什么**：外部会话（cwd 不在 `projectRoot` 下）不触发插件提前压、不写保护/回注/成本；本项目会话四件套齐全；双会话不串写。
- **怎么验**：真机双窗口——本项目会话 + 外部工作区会话（如 `G:\DS-HARNESS`）各压到阈值；审计 `grep -n 'early-skipped\|foreign-session'`；对 `compactNow` 下 spy 计数；`/cg status` 看 skip 原因。
- **通过判据**：外部会话 `compactNow=0`、无 `early-forced`、无 `protection-*`/`reinjection`/`compaction-cost` 写入；本项目会话 `protection-write → materialized → reinjection → compaction-cost` 四件套齐；status 可见 skip 原因。
- **证据**：`analysis/req-20261025-12/1.0-10条-复验/01-B1/`（audit 摘录、status 输出、测试名、双会话 id）。

### 2. B-2 `committed` fallback

- **验什么**：无 fresh report 时 `compaction` 不写 `committed`；有报告时才写；枚举有定义。
- **怎么验**：单测构造「accepted + report=null」；复跑一次 R-2 看审计；抽样审计核字段。
- **通过判据**：全仓无「无报告也写 committed」路径；无报告时写 `null`/`unknown`（按定稿语义）；有报告时 `committed` 可解释；`/cg status` 与 audit 对得上。
- **证据**：`.../02-B2/`（测试输出、audit 行、R-2 复跑记录）。

### 3. 两个死键 `compact.cooldownMin` / `compact.minDeltaTokens`

- **验什么**：两键真正生效（cooldown 内不重复触发、delta 不足不触发），不是只被解析。
- **怎么验**：单测两个方向（cooldown、minDelta 各一条负向）；真机把 cooldown 设大、把 minDelta 设大各观察一轮；`/cg status` 看两键显示。
- **通过判据**：改值带来可观测的行为差异；两键在解析→wiring→status 全链路可达；非法值被拒绝。
- **证据**：`.../03-keys/`（测试名、status、两次触发时间差）。

### 4. 触发窗上界随 native 变

- **验什么**：`compact.at` 允许上界与 native 的关系（`≥ native−0.02` 不主动压）、跨不同窗口（如 1M/200k）的换算与展示。
- **怎么验**：单测不同 `windowTokens`；真机 `/cg status` 看有效上界与来源；配超上界值看是否拒绝/提示。
- **通过判据**：上界动态计算且展示；越界配置不被静默接受；跨窗口口径一致。
- **证据**：`.../04-window/`（测试、status 输出、拒绝提示文本）。

### 5. 空窗 `(native−0.02, native]` 的合法性

- **验什么**：合法但永不触发的配置不再静默显示 `early=on`；给诊断（提示或拒绝）。
- **怎么验**：配置 at 落空窗 → 看 `/cg status` / `/cg set` 输出；单测覆盖该区间。
- **通过判据**：有明确诊断（warning/拒绝 + 原因），不误导用户以为在生效。
- **证据**：`.../05-gap/`（命令输出文本、测试名）。

### 6. 会话层实为进程级 → 按会话级实现（用户已拍路 B）

- **验什么**：`/cg set`、`/cg compact arm|disarm` 按 sessionId 分桶；A 会话关闭不影响 B；重启回默认。
- **怎么验**：单测双 session 分桶；真机同进程双会话（或双会话注入集成测试）A `disarm` 后 A 不触发、B 仍触发；`/cg status` 各会话独立显示来源。
- **通过判据**：分桶隔离成立；`source=session` 只对当前会话；重启清空；与 §4.5 文案（会话级、立即生效）一致。
- **证据**：`.../06-session/`（测试、双会话 status/audit 对照）。

### 7. profile 全局单值 → 按会话打标

- **验什么**：同一 profile 不同会话可用不同档位/preset（需求 `v0.6:164-165`）。
- **怎么验**：单测两会话不同 preset；真机两会话各自 `/cg status`。
- **通过判据**：按 sessionId 记忆、互不影响；持久化/结束后的语义明确。
- **证据**：`.../07-preset/`（测试、两会话 status 对照）。

### 8. 发布包写死 `projectRoot`

- **验什么**：发布包/示例不含本机绝对路径；`projectRoot` 安装时解析（默认或可配）；换机器可用。
- **怎么验**：在干净目录/隔离 profile 做一次安装演练；对发布包 `grep -R` 本机路径应为 0；README 示例全占位。
- **通过判据**：0 本机路径命中；安装后日志里 `projectRoot` 指向安装项目而非作者机器；换机器无报错。
- **证据**：`.../08-install/`（安装演练日志、包内文件清单、grep 结果）。

### 9. 判定压力取全局最近会话

- **验什么**：窗口/压力取当前会话（或本项目会话），不取全局最近会话；跨会话不串号。
- **怎么验**：双会话同时不同压力 → `/cg status` 与审计的 `current/native` 标注来源会话；单测注入两会话窗口。
- **通过判据**：来源会话正确、可复算；换会话不串号（此条正是此前 00 压力数字误读的根因）。
- **证据**：`.../09-window-source/`（双会话对照表、测试、audit 行）。

### 10. 自动压缩保护失败不落审计

- **验什么**：`manual:false`、`trigger:auto` 的保护失败也落 loss 事件（事件名/字段按定稿）。
- **怎么验**：单测构造 auto + 保护失败；若真机可造 auto 失败则补一条现场证据。
- **通过判据**：auto/manual 都落；字段能区分 `manual`/`trigger`；不重复写。
- **证据**：`.../10-auto-loss/`（测试、audit 行；现场证据有则附、无则标「仅代码路径+单测」）。

## 2. 批间门禁（批次由开发排，门禁由我卡）

| 门禁 | 规则 |
|---|---|
| **G-A** | 一批内条目必须**全过**（10 条清单逐项有证据）才允许进下一批；任一条未过 → 停在批内 |
| **G-B** | **6/7 与 1 必须同批或先行**（三者共用配置解析/session 判定，半改状态不可验收） |
| **G-C** | 每批结束：全量测试（当前 323 + 新增）必须绿；我**独立再跑一遍**，不采信开发自测输出 |
| **G-D** | 每批结束我按清单**现采**一次（真机/审计/命令输出）并落盘；未现采的条目不算过 |
| **G-E** | 8 必须在「打包/安装演练」批内过；否则不许出包 |
| **G-F** | 10 条全过之前：不清史、不改可见性、不删 run、不打 tag、不推分支、不出 Release |
