## 2. 架构：RootStorePool（每根 store 池）

### 2.1 数据结构

```js
// src/roots/store-pool.js
RootStorePool {
  #entries = new Map();   // rootId -> {
                          //   entry, store|null, audit|null, refs, lastUsed,
                          //   opening: Promise|null, readOnlyReason
                          // }
  #pending = new Map();   // rootId -> Promise<store>（并发打开去重）
  #warnedOpenLimit = false;
}
```

- 键 = `rootId`（P1 路径 hash），不是路径串；同名根不撞。
- 每个 entry 绑定：registry entry（root/rootId/project/memoryRoot）、`MemoryStore`、该根 `AuditLog`（`<memoryRoot>/audit.jsonl`，`allowedBase=memoryRoot`）。
- **不放** root audit（用户级）在池里：root audit 由 index 全局持有，池只写每根 audit + 调 `rootAudit` 记录池事件。

### 2.2 打开（懒、去重、fail-closed）

```
async get(registryEntry) -> {entry, store, audit, release}
  key = entry.rootId
  if entry.state !== 'active' -> fail(ROOT_FAIL_CLOSED)
  mem = memoryRootFor(entry.root)        // 固定 memory/governance + containment
  if !mem.ok -> registry.failClosed(entry.rootId, mem.reason); fail(ROOT_FAIL_CLOSED)
  if #pending.has(key) -> await #pending.get(key)
  else #pending.set(key, openOnce(...))
  openOnce:
    store = await MemoryStore.open({ rootDir: mem.memoryRoot, project: entry.project })
    audit = new AuditLog({ file: join(mem.memoryRoot,'audit.jsonl'), allowedBase: mem.memoryRoot, maxBytes: config.audit.maxBytes })
    entry = { ...meta, store, audit, refs: 0, lastUsed: now }
    #checkOpenLimit()                      // >16 只 warn/root audit，不拒绝
    rootAudit.append('memory-store-open', { root, rootId, count })
  #entries.set(key, entry); #pending.delete(key)
  entry.refs += 1; entry.lastUsed = now
  return { entry, store, audit, release: () => this.release(key) }
```

- **不预打开**：registry 登记根/会话事件不建 store；只有工具 resolver 调 `get` 才建。
- 打开失败：不缓存坏 entry；下次重试；连续失败由 resolver 按 `ROOT_UNAVAILABLE` 拒绝。
- store 只读（writer lock/containment/root-not-writable）：仍返回 store（查询可用），`mem_write` 抛 `[READ_ONLY]`；池记录 `readOnlyReason`，root audit 记 `memory-store-readonly`。
- 每根 audit 用 `allowedBase`，实际路径 containment；与 P1 v3 一致。

### 2.3 refCount / TTL / 关闭

| 动作 | 规则 |
|---|---|
| `get` | `refs += 1`，`lastUsed = now` |
| 工具 execute `finally` | `release()`：`refs = max(0, refs-1)`，`lastUsed = now` |
| 空闲清理 | 定时（默认 60s）扫：`refs === 0 && now - lastUsed > ttlMs` → `store.close()` + 从 Map 删除 + root audit `memory-store-close {reason:'ttl'}` |
| 打开数软上限 | 默认 `ROOT_WARN_THRESHOLD=16`；超过只 `memory-store-pool-warn` + logger，不拒绝；先尝试关闭最久空闲 entry |
| dispose | `closeAll()`：逐个 `store.close()`，清 Map；失败记 logger/root audit，不抛宿主 |
| 关闭中 | 只关闭 `refs===0` 的；`refs>0` 跳过，等下次 sweep |
| 重新打开 | TTL 关闭后同根下次 `get` 重新 open；memory 文件持久、不丢 |
| 进程退出 | store.close 释放 writer lock（现有）；池不额外写盘 |

- 默认 `ttlMs = 30 * 60 * 1000`，`sweepMs = 60 * 1000`；可配置（`roots.storeTtlMin`、`roots.sweepSec`，非发布必需，先常量）。
- **不设硬上限**；软上限只告警（与 P1 根数阈值一致）。

### 2.4 每根 writer lock 与多进程

- `MemoryStore.open` 现有 `.writer.json` 每根独立；第二进程同根 → `readOnlyReason='writer-lock:<pid>'`，工具只读并带回 reason；**不合并、不覆盖**。
- 不同根各自锁，互不影响。
- 同进程同根并发：池 refCount 只打开一个 store；MemoryStore 内部 `#queue` 串行化写入；不会两个 writer。
- 同根两个插件实例/两进程：第二实例只读；`/cg status` 的 `memory-readonly` 行可见（P1 已有）；P2 在工具错误里保留 `[READ_ONLY]`。

### 2.5 池事件（root audit）

新增事件（root audit，字段白名单已有 root/rootId/count/reason）：

- `memory-store-open`：`{root, rootId, count}`（count=当前打开数）
- `memory-store-close`：`{root, rootId, reason:'ttl'|'dispose'|'fail-closed', count}`
- `memory-store-readonly`：`{root, rootId, reason}`（每根一次）
- `memory-store-pool-warn`：`{rootCount/count, threshold}`（只一次/阈值跨越）
- 打开失败：`memory-store-open-failed`：`{root, rootId, reason}`

> 不写正文/sessionId；root audit 只汇总。每根 audit 仍只写该根会话事件；`memory-tool-rejected` 按 §3 落点。

## 3. `mem_*` 按根 resolver

### 3.1 接口（在 P1 预留形状上扩展）

```js
// index.js 生产
const pool = new RootStorePool({ registry, rootAudit, config, logger });
const resolveStore = async (exec) => {
  if (registry === null) return { ok:false, code:'ROOT_UNAVAILABLE', reason:'identity-unavailable' };
  const session = exec?.agent?.session ?? null;
  const resolved = registry.resolveSessionRoot(session);
  if (resolved.status === 'no-root') return { ok:false, code:'NO_ROOT', reason:resolved.reason };
  if (resolved.status === 'unmanaged' || resolved.entry?.state === 'fail-closed') {
    return { ok:false, code:'ROOT_FAIL_CLOSED', reason:resolved.entry?.failClosedReason ?? 'unmanaged-root' };
  }
  const opened = await pool.get(resolved.entry);   // 懒开、refCount
  return { ok:true, store:opened.store, audit:opened.audit, entry:opened.entry, release:opened.release };
};
registerMemoryTools(ctx, null, { resolveStore, audit: rootAudit });
```

- `createMemoryTools` 的 `store` 参数可为 null；生产恒注入 resolver；单测仍可 `createMemoryTools(store)`（兼容）。
- `storeFor` 改为 `await resolveStore(exec)`；`execute` 的 `finally` 调 `release()`（防止 refCount 泄漏）。
- 解析失败 → `memory-tool-rejected`（落点见 §3.3）；错误码：
  `NO_ROOT` / `ROOT_FAIL_CLOSED` / `ROOT_UNAVAILABLE` / `SUBAGENT_NO_MEMORY_WRITE` / `READ_ONLY`（store 自身）/ `BAD_ARGS`（现有）。
- `mem_query` 增加 `exec`；`mem_write` 已接收 `exec`；schema **不加** `root`/`allRoots`。
- **跨根写入拒绝**：没有 `root` 参数；resolver 只按会话根；即使调用方伪造 `args.root`，`additionalProperties:false` 由宿主 schema 拒绝 + 工具侧显式忽略/报 `BAD_ARGS`（双保险）。
- 子会话：`mem_write` 拒绝（早于 resolver，P1 已有）；`mem_query` 允许只读父根；P2 不写持久记忆（P3 保护 journal 另行）。

### 3.2 根归属与 configRoot 强制合并

- `registry.resolveSessionRoot` 已实现 v3：configRoot 非空 → cwd 在其下即归 configRoot（嵌套 `.git` 不另立根）；configRoot 外/默认空根 → 最近 `.git`。
- P2 不得再写第二套根判定；`mem_*`、store、audit、status 全部用同一 `entry.rootId`。
- **已知限制**：显式配置根内多根隔离不完整（configRoot 下嵌套仓库合并到外层）；P2 文档/测试必须保留该断言，不宣称嵌套独立。

### 3.3 拒绝审计落点

| 条件 | 审计 | 字段 |
|---|---|---|
| `NO_ROOT`（cwd 空/无 `.git`） | **不审计**（3A 完全不碰） | — |
| 根 fail-closed / unmanaged（P2 正常无，防御） | 用户级 root audit | `memory-tool-rejected {tool,code,root,rootId,reason}` |
| 子会话 `mem_write` | 用户级 root audit | `{tool:'mem_write', code:'SUBAGENT_NO_MEMORY_WRITE', root, rootId, reason:'subagent', sessionShortId?}` |
| store 只读 | 该根 per-root audit（若可写） | `{tool, code:'READ_ONLY', reason}` |
| 解析器异常 | root audit | `ROOT_UNAVAILABLE` |

- 不写正文/消息；全 id 只在 root audit 现有白名单允许时写（P1 使用 sessionId/sessionShortId）；**root-unmanaged** 仍不写 sessionId（v3）。
- 拒绝不影响 store 状态；不因拒绝关根。

### 3.4 跨根负向（P2 硬验收）

- A/B 两个可判定根；A 会话 `mem_write` → 只落 A `topics/MEMORY.md`；B 文件 hash/mtime 不变。
- A 会话 `mem_query` 查 B 的 id：**需求已判保持现状**——各根独立编号、查询永不跨根；同号时 A 只可能返回 A 自己的同号条目，**绝不返回 B 的正文/标题**；P3/P4 跨根聚合用 `rootId + id` 消歧，**不改 ID 格式**。B 文件不变、不回退。
- A 会话 `mem_query({text})` 不命中 B 的 title/detail。
- A 的 `audit.jsonl` 不出现 B 的 session/tool 事件；B 的 root audit 不出现 A 的。
- 删除 A 状态 → 重新推断可见；B 不受影响。
- 同根两 store/两进程 → 第二只读；第一写入不丢（现有锁语义）。

## 4. `logFile` / containment（保持 P1 v3）

- 两处白名单：用户级 `<home>/context-governance/`、该根 `<root>/memory/governance/`；`<root>/logs/` 拒绝。
- `logFile` 是 **profile 级单值**：只有用户级对多根安全；根内路径只能作 per-root sink（P2 不把根内路径当全局日志）。
- 每次实际写入前 `checkWriteTarget`（realpath/`..`/symlink/junction/UNC/盘符）；state/root audit/memory/audit/log 都覆盖；白名单外 fail-closed。
- P2 不改变现有 P1 测试：`logfile-whitelist`、`write-containment` 必须继续绿。

## 5. P2 不碰 P3（边界）

- `CompressionGuard` 仍只由 index 按主根挂载；P2 不把 guard 改成多根。
- `memory-header` 仍只按 P1 主根/子会话规则；P2 不扩到其他根。
- `protection`/`reinjection`/`early-*` 代码不动；P2 只新增 memory store 池/路由/每根 audit。
- 其他根会话在 P2 即使能写记忆，其压缩事件仍不保护/不回注/不提前压 → **P2 仍不可安装/不可发布**，P3 才闭合 B-1。

## 8. 时序/并发细节

- `get(rootId)` 并发：`#pending` Promise 去重；打开成功后所有调用者共享同一 store，refs 按调用次数增加。
- 工具 `execute` 抛错也 `finally release`；若进程崩溃，锁由 store.close/进程退出释放。
- TTL sweep 与 get 并发：sweep 只处理 refs=0；get 在 sweep 删除前捕获 entry；删除时 `store.close` 失败保留 entry 并下次重试（记录 root audit）。
- `closeAll` 时不接受新 get（`#disposed=true` → `ROOT_UNAVAILABLE`）。
- 每根 audit 写失败不影响工具：`AuditLog` 已有 writeFailures/logger 降级；`memory-tool-rejected` 失败只 logger。
- 根状态 fail-closed：pool 若已开 store → 下一次 resolver 拒绝并关闭（refs=0 时）；不继续写。

## 9. 风险与回滚

| 风险 | 处理 |
|---|---|

| TTL 关store 时工具仍在用 | refs>0 不关；release finally |
| 同根第二进程只读被误当失败 | 返回 READ_ONLY + reason；查询可用 |
