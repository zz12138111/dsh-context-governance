## 2. v3 冻结口径（必须与需求/审核一致）

1. **根判定 = 强制合并**：`configRoot` 非空 → cwd 在其下即归该根、`source=config`，**嵌套 `.git` 不另立根**；configRoot 外/默认空根 → 最近 `.git` 多根。**已知限制：显式配置根内多根隔离不完整**（不是 bug；P2/P4 文档必须保留这句）。
2. **`root-unmanaged`**：每根在 root audit 汇总一条，字段仅 `root`/`rootId`/`count`/`reason`；**不写 sessionId（全/短都不写）**、不写正文；同根多会话只累计 `count`；不写 per-root/cost/protection/记忆。
3. **授权边界 = 两处白名单**：`<home>/context-governance/`（根状态/根审计/默认诊断）与 `<root>/memory/governance/`（记忆/根内审计）；`<root>/logs/` 不允许。每次**实际写入路径**做 realpath/`..`/符号链接/junction/UNC/盘符归一 containment；白名单外 fail-closed。
4. **`logFile`**：只允许上述两处；旧 `D:\DS-PROJECT\DSH插件开发\logs\governance.log` 会 **CONFIG 拒绝、插件不加载该 profile**（显式失败）。本机已迁移到 `C:/Users/19091/.dsh/context-governance/logs/governance.log`（desktop `cordis.patch.yml`，旧文件保留未动）。多根下只有用户级路径安全；根内路径只能作 per-root sink。
5. **`mem_write`**：默认写本会话根，跨根写入拒绝；多进程同根不合并（第二进程只读/锁提示，既有 `lock.test` 覆盖）。

## 3. P1 不做什么（P2/P3/P4 边界）

- **P1 只主根完整治理**：其他根已登记，但压缩观测/成本/保护/回注/记忆/header/提前压全部不跑（不产生 cost-only 行）。**P1 完成 ≠ 功能闭环**。
- **P2**：每根 store 懒打开/池化、`mem_*` 按会话根路由、每根 `.cg-policy.json`、成本账本按根、全部根的成本/审计。
- **P3**：全会话保护/回注/header/提前压；子会话保护 journal **不 materialize 成持久记忆**（周期结束丢弃）。
- **P4**：安装/升级/卸载/回滚演练、`logFile` 迁移文档、多根已知限制、Release notes；版本策略由审核/用户定。
