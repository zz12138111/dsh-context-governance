## 1. `/cg status`

- 注册：`apply()` 内 `ctx.commands.register({name:'cg', ...})`；`inject=['tools']`，`commands` 走可选探测 + 晚挂载重试；注册失败只 warn，不影响插件其余部分。
- 用法：`/cg status`、`/cg status last-cost`、`/cg policy show`、`/cg set <key>=<value>`、`/cg set reset`；空参数等价 `/cg status`；其他参数返回 usage。
- 输出字段：

| 字段 | 内容 |
|---|---|
| policy | 生效阈值 `compact.at`（含 `source=`）、`native` 上限、`early=on|off`（0.2.0；与观察器是否挂载无关，固定输出在第二行） |
| policy-invalid | 只有 N>0 时出现：`N (source/key:reason, …)`；被拒的层与原因直接可见，不只写审计（0.2.0） |
| policy-session | 有 `/cg set` 会话覆盖时出现：`key=value, …`（0.2.0） |
| compression | `mode`、`adapter`、`perception`、`summary`（可读性/风格）、`backend-kind`（枚举；推断时另附 `backend-label`）、host/backend 版本 |
| capabilities | 控制权、前/后钩子、保护角色（validator） |
| pressure | 压力四段（0.2.0，只展示不压缩）：`measured`（最近 usage 实测占窗口）、`estimated`（tokenMeter 估算）、`adjusted`（×`estimateSafety`）、`effective`（取大）+ `ratio`（实测/估算）+ **`window=<1.00M/256k>`（分母可见，P3-3）**+ 与 `at` 的比较；任一来源缺失写 `-`，不伪造 |
| degraded | 降级原因（`protection-write-failed`、`reinjection-failed` 等） |
| conflicts | 版本/provider/事件面等冲突码与严重级 |
| write-latency | 压缩前同步写盘的 `n / p50 / p95 / max`（毫秒） |
| last-compaction | compactionId 前 8 位、manual、`compaction=committed\|skipped\|failed`、`protection=ok\|failed`、shadowed 数、checkpoint、失败检查名；**protection 只表示保护项是否保留，不代表压缩成功** |
| last-reinjection | `status`（injected/skipped-*/failed）、seq、行数 |
| last-cost | `before`/`after`、各自来源（tokenMeter/usage/none）、trigger、`pruned=<tokens>`、`tools=<top5>`；无记录显示 `none` |
| protection | 写/注计数、失败数、pending journal 数、是否已禁用回注 |
| memory | 项目、根目录、active/proposed/total、pending journal、只读原因/告警数 |
| audit | 审计文件路径、最近 5 条失败/丢类事件名 |

### 1.1 策略链（0.2.0）

- 合成顺序（低 → 高）：**内置 → profile 标签 → 插件配置 → 项目 `.cg-policy.json` → 会话 `/cg set`**；每键记录 `source`。
- 策略只在 `apply()` 里算一次（`buildPolicyState`）：命令侧只读同一份，不二次计算；项目层经真实 `apply` 生效，不会出现“文件在、命令看不到”。
- `compact.at` 语义：**占窗口比例**（默认 0.60）；上限是动态 `native`（`floor(min(W×0.8, W−O−65536))/W`）。**0.2.1 起默认取观测窗口 1,048,576 → `0.6934`**；配置窗口 `1,000,000` 只在无观察时回退，得 `0.6785`。`at > native` 拒绝并提示“不支持推迟”。
- `compact.early` 是**纯配置开关** `on|off`（默认 on；`research` profile 默认 off）。它不是“引擎是否可取到”的状态位——引擎通道状态留给 0.2.1 的 `early-channel`，0.2.0 没有任何引擎接线。
- `compact.at < 0.30` 需配置文件 `compact.lowThresholdAck=true`；未确认时回退到内置值并记 `low-threshold-unacked`。

### 1.2 项目文件 `.cg-policy.json`（不可信输入，A+C 口径）

- 位置：`<projectRoot>/<policy.projectFile>`，默认 `.cg-policy.json`；`projectFile` 只允许项目内相对路径（绝对路径与 `..` 在 `resolveConfig` 直接拒绝），`buildPolicyState` 再做一次 containment，超过 64KB 不读（记 `too-large`）。
- **containment 是词法层**（`path.resolve`）：项目内的 junction/symlink 指向项目外时不会解析（P3-4 残余面；Windows git 默认不落 symlink，风险低；0.2.1 视需要加 `realpath` 比较）。
- **只在 `apply` 读一次**：改 `.cg-policy.json` 后必须重启/重载插件才生效（P3-7；与 `/cg set` 的“重启即失效”同一时点）。
- 安全子集：**禁止** `compact.lowThresholdAck`、`compact.estimateSafety`（`reason=project-denied`）；`compact.at` 下限 **0.45**（`below-min`），上限仍 `native`（`over-native`）。
- 拒绝语义：**整层拒绝**（不逐键降级），退回下一层生效；`source=project` + 拒绝键 + 原因同时进 `policy-invalid` 审计与 `/cg status`（`policy-invalid:` 行）。
- 目的：恶意仓库不能把阈值压到 0.20、不能替用户自盖确认、不能静默降级。

### 1.3 `/cg policy show` 与 `/cg set`（0.2.0）

- `/cg policy show`：逐键展开生效值与来源、`layers:` 链（空层标 `(empty)`）、`session:` 覆盖、`invalid:`（含 detail，如项目层下限 0.45）。
- `/cg set <key>=<value>`（也接受 `key value`、多对）：写**会话层**（最高优先级），只允许 `compact.at` / `compact.early` / `compact.cooldownMin` / `compact.minDeltaTokens` / `cost.remainingTurns`；`estimateSafety` / `lowThresholdAck` 明确拒绝（只能改配置文件，改完重启）。一条命令里同一键出现两次直接拒绝（P3-6），不静默后写胜。
- `/cg set`（空参）、`/cg set show`、`/cg set list` 列出当前覆盖；`/cg set reset` 清空并回落下一层。覆盖是**进程内**的：重启插件即失效（0.2.0 未拿宿主会话 id，所以不宣称按会话隔离）。
- `<0.30` 未确认的会话覆盖会被 resolve 回退：此时命令直接报错并撤销，不留半截覆盖（避免“设了但没生效”）。**只判本次会话层引入的未确认**（P3-2）：配置文件本身 `at<0.30` 时，`/cg set compact.early=off` 这类无关设置不会被连坐。
- 审计：每次成功覆盖写 `policy-set`（`source=session`、`key`、`value`），`reset` 写 `key=*`、`value=reset`；不写消息正文。

### 1.6 记忆 header（M3 T2 / 0.3.1，默认开）

- 注入时机：`agent/pre-step` 第一步、每会话一次；`source.form=memory-header`。

### 1.5 窗口来源与校验（0.2.1，`DEC-20261025-66/67`）

- `windowState`：`current` = `#lastSession` 最近观察到的 `request/context.data.contextWindow`；`conservative` = `min(已观察窗口)`；`observed[]` = 每会话 `{sessionId, tokens, observedAt}`。
- **删除语义**：`request/context` 不带 `contextWindow` → **删除该会话旧值**，显示 `window=unknown (removed by request/context)`，不沿用旧值；再次观察到自动恢复。
- **动态 native**：`nativeFromWindow(W,O) = floor(min(W×0.8, W−O−65536))/W`；`W` 非正整数 → unknown（回退配置并标 `config-fallback`）；`W ≤ O+65536`（`floor(...) ≤ 0`）→ **`unknown (degenerate)`**，**禁止用常数 `0.6785` 冒充**（`DEC-20261025-68` A）。
- **退化语义**：设置 `compact.at` 的层**一律拒绝（含会话层）** + `policy-invalid(reason=native-uncomputable)`；已生效的继承值标 `unverified-degenerate`；`0.2.2` 提前压不得触发；`W` 恢复后自动恢复可校验。**与“无观察”区分**：无观察允许设 `at` 但标“未经校验”；退化是**拒绝设置**。
- **同源**：`native` 与压力分母共用同一个 `W` 解析（current），`/cg status` 的 `policy:`/`pressure:` 不各算一套。
- **校验用 conservative**：`/cg set` 与运行时检查都用 `min(已观察窗口)` 的 native；无观察时允许设 `at`，但状态标 `unvalidated (at 允许但未经保守窗口校验)`；运行时窗口变小导致 `at > native` → **拒绝该层 + `policy-invalid` 审计**（`over-native-runtime`），不静默降级。
- **conservative 是“全历史 min”**（含已结束/其它会话，直到 0.2.2 再定 TTL、`session/end` 与“活跃会话”口径）；因此新会话窗口更大时，保守值仍可能压着更早的小窗口。
- 层被拒后若回落到 builtin 的 `at` 仍 > conservative（如 `0.60 > 0.375`），`/cg status` 会多一条 `policy-invalid: … (builtin/compact.at:fallback-over-native)` 提示，不默默生效。
- **历史窗口回填（`ART-20261025-101/103`）**：宿主只在路由变化时发 `request/context`，既有会话重启后可能拿不到新窗口；因此**首次收到某会话任一事件时**，用 `ctx.get('sessionProjections').stateOf(session,'contextPressure')` 回填一次 `contextWindow`（按会话缓存，`stateOf` **每会话至多一次**）。回填来源标 `source=projection(backfilled)`，`observedAt` 取**历史 `request/context` 事件时间**（不是回填时刻）；拿不到/字段缺失/值非法（0/负数/字符串）一律保持 `unknown + config-fallback + unvalidated`，**不伪造**。同一会话后续收到实时 `request/context` → 来源回到 `source=projection`、`observedAt` 更新为观察时间。
- 会话层被拒的覆盖在 `/cg status` 的 `policy-session:` 与 `/cg policy show` 的 `session:` 里标 `(rejected)`；窗口恢复后**自动消失**（transient 只在当前 episode 内有效）。
- `/cg status` 双显行（示例用 `O=16k` 以演示差异；当前配置默认 `reservedTokens=256000`）：

```
window: current=1M (session 58a2e845) observed 2026-10-26T… source=projection
        conservative=128k (session bbbbbbbb) native-current=0.8000(projection)
        native-conservative=0.3750 validated 校验按 conservative
```

- 退化时显示：`native-current=unknown (degenerate: W=128k O=256k)`、`unverified-degenerate`。

- **本版不触发任何压缩**：`src/` 无 `compactNow`/`compactRegion` 调用（仅 `adapters.js` M1 能力探测），并有单测「验收#6」锁住（窗口变化 + resolve/status 全过程 0 次压缩调用）。

## 2. 审计正式化

### 2.1 文件与写入

- 文件：`<memoryRoot>/audit.jsonl`；每行一个 JSON 对象。
- **apply 即建文件 + 写一条 `apply` 记录**（v0.1.3）：装载后立刻能在磁盘确认路径与写入时机，不必等第一次压缩。
- **同步追加**：`protection-write-failed` / `reinjection-failed` 等必须在失败当场落盘；写审计失败只 warn，不抛宿主。
- 保留：进程内最近 200 条；磁盘文件按 `audit.maxBytes`（默认 8 MiB）轮转为 `audit-YYYYMMDD.jsonl`，历史文件不删（v0.1.4；详见 `docs/T6-失败与降级.md`）。

### 2.2 字段白名单（唯一来源）

代码：`packages/dsh-context-governance/src/audit.js` → `AUDIT_FIELD_WHITELIST`。
只有以下字段能进入审计；未知字段（`text`/`title`/`detail`/任意新键）**直接丢弃**：

| 字段 | 类型 | 用途 |
|---|---|---|
| `sessionId` | id | 会话标识 |
| `compactionId` / `cycle` | id | 压缩周期幂等键 |
| `manual` | boolean | 手动/自动压缩 |
| `count` / `moved` / `seq` / `durationMs` / `entries` / `omitted` / `lines` / `window` | number | 计数、位移、耗时、预算 |
| `ids` | id 数组 | 记忆条目标识 |
| `kinds` / `failures` | 文本数组 | 保护类别、失败检查名 |
| `reason` / `code` / `mode` / `adapter` / `backend` / `host` / `version` / `perception` / `status` | 文本 | 失败原因、模式、版本、感知层级等 |
| `eventApi` | boolean | 事件订阅 API 是否存在（v0.1.3） |
| `readOnly` | boolean | 只读降级标记 |
| `key` / `value` | 文本 | 0.2.0 `/cg set` 覆盖的键与字面值（`reset` 写 `key=*`、`value=reset`） |
| `project` / `model` / `trigger` / `occurredAt` | 文本 | T8-2 成本维度（项目、`provider/model`、auto/manual、ISO 时间） |
| `tokensBefore` / `tokensAfter` / `tokensSummary` / `tokensInjected` | 可空数字 | T8-2 token 归属；`null`=取不到，不伪造 |
| `tokensShadowed` / `tokensDropped` / `injectedEntries` | 数字 | 被压缩的 token、被下一次压缩吞掉的回注 token、回注条数 |
| `backendUsage` | 固定对象 | 只保留 input/output/cacheRead/cacheWrite/total 五个非负数值字段 |
| `backendCostSource` / `governanceCostSource` / `estimateMethod` / `auditVersion` | 文本 | `measured|estimated|unknown`、`chars/4|none`、`cost-v1` |

- 字符串字段统一 `detectSensitive()` 扫描；命中凭据形态 → 写作 `[redacted:<kind>]`，不落原文。
- **绝不写入**：消息正文、摘要正文、标题、detail、文件内容。
- 事件名清单：`AUDIT_EVENTS`（`apply`、`capability@apply`、`capability@ready`、`adapter-inferred`、`policy-invalid`、`policy-set`、`protection-write`、`protection-write-failed`、`protection-write-skipped`、`protection-materialized`、`protection-materialize-failed`、`protection-skip`、`reinjection`、`reinjection-skipped`、`reinjection-failed`、`reinjection-budget`、`reinjection-shadowed`、`reinjection-recovered`、`reinjection-degraded`、`compaction-cost`、`prune-observed`、`manual-compaction-loss`、`duplicate-cycle-start`、`cycle-interrupted`、`cycle-abandoned`）。
- `policy-invalid`（0.2.0）：策略层被拒的一条一记录（`source`=plugin/project/session、`code`=键、`reason`=原因；含 `layer-must-be-object`/`invalid-json`/`read-failed`/`too-large`/`outside-project-root`/`unknown-key`/`project-denied`/`below-min`/`over-native`/`low-threshold-unacked`）；`apply` 同时 warn 一行，`/cg status` 的 `policy-invalid:` 行给出同样信息（仅 N>0）。
- `policy-set`（0.2.0）：`/cg set` 成功覆盖（`source=session`、`key`、`value`）或 `reset`；不记消息正文。
- `compaction-cost`（0.1.16 / `cost-v1.4`）：`backend`/`backendKind` 只写枚举（`none`/`unknown`/`host-basic`/`context-zip`，不含括号/空格；0.1.17 起含 `none`，实测 none 不折叠），展示串在 `backendLabel`，推断补位由 `backendInferred` 标记；`/cg status` 用 `backend-kind=<枚举>`（仅推断补位时另附 `backend-label=<展示串>`）。
- `protection-skip`（0.1.13 起）：保护校验里带**明确原因**的 `skip` 留痕；字段 `reason` + `names`（检查名数组）+ `count`/`manual`，不含消息正文。当前原因：`no-ratio-in-user-messages`（有批次语义但没有可用比例）、`no-batch-semantics`（有比例但同消息无 `批次|进度|progress|batch`）、`date-like-ratio`（只有 `YYYY/MM` 这类日期）。
