### 1.1 提前压开关（✅ 已确认：默认开 —— 2026-10-26 用户拍板）

**🔍 现状（2026-10-26 02:41 现采）**：`src/index.js:527` 传 `getArmed: () => false`，写死；`early-wiring.js` 在 `armed=false` 时**不审计、不取 agent/engine、不调用**；`early.js` 的 `arm()/disarm()` 无人调用；全仓无配置项或命令能打开它。所以「提前压」能力已通（判定十道闸 + `turn/end` 接线 + `early-*` 审计都复核通过），但**永远不会真实触发**。打开它由 `TASKS/REQ-20261025-09-提前压启用-拆解.md`（版本 **0.2.4**）负责。

**决议（✅ 已确认）**：**1.0 默认开（`armed=true`，来源 `default`）**。

**口径变更记录（显式覆盖，不静默）**：本文档 v1 曾建议**默认关**，理由四条（保留作历史）：
1. **无真实触发样本**：G2/G3 验的是「读数是否即时、busy 是否映射成 `busy` 而非 `failed`」，全程 `armed=false`；
2. **不可逆**：真实压缩会丢会话原文（只剩记忆指针 + 最后一句）；
3. **与 header 默认开的性质不同**：header 只**增**一段注入，提前压**改变会话历史**；
4. **与既定原则一致**：「失败显式、可回退、不静默降级」（M2 草案 §3）。

**用户 2026-10-26 拍板改为默认开**，理由变更：与 M2 草案「**提前压默认开**」的原口径一致（用户原始诉求即"提前压、去掉过时信息"）；用户在了解不可逆风险的前提下，选择以「默认开 + 可退通道」换取开箱可用。**交换条件（硬）**：默认开必须同时交付可退通道，否则等于不可控——见下表与任务单 T4。

**开关通道（✅ 已确认，最终命名由开发定，语义边界需求侧锁死）**：

| 通道 | 形态 | 约束 |
|---|---|---|
| 内置默认 | `compact.early.armed = true` | 来源 `default`；**`compact.early=false`（profile 策略）始终优先**，命令不可绕过 |
| 配置 | 插件配置 `compact.early.armed: false` 关闭 | **项目层出现该键即不生效**（忽略该键 + `policy-invalid`；既不能开也不能关，审核 §4.6 定论）；**不做环境变量** |
| 命令 | `/cg compact arm` / `/cg compact disarm` | 只影响当前会话，会话结束回默认；`/cg status` 显示来源 |
| 状态 | `/cg status` 一行 `early=on (default\|config)` / `off (config\|session-disarm\|policy:…)` + `last-early=…` | 一眼看出开/关与原因 |
| 审计 | `early-armed` / `early-disarmed`（来源 + 会话短 id） | 与 `early-forced` / `early-aborted` / `early-failed` 同族；不写正文 |

**默认开的风险边界与回退（用户要求写清）**：

| 风险 | 控制 | 回退 |
|---|---|---|
| 真实压缩不可逆 | 每次触发留 `early-forced` + `compaction-cost`；`/cg status` 可查最近一次决策 | 会话内 `/cg compact disarm`（立即生效，0 触发） |
| 默认开用户不知情 | `/cg status` 明示；README 首屏风险提示；首次触发 logger 一行 info（不含正文） | 配置 `compact.early.armed=false` 全局关 |
| busy 误判成失败 | busy → `early-aborted`（**不得写 failed**） | 沿用 0.2.2 已验映射 |
| 恶意仓库打开 | 项目层出现该键即忽略 + `policy-invalid` | 无（不开放） |

**关闭必须可证**：三层回退（会话 / 配置 / profile）各留证据——`compactNow` 调用计数 0 且无 `early-forced`；不能只写文档。细节见任务单 T4。
