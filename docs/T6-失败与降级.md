# T6 · 失败与降级（v0.1.4）

> 目标：所有失败路径**可预期、可回退、显式告警**，且**不抛宿主**；降级后仍能跑完一次完整压缩周期。
> 代码：`packages/dsh-context-governance/src/{compress/runtime.js,audit.js,memory/store.js}`；测试：`test/t6-degradation.test.mjs`。

## 1. 失败矩阵

| 失败 | 触发 | 行为 | 留痕 | 测试 |
|---|---|---|---|---|
| 保护写盘失败（EACCES/EPERM/EROFS/ENOSPC/EBUSY/只读） | `protectSync` 抛错 | 转只读，**本周期继续**；之后不再尝试写 | `logger.warn`（一次/原因）；audit 不可写时不写 | `T6-readonly-root`、`T6-external-change` |
| 其他保护写失败 | `protectSync` 抛非 IO 错 | `degraded-protection`，压缩继续 | `protection-write-failed` audit + warn | T4-4（已有） |
| 审计追加失败 | 目录不可写/被占 | 只计数 + warn，**不抛**，周期照常完成 | `audit write failed (<code>)` | `T6-audit-failure` |
| `ctx.on` 抛错 | events 服务不可用 | guard 不 start，插件其余功能正常 | `registration failed` warn | `T6-ctx-on-throws` |
| 事件流中断（start 后无 end 又来新 start） | 同会话 pending 未清 | 丢弃旧周期并继续新周期；旧周期不再等待 | `cycle-interrupted` audit + warn | `T6-cycle-interrupted` |
| 插件卸载时周期未 end | dispose | 清 pending，不静默 | `cycle-abandoned` audit | `T6-cycle-interrupted` |
| 记忆被外部改动 | 写前 hash/stamp 比对 | 存储转只读；周期继续（读旧记忆、回注既有指针）；`reload()` 或下一次 start 探测可恢复 | `memory read-only (external-change)` warn | `T6-external-change` |
| 记忆根不可写 | 装载时写探测失败（含 mkdir/锁失败） | 整体只读：能读、能回注，**不写记忆、不写审计正文**，压缩不被阻断 | 启动行 `memory-read-only=<原因>` + warn | `T6-readonly-root` |
| 回注失败 | `session.append` 抛错 | `observe-only`，下一周期不再写/注 | `reinjection-failed` audit + warn | T4-5（已有） |

## 2. 只读降级

**触发判据**（任一成立）：

1. 装载时 `mkdir(<memoryRoot>/topics)` 失败（`root-not-writable:<code>`）；
2. 装载/恢复时写探测 `probeWritable()` 失败（写临时文件再删，`root-not-writable:<code>`）；
3. 写者锁被其他活跃进程持有（`writer-lock:<pid>`）；
4. 写前外部改动检测命中（`external-change`）；
5. `protectSync` 抛 IO 类错误（`write-failed:<code>`）。

**只读时的语义**：

- 不写记忆（不建 journal、不改主题文件、不重建索引）；
- 不写审计（`AuditLog` 可能根本建不出来）；失败改走 `logger.warn`，同一原因只告警一次；
- **能读**（`mem_query`、`allEntries`、索引）与**能回注**：回注来源改为本会话既有的保护条目（`source=session:<id>#…`），不再新增写入；
- 压缩周期照常走完，报告与降级原因在 `/cg status` 可见（`protection read-only=<原因>` + `audit-health`）。

**恢复**：每次 `compaction/start` 会尝试恢复（`root-not-writable` → 写探测；`external-change` → `store.reload()`）；探测成功即清只读，下一周期恢复写入。恢复只自动处理上面 1/2/4，写者锁与显式 `readOnly` 配置不会自动清。

## 3. 审计轮转

- 默认上限 **8 MiB**（`DEFAULT_AUDIT_MAX_BYTES`），可配 `audit.maxBytes`（64 KiB–1 GiB，整数）。
- 命名：`audit-YYYYMMDD.jsonl`；同日多次轮转追加 `-2`、`-3`（最多 999 个，极端情况 `-overflow`）。
- 触发：追加前判断 `当前大小 + 本条字节数 > 上限`；**先 rename 再写**，记录不丢；rename 失败则继续写当前文件并计数，不阻塞压缩。
- 轮转是同步 `rename`（一次压缩低频，开销可忽略）；不删历史文件（保留证据，清理留给人工/T7）。
- `/cg status` 显示 `audit: file=… max=… size=… rotations=… recentFailures=…`。

## 4. 失败显式（不抛宿主）

- `#handle` 整体 try/catch：任何观察器异常只 warn + `stats.failures`，不冒泡；
- `AuditLog.append` 永不抛；`appendDiagnosticLine` 永不抛；`start()` 注册失败只 warn；
- 每条降级都至少有一条 `logger.warn`（含原因类别）或 audit 记录（只读时 audit 不可写，用 log 兜底）；
- `/cg status` 的 `audit-health` 行汇总 `writeFailures` / `skippedReadOnly`。

## 5. 测试与结果

`test/t6-degradation.test.mjs`（7 条）：

- `T6-audit-rotate`：1500 条记录、64 KiB 上限 → 轮转命名正确、记录一条不少；
- `T6-audit-failure`：审计目录被文件占用 → 追加失败只告警、周期完成；
- `T6-readonly-root`：记忆根不可写 → 只读降级、周期完成、不写记忆/审计；
- `T6-external-change`：外部改动 → 只读 + 周期完成；start 探测恢复后写入恢复；
- `T6-ctx-on-throws`：订阅抛错不崩；
- `T6-cycle-interrupted`：无 end 的新 start → `cycle-interrupted`；dispose → `cycle-abandoned`；
- `T6-readonly-reinject`：只读下从既有记忆回注指针，不写新记忆/审计。

全量：`node --test "test/*.test.mjs"` → **全部通过（数量见测试输出）**（T2 40 + T3 56 + T4 15 + T5 7 + 感知 9 + T6 7 + T7 15）。
