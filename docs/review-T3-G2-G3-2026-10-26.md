## 4. `ok=false` 口径（00 采纳“两个正交字段”）

- 现状：`protection.js:542 ok = failures.length===0`；`runtime.js:1112` 把 `ok=false` 计入 `stats.failures`；`early.js` 的 `{ok:true}` 又是第三种含义 → **三个 ok 混用**。
- 采纳方案：`early-forced` 用 `compaction=committed|skipped|failed` + `protection=ok|failed` + `failures[]` + `reinjected`；stats 拆 `compactionFailures`/`protectionFailures`；status 用 `protection=` 或 legend；`attempt()` 返回改 `accepted`。
- 原则：`protection=failed` 不得触发重试/关开关；只有 `compaction=failed` 或 `reinjected=false` 才升级。

**`messages.length` 口径歧义（复核发现，需 00/开发定）**：`header.js` 注入是 `messages: [header, ...messages]`，**总长 = 基线 + 1**；`t7-scenarios` 测试里基线有 1 条 system，总长断言为 **2**。T3 记到 **1** 是因为当时基线为空。若把“原始数组长度”当判据，一旦宿主在 step 1 的 decision 里带上 system 消息，**零注入会读成 1**、被误判为“注入了一次”。建议口径写成 `injected=0|1`（或 `messagesBefore/After`），而不是裸 `messages.length`；`count=N` 继续表示条目行数。
