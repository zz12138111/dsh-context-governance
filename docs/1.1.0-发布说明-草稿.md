## 1. 版本与兼容

- 版本：**`1.1.0`**（`packages/dsh-context-governance/package.json:3`；运行时 `PLUGIN_VERSION` 由 `src/diagnostics.js:37` 读同一处，无第二处硬编码）。
- `engines.dsh`（`package.json:38`）：
  `">=0.2.1-rc.2 <0.2.2-0 || >=0.2.2-rc.3 <0.3.0-0"`
  - 0.2.1 线：**实测到 `0.2.1-rc.3`**（本机）；
  - 0.2.2 线：以 **`0.2.2-rc.3` 为下界**声明，`rc.4+` 与 `0.2.2` 稳定版自动在内；`rc.1/rc.2` 仍拒绝；
  - `0.3.0+` 挡住（`<0.3.0-0` 连 rc 一并挡）。
  - **不跟随** `dsh-context@0.84.1` 的 `|| >=0.2.2-rc.1` 无上限写法（未验宿主不声明）。
- 单一真源：`src/compress/adapters.js` 的 `DEFAULT_MATRIX.host` 两项，`engines.dsh === DEFAULT_MATRIX.host.join(' || ')`，有测试钉住（C1）。

## 2. 引擎门禁是什么行为（实证，非推断）

宿主 `app.asar/dsh/node_modules/@deepseek-ai/dsh-app-boot/lib/index.js`：

- `:271-278` `getDshRuntimeVersion()` 取 **app-boot 自身 package.json version**（本机 `0.2.1-rc.3`），`satisfies()` 用真 `semver.satisfies(v, range, { includePrerelease: true })`（`:15`）；
- `:311-316` 引擎未满足 → `{ requirements: { 'engines.dsh': range } }`；
- `:1015-1051` 不兼容的 profile bundle 被 **跳过**（throw → 捕获 → `skippedBundles`，patch 层不加载 ⇒ 插件不加载）；
- `:537-538` CLI 侧打印：`dsh: skipping profile bundle "<pkg>": Plugin <pkg>@<ver> is incompatible with dsh <runtime>: requirements {...}`；
- 安装/管理路径另抛 `incompatible-version`（`dsh-plugin-manager/lib/index.js:1759/2076/2288`）。

真 semver 实测（本机 `semver@7.8.5`）：旧区间对 `0.2.2-rc.3/rc.4/0.2.2` 全 **false**；本版双区间全 **true**；`0.2.2-rc.1/rc.2`、`0.3.0-rc.1`、`0.3.0` 全 **false**。
