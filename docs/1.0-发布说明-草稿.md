## 2. 核心变化

1. **全会话多根治理**：以会话 cwd 最近 `.git` 判定根；`configRoot` 非空时其下会话强制归该根。每个纳管根独立 `MemoryStore`、`memory/governance/audit.jsonl`、writer lock、guard、header 与提前压状态；A 根的事件不落 B 根。
2. **`configRoot` 强制合并**：`projectRoot` 非空时，其下嵌套 `.git` **不另立根**；`projectRoot` 外会话按自身 cwd 独立成根。已知限制：显式配置根内多根隔离不完整（v3 冻结口径，不是 bug）。
3. **state v2 与迁移**：`<home>/context-governance/root-state-<profile>.json` 使用 `roots[rootId]`；v1 自动迁移并留 `.v1.bak`；重启沿用、不重推。`primaryRoot` 只保留作 v1 迁移锚点/展示，**config 不改写持久化主根**。
4. **多根压缩面**：`RootGuardPool` 一份 `session/event` 订阅按根路由；保护/回注/成本/损失按会话根落各自 audit；`firstInferenceRootWatcher` 只在 no-root 首推期间存在，推断完成后退订，不与 pool 并存。
5. **只读根披露**：`readOnly` 根在真实压缩后显示精确 `protection=unavailable`，root audit 写 `b1-host-native-unprotected`；不再显示 `protection=ok`。
6. **安装/回滚契约**：`file:` + junction + bundle，不跑 pnpm；隔离 profile 完成 fresh、v1→v2、多根、configRoot、只读、卸载；v0.2.1 只验证**兼容回滚**（单根语义）。
7. **工程面**：`test/` 不进发布包；全量 486；包内 0 本机绝对路径。

## 4. 多根与作用域（最重要的行为变化）

- **根判定**：`configRoot` 非空 → cwd 在其下即归该根（`source=config`，嵌套 `.git` 不另立根）；否则按 cwd 最近 `.git` 推断。无 cwd / 无法判定 → fail-closed，不猜主根。
- **每根治理**：每个根各自 `memory/governance/`、`audit.jsonl`、`.writer.json`、保护 journal；第二进程同根不合并，只读/锁提示。
- **`/cg roots`**：列出全部已登记根（id/name/project/state/memory/audit 末行）；`/cg status` 也含 roots 段。
- **`/cg status`**：`project-root` 显示本会话根与来源；`memory-readonly` 只读显示；`roots:` 显示根数。
- **不再有旧版“根外不碰”的作用域语义**：可判定根都纳入治理；`configRoot` 外的根独立纳管。

**已知限制**：显式配置根内多根隔离不完整——`projectRoot` 下嵌套 `.git` 归外层根，不单独隔离。发布说明必须保留这句。

## 5. 提前压（默认开启）

当会话上下文压力达到或超过 `compact.at`（默认 **0.60**）且低于宿主 `native−0.02` 时，插件在 `turn/end` 后 50ms 调用宿主 `compactNow`，触发**真实压缩**。压缩不可逆，原文只剩摘要与记忆指针。

关闭通道：
1. 当前会话：`/cg compact disarm`（`/cg compact arm` 恢复）；
2. 全局：配置 `compact.early.armed: false`；
3. profile：`compact.early: false`（`research` 已预置）。

项目层 `.cg-policy.json` 不能开关 armed；**不存在环境变量开关**。关闭提前压不阻止宿主原生压缩。

## 7. 已知限制

### 7.1 记忆工具按根，但 1.0 不做跨根查询

`mem_write` / `mem_query` 通过会话根 resolver 限定本根；跨根查询 1.0 不做。无根/未纳管/fail-closed 的会话拒绝并审计 `memory-tool-rejected`。

### 7.2 自动去重未实现

重复写入不会自动 supersede；同类 `active` 条目超过 header 配额时旧条目也可能注入。用 `mem_write` 的 `supersede` / `expire` 显式处理。

### 7.3 其他

- 不提供动作校验（pre-execute 拦截）、折叠/账本。
- `engines.dsh` 只承诺 `>=0.2.1-rc.2 <0.2.2-0`；0.2.2+ 拒载。
- `/cg status` 的 `adapter=` 是插件侧识别结果，不等于实际后端；后端以 profile redirect + bundle 为准。
- `trigger=manual` 不等于用户手动压缩：插件提前压走宿主 manual API 路径，宿主按 manual 记录。
- `compaction-loss` 与四件套可同时存在：保护校验失败不阻断压缩，但必须如实出现在审计与报告中。
