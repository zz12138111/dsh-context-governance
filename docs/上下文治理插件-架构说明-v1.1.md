# 上下文治理插件 · 架构说明

> 版本：v1.1（事实回写）
> 日期：2026-10-25
> 状态：架构定稿。v1.1 为**事实回写**，不改变架构主张；其余仍只接受实验回写与措辞修订。
> 变更：见 §19 版本记录（v1.1 修正 preset 阈值、tokenMeter 口径、`ctx.compaction` 可得性、工具输出折叠取消）。

## 0. 一页摘要

**问题**：长会话的上下文越来越贵；压缩之后容易接不上；已经定下的事、批次进度、判据没有稳定落点，导致重复决策和返工。

**方案**：不做第二个压缩引擎、记忆数据库或配置框架；只做一层薄治理——

1. **任务态契约**：决定、偏好、待办、进度、判据、锚点；
2. **压缩保护与固化**：持续固化为主、压缩钩子为辅；
3. **按语义回注**：默认只放 ID/状态/指针，详情留记忆；摘要不可读就只读；
4. **策略与审计**：什么时候做、做到什么程度、有没有守住。

**复用**：压缩沿用现成后端；M1 支持宿主默认与 context-zip，billion-context（ACP）在 E3/E4 通过前只进“只读模式”或不接入；配置用宿主设置与 Schemastery；观测用宿主 token 计量与 context 面板。

**记忆**：内置最小文件存储；调用少、要求低；不引入数据库，不依赖第三方记忆插件。

**边界**：不改 DSH、不接管会话、不保存原始对话、不做领域专用功能。

**形态**：单插件、对宿主零硬依赖、可选后端软适配、标准安装；本机自用 + 通用发布。

## 1. 背景与问题

### 1.1 三个反复出现的问题

| 问题 | 表现 | 后果 |
|---|---|---|
| 上下文膨胀 | 对话越长，每次模型调用都要重读全部历史；工具输出、工具定义占很大比例 | 成本随轮次上升；接近上限时被迫压缩 |
| 压缩后断线 | 摘要把任务状态、决策、批次进度丢掉；压缩后要重新问、重新找 | 长任务接不上；严重时返工 |
| 重复与无痕 | 已拍板的事被重问；批次中断只能翻对话猜进度；判据只存在于对话里 | 返工成本高于“写下来”的成本 |

### 1.2 一个基本判断

**会话是易失的，项目是长期的。** 要点应该跟项目走，而不是跟某一次会话走。压缩、换会话、定时唤醒，本质是同一件事：当前上下文不要了，但任务还要继续。

### 1.3 两种“真相”

- **原始对话**：证据真相。由 DSH 保存，只读，插件不删不改。
- **项目记忆**：操作真相。唯一长期可写的状态，决定“接下来做什么”。
- **摘要、索引、每轮视图**：派生数据。由对话和记忆生成，不能反过来覆盖记忆。

## 2. 目标与非目标

### 2.1 目标

1. **长会话可续**：压缩、换会话、定时唤醒后能接上，不用重新问。
2. **花费可控**：能看见上下文构成，能按策略减少进入量。
3. **用户可定义策略**：用配置文件表达“什么时候、对什么、做到什么程度”，不写代码。
4. **通用**：标准 DSH 插件，桌面/Web 可用；不绑定业务领域。
5. **稳定**：失败显式、原文可回读、可整体禁用或摘除。

### 2.2 非目标

- 不写压缩引擎；
- 不写通用记忆数据库、向量库、embedding 服务；
- 不写配置框架或新的设置 UI 框架；
- 不写内容安全 guardrail；
- 不做调度器；
- 不修改 DSH 本体、不接管会话循环；
- 不做某个领域（影音、游戏、开发等）的专用功能。

**关于“全局偏好”**：可以有一个很小的全局偏好文件，但默认关闭、只放偏好与教训、不放任务状态；它不是“全局记忆库”，也不跨机器同步。

## 3. 总体结构与定位

```
DSH 与现成插件
  ├─ 压缩后端：宿主默认 / context-zip / billion-context（M1 前两个）
  ├─ 设置与配置：cordis.patch + 设置页 + Schemastery
  ├─ 计量：token meter / context 面板
  └─ 文件策略与审批
            │ 适配（薄，行为契约）
┌───────────┴──────────────────────────────┐
│ 治理层（自研薄层）                         │
│  任务态契约 · 策略与保护 · 压缩前后 · 审计  │
│  内置最小记忆（项目文件夹）                 │
└───────────────────────────────────────────┘
```

### 3.1 一句定位

**现成的轮子继续用；我们只做把轮子接起来的治理层，并把后端的差异挡在治理层之外。**

### 3.2 复用与自研边界

| 能力 | 直接复用 | 我们只做薄层 |
|---|---|---|
| 压缩 | 宿主 `compaction-basic`、context-zip；billion-context 待验证 | 行为适配、保护清单、持续固化、按语义回注、审计 |
| 记忆 | 不引入外部存储 | 最小文件存储、任务态契约、索引、原子写、确认/冲突/过期 |
| 校验 | Schemastery/JSON Schema；宿主文件策略与审批 | 固定检查库、受保护内容检查 |
| 配置 | `cordis.patch` + 设置页 + Schemastery | 策略 schema、解释生效来源、干跑 |
| 观测 | token meter、context 面板、cost meter | 动作审计、压缩前后归因、成本归属 |

**不写**：压缩引擎、通用记忆数据库、配置框架、内容安全 guardrail、调度器、向量库。

### 3.3 为什么这样分

- 压缩、记忆、配置都是成熟领域，重复实现只会带来维护负担和冲突；
- 但“任务态契约、压缩保护/固化/回注、策略解释、审计”是现有插件普遍不做的缺口；
- 后端差异通过“行为契约”隔离，治理层不按后端名字写 if-else。

## 4. 核心不变量

以下不交给用户配置：

1. **原始对话只读、可回读**：插件不删、不改、不搬原始记录。
2. **项目记忆是唯一长期可写状态**：摘要、索引、每轮视图都是派生，不得反向覆盖记忆。
3. **摘要不是执行依据**：摘要用于接续与检索；摘要里出现的决定，若尚未进入记忆，标为“待确认”，执行前必须查记忆。
4. **摘要不得绕过记忆**：压缩前发现的新要点先写记忆（带来源）；后端不支持引用记忆时，压缩后审计并补录，不假装能强制。
5. **回注只放指针，详情留记忆**：回注只放记忆 ID、一行状态、指针；详情通过记忆工具按需读取，不把自由文本塞回摘要旁边。
6. **摘要不可读则回注退化；完全不可见才只读**：后端摘要无法读取时，回注退化为“ID + 状态 + 指针”；若连压缩范围/产物都不可见，治理层对该后端只做记忆与审计，不做回注和压缩干预。
7. **摘要与记忆冲突时记忆赢**：标记冲突，不把摘要里的说法当执行依据。
8. **折叠可回读**：任何被折叠的内容，保留原文或可定位的指针。
9. **失败显式、回退默认**：插件失败不影响 DSH；配置非法时插件不加载，DSH 继续用默认行为。
10. **受保护内容按 S4=B 处理**：压缩前先把受保护内容写进记忆（标题+指针），压缩后从记忆回注。自动压缩下，最新用户消息、规则注入、工具配对、批次 STATE、回滚点映射 0 丢失；手动压缩允许原文丢失（宿主仅保留最后 1 个 surface 节点，治理层无否决权），但必须有记忆指针、audit 显式告警、回注后能看出“最后一句是什么”。任何“写不进/注不进”必须 audit，不静默。
11. **定时唤醒只读记忆**：只注入摘要与未完成批次，不拉整段历史。
12. **同一时间只有一个压缩后端**：不自建第二压缩，不与宿主或其他插件抢 provider；冲突显式提示。
13. **记账用宿主口径**：上下文用量以 DSH 自己计量为准，不另造“省钱数字”。

## 5. 记忆：内置最小文件存储

### 5.1 定位

- 只记**任务态**：决定、偏好、待办、进度、判据、锚点。
- **调用少、要求低**：不做向量检索、不做 embedding、不做复杂查询；关键词、文件路径、按需读取足够。
- 不替代原始对话；不追求“记住一切”。

### 5.2 存储约定

- 放在**项目文件夹**里，跟项目走；新会话、压缩后、定时唤醒都读它。
- 结构参考成熟做法：一份索引（`MEMORY.md`，一行一条）+ 主题文件；索引只注入摘要或按需读取。
- 项目/领域一个命名空间；同一项目多会话时按写者分目录，避免互相覆盖。
- 原子写（临时文件 + 重命名）；文件可 git 管理、可人工编辑。
- 敏感信息不进记忆；支持本地专用文件与忽略规则。

### 5.3 最小结构

| 字段 | 含义 |
|---|---|
| `id` | 稳定编号，便于摘要引用与去重 |
| `type` | 决定 / 偏好 / 待办 / 进度 / 事实 / 判据 |
| `status` | 待确认 / 生效 / 已被取代 / 过期 |
| `project` | 归属项目或领域 |
| `title` | 一行摘要 |
| `detail` | 必要细节，不抄整段对话 |
| `source` | 来源会话与消息位置（指针，不是原文） |
| `writer` | 用户确认 / 规则提取 / 模型提取 |
| `confidence` | 可信度；模型提取必须标 |
| `时间` | 创建、更新、过期 |
| `supersedes` | 取代了哪条旧记录 |
| `evidence` | 证据指针：文件、哈希、日志位置 |

### 5.4 写入来源与确认

- **用户确认**：可以直接生效。
- **规则提取**：低风险进度、批次计数可直接生效；高风险动作必须待确认。
- **模型提取**：默认“待确认”，不直接生效。
- **高风险**（不可逆删除、预算、权限、技术路线变更）：先入“待确认”，压缩可以继续，但**执行动作**必须等确认。

### 5.5 冲突与过期

- 不原地覆盖；新记录用 `supersedes` 指向旧记录。
- 两条记录矛盾时标记冲突，等确认；不自动合并成“折中说法”。
- 过期用状态标记，不静默删除；删除留一行“谁删、删什么、为什么、何时重议”。

### 5.6 并发写（M1 的硬语义）

- **进程内**：索引写入走单写者队列，串行化；原子写（临时文件 + 重命名）保证文件不损坏。
- **跨进程**：M1 不承诺合并；检测到外部修改（mtime/hash 变化）时告警，必要时转只读。
- **多会话同项目**：如果同时有多个写会话，显式提示用户避免；不假装“加锁就安全”。
- 合并靠 `supersedes` 与状态，不做“最后写入者赢”。

### 5.7 敏感信息与项目识别

- **敏感**：不存凭据、密钥、账号密码；必要时只存引用位置；审计日志同样脱敏。
- **项目识别**：优先显式配置；没有配置时退到 git 根目录；再没有则用路径规则；跨项目不自动继承。

### 5.8 不做什么

- 不做数据库、向量检索、embedding 服务；
- 不做全局记忆库；
- 不自动把所有对话都“记下来”；
- 不依赖第三方记忆插件（未来可作为可选适配，但不是默认）。

## 6. 压缩：行为契约与后端适配

### 6.1 原则

- **不写引擎**。
- 默认**不强制替换**：当前 profile 已装什么后端就用什么；没有就用宿主默认。
- 用户可显式指定后端；切换失败时回退默认，并明确提示。
- **M1 支持**：宿主默认 + context-zip，且以**事件级契约**为准——本插件 scope 拿不到 `ctx.compaction`（见 §6.8），因此不参与 provider 选择。**billion-context（ACP）** 在 E3/E4 通过前不接；拿不到可见性时只进“只读模式”。

### 6.2 行为契约（不是“能力声明”）

适配器至少要说明九件事：

| 维度 | 取值 | 为什么重要 |
|---|---|---|
| **控制权** | 宿主触发 / 治理触发 / 模型工具触发 / 混合 | 决定“压缩前固化”能否在正确时机发生 |
| **感知层级** | 事件级 / 工具级 / 状态级 | 决定治理层能否知道压缩开始、范围与结束；M1 最低要求状态级 |
| **触发面** | 压缩事件 / 工具调用 / 引擎调用 | 从哪里感知压缩 |
| **前/后钩子** | 支持 / 尽力 / 不支持 | 决定固化是钩子还是持续写入 |
| **摘要权威** | 独占 / 共享 | 决定回注是“补充未完成事项”还是“可叠加” |
| **摘要可读性** | 可读 / 部分可读 / 不可读 | 决定回注形态：标题+指针 / 仅 ID+状态 |
| **改写边界** | 替换事件 / 插入私有事件 / append / 是否维护工具配对 | 决定保护清单是“执行者”还是“校验者” |
| **可观测性** | 压缩成本是否经宿主计量 / 能否看到范围与产物 | 决定审计与成本归因的可信度 |
| **契约自检** | 初始化时能验证哪些行为 | 防止版本升级后“能跑但漂移” |

其余用能力开关：能否按段回读、能否搜索、是否支持摘要引用记忆 ID、已验证版本范围。

### 6.3 现有后端的行为矩阵（E1/E2 实测回写，2026-10-25）

> 实测口径：宿主 0.2.1-rc.2（asar，E1/E2 时点；当前部署为 rc.3）；context-zip 0.1.10（profile redirect 接管 `compaction-basic` 行）；47 会话 / 16 次真实压缩（10 手动 + 6 自动；五段式 10、自由 6；0 失败；16/16 有 usage）；最长会话 7 次压缩。ACP 未安装/未验证。
>
> **补充（2026-10-25）**：真机的“事件级验证”来自 **redirect 接管后的宿主事务**；**宿主默认后端（未被接管）未单独跑**。表中“M1 默认”指宿主契约，不等于“宿主默认后端已实测”。

**控制与感知**

| 后端 | 控制权 | 感知层级 | 触发面 | 前/后钩子 | 状态 |
|---|---|---|---|---|---|
| 宿主 `compaction-basic`（0.2.1-rc.3） | 宿主压力（`agent/pre-step` 阈值判定；**引擎在 preset：`thresholdRatio 0.8` + `headroomTokens 65536`，有效点 ≈67.85%；patch 层 `thresholdRatio` 不生效**）+ 手动 `/compact` | **事件级（已验证）**：`compaction/start`→`summary`→checkpoint→`end` 均为持久会话事件，`ctx.on('session/event')` 可观察 | 压缩事件（`session/event`）+ 命令（`/compact`） | **约束：无拦截型前钩子**。`start` 在摘要调用前同步发出，但无范围/否决能力，只能确认固化，不能改范围或阻止；后钩子=`end`；失败恢复=`compaction/summary-error` waterfall | M1 默认 |
| `context-zip`（0.1.10，接管该行） | 同左 + 手动 `/zip-compact`（manual seat） | **事件级（已验证）**；唯一覆写 `summarize()`，事务与事件继承宿主 | 同左 | 同左 | M1 支持 |
| `billion-context`（ACP） | 模型工具触发（文档口径，**未安装/未验证**） | 未验证 | 工具调用 | 未验证 | M1 不接（只读/未接入） |

**摘要与改写**

| 后端 | 摘要权威 | 摘要可读性 | 改写边界 | 保护角色 | 状态 |
|---|---|---|---|---|---|
| 宿主 `compaction-basic` | 独占 | **可读（已验证）**：`compaction/summary.summary` 纯文本；实测 6 次自由摘要 2,260–11,640 字符 | 替换 surface span 为 1 个 compact-checkpoint `user/message`（`surfaceOp.replace`）；工具配对由宿主维护（选择时 balanced，提交前再断言） | 宿主=执行者；治理层=校验者/观察者 | M1 默认 |
| `context-zip` | 独占 | **可读（已验证）**：五段式，10/10 命中 5 个标题；实测 10 次 3,096–5,018 字符 | 同左（不额外写会话事件；只改摘要生成） | 宿主/后端=执行者；治理层=校验者/观察者 | M1 支持 |
| `billion-context`（ACP） | 独占（模型自写 checkpoint）；记忆只做补充 | 部分可读/不可读（**未验证**） | 插入 replace/checkpoint 节点；append-only 原文（**未验证**） | 校验者/观察者（**未验证**） | 只读或待验证后接入 |

**实测对回注策略的约束（E2）**

- 6/6 真实压缩对显示：checkpoint 之后注入的内容，会落在下一次压缩的 shadow 区间内，被下一次摘要吞掉；下一次压缩的起点通常就是上一次 checkpoint。
- 因此回注时机固定为：`compaction/end` 发布后的**首个 microtask** 注入一次（同一 tick、下一次模型调用前）；会话开始/唤醒再注入一次；不每步/每轮注入。
- **实现约束**：不在 checkpoint 之后、end 之前插入——checkpoint 的 append 处于发布期，`session.append` 重入会被宿主拒绝；宿主在同一同步栈里立刻发 `end`，中间没有可插入窗口。字面时序需替换压缩 provider；**该路径已结案不可行**（本插件 scope 未提供 `ctx.compaction`，`strict=false → undefined`）。**根因已定位**：preset 组 `isolate.compaction: true`（`dsh-web-app/presets/standard.patch.yml`），压缩服务被隔离在 preset scope。M1 以 end 后 microtask 为准。
- 注入前查当前表面是否已有同一 ID 行，治理层自己做去重（引擎不去重）。
- “被吞”审计口径：记录注入 `seq` 与当时 `compactionId`；下一次 `compaction/summary` 到达时，若 `injectionSeq ∈ shadowedRange`，标记“被吞”。
- 默认形态仍是 ID+状态+指针；只有“摘要可读且未覆盖”时补一行标题；详情永不回注。

**保护口径（S4=B）**：压缩前先把受保护内容写进记忆（标题+指针），压缩后从记忆回注。自动压缩：最新用户消息、规则注入、工具配对、批次 STATE、回滚点映射 0 丢失；手动压缩：允许原文丢失（宿主仅保留最后 1 个 surface 节点，治理层无否决权），但必须有记忆指针、audit 显式告警、回注后能看出“最后一句是什么”。任何“写不进/注不进”必须 audit。

> 表中“未验证”只适用于 ACP；宿主与 context-zip 的“待验证”已由 E1/E2 替换。

### 6.4 治理层职责：按控制权分，不按后端分

| 控制权 | 固化 | 保护 | 回注 | 审计 |
|---|---|---|---|---|
| 宿主压力 | **持续固化为主**；**无拦截型前钩子**（`compaction/start` 只作通知，用于确认固化已发生），压缩后审计补录 | 校验者：压缩前断言配对/保护清单完整，不自己改写 | 读摘要 → 比覆盖 → 只放 ID/状态/指针；详情查记忆 | 必须有：压缩前后范围、用量、失败 |
| 模型工具 | 持续固化 + 拦截 `compress` 工具调用（若可用）；不可拦截则事后审计 | 校验者/观察者：能断言就断言，不能就记录 | 工具返回后，下一轮只放 ID/状态/指针；摘要不可读就仅 ID+状态 | 必须有：谁触发、范围、产物 |
| 治理触发（未来） | 前钩子 | 执行者 | 按摘要权威回注 | 必须有 |

**“压缩前固化”的准确含义**：不是“一定在压缩那一刻写”，而是“**确保固化已经发生**”。主机制是回合结束/决策产生时持续写；压缩钩子只是补一次，不能依赖它。

### 6.5 回注规则：读摘要、比覆盖、只放指针

回注前做三步：

1. **读摘要**：如果适配器声明摘要可读，读取本次压缩的摘要视图（文本或条目 ID）；不可读则跳到第 3 步。
2. **比覆盖**：先按记忆 ID 匹配，再按标题关键词粗匹配。命中则视为“摘要已覆盖”；不命中则视为“未覆盖”。匹配是启发式，不承诺 100% 准确。
3. **选形态**：

| 情况 | 回注内容 | 说明 |
|---|---|---|
| 摘要可读，条目已出现 | `D-017 仍生效（见记忆）` | 只放 ID + 状态 + 指针 |
| 摘要可读，条目未出现 | `D-017 待确认：<一行标题>（见记忆）` | 可补一行标题，仍不放详情 |
| 摘要不可读 | `D-017 待确认（详情查记忆）` | 明确“摘要不可读”，只放 ID + 状态 |
| 摘要与记忆冲突 | 以记忆为准，标记冲突 | 不把摘要里的说法当执行依据 |

**硬规则**：

- **详情永不回注**；详情通过记忆工具按需读取；读取失败时只保留 ID/状态。
- 回注有 token 预算；超预算先删标题，保留 ID/状态/指针。
- **时机：只在 `compaction/end` 发布后的首个 microtask 注入一次**（同一 tick、下一次模型调用前）；会话开始/唤醒再注入一次；不每步/每轮注入（E2：同一周期重复注入会重复，引擎不去重）。
- 注入前查当前表面是否已有同一 ID 行；有则不重复写。
- 回注内容优先用短指针；被吞无法避免时，审计记录“回注被吞”（`injectionSeq ∈ shadowedRange`），不重复尝试同形态。

### 6.6 保护清单：执行者还是校验者

- 如果后端已经维护工具配对、保护注入行，治理层只做**压缩前断言**与**压缩后核对**，不重复改写。
- 如果后端不维护，治理层才需要在适配器里调整范围或阻止本次压缩。
- 具体由 6.2 的“改写边界”声明；不在治理层写后端特判。
- **S4=B 口径**：自动压缩 5 类受保护内容 0 丢失；手动压缩允许原文丢失，但压缩前必须把标题+指针写进记忆、audit 必须显式告警、回注后要能看出“最后一句是什么”；写不进/注不进必须 audit。手动压缩无否决权，治理层不假装能阻止。回注时序按 §6.3：`compaction/end` 发布后首个 microtask，不在 checkpoint/end 之间插入。

### 6.7 降级阶梯

```
契约自检通过 + 版本在矩阵内 → 全功能
仅摘要不可读                → 回注退化为 ID+状态+指针；详情查记忆
契约自检失败 / 版本不符     → 回退宿主默认压缩；治理层继续保护与审计
宿主默认也不可用            → 治理层只做观测 + 记忆固化，不做压缩干预
摘要/范围/产物都不可见       → 该后端只读：记忆 + 审计，不回注、不干预
每一步都显式报告，不静默
```

“契约自检”在适配器初始化时执行，不只查版本号，还查关键行为：摘要是否可读、分段是否可回读、压缩事件是否可感知、工具配对由谁维护。自检失败视为适配器不可用。

### 6.8 冲突检测

至少检查五类：

1. `ctx.compaction` 是否已被其他插件占用（**注：本插件 scope 不可得**——`ctx.get('compaction', false)` 返回 `undefined`，**根因是 preset 组 `isolate.compaction: true`**，服务被隔离在 preset scope；此项降级为“无法检测，按事件级假设处理”）；
2. 宿主的 `compaction-basic` 是否仍然活跃（与替换型后端冲突）；
3. 其他插件是否声明了压缩相关扩展点（接管、禁用基础压缩、工具结果剪枝）；
4. 适配器与后端版本是否在已验证矩阵内；
5. **控制权冲突**：后端是模型工具触发，而治理层拿不到 `compress` 的拦截点或范围可见性。

检测到冲突时，报告：**当前生效的是哪个后端、治理层哪些能力被降级、建议用户怎么处理**，而不是只弹一句“冲突”。

## 7. 校验：配置 + 动作

### 7.1 配置校验

- 用 Schemastery / JSON Schema 校验字段类型、取值范围、互斥关系；
- 声明**最低已验证的 Schemastery 版本**；低于该版本时健康检查告警，不假设校验一定生效；
- 配置非法：**插件不加载**，在设置页/命令/日志显式报告；DSH 继续运行；
- 支持干跑：只校验、不执行。

### 7.2 动作校验

- **固定检查库**：命名检查项（如“删除前必须有回滚映射”“入库前确认上级目录不是剧集”），配置只引用检查项，不写任意脚本；
- **受保护内容检查**：压缩/折叠前确认保护清单未被覆盖；
- **高风险动作**：复用宿主权限与审批，不自己造审批系统；
- **内容安全**：不在本插件范围。

### 7.3 不做什么

- 不写 guardrail 引擎；不做内容审查；v1 不执行用户任意脚本。

## 8. 配置与策略

### 8.1 四层配置

从低到高：**内置默认 → 插件配置 → 项目配置 → 会话覆盖**。后者覆盖前者；任何一层都可只写差异。复用宿主 `cordis.patch` 与设置页，不新造配置系统。

### 8.2 规则四要素

- **条件**：任务类型、上下文压力、轮次、工具调用量、手动；
- **动作**：折叠、注入、压缩、限制工具、提醒；
- **保护**：哪些内容不能动；
- **预算**：注入多少、保留多少、压缩后剩多少。

规则是配置文件，不是代码；启动时校验，非法直接拒绝；支持解释“最终生效的是哪一层、哪条规则、为什么触发”。

### 8.3 不做什么

- 不写配置框架；不新造设置 UI 框架；不承诺任意脚本扩展（留接口，后议）。

## 9. 运行流程与生命周期

### 9.1 一次会话的流程

1. **开始 / 唤醒**：读项目记忆，注入一小段摘要（目标、待办、最近决定、关键约束）。
2. **每次模型调用前**：按策略决定是否补充提醒、是否限制工具、是否提示批量。
3. **工具返回后**：不做折叠（M1.1 折叠已取消）；大结果由宿主 `tool-result-pruner` 在压缩点处理，我们只观测与记账。
4. **回合结束 / 决策产生**：持续固化要点到项目记忆。
5. **到压缩条件**：确保固化已发生 → 调用当前压缩后端 → 读摘要、比覆盖 → 按形态回注 → 记录审计。
6. **结束**：更新记忆与审计；原始对话仍在 DSH 日志里。

### 9.2 生命周期与失败语义

| 阶段 | 输入 | 输出 | 重复执行是否安全 | 失败时回退 | 告警 | 预算 |
|---|---|---|---|---|---|---|
| 开始 / 唤醒 | 项目标识、记忆文件 | 每轮视图的初始摘要 | 是 | 空摘要，继续会话 | 记忆不可读时告警 | 摘要 token 上限 |
| 模型调用前 | 视图、策略 | 注入内容、工具状态 | 是 | 跳过注入，用默认工具面 | 注入失败告警 | 注入 token 上限 |
| 工具返回后 | 工具结果 | 不折叠（仅观测） | 是 | — | — | — |
| 持续固化 | 决策/进度/事件 | 记忆条目 | 是（幂等写入） | 下次补写 | 写失败告警 | 条目数/字节 |
| 压缩 | 旧对话、保护清单、后端 | 摘要、被收起范围、审计 | 视后端而定 | 回退宿主默认压缩 | 必须告警 | 调用次数/时间 |
| 回注前 | 摘要、记忆 | 覆盖判断、回注形态 | 是 | 摘要不可读 → 仅 ID+状态 | 覆盖判断失败告警 | 读取/匹配时间 |
| 压缩后 | 摘要、记忆 | 回注后的视图 | 是 | 只注入最小 ID/状态/指针 | 回注失败告警 | 注入 token 上限 |
| 回合结束 | 事件、用量 | 指标、审计记录 | 是 | 先缓存，下次补写 | 写失败记日志 | 字节上限 |
| 会话结束 | 状态、未决项 | 记忆更新、收尾记录 | 是 | 下次开始时补写 | 写失败告警 | 时间/字节 |

### 9.3 恢复路径

- **记忆写入失败**：不阻塞会话，下次补写；若紧接着要压缩，先重试一次，仍失败则跳过本次压缩并告警。
- **压缩失败**：回退宿主默认；默认也失败时，保留原上下文并报错，不丢原文。
- **摘要不可读**：回注退化为 ID+状态+指针；若范围也不可见，进入只读模式。
- **记忆文件损坏**：进入只读，使用最近备份；不阻塞会话，但告警。
- **插件被禁用**：行为无残留；记忆文件仍在，可人工读取。

## 10. 与 DSH 的集成

- **只使用公开接口**：读取事件与用量、模型调用前补充内容、适配压缩后端、注册工具/命令/设置页。
- **对宿主零硬依赖**：只装宿主也能用；context-zip、billion-context 是**软适配**。
- **软适配的边界**：适配器随插件发布，但只对已验证的后端版本生效；初始化做契约自检；自检失败或后端升级后行为漂移，走 6.7 降级。
- **标准安装/卸载**：普通 DSH 插件；可整体禁用；卸载后不留行为残留。安装方式见下方“安装/升级约束”。
- **冲突检测**：见 6.8；不静默。
- **版本检查**：接口不匹配时降级并报告原因。
- **S4 口径**：受保护内容按 6.3/6.6 的 S4=B 处理——自动压缩 5 类 0 丢失；手动压缩允许原文丢失，但必须有记忆指针、audit 告警、回注后能看出“最后一句是什么”。

**安装/升级约束（2026-10-25 实测）**

1. **装载通道已验证**：`cg-stub` 三次 apply 成功；本地插件可装载，事件观察器能注册。
2. **不要把 `dsh plugin add <本地路径>` 当默认安装方式**：实测会 prune（`Packages: -33`）、把 `@deepseek-ai/dsh-compaction-basic` 的 redirect 版本挪进 `node_modules\.ignored`、并用 `link:` 写 lock。标准安装应使用 **`file:` 协议 / 显式 patch + bundle 登记**；安装后必须跑 `check-env.ps1`，全绿才算通过。
3. **写 `.dsh` 下任何 JSON 必须 UTF-8 无 BOM**：PowerShell 5.1 的 `Set-Content -Encoding UTF8` 会写 BOM，DSH 的 `JSON.parse` 直接失败，导致 `workspaceRegistry` 挂起、工作区全不可用。已真实发生一次，由另一会话修复；插件写配置/状态时必须显式使用无 BOM 写法。

## 11. 关键设计决策

| 决策 | 选择 | 理由 | 替代方案 |
|---|---|---|---|
| 架构厚度 | 薄治理层 + 行为契约适配 | 不重复造轮子；后端差异被隔离 | 全栈自研 |
| 记忆存储 | 内置最小文件存储 | 调用少、要求低；零依赖、可读可 git | 数据库、第三方记忆插件 |
| 压缩后端 | 可插拔；M1 宿主 + context-zip | 社区百花齐放；先用稳的，ACP 验证后接 | 自研引擎、强制单后端、一次接三个 |
| 固化时机 | 持续固化为主、钩子为辅 | 不依赖后端私有钩子 | 只靠压缩前钩子 |
| 回注 | 只放 ID/状态/指针，详情留记忆 | 避免与摘要冲突、避免被二次压缩吞掉 | 回注自由摘要/详情 |
| 回注不可读 | 只读 + ID/状态 | 不假装能读懂摘要 | 猜摘要内容 |
| 保护角色 | 后端维护则校验，不重复改写 | 防止“薄层变厚” | 治理层全量接管 |
| 配置 | 宿主配置 + Schemastery | 复用成熟校验与设置页 | 自研配置框架 |
| 校验 | 固定检查库 + 宿主审批 | 安全、可解释、可控 | 通用 guardrail 引擎 |
| 观测 | 复用宿主计量 + 成本归属 | 避免第二套数字 | 自建全量面板 |

## 13. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 覆盖判断误判（漏判/误判） | 默认只放 ID/状态/指针；详情不回注；E2 实测三种形态 |
| 摘要不可读，回注无效 | 退化为 ID+状态；范围也不可见则只读 |
| 回注被二次压缩吞掉 | 短指针；审计“被吞”事件；不重复同形态 |
| 摘要与记忆冲突 | 记忆赢；标记冲突；不把摘要当执行依据 |
| 适配器把后端复杂性吸进治理层 | 只按控制权/摘要权威/改写边界分支；不支持的后端标只读 |
| 适配器版本漂移 | 契约自检；版本矩阵；降级阶梯 |
| 与已装压缩插件冲突 | 五类检测；报告降级能力 |
| 记忆文件损坏或并发写坏 | 进程内单写者队列、原子写、只读降级、备份 |
| 后端成本不可见 | 成本归属分列；估算口径明确；实测/估算不混算 |
| 规则太复杂，用户不会配 | 预设、示例、解释生效来源、干跑 |
| 折叠过度，信息丢失 | 已取消自研折叠（M1.1）；宿主 pruner 的折叠行为由宿主承担，我们只观测与记录 |

## 14. 验收指标

### 14.1 测量方法

- 同一组任务场景，分别在“关闭插件”和“开启插件”下跑，记录基线；
- 上下文构成按类目统计：规则、工具定义、用户、模型文本、工具参数、工具结果、注入记忆；
- **成本归属分两列**：治理层（注入/回注/记忆读写/策略）与后端（压缩模型调用）；
- **实测与估算分开报**：
  - 实测：`assistant/message.usage`（提供方回传）；
  - 估算：`tokenMeter`（**chars/4 启发式，系统性偏低**，实测样本低估约 28%），或后端自报用量，或“摘要产出 token × 该路由单价”；
  - 两者不能混算净节省；估算值在指标表里带标记。
- 净节省 = 减少的输入 token − 治理层成本 − 后端成本；
- 先测量、后定目标；没有基线不承诺百分比。

### 14.2 指标

| 类别 | 指标 | 说明 |
|---|---|---|
| 续接 | 压缩后接续成功率 | 压缩/换会话后继续，无需重新问关键信息 |
| 续接 | 重复决策次数 | 已生效决定被再次询问或再次决策的次数 |
| 回注 | 回注重复率 | 回注内容与摘要重复的比例 |
| 回注 | 回注被吞率 | 回注内容在下一次压缩中被收起的比例 |
| 回注 | 回注后检索成功率 | 模型按指针找回记忆详情的比例 |
| 成本 | 上下文构成与每轮用量 | 按类目统计，能回答“为什么大” |
| 成本 | token 净节省（实测/估算分列） | 治理层与后端分开；估算以 chars/4 为主，系统性偏低 |
| 折叠 | — | 已取消（M1.1 收口为宿主 prune 观测） |
| 失败 | 失败显式率 | 失败被报告而不是静默的比例 |
| 失败 | 回退成功率 | 回退后会话仍可继续的比例 |
| 适配 | 行为矩阵覆盖率 | M1 支持的后端在矩阵内通过验证的比例 |
| 适配 | 冲突检测 | 冲突能被发现并报告降级能力 |
| 依赖 | 零硬依赖可用性 | 只装宿主时功能可用；适配器可选 |
| 安全 | 自动压缩未保护删除次数 | 自动压缩下受保护内容被误删/误压的次数，目标为 0；手动压缩不计入“0 丢失”，但必须有 S4=B 审计 |

## 16. 建议的最小闭环（M1，待定）

### 16.1 M0：观测基线（不改行为）

只接宿主原语，跑一周：记录上下文构成、压缩事件、动作与失败；不做自动压缩、不隐藏工具、不改行为。M0 顺带记录折叠相关数据（工具输出字节、回读次数），但不实际折叠。

### 16.2 M1：核心闭环（不含折叠）

- **后端**：宿主默认 + context-zip（E1/E2 通过后）；billion-context 暂不接入；
- **任务态契约**：内置最小文件存储，只记决定、待办、进度、判据的最小集；
- **持续固化**：回合结束/决策产生时写入；压缩前只做“确认已固化”；
- **压缩保护（S4=B）**：压缩前把受保护内容写进记忆（标题+指针）；压缩结束（`compaction/end` 发布后首个 microtask、下一次模型调用前）从记忆回注；自动压缩 5 类 0 丢失；手动压缩允许原文丢失，但必须有记忆指针、audit 显式告警、回注后能看出最后一句；写不进/注不进必须 audit。
- **回注**：读摘要 → 比覆盖 → 只放 ID/状态/指针；详情查记忆；
- **审计**：后端选择、压缩前后、成本归属、回注被吞/重复、失败。

**前置门禁**：E1 至少达到“状态级”感知；E2 选出默认回注形态。

**核心验收**：压缩后接续成功率、重复决策次数、自动压缩 5 类受保护内容 0 丢失、手动压缩满足 S4=B 三条（记忆指针/审计告警/回注最后一句）、失败显式与回退可用。

### 16.3 M1.1：增量（已收口，2026-10-25）

- **工具输出折叠**：**取消**——宿主 `tool-result-pruner` 已在压缩点覆盖 >8192；自研可折上限仅约 15.3%，收益未证。T1 门禁结论与 B2 差异表保留（`docs/M1-可行性复查-20261025.md`）。
- **批量调用提示实验**：**取消**。
- **改为**：宿主 prune 观测 + 成本接入（`REQ-20261025-02`）。

### 16.4 延后

- billion-context 接入（待 E3/E4；不可见则只读）；

## 18. 术语

- **上下文**：每次模型调用时实际发送的内容，包括历史消息、工具结果、系统提示等。
- **压缩**：把旧对话替换成摘要、删除可删段或只保留关键段，目的是减少上下文占用。
- **回注**：压缩后把记忆 ID、状态、指针放回上下文；详情仍留在记忆。
- **固化**：把关键状态写入项目记忆的动作；M1 以“持续固化”为主。
- **折叠**：把长工具输出缩成头尾摘要 + 文件指针，原文仍可回读。
- **项目记忆**：放在项目文件夹里的要点记录，跨会话保留，是唯一长期可写状态。
- **每轮视图**：本轮真正注入上下文的那部分内容，由记忆和对话派生。
- **策略**：用户配置的规则，决定何时、对什么、做到什么程度。
- **判据**：判断对错的规则或依据；落成记忆条目后可被引用和检查。
- **回滚点**：能撤销一次变更的证据或映射，属于受保护内容。
- **定时唤醒**：由调度在约定时间触发的会话启动；插件只读记忆摘要，不自己建调度。
- **全局偏好**：可选的、很小的跨项目偏好文件；默认关闭，只放偏好与教训。
- **行为契约**：适配器必须说明的控制权、感知层级、摘要权威、摘要可读性、改写边界等行为。
- **摘要权威**：压缩后的摘要是否是被压缩范围的唯一可见表示；决定回注方式。
- **摘要可读性**：治理层能否读到摘要内容/条目；决定回注是“标题+指针”还是“仅 ID+状态”。
- **感知层级**：事件级 / 工具级 / 状态级；M1 最低要求状态级。
- **契约自检**：适配器初始化时对关键行为的只读探测，防止版本升级后“能跑但漂移”。
- **覆盖度预判**：回注前用 ID/标题粗匹配摘要，判断是否需要补一行标题。
- **降级阶梯**：适配器不可用时的回退顺序，最终落到“只观测 + 固化，不做压缩干预”。
- **实测/估算**：成本可见性不同时的两种口径，分开报，不混算。
