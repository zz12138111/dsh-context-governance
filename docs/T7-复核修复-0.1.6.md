## 1. P1 阻断：`mem_write` / `mem_query` 真机未注册

**根因**（报告 COMPAT-01 已给源码依据）：描述符用了 ParameterSchemaSpec 形状，`output.schema` 的属性级
`required: true` 被宿主 `ctx.tools.register()` 的 `assertSupportedJsonSchema` 拒绝；`parameters` 也被宿主
模型侧当 JSON Schema 直通，同样不合法。异常被 `registerMemoryTools` catch 成 warn，导致两个工具都没注册。

**修法（已落地）**：

1. `src/tools/mem-tools.js` 手写**标准 JSON Schema**：
   - `parameters` → `{type:'object', properties:{…}, required:['op'], additionalProperties:false}`（去掉属性级 `required`；`mem_query` 用 `required: []`）；
   - `output.schema` → 顶层 `required` 数组（`mem_write: ['id','status','type','title']`；`mem_query: ['count','entries']`，条目 `['id','status','type','title']`；新增 `detail` 属性声明）。
2. 删除不可实现的 `defineTool` 注入路径（YAML 无法传函数），`registerMemoryTools(ctx, store)` 直接调用 `ctx.tools.register`。
3. 新增**宿主 schema 契约测试**：
   - `test/host-schema-contract.mjs`：从 `dsh-tools` 复刻 `CONSTRAINT_KEYWORDS/ANNOTATION_KEYWORDS/checkSchemaNode`（required 必须在 object、必须是字符串数组、名字必须在 properties；properties/items/enum/const 的类型位置；oneOf 规则），并提供 `assertToolDefinition`；
   - `test/tools-schema.test.mjs`（5 条）：两个工具 `parameters`/`output.schema` 全过子集；必填只在顶层；宿主 register 校验后注册成功；**旧 spec 形状被拒**（防回归）；注册失败原因可见。
4. 回归证据：旧形状会得到 `schema.properties.id.required is not supported on type "string"`，与报告复现一致。

**真机验证（需用户重启）**：新会话 `request/header` 工具清单出现 `mem_write`/`mem_query`；若仍没有，看启动日志的 `tool mem_* was not registered`（v0.1.6 起 schema 已过子集，理论上不应再出现）。

### 2.2 隐私口径 + `captureTitle`（SEC-01）

- 文档改为准确口径（README “隐私边界”）：保留的是**最新用户消息首行 ≤200 字 + 路径/批次/回滚点指针**，不是“完整正文”，也不是“只有 ID”；`MEMORY.md` 可被人读/提交。
- 新增 `captureTitle: true|false`（默认 `true`，保持现状）：
  - `false` 时 `buildProtectionItems` 只写**通用标签**（“最新用户消息”“规则注入在场”“批次进度”“回滚点”“未闭合工具调用”）与 `source=session:<id>#<seq>`，不写首行/路径；
  - 条目数量/类型/ID 不变，回注仍是 ID+状态（详情靠 `mem_query`）。
- 凭据形态拒写（8 类）保持 fail-closed，审计仍只写元数据。
- 测试：P2 用例断言 `captureTitle=false` 时标题不含首行、指针完整、条目数一致。
