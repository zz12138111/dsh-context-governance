## 0. 一页摘要

**M2 的核心目的：让“什么时候压缩”可控，并且把压缩前后的账算清楚。**

用户原始诉求只有一句：**提前压缩，省上下文、去掉过时信息**。所以：

- **提前压是主路径，不是可选项**（默认开启）；
- 抑制（推迟）是配套能力，用于“不想压太早”的会话；
- 成本账本回答“这次提前压值不值”。

**不做**：不造压缩引擎、不替换摘要后端、不接管 provider、不做 UI 仪表盘、不做货币成本。

---

## 1. 背景与关键事实

### 1.1 DSH 原生机制

- 引擎挂在 **agent preset**，出厂 `thresholdRatio: 0.8` + `headroomTokens: 65536`；有效触发点 = `floor(min(W×0.8, W−O−65536))`，1M 窗口下 ≈ **67.85%**。
- **preset 平面任何 patch 层都够不到**（profile 里写 `thresholdRatio` 无效）。
- 取引擎的唯一路径：`agentPresets.serviceFor(agent, 'compaction')`。
- 引擎契约：`compactIfNeeded`（自动压力/溢出）、`compactNow`（显式按需）、`compactRegion`（指定范围）。
- 手动 `/compact` 就是 `ctx.compaction.compactNow(agent, signal, commandId)`。

### 1.2 生态

| 插件 | 角色 | 与 M2 的关系 |
|---|---|---|
| `compaction-basic` | 原生引擎 | 包它的决策点，不改引擎 |
| `context-zip` | 替换摘要（五段式 + 分段检索） | 不动；闸门对它同样生效 |
| `tool-result-pruner` | 压缩点折叠大工具结果 | 不动 |
| `dsh-context` | 上下文/成本**可视化** | 不重复做图表；我们做“策略效果账本” |
| `dsh-compact` | 按路由比例的第三方闸门 | 证明可行；**本期不安装、不验证**，共存按保守策略处理 |

### 1.3 本机实测

- 本插件 scope 拿不到 `ctx.compaction`（`strict=false → undefined`）；
- `tokenMeter` 是 **chars/4 估算**，本例**低估约 28%**；
- `usage`（`assistant/message`）是**实测**，滞后一步；
- 手动 `/zip-compact` 不触发 `pruneSession`。

## 2. 目标（可验收）

1. **提前压可用**：`compact.at` 低于宿主原生点时，按策略主动压一次，无需等宿主的 67.85%。
2. **推迟也可用**：`compact.at` 高于宿主原生点时，抑制宿主引擎直到策略点。
3. **每层可配**：内置 / 插件配置 / 项目配置 / 会话覆盖四层；`0.30–0.85` 为默认范围。
4. **可解释**：`/cg status` 打印合成链与宿主原生触发点，以及本次闸门决策。
5. **可审计**：每次闸门判断、每次主动压、每次失败都留审计。
6. **成本可见**：按会话/项目/天/模型聚合，实测与估算分列，未知保持 unknown。
7. **与记忆协作**：显式 profile 打标；偏好只作默认值（`active` 才生效）。

## 3. 非目标

- 不造引擎、不换摘要后端、不接管 provider、不改 preset 平面；
- 不做 UI 图表；不做货币成本；不做跨机同步；
- 不改 pruner / 折叠 / spill；
- 不做行为推断自动打标（只给建议，不自动生效）。

## 4. 组成

### 4.1 策略层（0.2.0）

- 四层：内置默认 → 插件配置（`cordis.patch.yml`）→ 项目 `<project>/.cg-policy.json` → 会话 `/cg set`。
- 参数（初版）：

| 参数 | 含义 | 默认 | 范围 |
|---|---|---|---|
| `compact.at` | 到多少压力就压 | `0.60` | `0.30–0.85`（`0.20–0.30` 需 `lowThresholdAck`） |
| `compact.early` | 是否允许**主动提前压** | **`true`**（核心诉求） | bool |
| `compact.cooldownMin` | 两次压缩最小时间间隔 | `10` | 分钟 |
| `compact.minDeltaTokens` | 距上次压缩至少新增多少 token 才允许再压 | `20000` | token |
| `compact.estimateSafety` | 估算值放大系数 | `1.35`（可自校准） | `1.0–1.6` |
| `reinject.maxChars` / `maxLines` | 回注预算（既有） | 800 / 8 | 既有 |

- 校验：白名单键；未知键或越界 → 拒绝该层 + `policy-invalid` 审计，退回上一层。
- 解释：`/cg status` 打印合成链。

### 4.2 闸门层（0.2.1）

**取引擎**：`agentPresets.serviceFor(agent, 'compaction')`；拿不到 → 闸门降级为“只提示不拦截”（写审计，`/cg status` 标 `gate=unavailable`）。

**两条路径**：

| 方向 | 机制 | 何时 |
|---|---|---|
| **推迟** | 包装 `compactIfNeeded`：压力 < `compact.at` 返回 `null`；≥ 则调用原方法 | `compact.at` > 宿主原生点 |
| **提前压** | 压力 ≥ `compact.at` 且低于宿主原生点时，调 `compactNow(agent, signal)` | `compact.early=true`（默认） |

**硬约束（评审回写）**：

1. **Fail-open**：闸门自身任何异常（测量失败、策略解析失败、包装报错）→ **必须放行**并留审计 `gate-error`，绝不能让治理层把宿主压缩堵死。
2. **异常透传**：捕获到溢出/上游错误时，**原异常无条件透传**给宿主，不吞、不改造。
3. **溢出救援永不放拦**：`trigger` 为 `context-overflow` 时直接透传。
4. **`compactNow` 限制**：仅 agent 空闲时调用；失败走指数退避，最多 N 次，严禁重试风暴。
5. **共存保守**：包装时打 Symbol 标记（防自己重复包）；检测到无法确认的来源 → **禁用自身 + 告警**，不硬包；`gate.force=true` 可强开（用户明确知情）。
6. **防抖**：`cooldownMin` **且** `minDeltaTokens` 双条件满足才允许再次触发，防阈值边缘反复压。

**审计**：`gate-decision { measured, policy, source, decision(skip|delegate|forced), trigger }`；`gate-forced` 记压缩调用与结果。

### 4.3 成本账本（0.2.2）

- 数据源：`compaction-cost`（`cost-v1.2`）+ `gate-decision`。
- 聚合：`sessionId` / `project` / `day` / `model` / `backend`。
- 命令：`/cg cost [--by day|project|model] [--since …]`；输出周期数、shadowed、summary、injected、dropped、pruned，并标来源。
- 预算：只提示（`budget.warnAt`），不阻断。
- 口径：`usage` = measured；`tokenMeter×safety` = estimate；不混算；未知保持 unknown。
- **重点**：记“提前压赚了多少、花了一次摘要多少钱”，即策略效果账本（与 dsh-context 的仪表盘区分）。

### 4.4 表面与命令

- `/cg status`：策略链 + 宿主原生点 + 闸门状态 + 最近决策 + last-cost。
- `/cg set compact.at=0.5`：会话覆盖。
- `/cg compact now`：手动立即压一次（评审建议，采纳）。
- `/cg policy show`：解释当前生效来源。

## 5. 会话特点与偏好

- **profile 显式打标**：`batch` / `coding` / `research` / `review`；不自动推断。
- **默认参数表**：

| profile | compact.at | 回注预算 |
|---|---|---|
| `batch` | 0.45 | 400 / 4 行 |
| `coding` | 0.60 | 800 / 8 行 |
| `research` | 0.75 | 1600 / 16 行 |
| `review` | 0.55 | 800 / 8 行 |

- **偏好**：`type=preference` 且 `status=active` 才影响默认值；`proposed` 不生效。
- **合成顺序**：显式层（会话 > 项目 > 插件）> 标签层（profile/偏好）> 内置默认。

## 6. 安全机制（评审补强汇总）

### 6.1 估算误差与安全系数

`tokenMeter` 按 chars/4 估算，实测低估约 28%。**直接拿估算值卡阈值会危险**：以为在 60% 拦截，真实可能已 83%。

做法：
- 判定用 `pressure = max(上次 usage 实测比例, 估算比例 × estimateSafety)`；
- `estimateSafety` 默认 1.35（按观测 28% 低估换算 ≈ 1.39，留一点余量），可配；
- 长期用「同一时刻 usage 与估算的比值」按模型自校准，取 p90；
- 文档明确：**误差代价是“更早压”，这是为不溢出付的账**。

### 6.2 冷却与相对增量

- 时间冷却 `cooldownMin`；
- 增量冷却 `minDeltaTokens`（默认 20k）；
- 两条都满足才允许下一次自动触发，避免震荡。

### 6.3 溢出双保险

- `compactIfNeeded` 的 `trigger` 为溢出 → 透传；
- 任何异常 → 透传原异常 + 审计，绝不吞。

## 8. 验收标准（草案）

1. **提前压生效**：`compact.at` 低于宿主原生点时，会话在策略点被主动压缩一次；审计有 `gate-forced`；压缩后事件流完整（start→summary→checkpoint→end）。
2. **推迟生效**：`compact.at` 高于原生点时，闸门抑制到策略点才放行。
3. **Fail-open**：人为注入闸门异常 → 宿主仍能正常压缩，审计有 `gate-error`。
4. **溢出不拦**：溢出触发路径全程透传（测试/回放证明）。
5. **防抖**：cooldown + minDelta 双条件生效，不出现连环压缩。
6. **可解释**：`/cg status` 打印合成链、原生点、闸门状态。
7. **成本账本**：聚合值 = 逐条求和；实测/估算分列；能回答“提前压赚了多少”。
8. **记忆协作**：`proposed` 偏好不生效；显式 profile 只影响默认。
9. **不回归**：M1 的 S1–S6 通过；生产代码仍无折叠。
