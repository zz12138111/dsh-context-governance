## 4. 发布前必须解决的口径冲突

**已定（审核，2026-10-26）**：

1. **`engines.dsh` 维持 `">=0.2.1-rc.2 <0.2.2-0"`，不改宽**——1.0 只承诺已验证范围；矩阵明确写「**0.2.2 未验、不支持**」。理由：宿主升到 0.2.2 时插件会被 engines 拒载，这是**显式安全行为**，比“放行但未验”诚实；等拿到 0.2.2 构建并在隔离复跑后，再随版本放宽（post-1.0 任务，记入 `docs/REQ-12-发布就绪-计划.md` §4）。
2. **版本号**：`package.json` 仍 `0.2.1`，1.0 发布须 `1.0.0`（开发提交、审核复核）。
3. **context-zip × 0.2.1-rc.3：已复跑（2026-10-26）**。`desktop-test-contextzip` 上完成**自动触发**（非仅探针 G2-A）：`early-forced accepted=true / effective=0.437 / at=0.35`、`compaction-cost 161580→2981`、保护/回注齐全；证据 `analysis/req-20261025-12/drills/contextzip-R2-20261026.md`。**adapter 识别/摘要形态仍未验**（实测仍 `host-basic (inferred)`/free-form），不逆向宿主内部；实际后端由 redirect+bundle 钉住。
4. **CI 门禁**：按需求 `6005e7c`——CI 失败即阻发布、不可 `--no-verify` 跳过；已接入 `.github/workflows/security.yml`（#3 通过：windows 单测 + ubuntu 扫描/gitleaks；gitleaks 未需 license）。
