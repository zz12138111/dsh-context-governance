# 快速上手 —— 上下文治理插件

> **v2.1 定稿**（用户 2026-10-26 验收通过）。面向用户的正式指南，位于 `docs/guides/`；npm 安装包只含插件运行文件，**不含本目录**（完整指南在仓库/公开仓内）。
> 原则：只写**已具备**的能力；不写未量化的收益；不承诺未做的功能。

## 一句话

**给长任务加一层"防失忆 + 自动清理"的治理**：压缩前替你记笔记，压缩后帮你接上；不用写复杂配置，装好默认就工作。

## 你是不是遇到过这些"崩溃瞬间"？

- 刚跟模型确认完 5 个架构决定、跑了 20 轮工具，**突然触发系统压缩**。下一秒模型问你："好的，我们要做什么来着？"——你得把之前的决定、进度再啰嗦一遍。
- 换个会话接着干，模型像失忆了一样：不记得架构规范，也不记得定好的技术路线，只能手动把上一把的总结复制过来。
- 系统压得太晚：快撑爆了才压，一压丢一大片，留一堆烂摊子接不上。
- 手上好几个项目文件夹，在这个配了插件，切到另一个等于没装。
- 压了好几次，到底腾出了多少上下文、哪次压得值，心里没底。

## 它是怎么保护你的（装完即生效）

1. **压缩前先写备忘**：系统动手之前，它先把【目标、待办、最近决定、关键约束】存进**项目记忆**；压缩后只把核心索引回注，**绝不生成第二份啰嗦的摘要**。
2. **新会话自动带前情提要**：开局注入上一把的关键状态。它非常克制——**最多 8 行摘要（实测约 69 tokens，几十个字的量）**，只带动态状态，绝不霸占模型内存。**如果和规则文件（AGENTS.md）冲突，以规则文件为准。**
3. **提前压，但不抢戏**：系统原本要等窗口**接近七成**才压；本插件默认在 **60%** 就找安全时机清理旧账，给模型留出思考空间。清理完就收手，绝不干扰系统的兜底压缩。
4. **一个会话一个档**：长时间跑自动任务用「长跑档（batch）」、写代码用「编码档（coding）」、评审用「评审档（review）」、研究用「研究档（research，完全不提前压）」。**同一个人的不同会话各用各的档，互不影响**；会话里还能临时微调，重启就回默认——敢试、不污染全局。
5. **多工作区全覆盖**：按你打开的文件夹自动识别项目根，各项目**记忆独立、压缩独立**，不用挨个配一遍。
6. **老决策自动让位**：记忆里的旧决定会被标 `[Old]` 排到末尾，**不占主预算**；真正的去重清理在 1.1 版本。
7. **压缩留痕**：每次压缩前后的 token 消耗、用的什么后端，都有记录（**跨会话汇总账单在 1.1**）。

## 怎么用？

装完就能用，默认全部开启。

- **看状态**：`/cg status`
- **给这个会话换档**：`/cg profile review`（或 `batch` / `coding` / `research`）
- **临时改阈值**（只影响本会话，重启回默认）：`/cg set compact.at=0.65`
- **关掉本会话的提前压**：`/cg compact disarm`
- **全局关掉**：在插件配置里设 `compact.early.armed=false`，重启生效

## 🚫 它不做什么（重要提醒）

- **不防误删**：系统暂不支持可靠的拦截前钩子，本插件**不能阻止**模型执行 `rm -rf` 这类危险命令。请不要让它乱删文件。
- **不存原文**：压缩不可逆，旧对话会被丢弃，只留记忆指针。**重要结论请自行存档。**
- **不做图表和计费**：只提供 token 级别的单次记录，不换算成钱，暂不支持多机器同步。

## 谁适合用？谁不适合？

- **适合**：写长代码、跑长工具链、单次任务超过 **20 轮**、需要跨会话接着干的人；同时开多个项目工作区的人。
- **不适合**：只问几句短问题的人；要求压缩后"原始对话一字不差完整保留"的人。

## ⚠️ 当前版本的已知限制

- **提前压的收益没有 A/B 数据**：机制上能更早释放上下文，但"到底省了多少"尚无实测量化。
- 单次压缩会产生少量重建开销（约 **3.4KB/次**），暂未单列进成本字段。
- **自动压缩在常规聊天里触发很少**（防护与验证重心在长任务、高频工具调用引发的极端上下文过载）；该路径已在桌面默认部署**真机触发 ≥3 次**（2026-10-25，`early-forced` + `compaction-cost`），但**完整闭合链仍缺一份同会话 `/cg status` 原文**——这是**证据范围**的说明，不代表稳定性问题。

## 技术说明（给要深究的人）

- 提前压阈值 `compact.at` 默认 **0.60**（真实占窗口比例，可调范围 0.20 ~ `native−0.02`）；宿主原生触发点约 **67.85%–69.34%**（本机实测 0.6934；**受模型输出预留下限影响**，换模型会变）。
- header 预算默认 **8 行 / 800 字符**，实测注入约 **69 tokens**；有规则文件时只带"进度/待办/决定/锚点"，无规则文件时多一行"偏好（非硬规则）"。
- 多工作区：每个会话按自身 cwd 上溯最近的 `.git` 认定为项目根；显式配置的项目根优先（其下会话统一归该根）。
- 成本：每次压缩写 `compaction-cost`（压前/压后 token、来源、后端类型）；账本与汇总在 **1.1**。
