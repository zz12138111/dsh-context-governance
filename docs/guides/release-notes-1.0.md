# 1.0.0 发布说明

> **发布形态**：仅 GitHub（tag `v1.0.0`），不发布到 npm。
> 当前 tag：`v1.0.0`（`55a8c08`）。`v0.2.1`（`f585434`）作为**历史兼容 tag 保留在仓库中、可见**，仅作旧版兼容回滚参考，**不推荐新装使用**；1.0 的回滚以 `v1.0.0` 为准，见文末「回滚」。

## 亮点

1. **全会话多根治理**：按会话 cwd 上溯最近的 `.git`（文件或目录）判定项目根；每个纳管根独立 `MemoryStore`、`memory/governance/audit.jsonl`、写者锁、`RootGuardPool` guard、header 与提前压状态。A 根的事件不落 B 根。
2. **`configRoot` 强制合并**：`projectRoot` 非空时其下会话统一归该根，嵌套 `.git` 不另立根；根外会话按自身 cwd 独立成根。
3. **压缩保护与重建**：压缩前把任务态写进项目记忆；压缩后只回注核心索引。被 shadow 的最新用户消息/规则注入会用同源内容重建副本，再按新序号校验。
4. **新会话 header**：最多 **8 行 / 800 字符**，只带动态状态；与 `AGENTS.md` 冲突时以规则文件为准；子会话不注入、不写记忆。
5. **提前压**：默认窗口 **60%** 找安全时机触发，近宿主原生阈值时让给宿主；冷却 10 分钟、增量 1 个百分点。可会话级 `disarm` 或配置关闭。
6. **安装 / 卸载 / 迁移**：`file:` 依赖 + junction + bundle；v1→v2 状态自动迁移并留 `.v1.bak`；卸载保留各根记忆与用户级根状态。
7. **成本与留痕**：每次压缩写 `compaction-cost`（压前/压后 token、来源、后端类型）；审计只写元数据，不写正文。

## 默认值

| 键 | 默认 | 说明 |
|---|---|---|
| `compact.early.armed` | `true` | 默认允许真实提前压；`/cg compact disarm` 或配置 `false` 关闭 |
| `compact.at` | `0.60` | 占窗口比例；有效上界 `< native − 0.02`（1M 窗口本机实测 native ≈ `0.6934`） |
| `header.enabled` | `true` | 新会话注入记忆 header；`/cg header off` 或配置关闭 |
| `projectRoot` | `""` | 空 = 按会话 cwd 推断；显式配置优先且强制合并 |
| `memoryRoot` | `memory/governance` | 相对项目根 |
| `diagnostics.logFile` | `""` | 空 = 不写诊断文件；非空必须绝对路径 |

## 已知限制

- **提前压的收益没有 A/B 量化数据**：机制上更早释放上下文，实际节省未实测。
- 单次压缩有少量重建开销（约 **3.4KB/次**），暂未单列进 `compaction-cost.tokensInjected`；成本以 `tokenMeter` 的 before/after 为准。
- **自动压缩在常规聊天里触发很少**（防护重心在长任务、高频工具调用）；该路径**尚未真机验证**——证据范围说明，不代表稳定性问题。
- **1.1 才提供**：记忆去重清理、跨会话汇总账单；本版不宣称已提供。
- `configRoot` 内嵌套 `.git` 不另立根，显式配置根内多根隔离不完整（已知限制，不是 bug）。
- 不防误删：不能阻止模型执行 `rm -rf` 等危险命令。
- 不存原文：压缩不可逆，旧对话丢弃后只留记忆指针；重要结论请自行存档。
- 不做图表与计费：只有 token 级单次记录，不折算金额、不支持多机同步。
- 宿主兼容：`engines.dsh = ">=0.2.1-rc.2 <0.2.2-0"`；DSH 升到 0.2.2+ 会被拒载。

## 安装

解压包目录，在 DSH profile 中用 `file:` 依赖 + bundle 挂载，`node_modules/@local/dsh-context-governance` 指向包目录（junction）。**不要**运行 `pnpm install` / `dsh plugin add`。
