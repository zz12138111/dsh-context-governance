## 2. 目标（可验收）

1. **动作校验可用**：三条固定检查项，能在执行前拦截并要求确认；不能拦截时降级为检测 + 告警 + 审计（需用户预先接受）。

4. **可发布**：仓库无未脱敏真实正文；文档命令与实现一致；兼容矩阵与回滚步骤齐备。

## 4. 组成

### 4.1 动作校验最小集（§7.2）

**固定检查库（初版三条）**

| # | 检查项 | 触发 | 行为 |
|---|---|---|---|
| C1 | 删除/移动前必须有回滚点 | `rm`/`del`/`move`/`format`/`git reset --hard` | 拦截并要求给出备份路径或 commit |
| C2 | 写操作不得越出工作区 | 写/改/删路径解析后不在工作区根下 | 拒绝，提示目标路径 |
| C3 | git 危险动作 | `push --force`、`filter-branch`、改 remote、tag 发布 | 直接拒绝（tag/发布归用户批准） |

**约束**
- 配置只引用检查项（`checks: [C1, C2]`），**不写脚本**；
- 不自己造审批系统，交互复用宿主权限/审批；
- 门禁 **G-M3-1**：pre-execute 能否拦截/否决。
  - 可拦截 → 按上表“拦截/拒绝”；
  - 不可拦截 → 降级为“检测 + 告警 + 审计”，**用户需预先接受**（否则砍掉本节）。

**验收**
- 三条检查项各有正例/反例单测；
- 拦截时给出明确理由与替代方案（如备份路径）；
- 降级模式下告警可见、审计可查；
- 不产生误伤：普通写文件/正常 git 操作不触发。

### 4.2 S3 header 默认开

**默认开（内置层）**，按“有无规则文件”分两种形态：

| 形态 | 判定 | 注入内容 |
|---|---|---|
| **精简（有规则文件）** | 工作区根存在 `AGENTS.md` / `CLAUDE.md` 或同类 | 只放 **进度 / 待办 / 最近决定 / 锚点**；**不放偏好与规范**（避免与规则重复/冲突） |
| **完整（无规则文件）** | 上述文件不存在 | 额外加 **偏好 / 约束** 一类，标注“偏好（非硬规则）” |

**六条护栏**
1. 预算：≤8 行 / ≤800 字符，只放 `ID + 一行标题`，详情不进 header；
2. 来源过滤：只取 `status=active`，按更新时间倒序，超 7 天标 `stale` 排末尾；
3. 零注入：无项目目录或记忆为空 → **完全不注入**；
4. 冲突声明：固定一行“以下为记忆状态；与 AGENTS.md/系统规则冲突时以规则为准”；
5. 可关闭：`/cg header off`（本会话）、项目配置、插件配置；
6. 审计：每次注入记 `header-injected`（条数、token 估算、形态 A/B、来源层）。

**边界**
- 子会话：默认不注入（或预算减半）——**待评审定**；
- 只读模式：不注入记忆写内容，仅提示；
- 记忆过期：不删除，标 `stale`。

**验收**
- 有/无规则文件两种形态各跑一次，内容符合上表；
- 关闭后零注入；空记忆零注入；
- 注入内容不含详情、不含敏感项；
- 审计可查“这次为什么带了这段”。

### 4.3 “不重问”评测（非功能）

- 场景：压缩后提问一个“只有记忆里才有”的问题（如“我们决定不做哪件事”），观察模型是 `mem_query` 还是重问；
- 至少 3 个场景（决定 / 待办 / 进度各一）；
- 产出评测记录（非代码）；不达标则回到 M2 检查回注内容与 header 文案。

### 4.4 发布就绪

- **脱敏**：`analysis/**/snapshot-*.json`、含真实正文的样本必须删除或脱敏（公开仓库前硬门禁）；
- **文档定稿**：README、使用说明的命令与版本一致（0.2.x 实际可用 vs 计划）；
- **兼容矩阵**：DSH 版本（0.2.x）、压缩后端（原生 / context-zip）、M1.1 取消项；
- **安装/卸载/回滚**：卸载后行为恢复、审计/记忆文件处理；
- 打包与 Release 由审核打包负责。
