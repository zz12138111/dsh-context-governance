## 5. 自证门禁（发布前必须全过）

先给结论：`node scripts/compliance-scan.mjs --strict` **不够**。它只在 `blocker` 时退 1，而 `path:windows-user-path` 记的是 `review`（实测：`blocker=0 review=2 info=92`，其中 `path:windows-user-path: 21` 不阻断）。必须补下面 7 条硬门禁：

| # | 门禁 | 通过条件 |
|---|---|---|
| G1 | 白名单比对：`git ls-files` 与 §1 白名单逐项 diff | 差集为空（公开树只有白名单路径） |
| G2 | `git grep -nE '[A-Za-z]:[\\/]{1,2}Users'` | **0 行**（真实路径与转义占位全覆盖） |
| G3 | `git grep -nI "$env:CG_NEEDLE"`（needle=真实用户名，执行时由 00 提供，只放环境变量） | **0 行** |
| G4 | `git grep -nE 'DS-PROJECT|DSH插件开发'` | **0 行**（示例统一用占位） |
| G5 | `git grep -nE 'session-[0-9a-f]{8}-' -- packages/dsh-context-governance` | 仅 fixtures 允许，且逐文件白名单；其余 0 |
| G6 | `node scripts/compliance-scan.mjs --strict` | `blocker=0`（**不能单独作为通过依据**） |
| G7 | `git rev-list --count HEAD`；`git tag`；`git ls-remote --tags/--heads` | =1（单根）；tag 仅 `v1.0.0`；远端无旧 ref |

> G3 的 needle 不落盘、不写进本文件的原因：门禁文件本身若写入真实用户名，等于把隐私搬进公开仓。执行时取一次，放进程环境变量，输出只打印长度。

## 6. 执行后我贴的验收输出（脱敏）

1. G1–G7 原样输出（needle 只显示长度，不显示值）；
2. `git log --oneline`（单根提交）；
3. `git ls-files | wc -l` 与白名单计数一致；
4. `compliance-scan --strict` 摘要 + `path:windows-user-path` 计数 **0**。
